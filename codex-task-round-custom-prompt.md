# Задание: «Custom» в списке ролей раунда и карточка промежуточного синтеза

База: `main` 2.81.651. Файлы: `results.js`, `results/stage-card.js`, `pipeline/pipeline-runtime.js`, `disput/custom-engine.js` (если нужно), тесты, документация. Решение минимально достаточное, без новых настроек.

## 1. Пункт «Custom» в списке ролей

В списке ролей (мини-запросов) Custom-раунда появляется пункт **Custom**. При его выборе показывается поле ввода своего мини-запроса.

- Где виден пункт: в выпадающем списке карточки раунда («Роль для всех моделей раунда») и в `.role-selector` каждого блока модели раунда. Только когда выбран pipeline на движке Custom (`getPipelinePreset(...).runner === 'custom'`); другие pipeline список не меняют (`.role-selector` создаётся в `pipeline/pipeline-runtime.js`, опции — `buildJudgePromptOptionsHtml`).
- Поле ввода — в карточке раунда, показывается только когда выбрано Custom. Это единственное место ввода: в блоке модели пункт Custom означает «использовать текст раунда».
- Хранение: один текст на раунд, `customDefaults.roundPrompts[ref]` (`ref` = `r2`, `r3`, …) — рядом с остальными значениями ▶, без нового механизма: сохранение, копирование, экспорт/импорт, встроенный шаблон теряет до перезагрузки — как у `modelNotes`.
- Применение: в `customStepsFromPlan` для модели с ролью Custom `extra` = текст раунда (пусто → пустой `extra`). Остальные роли работают как сейчас. Модель с другой ролью в своём блоке получает её, а не текст раунда.
- Роль-значение `custom` не должна сбрасываться при сохранении/восстановлении стека (`resolveJudgePromptId` и восстановление `.role-selector` в `results.js` знают только id из списка мини-запросов — проверить и учесть).
- Карточка раунда для Architecture без изменений.

## 2. Пометка в карточке модели

Если у модели сохранён персональный запрос (`promptTemplate`), а в блоке выбрана роль, в карточке модели одна строка:
«Роль не применяется: используется персональный запрос». Поведение сборки не менять (персональный запрос заменяет сборку целиком).

## 3. Карточка промежуточного синтеза

Финальный синтез открывает карточку модели с персональным запросом (`customBlockRef` → `'final'`).
Промежуточный синтез (вставка между раундами, шаг `ref: synth:<plannedStageId>`) карточку, судя по коду, не открывает:
`customBlockRef` возвращает пустой ref → «Шаг модели не найден в плане».

- Проверить это на деле; если так — вернуть для блока промежуточного синтеза ref `synth:<plannedStageId>` и открыть ту же карточку (персональный запрос, длина, дисциплина) — тот же код, второго пути не заводить. Настройки хранятся как у других ref (`customCardSettings[ref][модель]`).
- Роль и пункт Custom синтезу не нужны.

## Проверка

Тесты проверяют текст, который реально уходит модели (`starts[i].promptsByModel`), как в существующих Custom-тестах.
1. Custom в карточке раунда: поле появляется только при выборе; текст попадает в «Дополнительно для тебя» всех моделей раунда; модель с другой ролью получает свою; пустой текст → без `extra`.
2. Текст раунда сохраняется/копируется/экспортируется; встроенный шаблон теряет его после перезагрузки.
3. Пункт Custom есть только у pipeline на движке Custom; значение переживает перерисовку стека.
4. Пометка о персональном запросе видна и не меняет сборку.
5. Карточка промежуточного синтеза открывается, персональный запрос уходит модели этого синтеза.
