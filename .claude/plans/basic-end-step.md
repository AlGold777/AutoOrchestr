# Basic: шаг End

## Концепция (согласована с владельцем 2026-11-22)

ПРИНЦИП: In — то, что User даёт прогону; End — то, что User получает от прогона. End — второй особый шаг User, пара к In.
1. End — постоянная колонка в конце холста, как In. Одна в каждой схеме, не удаляется и не переставляется.
2. В схеме End указывает, что считается итогом: какие артефакты и ответы каких раундов. Ничего не указано — итог = принятый ответ последнего раунда. На холсте от этих раундов к End идут линии, как к артефактам.
3. В прогоне End — последний шаг User: окно с итоговыми документами в последней утверждённой версии, копирование и сохранение в папку прогона. Закрытие окна завершает прогон. Окно заменяет финальное уведомление «Basic: <причина>.» как то, что User видит в конце.
4. Движок End не отправляет моделям. Только собирает указанные артефакты. Без проверок и решений за User, без переходов назад.

НЕИЗМЕНЯЕМОЕ: схемы без End работают как раньше (итог по умолчанию); причины остановки и lifecycle не меняются; при остановке не по steps_done End показывает накопленное с причиной; resume восстанавливает открытое окно End, как окно owner.

## План
(ведёт ведущий; решения исполнителя на этапе документов, 2026-11-22)

- Имя поля: `end` в корне схемы, рядом с `run` и `spec`. Причина: совпадает с названием колонки в интерфейсе.
- Формат итога: `end.from` — список источников той же формы, что вход шага (5.7). Причина: одна проверка ссылок с входами, новый синтаксис не нужен.
- Нет `end`: принятый ответ последнего раунда с включённой моделью; у раунда с документом — последняя версия документа. Причина: концепция, п. 2.
- End не элемент `steps[]`: нет `ref`, моделей, вклада в предел раундов. Причина: движок End не выполняет.
- Окно: одно окно со всеми итоговыми документами в порядке `end.from`; каждый — раздел с названием, версией и своей кнопкой копирования; «Сохранить» пишет все в папку прогона; закрытие завершает прогон. Причина: решение ведущего (концепция, п. 3: одно окно с итогом). Новая вёрстка окна — часть этапа кода, не ограничение.
- Колонка End на холсте: источники берутся из исходной схемы, как `spec`, не редактируются на холсте. Причина: минимальное решение.
- Уведомление: окно End полностью заменяет финальное уведомление «Basic: <причина>.»; причина в заголовке окна, в том числе при `steps_done`. Без принятых ответов окно пишет «Принятых ответов нет.». Ошибка вне движка окна не открывает. Решение ведущего.
- Шаги: документы — сделано (этот этап); код (схема, движок, страница, тесты, версия) — не начат, по указанию координатора.
- Stop во время окна End: прогон уже завершён, поэтому Stop на панели только закрывает окно End; причина остановки не меняется. Причина: окно End — часть завершения прогона, причина уже записана в запись и не должна меняться.

## Контракт этапа кода (ведущий, 2026-11-22)

Три части, у каждой свои файлы. Части опираются только на этот контракт.

**Схема — `disput/basic-schema.js`.**
- Корневое поле `end` теперь известно. Валидатор проверяет его по 5.11 и пишет ошибки с путём `end.from[i]`.
- `BasicSchema.endSources(schema)` → массив нормализованных источников `[{ step: 'r2' } | { step, participant } | { step, participant, artifact: '<id>' }]`. Без `end` возвращает `[{ step: <последний раунд с включённой моделью> }]`, а если такого раунда нет — `[]`.
- `toCanvas` отдаёт `end: { sources }` (тот же массив).

**Движок — `disput/custom-engine.js`.**
- Новая опция `run`: `provideEnd` (async). Нет опции — поведение прежнее.
- После цикла шагов, при любом `stopReason`, кроме ошибки вне движка (исключение), движок собирает `items` по `options.end` (массив из `endSources`; не передан — последний раунд с принятыми ответами). Формат элемента: `{ step, participant, title, version, text }`. Для документа текст берётся из последней версии реестра артефактов, включая правку User; иначе — принятый ответ (очищенный текст).
- Перед окном: `checkpointNow(..., { pendingOwner: { kind: 'end' } })`, затем события `custom_wait_start` и `custom_wait_end` с `waitKind: 'end'`. Вызов: `await provideEnd({ items, stopReason, stopDetail })`. После него — `checkpointNow` с `pendingOwner: null`. Результат прогона (`stopReason`, `answers`, `stopDetail`) не меняется.
- Resume: при `pendingOwner.kind === 'end'` шаги не выполняются, окно End открывается снова.

**Страница — `results.js`, `results/stage-card.js`.**
- `basicSchemaFromPage` переносит `end` из исходной схемы, как `spec`.
- `syncControlColumns` рисует колонку End в конце холста и линии от источников из `toCanvas(...).end.sources`.
- `runCustomFromPage` передаёт `end: BasicSchema.endSources(schema)` и `provideEnd`: одно окно End, в заголовке `basicRunNotice(...)`, для каждого элемента — раздел (title, version, text, кнопка копирования), «Сохранить» пишет все документы существующим механизмом сохранения результата, «Закрыть» завершает ожидание. Stop на панели при открытом окне только закрывает окно.
- Финальный `showNotification(basicRunNotice(...))` не вызывается, если `provideEnd` был вызван; при ошибке вне движка остаётся как есть.

Тесты частей: `tests/basic-end-schema.test.js`, `tests/basic-end-engine.test.js`, `tests/basic-end-page.test.js`.
