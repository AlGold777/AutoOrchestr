# Функции локальной модели: реестр, режимы, окно настроек

## Концепция (согласована с User 2026-11-21)

ПРИНЦИП: функция локальной модели описывается заданием (когда вызывается, что возвращает, как приложение проверяет ответ, уровень влияния), а не моделью. Модель можно заменить; плохой ответ отбрасывается проверкой и ничего не меняет. Каждую функцию владелец включает и выключает чекбоксом отдельно для каждой модели. Режимы Light / Middle / High / Extra High выставляют чекбоксы по уровню влияния функции.

ЧАСТИ:
- Реестр функций (`disput/local-model.js`) — список функций и их уровней; хранение выбора; проверка `feature(id)`.
- Очередь вызовов (`disput/local-model.js`) — все запросы к Ollama идут по одному, участник раунда первым.
- Кнопка и окно (`pipeline_panel.html`, новый `results/local-model-features.js`, стили) — показ и правка выбора.
- Места вызова (`results.js`) — спрашивают `feature(id)` вместо `enabled()`.

НЕИЗМЕНЯЕМОЕ:
- «without LLM» — локальной модели нет, кнопки нет, ни одна функция не вызывается, приложение работает как раньше.
- После обновления поведение не меняется: три существующие функции по умолчанию включены.
- Новая функция в будущем по умолчанию выключена.
- Участник раунда «Qwen 4B» не функция окна: его включает схема; проверка перед стартом (`results.js` ~7349, `enabled()`) остаётся.
- Выбор модели — только в переключателе `#local-model-select`; в окне выбора модели нет.

## План

### Решения ведущего

Уровни влияния (по возрастанию) и режимы — режим включает все функции своего уровня и ниже и выключает остальные:

| Уровень | Режим | Смысл |
|---|---|---|
| `log` | Light | только читает и пишет в Log |
| `hint` | Middle | плюс подсказки владельцу |
| `heavy` | High | плюс функции с частыми вызовами или большим контекстом |
| `act` | Extra High | плюс действия после подтверждения владельца |

Первые функции реестра:

| id | Название в окне | Группа | Уровень | По умолчанию | Место вызова |
|---|---|---|---|---|---|
| `stall_watch` | Наблюдение за зависшими вкладками | Наблюдение за вкладками | `log` | вкл | `results.js` ~7547, `createStallWatch({ enabled })` |
| `failure_look` | Разбор вкладки, не давшей ответа | Наблюдение за вкладками | `hint` | вкл | `results.js` ~7973, `decide` → `observeTab` |
| `owner_hint` | Подсказка владельцу: принять или вернуть | Подсказки владельцу | `hint` | вкл | `results.js` ~7988, `ownerHint` |

Значит, по умолчанию у обеих моделей режим Middle.

Хранение: `chrome.storage.local`, ключ `localModelFeatures` = `{ [modelId]: { [featureId]: boolean } }`. Нет записи — значение `defaultOn` из реестра. Режим не хранится: он вычисляется по чекбоксам (совпал с набором режима — его имя, иначе «Свой»).

Окно показывает только режимы, у которых есть хотя бы одна функция своего уровня (сейчас Light и Middle). Изменения применяются сразу, кнопки «Сохранить» нет.

Очередь: одна на страницу. Приоритет: участник раунда и `ping` (`participant`) → подсказка владельцу (`owner_hint`) → наблюдение (`stall_watch`, `failure_look`). Внутри одного приоритета — по порядку поступления. Таймаут вызова считается с момента, когда вызов вышел из очереди. Если `signal` отменён до начала — вызов снимается без запроса.
