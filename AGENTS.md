# Простота решений и общения

- Предлагать минимально достаточное решение задачи. Не раздувать интерфейс, архитектуру и ответы.
- Не добавлять функции, поля, настройки, проверки и пояснения без конкретной практической необходимости в рамках запроса пользователя.
- Для рабочего инструмента оставлять только то, что помогает выполнить действие. Дополнительную информацию не превращать в самостоятельные разделы без необходимости.
- Если существующее решение достаточно, прямо сказать об этом; не придумывать улучшения ради списка предложений.
- Отвечать кратко и по существу. Расширять решение только по запросу пользователя или при выявленной необходимости.
