# Простота решений и общения

- Предлагать минимально достаточное решение задачи. Не раздувать интерфейс, архитектуру и ответы.
- Не добавлять функции, поля, настройки, проверки и пояснения без конкретной практической необходимости в рамках запроса пользователя.
- Для рабочего инструмента оставлять только то, что помогает выполнить действие. Дополнительную информацию не превращать в самостоятельные разделы без необходимости.
- Если существующее решение достаточно, прямо сказать об этом; не придумывать улучшения ради списка предложений.
- Отвечать кратко и по существу. Расширять решение только по запросу пользователя или при выявленной необходимости.

# Старт новой сессии

- Эти правила — постоянные инструкции проекта для новых и возобновлённых задач. Не просите User повторно обучать вас возможностям, уже описанным в `docs/Agents/`.
- Сначала прочитайте `docs/Agents/agent-onboarding.md`: откуда загружено расширение и как доставлять правки в основной чекаут, правила версии и git, как работать с User, текущий статус работ над схемами и ближайшие шаги.
- Для любого задания, затрагивающего интерфейс, кнопки, DOM, настройки или реальное тестирование страниц расширения, сначала используйте `docs/Agents/agent-extension-pages-spec.md`. В ней описаны обе страницы (`pipeline_panel.html` и `result_new.html`), элементы интерфейса, фактические обработчики и prerequisites реальных model runs.
- Изолированная проверка в настоящем Chrome с загруженным расширением: `docs/Agents/agent-live-chrome.md` (отдельный профиль и CDP; делать самим, User не просить). Для селекторов и методов страницы `pipeline_panel.html`: `docs/Agents/agent-extension-page-control.md`. Обычный Chrome User’а использовать самостоятельно при наличии подходящего инструмента, в рамках задачи; инструкция: `docs/Agents/agent-real-chrome-control.md`.
- «Универсальный доступ» для приложения Claude уже включён: `osascript` (UI-скриптинг, настоящий JXA-клик) работает прямо из `Bash`, вкладка терминала и подтверждения User не нужны. Не просите User включать доступ; при сомнении проверьте одной командой: `osascript -e 'tell application "System Events" to get name of first process whose frontmost is true'`.
- Реальный запуск на сайте модели требует явного разрешения на отправку конкретного тестового prompt; наличие авторизованных вкладок, доступного CDP и fixture сверяйте со спецификацией. UI-проверки без отправки выполняйте самостоятельно в обычном Chrome при наличии инструмента. Отдельный профиль используйте для проверок, которым нужна изоляция; авторизация моделей в новом профиле обычно отсутствует.
- Прогоны Basic в Chrome: процедура, чек-лист, скрипты, режимы моделей и состав участников — `docs/Run Automation/` (начинайте с `run-procedure.md` и `model-modes.md`). Поведение каждой платформы и среды (блокировка экрана, перезагрузка расширения, лимиты) — `docs/Platform specifics/`. Единый реестр нерешённых проблем движка — `docs/Agents/basic-issues-registry.md`: новую находку вносите в тот же ход. Мастерство составления схем и журнал уроков — `docs/Scheme create/schema-craft-handbook.md`.
- Правило прогона: если модель выбыла по любой причине, прогон идёт дальше без неё, владельца это не должно волновать и он не вмешивается (необязательных участников пропускают, обязательных смотрят на странице без отправки запросов). Любое видимое окно страницы расширения наблюдатель ловит и обрабатывает сам (три вида окон — в `docs/Agents/agent-live-test.md`). Состав и режимы моделей — только по `docs/Run Automation/model-modes.md`, не по памяти.

# Basic (pipeline)

- Basic — единственный развивающийся pipeline: универсальный движок и схема (JSON) поверх него. В коде называется `custom` (`disput/custom-engine.js`, `runCustomFromPage`), формат схемы — `disput/basic-schema.js`.
- Начните с `docs/Pipeline scenarios/basic-start-here.md`: что это, словарь, соответствие имён интерфейс → код, как идёт прогон и что пользователь видит в конце.
- Как писать схему — `basic-schema-guide.md`; окна настроек — `basic-windows.md`; код, правила, диагностика, открытые вопросы и постоянно падающие тесты (не из-за вас) — `basic-developer.md`.
- Документы Basic лежат в `docs/Pipeline scenarios/`. Изменяя поведение, обновляйте их в том же коммите (тесты `tests/basic-schema-guide.test.js` и `tests/basic-docs-refs.test.js` сверяют документы с кодом).

# Команда агентов (Claude и GPT)

- Claude делегирует субагентам по виду работы:
  - интеллектуальная работа — Sonnet 5.5 (`model: sonnet`): анализ кода и замыслов, review, поиск дефектов, архитектура, независимая проверка результата, разбор причин сбоя;
  - механическая работа и тесты — Haiku 5.5 (`model: haiku`): коммиты, поиск и чтение по заданному списку, перенос и механические правки, запуск тестов и сбор их вывода.
- GPT делегирует задачи субагентам GPT-6 Luna (`model: gpt-6-luna`, `reasoning_effort: high`).
- Запуск тестов, проверку сценариев и анализ результатов обязательно делегировать: GPT Codex — GPT-6 Luna (`model: gpt-6-luna`, `reasoning_effort: high`); Claude — запуск тестов Haiku 5.5, разбор результатов и проверку сценариев Sonnet 5.5. Передавать контекст изменений, сценарии, команды и пути проекта. Ведущий координирует проверки, разбирает результаты и исправляет найденные проблемы. Не подменять модель без согласования с User.
- Механику без понимания (тесты, коммит, доставка, сверка версии, ожидание события) выполнять скриптом, если он есть: скрипт надёжнее и дешевле агента. Агенту — только то, где нужно понимать текст. Подробно — `docs/Agents/long-task-playbook.md`, §1.
- Ведущий Claude (Opus) сам не исполняет: только анализ, стратегия, задания агентам и приёмка их результата. Всё исполнение — Sonnet и Haiku.

- Review, реализация сложных изменений и расследование сбоя силами команды (главный архитектор, ведущий, исполнитель, проверяющий) — [docs/Agents/agent-team.md](docs/Agents/agent-team.md).
- Долгая задача (несколько этапов, внешний агент-разработчик, живые прогоны, работа без User) — сначала прочитать [docs/Agents/long-task-playbook.md](docs/Agents/long-task-playbook.md); новый урок вносить туда же.

# Работа с git

- После всех изменений всегда делать commit.
- Commit и доставку делать скриптом, если он есть; иначе поручать субагенту своей платформы: Claude — Haiku, GPT — GPT-6 Luna.
