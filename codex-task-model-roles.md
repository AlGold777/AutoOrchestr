# Задание для Codex: роль модели в раунде и особенность модели в ▶

База: `main` 2.81.649 (c611767). Файлы: `results.js`, `results/stage-card.js`, `disput/custom-engine.js`, `styles/pipeline.css`, тесты, документация.

## Суть

Сейчас в Custom выбор мини-запроса в блоке модели (`.role-selector`: None, Meta-Синтез, Критический аудит,
Select ideas, Clustering) **ничего не делает**: `customStepsFromPlan` берёт только имена моделей, а `model.extra`
в движке остаётся пустым. Нужно подключить и добавить два удобных входа. Источник у обоих один — поле `extra`
(«Дополнительно для тебя:» в `buildPrompt`); второго места хранения не заводить.

## 1. Роль модели в раунде

Данные уже есть: роль каждой модели хранится в стеке (`item.role`) и попадает в план как
`plannedStages[].participantBindings: [{ participantId, promptId }]` (results.js, `draftPlanForCanvas`).

- `customStepsFromPlan`: для каждой модели шага найти `promptId` по `participantBindings`, взять текст мини-запроса
  (`getJudgePromptById(promptId).text`) и передать как `extra` модели. `None` (null) = `extra` пустой.
- Карточка раунда (клик по `.round-badge`, `openStageCard` → `StageCard`): для Custom вместо списка «Участники раунда»
  — один выпадающий список тех же мини-запросов «Роль для всех моделей раунда». Выбор **записывает роль в
  `.role-selector` каждого блока раунда** через тот же путь, что ручной выбор (с тем же сохранением состояния
  стека). Отдельного поля «роль раунда» не создавать. Список показывает общее значение, если у всех одинаково, иначе пусто («разные»).
- Личный выбор в блоке модели работает как раньше и перекрывает общий. Если ручные роли в раунде различаются,
  перед записью общей — подтверждение («Заменить роли моделей раунда?»).
- Карточка раунда для шаблона Architecture (`templateStage`) не меняется.

## 2. Особенность модели в ▶

В карточке ▶ (`pipelineDefaults`) блок «Особенности моделей»: по одному текстовому полю на каждую модель,
которая сейчас стоит на холсте (по имени, без дублей). Пустое поле = ничего не добавлять. Пример: GPT — «Без вступлений и
пересказа вопроса, не раздувай ответ».

- Хранение: `customDefaults.modelNotes[имя]` (рядом с остальными полями ▶; сохранение, копирование, экспорт,
  встроенный шаблон — как у остальных полей ▶).
- Применение: текст уходит с **каждым** запросом этой модели во всех раундах и синтезах. Это дисциплинарная строка,
  как лимит и метка: добавляется отдельно **после** запроса и ответов владельца, **перед** лимитом, не входит в
  редактируемый текст запроса. Поэтому действует и при персональном запросе, и не «застывает» в нём.
- В карточке модели — одна строка только для чтения «Особенность модели (из ▶)» с текстом; редактировать там нельзя.
  Если пусто — строки нет.
- Повторный запрос (`correction`) особенность не получает.

## Порядок текста в запросе

```
запрос (с extra роли, если выбрана)
ответы владельца
особенность модели (из ▶)
лимит
требования к содержанию
метка доставки
```

## Проверка

Проверять **текст, который реально уходит** (`starts[i].promptsByModel`), как в тестах Custom-прогона.

1. Роль в блоке модели → её текст есть в запросе этой модели в «Дополнительно для тебя».
2. Выбор в карточке раунда → роль у всех моделей раунда; личный выбор после этого перекрывает; None даёт пустой extra.
3. Подтверждение перед заменой, если ручные роли различаются; при отказе ничего не меняется.
4. Особенность GPT из ▶ в запросе GPT всех раундов, не у других моделей; при персональном запросе тоже; после запроса и до лимита.
5. Особенность не попадает в повторный запрос.
6. Сохранение / копирование / экспорт-импорт pipeline сохраняют `modelNotes`; встроенный шаблон после перезагрузки их теряет.
7. Карточка раунда Architecture без изменений; карточка раунда Custom не содержит списка участников.
