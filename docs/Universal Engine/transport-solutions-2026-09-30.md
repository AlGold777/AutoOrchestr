# Транспорт Pipeline: решения по реестру дефектов

Дата: 2026-09-30. Ревизия кода: `bffd7e5` (ветка `claude/inspiring-bell-71qgbj`).
Область: браузерный транспорт (API исключён).
Реестр дефектов — сводка review Astra (`transport-review-2026-09-30.md`) и Claude.
Статус: **проект решений для обсуждения**. Код не менялся.

## Общие элементы решений

Решения в таблице ссылаются на эти элементы.

| Код | Элемент | Суть |
| --- | --- | --- |
| Р1 | Запись запроса | Единственный владелец — фон. Поля: `requestId` (логический, = `idempotencyKey`), `sendId` (каждая физическая отправка), `purpose` (`initial` / `retry` / `format_repair`), модель, вкладка, беседа, снимок промпта и вложений с хешем, поколение запуска, дедлайн, версия записи. Состояния: `created → admitted → intent_saved → command_accepted → submitted → receiving → terminal`. |
| Р2 | Строгая корреляция | Одна функция `validateEnvelope(record, event)`. Каждое событие несёт `requestId` и `sendId`. Отсутствие обязательного поля — отказ `missing_identity`. Подстановка ожидаемых значений запрещена. |
| Р3 | Единый результат | Объект `{requestId, sendId, delivery, completion, reason, rawText, rawHtml, displayText, evidence, revision}`. Текст и статус независимы. Терминальный результат неизменяем, позднее извлечение — новая ревизия. |
| Р4 | Почтовый ящик | Фон сохраняет результат в `storage.session` по `requestId` до уведомления. События нумеруются (`seq`) в пределах записи. Панель при пропуске или переподключении забирает результат сама. Живой и восстановленный путь — один вход. |
| Р5 | Ожидания по запросу | `Map<requestId, deferred>`. У каждого ожидания ровно один исход, включая `cancelled` и `superseded`. |
| Р6 | Аренда вкладки | Вкладка и беседа закреплены за одной `sendId`. Владелец, срок, освобождение только по терминалу или подтверждённой остановке. Вкладка сама отклоняет чужую команду. |
| Р7 | Таксономия статусов | Один модуль. Два измерения: `delivery` (`not_sent` / `sent` / `unknown`) и `completion` (`complete` / `partial` / `timed_out` / `failed` / `cancelled`). Все статусы интерфейса — проекции. |
| Р8 | Привязка к сообщению | До отправки — снимок ходов беседы. После — новый ход ассистента, следующий за нашим ходом пользователя с нашим текстом. Счётчик ходов и метка модели — дополнительные признаки. Общий модуль; адаптер даёт селекторы и признаки генерации. |
| Р9 | Отмена | Терминальная запись с поколением. Условная запись сохранений (версия не ниже текущей). Остановка генерации у провайдера с подтверждением. |
| Р10 | Параметры запроса | Профиль ожидания, дедлайн, политика беседы передаются в команде и фиксируются на время запроса. Глобальные флаги на запрос не влияют. |

## Принцип: сигнал «жив» не должен порождаться нашими же действиями

Найден 2026-10-01 по отчёту с Le Chat и Perplexity (версии 2.81.509–2.81.513).

Отсрочка неопределённого финала ждала, пока вкладка «затихнет», и считала тишиной отсутствие любой активности. Но визиты на вкладки, скролл и проверки, которыми система искала ответ, сами создавали активность. Замкнутый круг: визиты обновляют активность → отсрочка не кончается → финала нет → визиты продолжаются. Модели к тому времени давно ответили.

Правило для любого решения транспорта и движка (срок, отсрочка, продление, повтор, «завис»):

1. Прогресс определяется содержимым ответа (рост или смена текста) или подтверждённым финалом, а не активностью вкладки, фокусом, скроллом, диагностикой или проверками.
2. У любого ожидания есть жёсткий предел, не зависящий от активности.
3. Начало и конец ожидания попадают в журнал с причиной.
4. При добавлении действия восстановления проверять: не питают ли его побочные эффекты сигнал, который удерживает его запущенным.

Это частный случай правила движка: прогресс — подтверждённые результаты, а не объём сообщений (README, §6).

Аудит остальных потребителей активности: продление аппаратного стопа (`SCRIPT_RUNTIME_HARD_STOP`, не более 2 продлений) и отсрочка `HARD_STOP_DEFERRED` (один раз на отправку) ограничены. Цикл визитов человека (`human-presence`) ограничен только финализацией запроса: если финал не приходит по другой причине, визиты продолжаются; бюджет визитов по росту текста не сделан.

## Правило: область видимости фона

`job-orchestrator.js` выполняется внутри `if (…) { (function initJobOrchestrator() { 'use strict'; … })(); }`. Его объявления не глобальны: другие файлы фона видят только то, что экспортировано через `self`. Голое обращение из другого файла — это `ReferenceError` во время работы или проверка `typeof`, которая молча выключает функцию. Так в 2.81.504–2.81.519 не работали супервизор повторов (ссылка на `resolvePromptForDispatch`) и автоматический Get it. Тест `tests/background-global-scope.test.js` загружает настоящий фон и ловит такие обращения.
