# Полнота копирования ответов LLM: спецификация и контракт

Статус: рабочий документ. Исполнители (сессии WP1–WP5) читают его целиком до первой строки кода.

## 1. Задача

При копировании ответа из веб-интерфейса провайдера теряются или искажаются типы контента: схемы, диаграммы, блоки кода и другие. Скопированный ответ должен без потерь использоваться дальше: показываться в UI расширения, передаваться другой модели, сохраняться в файл.

**Целевой формат — каноничный Markdown в диалекте GFM (GitHub Flavored Markdown).** Обязательно по GFM: таблицы в виде pipe-таблиц (`| a | b |` + строка выравнивания `| :--- | :---: | ---: |`, `|` в ячейке экранируется `\|`, перенос в ячейке — `<br>`), зачёркнутый `~~текст~~`, списки задач `- [ ]` / `- [x]`, fenced-блоки с языком, автоссылки. Сноски — `[^1]` (расширение GFM). Всё, что в GFM выразить нельзя (объединённые ячейки и т.п.), сохраняется как исходник в fenced-блоке с указанием типа или как явная заглушка (раздел 12 требований).

Критерий приёмки: каждый элемент тестового промпта (ниже) присутствует в копии в пригодном для повторного использования виде либо заменён явной заглушкой.

## 2. Требования (источник — пользователь)

### 1. Текст и структура
- Заголовки h1–h6.
- Списки маркированные и нумерованные, вложенность 4+ уровней, смешанные (нумерованный внутри маркированного).
- Нумерация не с 1 (`5.`, `6.`).
- Абзацы и пустые строки между ними.
- Цитаты (`>`), в том числе вложенные.
- Горизонтальные линии.
- Жирный, курсив, зачёркнутый и их комбинации.
- Ссылки: сохраняется и текст, и URL (`[документация](https://…)` не превращается в «документация»).
- Inline-код: `chrome.storage.local`.

### 2. Блоки кода
- Содержимое побуквенно: отступы (пробелы и табы), пустые строки, хвостовые пробелы, очень длинные строки без визуального переноса.
- Язык блока (`js`, `python`, `json`, `bash`, `diff`) попадает в метку после открывающих бэктиков.
- Служебные элементы интерфейса не попадают в код: кнопка «Copy», подпись языка, номера строк, подсветка синтаксиса.
- Код, внутри которого тройные бэктики: внешний fence длиннее (четыре бэктика или тильды).
- Код внутри списков и таблиц не теряет отступов.
- Несколько блоков подряд не склеиваются.
- `diff`-блоки: `+` и `-` в начале строк сохраняются.

### 3. Таблицы
- Заголовок, выравнивание колонок, пустые ячейки.
- Inline-форматирование, ссылки и inline-код внутри ячеек.
- Переносы строк внутри ячейки (`<br>`).
- Символ `|` внутри ячейки экранируется.
- Широкие таблицы с горизонтальной прокруткой копируются целиком.
- Таблица, не выражающаяся в Markdown (объединённые ячейки): HTML-таблица или заглушка с пометкой.

### 4. Формулы
- LaTeX-исходник, а не отрендеренный текст (`\frac{a}{b}`, а не «a b»).
- Inline (`$…$`) и блочные (`$$…$$`) различаются.
- Источник берётся из того, что оставил рендерер (KaTeX/MathJax: `annotation`, `data-*`), если он там есть.

### 5. Диаграммы и схемы
- Mermaid, PlantUML, Graphviz/DOT и подобные: исходный текст диаграммы в блоке с соответствующим языком, а не картинка и не набор подписей узлов.
- ASCII-схемы и деревья каталогов (`├──`, `│`, `└──`, `->`): моноширинное выравнивание сохраняется. Пробелы, NBSP и Unicode-рамки не нормализуются.
- SVG в ответе: копируется как SVG-исходник.
- Диаграмма, показанная только картинкой: ссылка или data-URL плюс alt-текст, в тексте пометка, что это изображение.

### 6. Изображения и графики
- Сгенерированные и вставленные изображения: URL или base64, alt/подпись.
- Графики и чарты, отрисованные интерфейсом: исходные данные или код, если доступны, иначе изображение со ссылкой.
- Порядок изображений относительно текста сохраняется.

### 7. Отдельные панели с артефактами
- Содержимое Canvas / Artifacts / редакторских панелей (Claude Artifacts, ChatGPT Canvas, Gemini Canvas и аналогов): код, документ, HTML-страница.
- Связь с основным сообщением: в тексте ответа маркер «Артефакт: название, тип», полное содержимое отдельным блоком.
- Несколько версий артефакта: берётся актуальная, это помечено.

### 8. Источники и цитирование
- Сноски и «чипы» источников (`[1]`, значки сайтов): сохраняется связь «утверждение → источник».
- Список источников внизу ответа: заголовок, URL, название.
- Результаты веб-поиска, показанные карточками.

### 10. Файлы и вложения
- Ссылки на скачиваемые файлы, сгенерированные моделью: имя, тип, URL.
- Результаты code interpreter / data analysis: код, вывод, созданные файлы, графики.

### 11. Символы и кодировка
- Эмодзи, Unicode (кириллица, CJK, RTL), математические символы, стрелки.
- Специальные пробелы (NBSP, узкий пробел) и zero-width-символы: сохраняются там, где значимы (код, ASCII-схемы), нормализуются в обычном тексте; правило явно зафиксировано в коде и тестах.
- Нет двойного экранирования: `&lt;`, `\*`, `\_` не появляются там, где их не было.

### 12. Поведение при неудаче (важнее всего)
- **Тихая потеря недопустима.** Элемент, не скопированный полностью, заменяется заглушкой `[НЕ СКОПИРОВАНО: тип=mermaid, причина=..., позиция=N]`, а не пропуском.
- Копия сопровождается отчётом: какие типы блоков найдены в исходном DOM, сколько скопировано, сколько заменено заглушкой.
- Контроль полноты: число блоков каждого типа в DOM (код, таблицы, изображения, диаграммы) сверяется с числом в результате. Расхождение — ошибка, а не успех.
- Неполный ответ (генерация идёт, оборвана, обрезана «Continue generating») помечается, а не копируется молча как полный.

### 13. Контекст сообщения
- Копируется нужный ответ: при нескольких версиях (regenerate, ветки, переключатель `1/3`) берётся текущая отображаемая, версия фиксируется.
- Длинные ответы, разбитые на несколько сообщений или подгружаемые лениво (виртуализация списка), копируются целиком, а не только то, что в viewport.
- Свёрнутые блоки («Show more», раскрывающиеся секции) раскрываются или явно помечаются как нераскрытые.

### 14. Ссылки
(Пункт в исходном списке пуст. Покрывается разделом 1 — ссылки — и разделом 8 — источники.)

### 15. Провайдеры
Требования проверяются отдельно для каждого из 10 провайдеров: GPT, Gemini, Claude, Grok, Le Chat, Qwen, DeepSeek, Perplexity, Z.ai, Kimi. Результат — матрица «тип контента × провайдер» со статусами: сохраняется полностью / частично / не сохраняется.

### Тестовый промпт
> Дай один ответ, в котором есть: заголовки трёх уровней; вложенный список на 3 уровня; таблица 3×3 с кодом в одной ячейке; блок Python с отступами и пустыми строками; блок JSON; блок Markdown с тройными бэктиками внутри; формула `\int_0^1 x^2 dx` inline и блочная; диаграмма Mermaid (flowchart на 4 узла); ASCII-дерево каталогов; ссылка с текстом; цитата; сноска с источником.

## 3. Инвентаризация: что есть сегодня

Проверено чтением кода в основном чекауте на версии 2.81.801. Исполнители обязаны перепроверить утверждения, к которым привязана их работа, и при расхождении поправить этот раздел.

**Цепочка копирования.**
1. Элемент ответа выбирается адаптером провайдера (`content-scripts/content-<provider>.js`) и общим конвейером `content-scripts/unified-answer-pipeline.js`: `getAnswerElement()` → `extractAnswerWithHtml()`.
2. `answer` (текст) = `AnswerStructure.linearizeText` (`content-scripts/answer-structure.js`): обходит узлы, **схлопывает все пробелы в один**, пропускает кнопки, скрытое, reasoning. Для кода, таблиц, списков, ASCII-схем это уничтожает структуру. Текст нужен конвейеру для проверок (подпись, длина, устойчивость), но не годится как «копия».
3. `answerHtml` = `ContentUtils.buildInlineHtml` (`content-scripts/content-utils.js`, ~стр. 1255): клон элемента с computed-стилями в `style`, затем **удаляются** `script, style, noscript, svg, canvas, button, [role=button], [aria-hidden=true], [inert], header, footer, nav, aside, form`, reasoning-части и скрытые элементы. Следствия: SVG-диаграммы пропадают целиком; у KaTeX видимый слой `aria-hidden` удаляется, остаётся только MathML (если он есть); кнопки «Copy» удаляются, но подпись языка и номера строк остаются в DOM кода.
4. Адаптеры ChatGPT/Claude/Gemini/Grok имеют собственные `buildInlineHtml`-обёртки и `latestMarkup`/late-snapshot пути (`content-chatgpt.js`, `content-claude.js`, `content-gemini.js`, `content-grok.js`). Остальные провайдеры идут через общий конвейер. Файлы `dist/*` — сборка; способ сборки выяснить в `package.json`/`scripts`.
5. `AnswerStructure.inspect` проверяет только «все ли блоки сообщения покрыты выбранным элементом» (счёт `uncovered_message_blocks`). Типов блоков и сверки «найдено / скопировано» нет.
6. Сообщение с `answer` + `answerHtml` идёт через фоновый слой (`background/job-orchestrator.js`, `background/ui-broadcast.js`) на страницу результатов; `results.js` хранит текст и HTML карточки, рисует через `sanitizeInlineHtml`. TXT-экспорт берёт текст, HTML-экспорт — санитизированный HTML (`results/debate-export.js`, `buildAllResponsesExportHtml` в `results.js`).
7. Живые скелеты DOM (без текста) для 9 провайдеров — `tests/fixtures/live-answer-skeletons/*.json` (Kimi в списке ожидающих захвата). Это единственные реальные образцы разметки в репозитории; в них могут отсутствовать блоки кода/формулы/диаграммы, потому что снимались ответы без них.

**Чего нет совсем:** Markdown как формата ответа; заглушек и отчёта по типам; сверки счётчиков; извлечения LaTeX-источника; исходников диаграмм; артефактов/Canvas; списка источников и связи «утверждение → источник»; файлов и вывода code interpreter; разбора версий ответа (`1/3`), ленивой подгрузки и свёрнутых секций; пометки «ответ неполный» на уровне копии; матрицы «тип × провайдер».

## 4. Архитектура

Новый слой **DOM → Markdown** рядом с существующим, не вместо него: `answer` и `answerHtml` остаются как есть (на них держатся проверки полноты и рендер карточки). К ним добавляются `answerMarkdown` и `copyReport`.

Все модули — UMD в стиле `content-scripts/answer-structure.js` (работают как content script и как `require` в jest/jsdom), экспортируют в `root.AnswerMarkdown`.

### 4.1. Контракт API (заморожен; менять только через автора WP1 и этот документ)

```js
// shared/answer-markdown.js  (WP1)
AnswerMarkdown.convert(element, options) -> { markdown: string, report: Report }
//   options: { provider: 'GPT'|'Gemini'|'Claude'|'Grok'|'Le Chat'|'Qwen'|'DeepSeek'|'Perplexity'|'Z.ai'|'Kimi'|null,
//              maxChars?: number, context?: object /* из WP3: {version, generating, truncated, collapsed, ...} */ }
AnswerMarkdown.census(element, options) -> { [type]: number }   // независимый подсчёт блоков в DOM по селекторам, до конвертации
AnswerMarkdown.registerBlock(handler)       // см. ниже
AnswerMarkdown.registerProvider(name, rules) // см. ниже
AnswerMarkdown.PLACEHOLDER_RE               // /\[НЕ СКОПИРОВАНО: тип=([^,\]]+), причина=([^\]]*?), позиция=(\d+)\]/
```

**Report**
```js
{
  version: 1,
  provider: string|null,
  found:   { [type]: number },        // census: что есть в исходном DOM
  copied:  { [type]: number },        // что попало в markdown как содержимое
  placeholders: [ { type, reason, position } ],   // position — порядковый номер блока в документе, с 1
  mismatches: [ { type, found, copied, placeholders } ], // found !== copied + placeholders
  flags: { generating?: bool, truncated?: bool, collapsed?: number, version?: string, regenerated?: bool },
  complete: boolean   // false при любом mismatch, placeholder или неполноте из flags
}
```
Типы для счёта (`found/copied`): `heading, list, quote, hr, code, table, math, diagram, svg, image, link, artifact, source, file, output`. Для `math` допустимо различать `math_inline`/`math_block` в `found/copied`; число типов расширяется только добавлением.

**Заглушка** — строго: `[НЕ СКОПИРОВАНО: тип=mermaid, причина=<короткая причина>, позиция=N]`. Строится только через `ctx.placeholder`, чтобы попасть в report.

**Block handler** (`registerBlock`)
```js
{
  name: 'katex',                // уникальное имя
  type: 'math',                 // тип для счёта
  priority: 100,                // больше — раньше; дефолтные обработчики движка имеют 0
  claimsUi?: true,              // необязательно: если match истинен, элемент не считается интерфейсом (iframe, role=button, aria-hidden) — идёт в census и в обработчик
  censusSelector?: string,      // необязательно: CSS-селектор элементов этого типа для census (иначе copied без found даёт mismatch)
  match(el, ctx) -> boolean,
  render(el, ctx) -> { markdown: string, copied?: number } | null   // null = отказаться, пойдёт следующий
}
```
`ctx`: `{ provider, options, position, addFooter(line) /* строки дописываются после тела один раз, по порядку: сноски [^n] */, convertChildren(el) -> string, fence(text, lang) -> string /* выбирает длину fence */, placeholder(type, reason, el) -> string, text(el) -> string /* точный textContent без нормализации */, report }`.
Блок поглощает элемент целиком: движок не заходит в его потомков после успешного `render`.

**Provider rules** (`registerProvider(name, rules)`; все поля необязательны)
```js
{
  isUiNode(el) -> boolean,                        // кнопки, подписи языка, номера строк, чипы интерфейса
  codeBlock(el) -> { lang: string, text: string } | null,   // точная разметка кода провайдера
  tableRoot(el) -> Element | null,                // где реальная <table> (обёртки прокрутки)
  answerRoot(el) -> Element | null                // уточнить корень ответа внутри сообщения
}
```

**Правило нормализации пробелов (раздел 11).** В обычном тексте: NBSP и узкие пробелы → обычный пробел, zero-width удаляются (кроме ZWJ внутри эмодзи-последовательностей и ZWNJ внутри персидского/индийского слова), последовательности пробелов схлопываются. В code/diagram/ascii/pre: ничего не нормализуется, NBSP и Unicode-рамки сохраняются как есть. Экранирование Markdown ставится только там, где без него текст изменил бы смысл, и никогда повторно.

### 4.2. Интеграция (WP5)
`UnifiedAnswerPipeline.extractAnswerWithHtml()` дополнительно вызывает `AnswerMarkdown.convert(element, { provider, context })` (с защитой от отсутствия модуля и исключений: при сбое — заглушка уровня всего ответа и `report.complete=false`, не тишина). Поля `answerMarkdown`, `copyReport` проходят через финализацию, фоновый слой и конверт сообщения до `results.js`. Карточка хранит их рядом с `text/html`; «Copy»/TXT/передача другой модели используют `answerMarkdown`, если он есть; при `report.complete === false` карточка показывает заметный маркер с расшифровкой.
