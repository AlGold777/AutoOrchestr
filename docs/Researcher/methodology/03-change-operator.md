# Оператор изменения

Как система меняет собственный метод и доказывает, что изменение помогло. Перестройка при сработавшем триггере — обязанность, а не право.

## 1. Что меняется

Только конфигурация `C_n` ([../data/schemas/config.schema.json](../data/schemas/config.schema.json)):

| Раздел конфигурации | Примеры изменений | Класс |
| --- | --- | --- |
| Изменяемые пороги и приоритеты | Правило выбора шага, доля резерва | A |
| Состав | Замена модели в роли, новая роль | A, B |
| Приёмы ролей | Как генератор строит гипотезу, как искатель выбирает источники | A, D |
| Представление задачи | Язык, понятия, переформулировка | C |
| Оператор поиска | Способ порождения кандидатов | D |

Ядро, запросы ролей и схемы оператору недоступны ([../system/04-core.md](../system/04-core.md)).

## 2. Предложение изменения

Шесть полей, заполненных по существу, плюс карта переноса. Формат — [../data/schemas/change-proposal.schema.json](../data/schemas/change-proposal.schema.json).

| Поле | Требование | Не принимается |
| --- | --- | --- |
| Наблюдается | Триггер, показатель и его источник в журнале | «стагнация» без чисел и номеров циклов |
| Порог | Число из ядра и способ, которым оно задано | порог, придуманный в предложении |
| Что переписывается | Раздел конфигурации и текст «было → стало» | «улучшить подход» |
| Что запрещено трогать | Элементы ядра, которых изменение касается по смыслу | пустое поле |
| Предсказание | Рискованное: исход, которого прежняя конфигурация не даёт. Где показателя ещё нет — качественное, но опровержимое, с тестом, сроком и судьёй | «станет лучше», «ускорится» |
| Условие отката | Наблюдаемое условие в журнале | «если не сработает» |

**Карта переноса** — три списка номеров записей карты вопроса: что сохраняет силу; что устаревает; что нужно вывести заново. Для класса A — одна строка. Яма-предикат переносится только если её границы доказаны в новом представлении; иначе становится свидетельством.

## 3. Откуда берутся предложения

| Источник | Роль | Что даёт |
| --- | --- | --- |
| Меню | Методист | Классы A и B по типу провала (таблица ниже) |
| Каталог ходов | Изобретатель перестроек | Классы C и D: ход из [02-mechanisms.md](02-mechanisms.md), §3 |
| Библиотека перестроек | Оба | Перестройки, подтвердившиеся при том же триггере и барьере |
| Внешний канал | Искатель, владелец, модель вне цикла | Метод другой области; обязателен при T7 |
| Плацебо | Плацебо | Изменение той же цены без диагноза — для сравнения |

Меню методиста:

| Код провала | Допустимое изменение |
| --- | --- |
| `FAIL_WRONG_PLACE` | Сменить источник, запрос, критерий отбора |
| `FAIL_WRONG_HYPOTHESIS` | Добавить дешёвую проверку до заявки; изменить способ формулировки |
| `FAIL_SLOW_CHECK` | Добавить быстрый фильтр; сменить исполнителя |
| `FAIL_REPEAT` | Уточнить ключ ямы; добавить правило обхода |
| `FAIL_WEAK_EVIDENCE` | Требовать повтора или независимой проверки |
| `FAIL_CONTEXT_LOST` | Изменить состав пакета цикла |
| `FAIL_TOO_COMPLEX` | Разбить шаг на два |
| `FAIL_EARLY_STOP` | Изменить изменяемый порог остановки ветки |
| `FAIL_UNTESTABLE` | Строить проверку: ведущая валюта В3 |
| `FAIL_FALSE_PREMISE` | Ход 18 каталога |

Предложение вне меню и каталога допускается, но испытывается как класс D. Меню расширяет владелец по архиву отклонённых предложений.

## 4. Ход перестройки

```
в каждом цикле:
  диагност метода читает записи цикла и карту
  если триггер T1–T7 не сработал → «перестройка не требуется»
  если состояние не покрыто триггером → заморозить конфигурацию, флаг «пересмотр диагноза»
  если сработал:
    диагноз: причина + конкурирующие причины + различающий тест
    методист и изобретатель независимо пишут предложения
    в следующем цикле плацебо пишет изменение той же цены: пункт списка задаёт остаток от деления номера цикла на 10
    приёмщик проверяет форму каждого: шесть полей по существу, ядро не затронуто
    предложения встают в очередь карты вопроса

в окне решений:
  владелец выбирает одно предложение или ни одного

этап Э4 для выбранного:
  сборщик пишет C_n и перечень изменений
  проверяющий изменение сверяет: изменено только заявленное, ядро не тронуто
  владелец подписывает; хеш C_n — в журнал
  испытание по классу (§5): прежняя конфигурация, новая, плацебо
  судья сверяет предсказание с исходом (§6)
  подтверждено → C_n действует; запись в библиотеку
  не подтверждено → откат к C_{n-1}; яма с границами; запись в библиотеку
  срок истёк без проверки → «не подтверждено»
```

Состояния предложения: `предложено → принято к испытанию → собрано → на испытании → подтверждено | откат | истекло`. Каждый переход — запись журнала.

## 5. Испытание

Испытание парное: одна и та же задача и один и тот же пакет, различается только конфигурация. Каждое плечо — отдельный запуск схемы цикла в новых чатах. Отпечатки моделей записываются; смена модели провайдером посреди испытания делает его недействительным.

| Класс | Где | Плечи | Объём |
| --- | --- | --- | --- |
| A | Текущая задача | Прежняя, новая | Число циклов карантина из ядра |
| B | Зачётный набор полигона | Прежняя, новая, плацебо | Число пар из ядра |
| C | Текущая задача и задачи полигона с удалённым понятием | Прежняя, новая, плацебо | До срока тройного теста |
| D | Зачётный набор полигона | Прежняя, новая, плацебо | Число пар из ядра |
| E | Задачи следующего проекта, не участвовавшие в настройке | С приёмом, без приёма | Задаётся в следующем проекте |

Перед первым испытанием измеряется шум: прежняя конфигурация против самой себя на тех же задачах. Выигрыш меньше шума не засчитывается. Число пар задаётся до испытания так, чтобы минимальный интересный эффект был виден сквозь шум; способ — в [../verification/04-evaluation.md](../verification/04-evaluation.md), §4.

Обращения к зачётному набору расходуют его предел ([../system/04-core.md](../system/04-core.md), §7).

## 6. Суд

Судья перестройки получает предложение и итоги плеч, но не имена авторов. Перестройка подтверждена, если выполнено всё:

1. Исход совпал с предсказанием в его формулировке.
2. Предсказание было рискованным: плечо с прежней конфигурацией этого исхода не дало.
3. Новая конфигурация лучше плацебо больше, чем на шум. Иначе помогло «изменение вообще», а не диагноз.
4. Условие отката не наступило.
5. Посевы и проверки ловятся не хуже, чем до перестройки.

Пункт 3 для класса A не обязателен.

**Просадка и провал.** Новая конфигурация какое-то время работает хуже прежней. Просадка в пределах аварийного порога из ядра в течение карантина провалом не считается. Аварийный порог записывается до испытания: число, ниже которого испытание прекращается досрочно.

**Отложенный и перекрывающийся эффект.** Пока идёт одно испытание, второе не начинается. Эффект, проявившийся после карантина, приписывается перестройке только через новое испытание.

## 7. Дисциплина мета-уровня

| Правило | Как задаётся число |
| --- | --- |
| Минимальный срок жизни конфигурации: перестройка не раньше | Столько циклов, сколько нужно для одной полной проверки гипотезы при заявленной цене |
| Доля бюджета на перестройки | Замер по первым двум циклам с перестройкой, запись в ядро до третьего |
| `k` перестроек без подтверждённого прироста → следующая запрещена, диагност обязан сменить диагноз барьера | Сколько перестроек владелец готов оплатить вперёд |
| Ноль признанных ошибок, откатов и пересмотров диагноза за `N` циклов → флаг ручной проверки | Число циклов, за которое при заявленной частоте перестроек ожидается хотя бы одно такое событие |
| Одно испытание одновременно | — |

Обязанности производить провал нет: флаг означает проверку записей владельцем, а не требование отката.

Осцилляция — возврат к конфигурации, которая уже откатывалась, без нового свидетельства. Запрещена: приёмщик сверяет предложение с библиотекой.

## 8. Второй мета-уровень

Дефект самого оператора изменения — законный диагноз: например, триггеры не покрывают состояние или суд пропускает косметические перестройки. Он не исправляется автоматически. Диагност метода записывает его в карту как донесение владельцу; владелец меняет методологию, запросы или схемы операцией по [../system/03-decisions.md](../system/03-decisions.md), Р10. Третьего уровня нет.

## 9. Библиотека перестроек

Одна запись на каждую перестройку, включая откаты и плацебо: [../data/schemas/rebuild-record.schema.json](../data/schemas/rebuild-record.schema.json). Хранится в `library/rebuilds/` поверх задач.

Показатель обучения: доля бюджета на перестройки и число перестроек до первого подтверждения — по задачам подряд. Если они не падают, система не учится перестраиваться, и это записывается в итог задачи.
