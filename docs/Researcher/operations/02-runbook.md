# Руководство по эксплуатации

Что делает владелец руками. Команды выполняются в папке задачи.

## 1. Подготовка задачи

1. Создать папку задачи по [../data/README.md](../data/README.md), §3.
2. Пройти Э0 и Э1: схемы `1-task-card`, `2-preflight`. Утверждённую карточку сохранить в `core/task-card.json`, журнал отказов — в `runs/`.
3. Пройти Э2: схема `3-setup`. Подписанную страницу ратификации сохранить; числа порогов перенести в `core/thresholds.json`; конфигурацию — в `config/C0.json`.
4. Записать свои ожидания по ключевым вехам в `core/sealed-test.txt`.
5. Собрать `core/lock.json`: хеши из §2.
6. Начать цепочку (§3) и отправить первый якорь (§4).

## 2. Хеши для замка

Файл:

```bash
shasum -a 256 core/task-card.json
```

Папка — хеш от списка хешей её файлов (путь к папке запросов — от корня проекта):

```bash
find docs/Researcher/prompts -type f | sort | xargs shasum -a 256 | shasum -a 256
```

Так же считаются `docs/Researcher/basic/schemas` и `docs/Researcher/methodology`.

## 3. Цепочка журнала

Первая запись после ратификации — ссылается на замок:

```bash
f=0001_3-setup_2026-11-16.json; echo "1 $(date -u +%FT%TZ) $f $(shasum -a 256 "journal/$f" | cut -d' ' -f1) $(shasum -a 256 core/lock.json | cut -d' ' -f1)" >> journal/chain.txt
```

Каждая следующая — после каждого прогона, имя файла своё:

```bash
f=0002_4-cycle_2026-11-17.json; echo "$(($(wc -l < journal/chain.txt)+1)) $(date -u +%FT%TZ) $f $(shasum -a 256 "journal/$f" | cut -d' ' -f1) $(tail -n 1 journal/chain.txt | shasum -a 256 | cut -d' ' -f1)" >> journal/chain.txt
```

Событие без экспорта — операция над ядром, решение владельца, посев — записывается так же: содержание кладётся в текстовый файл `journal/NNNN_<вид>_<дата>.txt`, строка цепочки ссылается на него.

Проверка цепочки — каждая строка должна ссылаться на хеш предыдущей:

```bash
awk 'NR>1{c="sed -n " NR-1 "p journal/chain.txt | shasum -a 256"; c | getline h; close(c); split(h,a," "); print (a[1]==$5 ? "строка " NR " сходится" : "РАЗРЫВ в строке " NR)}' journal/chain.txt
```

Проверка одного файла: `shasum -a 256 journal/<имя>` и сравнение с четвёртым полем его строки.

`chain.txt` только дописывается. Ошибочная строка не стирается: следующей строкой записывается исправление.

## 4. Якорь

На каждом окне решений, а в непрерывном режиме — на каждом чекпоинте:

```bash
tail -n 1 journal/chain.txt
```

Эту строку: закоммитить в удалённый репозиторий, к которому у внешнего наблюдателя есть доступ на чтение, и отправить наблюдателю письмом. Отправка наружу — действие владельца.

## 5. Один цикл

1. Собрать `state/package.txt`: выжимка ядра, конфигурация, карта ([../data/README.md](../data/README.md), §4). Проверить длину:

```bash
wc -m state/package.txt
```

Больше 12 000 — сначала сжать карту по [../methodology/01-methodology.md](../methodology/01-methodology.md), §9.

2. Запустить `4-cycle`, вставив пакет в поле задачи.
3. Если нужен посев — подложить его в пакет или в ответ ручного задания ([../verification/03-control.md](../verification/03-control.md), §3) и записать об этом в свой файл посевов.
4. На шаге ручного задания — выполнить процедуру или ответить «нет».
5. В окне решений — прочитать сводку и донесение, исправить карту, дописать решение.
6. Сохранить экспорт в `journal/`, дописать цепочку.
7. Перенести записи цикла в `journal/records.jsonl`, утверждённую карту — в `state/map.json`.
8. Обновить остаток бюджета в выжимке ядра.

## 6. Перестройка

1. Выбрать предложение из очереди карты. Запустить `5-rebuild` с пакетом и текстом предложения.
2. Подписанную конфигурацию сохранить как `config/C<n>.json`; хеш — событием в цепочку.
3. Собрать пакеты плеч: одинаковые ядро и карта; раздел конфигурации — прежний, новый, плацебо.
4. Прогнать `4-cycle` по плечам в объёме из `core/thresholds.json`. Для классов B и D — на задачах зачётного набора; каждое обращение записать и увеличить счётчик в `core/lock.json`.
5. Запустить `6-rebuild-verdict`: в поле задачи — предложение, сводки плеч, шум.
6. Подтверждено — `C<n>` действует. Откат — действует прежняя; яму перенести в карту. Запись — в `library/rebuilds/`.

Пока идёт испытание, второе не начинается.

## 7. Сбои

| Сбой | Что делать |
| --- | --- |
| Модель не ответила; роль не одна | Пропустить; секретарь запишет неполный шаг |
| Не ответила единственная модель роли | Повторить шаг; если не помогает — остановить прогон, заменить модель в составе из той же группы, пересобрать схемы |
| Не ответил экспериментатор или секретарь журнала | Цикл недействителен: остановить, повторить цикл с тем же пакетом |
| Ответ не в формате JSON дважды | То же, что «не ответил» |
| `context_full` до отправки | Сжать карту; проверить длину пакета |
| `missing_input` | Обязательный источник без ответа: повторить шаг-источник |
| Прогон остановлен посреди цикла | «Продолжить» в ленте; заявка остаётся прежней |
| Провайдер сменил модель | Калибровка заново; незаконченные испытания недействительны; запись в цепочку |
| Потерян `state/map.json` | Пересобрать из `journal/records.jsonl`; сверить с последним экспортом |
| Цепочка не сходится | Остановить работу; найти первую расходящуюся строку; всё после неё — репетиция, пока расхождение не объяснено записью |
| Не отвечает вся группа проверки | Тревога; циклы не запускаются: без проверки они дают только гипотезы |

## 8. Смена запросов и схем

1. Править текст в `docs/Researcher/prompts/`.
2. Пересобрать: `node docs/Researcher/basic/build-schemas.mjs`.
3. Заново импортировать изменённые схемы в Basic.
4. Пересчитать хеши папок в `core/lock.json`, увеличить версию ядра, записать событие `core_change` в цепочку.

Результаты до и после смены напрямую не сравниваются.

## 9. Остановка и выход

Сработало стоп-правило или принято решение «стоп»: запустить `9-exit` с пакетом последнего цикла и перечнем вердиктов из `journal/records.jsonl`. Утверждённый итог — в `out/final.json`, пост-мортем — рядом. Последняя строка цепочки — финальный якорь.

## 10. Расписание

| Что | Когда |
| --- | --- |
| Окно решений | После каждого цикла; не чаще одного окна в день при нескольких циклах подряд |
| Якорь | Каждое окно решений |
| Калибровка | До первого цикла; при смене модели; при пополнении корпуса |
| Аудит и красная команда | Раз в период из карточки; перед принятием перестройки классов B–D |
| Контроль дрейфа | Раз в период из карточки |
| Пересмотр правил проверки | Раз в период из карточки |
| Смена скрытых правил контроля | Раз в период из карточки |
