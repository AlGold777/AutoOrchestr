# Состояние Basic после перезагрузки

## Reload самого расширения: исправление 2.81.961

01.11.2026 User подтвердил, что телеметрия оставалась после Reload расширения. Правка 2.81.959 очищала её при обновлении страницы, а `background/index.js:resetVolatileRuntime` продолжал сохранять `__diagnostics_events__` и локальную копию `messageDelivery.journal.v2.local`. Это была ошибка области исправления.

Теперь эти ключи, рабочий transcript и намерения перехода входят в очистку нового runtime. После очистки сохраняется новая граница `llmComparatorWorkingSessionStartedAt`, поэтому архивные записи Basic не подставляются в новую сессию. Явно сохранённые схемы и архив Basic не удаляются. Очистка завершается до `__extensionLifecycleReady`: таймер ожидания обычного старта не может раскрыть чтение состояния, пока сброс ещё идёт. Пробуждение того же service worker с сохранённой epoch очистку не запускает.

Снимок User также показал отказ подтверждения сброса страницы. Неподдерживаемый старым фоном `RESET_WORKING_SESSION` мог давать прежнее общее сообщение; теперь ответ `unknown_message` явно просит Reload расширения. Версию и фактический ответ фона на снимке определить нельзя; отсутствие подтверждения по-прежнему не считается успешной очисткой.

Проверка 2.81.961, GPT-6 Luna: behavioral VM-сценарии исполняют startup lifecycle для отсутствующей epoch, Reload/update с сохранённой epoch, обычного пробуждения worker, отказов записи и очистки дольше 2 с. Дополнительные интеграционные сценарии загружают весь `background/index.js` с фактическими `importScripts` и передают запрос всем зарегистрированным listeners: получен корректный ACK, телеметрия и журнал пусты, архив и схемы сохранены. Отдельно воспроизведена задержка очистки: budget maintenance ждёт её завершения и не возвращает старые события. Целевая группа интеграционных проверок — 129 тестов прошли. В живом Chrome проверка не выполнена: доступ к странице расширения заблокирован инструментом.

## Расследование 31.10.2026

Симптом на `pipeline_panel.html`: окно «Схема pipeline не прочитана» с ошибкой `steps[2].models[0].name` и сообщением об отсутствии исполнимого шага; в DevTools видны события прежнего прогона. Исходная версия основного чекаута — 2.81.957. Версия открытой страницы и её данные хранилища не прочитаны: браузерный инструмент запрещает доступ к `chrome-extension://`.

Сборка схемы в `results.js`, `basicSchemaFromPage`, принимала `.pipeline-empty-slot` за отключённого участника: у такого места нет имени. `PipelineRuntime.captureModelStackState` уже исключал эти места, поэтому снимок холста и схема расходились. Исправление 2.81.958 исключает пустые места и пустые идентификаторы из списка участников схемы. Настоящие отключённые участники сохраняются с настройками и `onCanvas`.

Отсутствие исполнимого шага проверяется отдельно: запуск и установка схемы требуют включённую модель либо шаг User. Пустой рабочий холст сам по себе не является исполнимой схемой. Некорректные сохранённые схемы не перезаписываются автоматически.

До 2.81.958 события телеметрии намеренно переживали перезагрузку страницы. User подтвердил, что ожидает пустую рабочую сессию, поэтому с 2.81.959 это поведение изменено; подробности — [телеметрия](../Telemetry/telemetry.md).

## Пустая рабочая сессия с 2.81.959

`ResultsBootUtils.prepareWorkingSession` при настоящей перезагрузке ждёт `RESET_WORKING_SESSION` до чтения состояния интерфейса. Фон останавливает прежний прогон, сбрасывает FSM в IDLE, очищает текущие привязки вкладок, телеметрию и журнал доставки с локальной копией, удаляет рабочий UI-снимок и намерение перехода. Вкладки моделей не закрываются. Отказ очистки останавливает загрузку старого состояния и показывает причину.

Граница сессии хранится в `llmComparatorWorkingSessionStartedAt`. Старые ожидающие записи журнала и UI не принимаются; отложенная очередь телеметрии сбрасывается, события старого прогона отбрасываются. Холст начинает без выбранной схемы и без `draftPlans`; схема не собирается из старого черновика. Явно сохранённые схемы остаются в списке. Архив `customRunRecord.*` сохраняется, но его прежние записи не возвращают карточки документов, предложение продолжить или экспорт Basic в новую рабочую сессию. Переход между страницами и Back/Forward внутри той же сессии сохраняют работу.

Восстановление UI-снимка не посылает событие смены моделей: оно восстанавливает поля, а выбор провайдеров имеет свой путь. Прежнее лишнее событие могло очистить карточку ответа, пришедшего во время загрузки. Отсутствующий снимок пропускается.
