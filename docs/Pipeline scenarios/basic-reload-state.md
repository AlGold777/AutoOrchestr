# Состояние Basic после перезагрузки

## Расследование 31.10.2026

Симптом на `pipeline_panel.html`: окно «Схема pipeline не прочитана» с ошибкой `steps[2].models[0].name` и сообщением об отсутствии исполнимого шага; в DevTools видны события прежнего прогона. Исходная версия основного чекаута — 2.81.957. Версия открытой страницы и её данные хранилища не прочитаны: браузерный инструмент запрещает доступ к `chrome-extension://`.

Сборка схемы в `results.js`, `basicSchemaFromPage`, принимала `.pipeline-empty-slot` за отключённого участника: у такого места нет имени. `PipelineRuntime.captureModelStackState` уже исключал эти места, поэтому снимок холста и схема расходились. Исправление 2.81.958 исключает пустые места и пустые идентификаторы из списка участников схемы. Настоящие отключённые участники сохраняются с настройками и `onCanvas`.

Отсутствие исполнимого шага проверяется отдельно: запуск и установка схемы требуют включённую модель либо шаг User. Пустой рабочий холст сам по себе не является исполнимой схемой. Некорректные сохранённые схемы не перезаписываются автоматически.

События телеметрии хранятся в `chrome.storage.local` и по действующему контракту переживают перезагрузку страницы и расширения. Это отдельное состояние от черновика холста. Кольцо очищается при старте нового прогона и явной очистке; подробности — [телеметрия](../Telemetry/telemetry.md). Наличие прошлых событий само по себе не доказывает смешивание прогонов.

## Проверка GPT-6 Luna

- На исходном `HEAD:results.js` воспроизведено: схема r1/r2 с GPT → пустой добавленный r3 → `.pipeline-empty-slot` превращается в модель без имени. На исправленном коде r3 сохраняет `models: []`.
- `tests/basic-schema-empty-slots.test.js`: 2 теста прошли — пустой слот исключён, схема остаётся валидной; настоящий отключённый участник сохраняет ID, подпись, задание, лимит и `onCanvas`.
- `basic-participants-page`, `basic-legacy-config-restore`, `basic-user-schemas-fixes`: 35 тестов прошли.
- `telemetry-run-scope`, `telemetry-run-waves-scope`, `telemetry-retention-regression`, `extension-reload-reset`, `telemetry-clear-all`: 29 тестов прошли. Ошибка смешивания сессий по этим сценариям не подтверждена.

Путь до окна ошибки на реальной странице не проверен. Обычная загрузка без намерения перехода очищает снимок рабочего холста; переход между страницами и Back/Forward восстанавливают его. Отдельно обнаружено по коду: редактирование участника в неисполняемом черновике может показать временное уведомление об отсутствии исполнимого шага (`applyParticipantSchemaEdit` повторно вызывает строгую проверку через `applyPipelineConfig`). Этот путь не объясняет пустое имя, отдельно не воспроизведён и данным исправлением не меняется.
