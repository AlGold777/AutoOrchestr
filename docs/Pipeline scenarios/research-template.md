# Шаблон Research в коде

Что из сценария [research-2.0.md](research-2.0.md) уже работает в панели Pipeline
(версия расширения 2.81.613), а что ещё нет. Шаблон выбирается в списке pipeline
по имени **Research**.

## Как это устроено

- Каталог этапов — `disput/research-framework.js`, 15 этапов; написан вручную
  (каталог Architecture генерируется скриптом из комплекта Automation GPT).
- Шаблоны достаёт реестр `disput/stage-templates.js`: имя шаблона из определения
  pipeline (`stageTemplate`) → каталог этапов. Страница больше не обращается к
  `ArchitectureFramework` напрямую; новый шаблон — это новый файл каталога и одна
  строка в реестре.
- Определение Research (`disput/pipeline-presets.js`): `stageTemplate: 'research'`,
  `roundLimit: '15'`, режим `auto`, профиль `DEEP_RESEARCH_ALPHA`.
- Режим `auto` останавливается только на воротах G1, G2, G3 и на вопросах
  владельца (`[[ASK: …]]`); режим «с остановками» — после каждого этапа.

## Этапы

| № | Этап | Кто работает | Цель этапа в движке |
|---|---|---|---|
| 1 | Спецификация исследования | Ведущая модель | позиция |
| 2 | Проверка спецификации | Другая модель | критика (`[[VERDICT]]`) |
| 3 | **G1** Утверждение спецификации | Владелец | ворота |
| 4 | Независимые разбиения вопроса | Все, независимо | позиция |
| 5 | Дерево вопросов | Ведущая | синтез |
| 6 | План доказательств | Ведущая | позиция |
| 7 | Сбор материалов | Все, независимо | позиция |
| 8 | Извлечение и сведение утверждений | Ведущая | синтез |
| 9 | Проверка утверждений | Другая модель | проверка (`[[VERDICT]]`) |
| 10 | Разбор противоречий | Другая модель | разбор доказательств (`[[VERDICT]]`) |
| 11 | **G2** Достаточность материала | Владелец | ворота |
| 12 | Отчёт | Ведущая | синтез |
| 13 | Критика отчёта | Другая модель | критика (`[[VERDICT]]`) |
| 14 | Приёмка отчёта | Другая модель | проверка (`[[VERDICT]]`) |
| 15 | **G3** Приёмка результата | Владелец | ворота |

«Ведущая» — первая выбранная модель, «другая» — вторая (при одной модели —
она же). Порядок моделей задаёт панель.

## Вопросы владельцу

На любом этапе модель может задать вопрос маркером
`[[ASK: вопрос || вариант 1 || вариант 2]]`. Владелец выбирает варианты в диалоге
и при желании пишет комментарий; писать ничего не обязательно
(`docs/Automation/markers.md`). Спецификация (этап 1) и план доказательств (этап 6) прямо
предписывают оформлять так вопросы, которые может решить только владелец.

## Веб-поиск

Профиль Research (`DEEP_RESEARCH_ALPHA`) объявляет инструмент `web_research`.
Реестр возможностей (`disput/debate-capability-registry.js`) считает его
подтверждённым только у моделей Perplexity/Sonar. Раньше при другом наборе
моделей запуск отклонялся («Профиль требует недоступный инструмент»). Теперь
запуск идёт: панель предупреждает владельца, а в «текущее указание» каждого
промпта прогона добавляется строка: веб-поиск не подтверждён, найденное нельзя
выдавать за проверенное по источнику, утверждение без проверенного источника
получает «слабо» или «не подтверждено», отчёт начинается с предупреждения.
Подтверждение поиска по факту (включён ли он в интерфейсе, получен ли источник)
в коде по-прежнему нет.

## Чего из research-2.0.md в коде нет

| Что | Как заменено сейчас |
|---|---|
| Получение страниц источников оркестратором, механическая проверка цитат | Нет. Проверка утверждений (этап 9) целиком на модели; если источник не открылся, она пишет «не удалось открыть». Разрешение на чтение страниц в расширении не запрашивается |
| Идентификаторы утверждений от оркестратора, цепочка источник → фрагмент → утверждение → отчёт | Нет. Номера утверждений раздаёт модель на этапе 8; соответствие проверяют этапы 9 и 14 текстом, а не кодом |
| Разные ракурсы поиска для разных моделей | Нет: шаблон даёт один текст этапа всем моделям. Опровержения требуются от каждой модели в том же запросе |
| Новая пустая беседа на каждом этапе с подтверждением пустоты | Используется существующее поведение запуска (`forceNewTabs`); подтверждения пустой беседы нет |
| Проверка независимости проверяющего по семейству модели, пометка ослабленной независимости | Нет: «другая модель» — вторая в списке |
| Счётчики запросов, времени и возвратов, резерв бюджета | Нет. Работает лимит раундов (15) и общий бюджет профиля; возвраты и дополнительные круги выполняет владелец на воротах |
| Опросник, который строят несколько моделей, и сведение вопросов | Нет отдельного этапа; вопросы возникают маркером `ASK` по ходу этапов |
| Спецификация как неизменяемый паспорт с поправками | Нет: правило записано в текст этапов, кодом не защищено |
| Повторный запрос модели для вопроса без вариантов | Нет: такой вопрос показывается со стандартным выбором «Решите сами и отметьте это допущением» |

Эти пункты — список работ для следующих версий; порядок и состав обсуждаются
отдельно.

## Что проверено

Тесты `tests/research-template.test.js`: каталог и ворота, кто работает на
