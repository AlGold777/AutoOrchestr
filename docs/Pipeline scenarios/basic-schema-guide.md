# Как написать схему Basic: полная инструкция

Версия формата схемы: **1**. Этот документ самодостаточен: чтобы написать рабочую схему, другие файлы читать не нужно.
Его читает человек или модель (в том числе небольшая) и выдаёт один JSON-файл, который расширение принимает с первого раза.
Все примеры и списки ниже проверяются тестом `tests/basic-schema-guide.test.js` против кода: если код изменится, а документ нет,
тест упадёт.

## 0. Как этим пользоваться

**Человеку.**
1. Скопируйте этот документ целиком в модель и допишите в конце, что должен делать pipeline (своими словами).
2. Модель вернёт JSON. Сохраните его в файл с расширением `.json` (внутри только JSON, без ``` и пояснений).
3. На странице pipeline нажмите **Import**, выберите файл, введите имя нового pipeline. Схема встанет на холст и будет в списке.
4. Введите задачу в поле модератора и запустите pipeline, как обычно.

**Запрос для модели** (вставьте перед описанием вашей задачи):

```text
Ты автор схемы pipeline для движка Basic. Прочитай инструкцию ниже целиком и выполни её буквально.
Верни ровно один JSON-объект: без пояснений, без комментариев, без markdown-ограждений.
Перед ответом пройди чек-лист из раздела 11 и исправь всё, что не проходит.
Что должен делать pipeline: <здесь описание задачи>
```

## 1. Что такое схема (коротко)

- **Basic** — движок, который выполняет pipeline: несколько шагов подряд, в каждом шаге один или несколько моделей отвечают на задачу.
- **Схема** — JSON-описание такого pipeline: из каких шагов он состоит, какие модели в каждом шаге и чем отличается от настроек по умолчанию.
- Схема описывает **как** обрабатывать задачу, а не саму задачу. Задачу пользователь вводит при запуске.
- Пишите в схеме **только то, чем она отличается от умолчаний** (раздел 4). Всё, что не указано, Basic возьмёт сам. Так схема короче, и ошибиться негде.

## 2. Формат ответа (жёсткие правила)

- Один JSON-объект. Первый символ `{`, последний `}`.
- Двойные кавычки у всех ключей и строк. Без комментариев (`//`, `/* */`). Без запятой после последнего элемента.
- Числа — числами (`300`, не `"300"`). Булевы — `true` / `false`.
- Не придумывайте поля: неизвестное поле — ошибка, схема не установится.
- Не пишите пустые строки `""` как значения: пустая строка — это «пусто», а не «по умолчанию». Чтобы получить значение по умолчанию, **не пишите поле вообще**.

## 3. Алгоритм: как собрать схему за 7 шагов

1. **Сформулируйте цель одной фразой** и разложите на этапы словами («сначала несколько моделей отвечают независимо, потом одна сводит ответы, потом две критикуют…»).
2. **Определите раунды.** Раунд — это шаг, где одна или несколько моделей отвечают. Первый раунд всегда получает только задачу пользователя. Раундов не больше 50; обычно 1–3.
3. **Решите, кто в каждом раунде.** Выберите имена моделей строго из списка в разделе 7.1. Одна модель не должна повторяться в одном раунде.
4. **Нужен ли синтез между раундами** (промежуточный): одна модель сводит ответы раунда в один, и следующий раунд работает уже со сводом. Если нет — пропустите.
5. **Нужен ли финальный синтез** (`final`): одна модель сводит всё в итоговый ответ. Почти всегда нужен; он стоит последним шагом.
6. **Для каждого раунда после первого решите три вещи** (если умолчания не подходят): порядок (`order`), вход (`input`), задание (`task`) — раздел 5.4. Роли моделей (`role`) — раздел 7.2.
7. **Соберите JSON** по шаблону из раздела 9, подставьте свои значения и пройдите чек-лист (раздел 11).

**Как выбрать вход раунда (`input`)** — самый частый вопрос:

| Что нужно | Что писать |
| --- | --- |
| Модели раунда работают с ответами предыдущего шага (улучшают, критикуют, проверяют) | ничего (умолчание: `previous`) |
| Модели должны видеть ответы **всех** предыдущих шагов, а не только последнего | `"input": "all"` |
| Модели раунда отвечают на задачу заново, не видя прежних ответов | `"input": "none"` |

**Как выбрать порядок (`order`)**:

| Что нужно | Что писать |
| --- | --- |
| Модели раунда отвечают независимо, одновременно | ничего (умолчание: `parallel`) |
| Каждая следующая модель видит ответы тех, кто отвечал раньше в этом же раунде («эстафета») | `"order": "sequential"` |

## 4. Что Basic берёт сам (это писать в схему не нужно)

| Что | Значение по умолчанию |
| --- | --- |
| Политика запуска `run.policy` | `manual` — после каждого шага владелец подтверждает продолжение. Для автоматической цепочки пишите `"auto"` |
| Общий предел длины `run.maxWords` | `300` |
| Порядок раунда | `parallel` |
| Вход первого раунда | `none` (только задача) |
| Вход остальных раундов и синтеза | `previous` (ответы предыдущего шага) |
| Задание раундов после первого | `Учти ответы предыдущего шага и дай свой улучшенный ответ на задачу.` |
| Задание синтеза | `Сведи эти ответы в один итоговый ответ на задачу.` |
| Инструкция длины | `[RESPONSE_LIMIT] Объём ответа: {от}-{слов} слов, не больше.` |
| Требования к содержанию | `Сосредоточься на ясной концепции и ключевых идеях; убери повторы, длинные пересказы и второстепенные детали.` |
| Инструкция доставки | `Последней строкой ответа напиши только метку {метка}` |
| Запрос исправления | `Твой предыдущий ответ {причина}. Дай ответ на задание полностью.` |

Задание первого раунда не отправляется: первый раунд получает только задачу пользователя.

## 5. Справочник полей

Условные обозначения: **обязательно** — без поля схема не пройдёт проверку; остальные поля можно не писать.

### 5.1. Корень схемы

| Поле | Тип | Значение | Если не указано |
| --- | --- | --- | --- |
| `schemaVersion` | число | всегда `1` | **обязательно** |
| `origin` | строка | всегда `"user"` | **обязательно** |
| `basedOn` | строка | на какой схеме основана эта (только пометка) | нет |
| `run` | объект | политика запуска и общий предел (5.2) | значения Basic |
| `defaults` | объект | общие значения для всех шагов (5.3) | значения Basic |
| `steps` | список | шаги по порядку выполнения (5.4) | **обязательно** |

### 5.2. `run`

| Поле | Значение | Если не указано |
| --- | --- | --- |
| `policy` | `"auto"` — шаги идут без остановки; `"manual"` — после каждого шага владелец подтверждает | `manual` |
| `maxWords` | общий предел длины ответа в словах: **только 300, 500, 700 или 1000** | `300` |

### 5.3. `defaults` (общие значения; необязательно)

| Поле | Значение |
| --- | --- |
| `roundTask` | задание для всех раундов после первого, у которых нет своего |
| `synthesisTask` | задание для всех синтезов, у которых нет своего |
| `discipline` | общая дисциплина ответа (5.6) для всех моделей |
| `modelNotes` | `{ "<имя модели>": "<текст>" }` — особенность модели; добавляется к каждому запросу этой модели (раздел 6) |
| `roundPrompts` | `{ "<ref раунда>": "<текст>" }` — текст для роли `custom` в этом раунде (7.2) |

### 5.4. Шаг (`steps[]`)

| Поле | Значение | Если не указано |
| --- | --- | --- |
| `ref` | уникальное имя шага (правила ниже) | **обязательно** |
| `kind` | `"round"` или `"synthesis"` | **обязательно** |
| `order` | только для `round`: `"parallel"` или `"sequential"` | `parallel` |
| `input` | только для `round`: `"none"`, `"previous"` или `"all"`. У синтеза поля нет | первый раунд — `none`, остальные — `previous` |
| `task` | задание шага для всех его моделей | задание из `defaults`, затем из Basic (4); при `input: none` задание не отправляется |
| `models` | список моделей шага (5.5) | **обязательно**; пустой список выключает шаг |

**Имена шагов (`ref`):**
- Раунды: `"r1"`, `"r2"`, `"r3"`… строго по порядку, без пропусков.
- Промежуточный синтез: `"synth:<id>"`, где `<id>` — только латинские буквы, цифры, `_` и `-` (например, `"synth:mid"`).
- Финальный синтез: `"final"`.

### 5.5. Модель шага (`models[]`)

| Поле | Значение | Если не указано |
| --- | --- | --- |
| `name` | имя модели из списка 7.1; в одном шаге не повторяется | **обязательно** |
| `enabled` | `false` — модель выключена: её настройки хранятся, но она не вызывается | включена |
| `role` | id роли из списка 7.2 | без роли |
| `request` | **полный** свой запрос этой модели вместо автоматического (раздел 6, внимание!) | автоматический |
| `maxWords` | личный предел длины ответа этой модели: целое положительное число | общий предел `run.maxWords` |
| `task` | личное задание этой модели (главнее задания шага) | задание шага |
| `discipline` | личная дисциплина ответа (5.6) | значения из `defaults`, затем Basic |

### 5.6. `discipline` (в `defaults` и в модели)

| Поле | Значение |
| --- | --- |
| `limit` | инструкция длины; подстановки `{от}` (предел минус 50) и `{слов}` (предел) |
| `content` | требования к содержанию |
| `delivery` | инструкция доставки; подстановка `{метка}` |
| `correction` | запрос исправления; подстановка `{причина}` |
| `lines` | список своих строк-инструкций (`["Отвечай по-русски.", "Приведи источники."]`); каждая добавляется в запрос отдельным абзацем после требований к содержанию. Строки из `defaults` идут первыми, затем строки модели |

Значение модели главнее значения из `defaults`, оно главнее значения Basic. Для `lines` это не замена, а добавление.

## 6. Что получает модель (зачем нужны поля)

Запрос модели собирается из частей в таком порядке; части, для которых нет данных, пропускаются:

1. **Задача:** текст, который пользователь вводит при запуске.
2. **Ответы предыдущего шага** (вход `previous`) или **Принятые ответы всех предыдущих шагов** (вход `all`).
3. **Ответы участников этого раунда до тебя** — только при порядке `sequential`.
4. **Задание** — `task` (в первом раунде не отправляется).
5. **Дополнительно для тебя** — текст роли модели.
6. Особенность модели (`defaults.modelNotes`), инструкция длины, требования к содержанию, свои строки (`lines`).
7. Инструкция доставки добавляется при отправке (метка, по которой расширение находит конец ответа).

Пример: второй раунд, модель GPT с ролью Critique, общая строка `"Отвечай по-русски."` в `defaults.discipline.lines`, задача «Придумай название для кофейни.» (предел 300 слов, две ответа первого раунда):

```text
Задача:
Придумай название для кофейни.

Ответы предыдущего шага:

Ответ 1:
Ответ первой модели.

Ответ 2:
Ответ второй модели.

Задание:
Учти ответы предыдущего шага и дай свой улучшенный ответ на задачу.

Дополнительно для тебя:
<ТЕКСТ РОЛИ Critique>

[RESPONSE_LIMIT] Объём ответа: 250-300 слов, не больше.

Сосредоточься на ясной концепции и ключевых идеях; убери повторы, длинные пересказы и второстепенные детали.

Отвечай по-русски.
```

**Внимание: `request`.** Если у модели есть `request`, он заменяет весь автоматический запрос, кроме последних частей (шаг 6–7), а роль не добавляется. В тексте `request` обязательно пишите подстановки `{задача}` (задача пользователя), для шагов с входом — `{вход}` (ответы), для `order: sequential` — `{ответы до тебя}`. Без них модель не увидит задачу и ответы. **Если нет веской причины, `request` не используйте**: хватает `task`, `role` и `discipline.lines`.

**Синтез** — обычный шаг: он получает ответы предыдущего шага и задание синтеза. Промежуточный синтез без своего `request` берёт `request` той же модели из шага `final`, если он есть.

## 7. Допустимые значения

### 7.1. Модели (точные имена, регистр важен)

Допустимы только эти десять имён:

| Имя |
| --- |
| `Claude` |
| `GPT` |
| `Gemini` |
| `Grok` |
| `Le Chat` |
| `Qwen` |
| `DeepSeek` |
| `Perplexity` |
| `Z.ai` |
| `Kimi` |

Любое другое имя (например, `ChatGPT`, `gpt-4`, `Claude 3`) — ошибка «модель недоступна».

### 7.2. Роли (`role`)

Роль — готовый мини-запрос, который добавляется модели как «Дополнительно для тебя». Допустимые id:

| id | Название | Что делает |
| --- | --- | --- |
| `interaction_meta_synthesis` | Synthes | строит собственное решение, используя версии как сырьё |
| `interaction_critical_audit` | Critique | аудит ответов: слепые зоны, ошибки, методология |
| `interaction_select_ideas` | Select ideas | извлекает все уникальные идеи списком |
| `interaction_pattern_clustering` | Clustering | группирует идеи по сути подхода |
| `custom` | Custom | берёт текст из `defaults.roundPrompts["<ref раунда>"]` |

Роль `custom` без записи в `defaults.roundPrompts` для этого раунда ничего не добавит. Нет подходящей роли — не пишите `role` и опишите нужное в `task`.

## 8. Правила холста (почему схема может не установиться)

Формат допускает больше, чем показывает холст страницы. При установке проверяется:

- **Раунды `r1`, `r2`, …** идут по порядку без пропусков: холст нумерует раунды сам, поэтому `r2` без `r1` — ошибка.
- **Промежуточный синтез** стоит между двумя раундами (сразу после раунда и перед следующим раундом). Два синтеза подряд, синтез перед первым раундом и синтез после последнего раунда не бывают: после последнего раунда ставится только `final`.
- **`final`** — последний шаг, один.
- **В синтезе одна модель** (у раунда — любое число разных моделей).
- **Хотя бы один раунд** и не больше 50.
- **Имена моделей и ролей** — из списков раздела 7.
- **`run.maxWords`** — 300, 500, 700 или 1000.
- Выключенный синтез (`"models": []` или все модели `enabled: false`) на холст не ставится, но его настройки сохраняются.

Порядок моделей внутри параллельного раунда на результат не влияет; после установки холст расставит модели в своём порядке.

## 10. Ошибки при установке и как их исправить

Расширение ничего не исправляет за вас: оно называет место ошибки (путь вида `steps[1].models[0].name`) и не устанавливает схему.

| Сообщение (в тексте ошибки) | Причина | Что исправить |
| --- | --- | --- |
| `версия формата не указана` | нет `schemaVersion` или это не целое число | добавьте `"schemaVersion": 1` |

## 11. Чек-лист самопроверки (пройдите перед ответом)

1. Ответ — один JSON-объект, без текста вокруг, без комментариев и запятых после последних элементов.
2. Есть `"schemaVersion": 1`, `"origin": "user"` и непустой список `steps`.
3. Раунды называются `r1`, `r2`, … по порядку; финальный синтез — `final`, и он последний; промежуточные — `synth:<id>` между раундами.
4. В каждом шаге есть `ref`, `kind`, `models`; у синтеза нет `order` и `input`.
5. Все имена моделей — из таблицы 7.1 точно как там; в шаге они не повторяются; в синтезе одна модель.
6. Все `role` — из таблицы 7.2; если `role` равно `custom`, для этого раунда есть запись в `defaults.roundPrompts`.
7. `run.maxWords` (если есть) — 300, 500, 700 или 1000; `run.policy` — `auto` или `manual`; `maxWords` у модели — целое число больше 0.
8. Нет выдуманных полей и нет полей со значением `""`.
9. В `request` (если он есть) присутствуют `{задача}` и, где нужно, `{вход}` / `{ответы до тебя}`.
10. Схема содержит только отличия от умолчаний раздела 4.

## 12. Установка и запуск

- **Import** (страница pipeline): выберите файл `.json` с одной схемой, введите имя. Имя шаблона (Basic, Polishing, Delta, Test, Research, Architecture) занять нельзя; существующее имя спросит подтверждение замены. Остальные pipelines не затрагиваются.
- После установки pipeline выбран в списке, холст показывает раунды, модели и синтезы; у раунда (клик по значку R1, R2…) видны порядок, вход и задание; у модели (двойной клик по блоку) — её запрос, длина и дисциплина.
- Введите задачу в поле модератора и запустите. При `run.policy: manual` владелец подтверждает каждый шаг; при `auto` шаги идут сами и останавливаются только если у шага нет принятых ответов.
- Схему можно менять на холсте и сохранять кнопкой Save: настройки сохраняются в той же схеме.

## 13. Чего не делать

- Не копируйте тексты умолчаний из раздела 4 в схему «для надёжности»: они тогда перестанут следовать за Basic.
- Не пишите `input` и `order` у синтеза, `input` у первого раунда (ему подавать нечего).
- Не нумеруйте раунды с нуля и не пропускайте номера.
- Не ставьте два синтеза подряд и синтез после последнего раунда (кроме `final`).
- Не используйте `request`, если хватает `task`, `role` и `lines`.
- Не вставляйте задачу пользователя в схему: её вводят при запуске.
- Не выдумывайте названия моделей и ролей: только из списков раздела 7.
