# Basic: справочник формата схемы

Формат версии **1**. Код: [`disput/basic-schema.js`](../../disput/basic-schema.js), тесты:
[`tests/basic-schema.test.js`](../../tests/basic-schema.test.js). Концепция и правила совместимости:
[basic-engine-and-schemas.md](basic-engine-and-schemas.md). Логика сценария (какие шаги нужны и зачем) —
[how-to-design-a-scenario.md](how-to-design-a-scenario.md); здесь только запись.

Справочник описывает сохраняемую схему, а не внутреннюю конфигурацию движка. Он обновляется в том же
коммите, что и поле.

## Правила

- Схема — данные, кода в ней нет. Хранит только явно заданное; всё остальное берётся из Basic.
- **Поля нет** — значение Basic. **Поле есть** — применяется, включая `""`: пустой текст — значение, а не
  наследование.
- Списки (шаги, модели, строки) заменяют список Basic **целиком**, порядок сохраняется.
- Шаг без моделей выключен: схема остаётся допустимой, шаг занимает своё место в нумерации, движок его не
  получает. Выключенный синтез не включается сам.
- Неизвестное поле, неизвестный тип или недопустимое значение — ошибка до первой отправки с указанием места
  (`steps[1].models[0].maxWords`). Схема молча не исправляется.
- Схема, созданная более новой версией формата, чем знает установленный Basic, не запускается. Все ранее
  выпущенные версии формата остаются поддерживаемыми.

## Схема

| Поле | Значение | Если нет |
| --- | --- | --- |
| `schemaVersion` | Целое число; сейчас `1` | Ошибка |
| `origin` | `builtin` — схема, поставляемая с кодом; `user` — схема пользователя | Ошибка |
| `basedOn` | Имя схемы, с которой начата эта; только пометка, на выполнение не влияет | — |
| `run` | Политика запуска и общий предел длины ответа (ниже) | Значения Basic |
| `defaults` | Значения ▶ для всех шагов (ниже) | Значения Basic |
| `steps` | Список шагов в порядке выполнения | Ошибка |

### `run`

| Поле | Значение | Если нет |
| --- | --- | --- |
| `policy` | `auto` — шаги идут без остановки; `manual` — после каждого шага владелец подтверждает | `manual` |
| `maxWords` | Положительное целое — общий предел длины ответа pipeline в словах; личный `maxWords` модели главнее | `300` |

Страница собирает `run` из шапки (Auto и список длины). Запуск фиксирует эти значения на весь прогон.

### `defaults` (карточка ▶)

| Поле | Значение | Если нет |
| --- | --- | --- |
| `roundTask` | Задание раундов со входом (R2+) | Текст Basic |
| `synthesisTask` | Задание синтеза | Текст Basic |
| `discipline` | Общая дисциплина ответа (ниже) | Тексты Basic |
| `modelNotes` | `{ "<модель>": "<текст>" }` — особенность модели, добавляется к каждому её запросу | Нет |
| `roundPrompts` | `{ "<ref шага>": "<текст>" }` — текст раунда для роли «Custom» | Нет |

### Шаг

| Поле | Значение | Если нет |
| --- | --- | --- |
| `ref` | Уникальный идентификатор: `r1`, `r2`… (раунды), `synth:<id>` (промежуточный синтез), `final` (финальный синтез) | Ошибка |
| `kind` | `round` или `synthesis` | Ошибка |
| `order` | Только `round`: `parallel` (все получают одинаковый вход) или `sequential` (каждая модель видит ответы предыдущих в раунде). У синтеза поля нет | `parallel` |
| `input` | Только `round`: `none`, `previous` (принятые ответы предыдущего шага), `all` (все принятые). Синтез всегда получает `previous` | Первый раунд схемы — `none`, остальные — `previous` |
| `task` | Задание шага для всех его моделей | Значение ▶, затем текст Basic; при `input: none` задание пустое |
| `models` | Модели шага; порядок — порядок вызова. Пустой список выключает шаг | Ошибка |

Порядок, вход и задание раунда на странице задаются на карточке раунда (клик по значку раунда); у первого раунда карточка предлагает только порядок. «Первый раунд» считается по порядку раундов в схеме, включая выключенные. Выключенный раунд сохраняет свой номер: если `r1` выключен, включённый `r2` остаётся «Раунд 2» в предпросмотре, журнале и прогоне, а его идентификатор `ref` попадает в журнал.

### Модель шага

| Поле | Значение | Если нет |
| --- | --- | --- |
| `name` | Имя модели; в шаге не повторяется | Ошибка |
| `enabled` | `false` — модель выключена: её настройки хранятся в схеме, но она не вызывается | Включена |
| `role` | Идентификатор роли (мини-запроса) модели | Без роли |
| `request` | Полный свой запрос; заменяет автоматическую сборку, роль при этом не добавляется. Подставляются `{задача}`, `{вход}`, `{ответы до тебя}`. `""` — значение: своего запроса нет, автоматическая сборка. Для промежуточного синтеза, у которого поля нет, берётся `request` той же модели из шага `final`, если он включён | Автоматическая сборка |
| `maxWords` | Положительное целое — предел длины ответа этой модели | Предел pipeline |
| `task` | Задание этой модели | Задание шага, ▶, Basic |
| `discipline` | Дисциплина ответа модели (ниже) | Значения ▶, затем Basic |

### Дисциплина ответа (`discipline`)

Допустима в `defaults` и в модели; значение модели главнее ▶.

| Поле | Значение | Если нет |
| --- | --- | --- |
| `limit` | Инструкция длины; `{от}` — предел минус 50 (не меньше 1), `{слов}` — предел | Текст Basic |
| `content` | Требования к содержанию | Текст Basic |
| `delivery` | Инструкция доставки; `{метка}` — метка запроса | Текст Basic |
| `correction` | Запрос исправления непринятого ответа; `{причина}` | Текст Basic |
| `lines` | Список своих строк-инструкций; добавляются в запрос после требований к содержанию, каждая отдельным абзацем | Нет |

`lines` не наследуются «вместо»: строки ▶ идут первыми, затем строки модели, и всегда добавляются в запрос
(в том числе при исправлении). Остальные поля — по цепочке модель → ▶ → Basic.

## Что считается явным значением

Текст, введённый владельцем в карточке, записывается в схему как есть, в том числе когда он совпал с унаследованным;
`""` не записывается, пустое поле возвращает наследование. Введённая инструкция длины, совпавшая с показанной (с числами),
записывается шаблоном (`{от}`, `{слов}`) и продолжает следовать пределу. Запрос карточки, совпавший с автоматическим, остаётся
унаследованным. Политика запуска и предел, выбранные в шапке, записываются в `run` даже при равенстве Basic; сама загрузка
схемы явными их не делает. Записи, сохранённые до схемы, читаются так: копия текущей инструкции длины по умолчанию — не
личное значение (как раньше), в схеме такое значение явное.

## Где схема хранится физически

Схемы не лежат отдельными файлами. Все pipelines пользователя — одна запись в хранилище расширения
(`chrome.storage.local`, ключ `llmComparatorPipelines`; через `CompressedStorage`, если он есть, тогда запись сжата;
записывает `persistPipelineStore` в `results.js`). Состав записи:

| Поле | Что это |
| --- | --- |
| `pipelines` | словарь «имя → запись pipeline»; схема Basic-pipeline — поле `schema` внутри своей записи, рядом с данными холста (`protocol`, `roundCounter`, `modelStacks`, `draftPlan`) |
| `order`, `active`, `lastSaved` | порядок в списке, выбранный и последний сохранённый pipeline |
| `draftPlans` | отдельный сохранённый план холста по имени (вставки синтеза, финальный синтез) |
| `overrides` | переопределения по именам (предел раундов, синтезатор, профиль) |
| `version` | версия записи (`PIPELINE_STORE_VERSION`) |

Не в этой записи: шаблоны (Basic, Polishing, Delta, Test, Research, Architecture) — они собираются из кода
(`disput/pipeline-presets.js`) при каждой загрузке и схемами в хранилище не являются; записи прогонов — отдельные
ключи по одному на прогон (`disput/custom-run-record.js`).

Файлом схема становится только при обмене: **Export** выгружает JSON всей записи (схемы внутри записей pipelines),
**Import** принимает либо такой экспорт (он заменяет все pipelines после подтверждения), либо файл с одной схемой —
тогда она добавляется как новый pipeline (см. «Как схема встаёт на холст»). Отдельной выгрузки одной схемы нет:
её можно взять из поля `schema` нужного pipeline в экспорте.

## Как схема хранится в записи pipeline

Запись Basic-pipeline держит схему в поле `schema` и больше не пишет `customModelSettings` и `customDefaults`.
Схема читается при загрузке: настройки карточек и ▶ берутся из неё, политика запуска и предел — из `run`
(а если их нет — из Basic). Схема, которую нельзя прочитать (в том числе созданная более новой версией Basic),
не запускается; запись, сохранённая раньше, читается как раньше. Структура холста (раунды, включённые модели,
роли, синтезы) пока восстанавливается по атомам холста той же записи; `steps` схемы обновляются при Save и при
сохранении карточки.

## Как схема встаёт на холст (установка)

Схему, которой нет в списке (например, написанную моделью), добавляет кнопка Import: файл JSON с одной схемой
(`schemaVersion` и `steps`, без `pipelines`) добавляется как новый pipeline под именем, которое вы зададите; остальные
pipelines не заменяются. Остальной файл Import (экспорт pipelines) работает как раньше. Установленная схема получает
`origin: user` (поле `basedOn` сохраняется), холст строится из неё, настройки моделей и шагов остаются в схеме.

Холст показывает не всё, что допускает формат, поэтому при установке дополнительно проверяется:

- раунды стоят как `r1`, `r2`, … по порядку, не меньше одного и не больше 50;
- промежуточный синтез `synth:<id>` стоит ровно между двумя раундами (после раунда и перед раундом), не больше одного в промежутке;
- финальный синтез `final` — последний шаг;
- в синтезе одна включённая модель;
- имена моделей — из тех, что знает холст; `role` — id роли страницы (`custom` — текст раунда);
- модель в раунде включена, если она не `enabled: false`; на холсте остаются модели, включённые хотя бы в одном раунде, в порядке
  холста (порядок в параллельном раунде не влияет на выполнение, поэтому после установки порядок моделей в схеме — порядок холста);
- выключенный синтез не ставится на холст, но его настройки хранятся.

Схема, которую холст показать не может, не устанавливается: ошибка называет место (`steps[1].models[0].name`),
сохранённые pipelines не меняются.

## Прежние настройки страницы

Пока Save хранит прежнюю форму (холст, `customModelSettings`, `customDefaults`), страница читает её в схему
на одной границе (`basicSchemaFromPage`): пустой сохранённый текст там не считался значением и отбрасывается,
снятое поле `ask` игнорируется, а промежуточный синтез без своего запроса, как и раньше, берёт сохранённый
запрос той же модели финального синтеза, даже когда финальный синтез выключен. Любое другое значение, в том
числе неверное (`0`, `false`, текст вместо числа), идёт в проверку как есть и останавливает запуск.

## Минимальный пример

Два параллельных ответа и синтез. Проходит проверку Basic; тест `tests/basic-schema.test.js` берёт этот блок
из справочника.

```json
{
  "schemaVersion": 1,
  "origin": "user",
  "steps": [
    { "ref": "r1", "kind": "round", "models": [{ "name": "GPT" }, { "name": "Claude" }] },
    { "ref": "final", "kind": "synthesis", "models": [{ "name": "Gemini" }] }
  ]
}
```

Всё остальное (порядок `parallel`, вход, задания, дисциплина) берётся из Basic.
