# Basic: если что-то пошло не так

Для кого и зачем: для человека или модели, которые разбирают сбой прогона Basic или схемы, которую не удаётся установить. Здесь собрано, где лежат данные о прогоне, что означает каждое сообщение и что проверить в первую очередь. Термины — в [basic-start-here.md](basic-start-here.md).

## Что у нас есть для разбора

| Источник | Где взять | Что в нём |
| --- | --- | --- |
| Уведомления страницы | Всплывающие сообщения внизу страницы | Причина остановки и ошибки схемы: «Basic: …», «Схема не установлена. …», «Pipeline: error (…)». |
| Журнал доставки (`delivery`) | Поле `delivery` в JSON Disput Flow | События прогона Basic: `custom_start`, `custom_answer`, `custom_step`, `custom_decision`, `custom_end` (движок) и `owner_answer` (ответ владельца на вопрос `[[ASK]]`). |
| Запись о прогоне (`customRun`) | Поле `customRun` в JSON Disput Flow: кнопка на вкладке Disput панели диагностики, значок загрузки с подсказкой «Export Disput telemetry as JSON» (`#disput-export-json`) | Полные тексты прогона: задача, запросы по попыткам, входы, ответы, исходы, `state` каждой попытки (`sent`, `done`, `not_sent`, `unknown`). |
| Extract (Transport) | Кнопка «Extract» на той же вкладке (`#disput-extract`) | Сохраняет JSON Disput Flow и разбор в Markdown. Для прогона Basic разбирает последний прогон: шаги как этапы. Если прогона Basic в журнале нет, выводит предупреждение. |
| Холст | Шаги на холсте pipeline | Статусы шагов: серый `pending`, синий или оранжевый `running`, `completed`. Итоговое состояние прогона: `COMPLETED` (все шаги пройдены), `CANCELLED` (остановлено или ограничено бюджетом), `FAILED` (ошибка). |
| Export schema | Кнопка «Export schema» в шапке pipeline | Схема того, что сейчас на холсте, одним JSON-файлом. |

## Симптом → где смотреть

| Симптом | Где смотреть | Что это значит и что делать |
| --- | --- | --- |
| «Basic: схема не запущена. <место: причина>» | Уведомление | Схема не прошла проверку перед запуском; запросов не было. Место ошибки указано в тексте (например, `steps[1].models[0].name`). Исправить поле; таблица ошибок — в [basic-schema-guide.md](basic-schema-guide.md), раздел 10. |
| «Basic: выберите модели хотя бы в одном раунде.» | Уведомление | Ни в одном раунде не включена модель. Включить модель в раунде и запустить снова. |
| Шаг долго остаётся «выполняется» | `custom_answer` в журнале (поля `status`, `reason`); окно паузы | Модель ещё не ответила или ответ не принят. Если открыто окно паузы («Продолжить / Повторить без ответа / Stop» или «Пропустить шаг / Повторить / Stop»), решение ждёт владельца. Stop завершает прогон. |
| Ответ модели не принят | `custom_answer` с `accepted=false` и `reason`; в `customRun` у попытки поля `accepted` и `reason` | Причина — текст из `REASON_TEXT` в `disput/custom-engine.js`: «пустой», «без текста», «слишком короткий», «оборван», «оборван на середине», «ошибка вместо ответа», «раунд закрыт владельцем». Движок повторяет запрос исправления в том же чате, до 2 попыток. |
| Итог «Принятых ответов нет.» | `custom_step` (`accepted`, `failed`) и `custom_decision` | Ни один шаг не принял ответ. Смотреть, на каком шаге и по какой причине ответы не приняты; если решение владельца не получено, итог содержит «Остановка: нет принятых ответов, решение владельца не получено.». |
| Остановка «промпт не помещается в бюджет» (`context_full`) | В `customRun` у попытки `state: not_sent`; `custom_end` с `stopReason: context_full` | Запрос не отправлен, потому что превышен предел длины. Сократить вход, задание или длину ответа. |
| Нужно знать, что именно ушло модели | `customRun`: у попытки `prompt` (запрос движка) и `sentPrompt` (как отправил транспорт, с меткой доставки) | Сравнить эти два поля, если транспорт дописал что-то к запросу. |
| В карточке ответа лишний служебный текст, потеряны абзацы или ответ пустой | Сравнить `answer` у попытки в `customRun` с карточкой; связать запись с журналом доставки (`delivery`) по `transportRequestId` | Если текст в `answer` уже искажён, проблема в транспорте или контент-скриптах, а не в схеме. |
| Схема не устанавливается через Import: «Схема не установлена. <место: причина>» | Уведомление | Схема не прошла проверку при установке; ничего не записано. Исправить место, указанное в тексте. |
| Import: «Файл не JSON.» | Уведомление | Файл повреждён или это не JSON. Проверить, что в файле только JSON, без обрамления ``` и пояснений. |
| Import: «Файл не похож на схему Basic.» | Уведомление | В файле нет полей схемы (`schemaVersion` и `steps`) и нет набора `pipelines`. |
| Настройки пропали после перезагрузки | Была ли нажата Save в шапке pipeline или сохранялась карточка | Настройки записываются в запись pipeline при Save и при изменении карточек уже сохранённого под именем pipeline. Несохранённые изменения шаблона живут до перезагрузки страницы. Резерв — Export schema. |
| Stop не закрыл окно паузы | Окно паузы | Stop закрывает открытое окно паузы: это делает блок `finally` в `runCustomFromPage`. Если окно осталось открытым после Stop, это ошибка: приложить Disput Flow JSON. |

## Как собрать материалы для передачи другой модели

1. Export schema: схема того, что на холсте.
2. Disput Flow JSON сразу после прогона: в нём `customRun` и `delivery`.
3. Extract (Transport) для сжатого разбора прогона.
4. Текст задачи, которую вводили в поле модератора, и что ожидалось.

Скриншоты вместо JSON не нужны: в JSON есть всё, что нужно для разбора.

## Известные особенности

- Итог «Basic · итог» берётся из последнего шага, у которого есть принятые ответы.
- Модель, у которой Send выключен во всех раундах, после перезагрузки с холста пропадает: холст строится только из включённых моделей (`toCanvas` в `disput/basic-schema.js`).
- Значения вне таблицы допустимых (модели, роли, пределы длины, порядок `r1…rN`, `ref` промежуточного синтеза) отклоняются при установке схемы.
