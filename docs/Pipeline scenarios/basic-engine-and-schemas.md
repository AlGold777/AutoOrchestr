# Движок Basic и схемы pipeline

Статус: **концепция согласована 9 октября 2026**. Реализовано в 2.81.671–2.81.679: формат (включая политику запуска
и общий предел), единая сборка, проверка перед запуском, **Save схемы**, **Export и Import схемы**
([`disput/basic-schema.js`](../../disput/basic-schema.js), справочник —
[basic-schema-reference.md](basic-schema-reference.md); как написать схему — [basic-schema-guide.md](basic-schema-guide.md)).

**Единый путь «схема → запись» (2.81.679).** Запись Basic-pipeline строится из схемы одной функцией `recordFromSchema`:
в записи лежит `schema`, а данные холста (число раундов, модели раундов и их роли, финальный синтезатор, промежуточные
синтезы, `protocol`) выводятся из схемы и с холста отдельно не снимаются. В хранилище пишет только `installBasicSchema`.
Этим путём идут Save, Import, сохранение карточки модели, ▶ и карточки раунда, а также правка структуры сохранённого
pipeline (вставка или снятие промежуточного синтеза, выбор финального синтезатора). Поэтому запись и схема не расходятся.
Прежние члены записи (`customModelSettings`, `customDefaults`) не пишутся; запись, сохранённая раньше, читается как раньше
и переходит на схему при первом сохранении. Save, Export и Import — см. разделы ниже.

**Установка схемы (2.81.675).** Схема без атомов холста (например, написанная моделью) устанавливается через Import:
холст строится из неё (`BasicSchema.toCanvas`, `installBasicSchema`), правила холста — в справочнике.

**Явные значения (2.81.676).** Текст, который владелец ввёл в карточке (задание, дисциплина, длина), сохраняется явным, даже
если он совпал с унаследованным; вернуть наследование можно кнопками «↶» и «×» (для длины — очистить поле). Политика
запуска и предел длины, которые владелец выбрал в шапке, тоже запоминаются как явные, даже если равны значениям Basic.
Исключение одно: запрос карточки, совпавший с автоматически собранным, остаётся унаследованным, потому что автоматический
запрос собирается из шагов и не является сохранённым значением.

**Карточка раунда (2.81.677).** Порядок работы, вход и задание раунда задаются на карточке раунда (клик по значку раунда),
хранятся в схеме (`order`, `input`, `task` шага) и переживают Save, загрузку и установку схемы.
Текущая реализация движка описана в [basic-pipeline.md](basic-pipeline.md).

## Термины

- **Basic** — универсальный движок pipeline (до 2.81.670 назывался Custom). Basic — это код движка вместе с его
  значениями по умолчанию. Это единственный pipeline, который исполняется.
- **Схема** — pipeline, созданный на базе Basic. Схема не содержит кода и не является копией
  pipeline. Это слой поверх Basic: она хранит **явные переопределения** —
  значения, которые автор схемы задал сам (раунды, модели, роли, задания, входы, политика запуска,
  маркеры и другие элементы дисциплины ответа).

## Наложение схемы на Basic

| В схеме | Результат |
| --- | --- |
| Поля нет | Значение Basic |
| Задано значение, включая `false` и `0` | Значение схемы |
| Пустая строка `""` | Пустой текст: унаследованный текст убран |
| Список (шаги, модели) | Заменяет список Basic целиком, порядок сохраняется |

Наследование задаётся только отсутствием поля. Пустая строка — явное значение. Так работает схема
(`BasicSchema.resolveFields`); прежние сохранённые настройки очищаются от пустых строк на границе
(`basicSchemaFromPage`), потому что карточка никогда не сохраняла пустое как значение.

## Save

- Сохраняет только явные переопределения. Явно заданное значение сохраняется, даже если оно
  совпадает со значением Basic. Возврат поля к наследованию удаляет переопределение.
- Открыть схему и нажать Save не превращает показанные значения Basic в явные. Политика запуска и предел длины записываются в `run` только если они различаются с Basic или были явными в загруженной схеме.
- Save шаблона создаёт схему `user` с `basedOn` = имя шаблона; повторный Save и сохранение карточки сохраняют `basedOn`.
- Настройки выключенной модели и шага, которого нет на холсте, остаются в схеме с `enabled: false`.
- Ответы, статусы и другие данные прогона в схему не попадают.
- В схеме записываются `schemaVersion` (с первого сохранения) и `origin`.
- Кнопка Save спрашивает имя. Имя шаблона занять нельзя; существующее имя спрашивает подтверждение замены.
- Схема собирается с холста (с `basedOn`, если это копия шаблона; повторный Save сохраняет прежний `basedOn`) и
  устанавливается тем же путём, что и импортированная. Поля `customModelSettings` и `customDefaults` не пишутся.
- Схема хранит все раунды `r1…rN` подряд, в том числе раунд, где никто не отправляет (`models` пустой или все
  `enabled: false`). При Save отбрасываются настройки удалённых раундов и промежуточных синтезов, которых нет на холсте.
  Сохраняются настройки выключенного финального синтеза и карточки промежуточного синтеза, настроенной до добавления
  его на холст: она остаётся выключенным шагом на месте, названном её id `planned-working-synthesis-after-canvas-rN`.
- Сохранение карточек и правка структуры сохранённого pipeline сразу пересобирают запись целиком из текущего холста.
  Поэтому снятая, но не сохранённая отметка Send у модели попадает в запись при ближайшей такой записи.

## Export и Import схемы

- **Export schema** выгружает одну схему pipeline, который сейчас на холсте, файлом `<имя pipeline>.json`
  (недопустимые для имени файла символы заменяются на `_`). Файл — голая схема, как в
  [basic-schema-guide.md](basic-schema-guide.md): `schemaVersion`, `origin: "user"`, `basedOn` (для копии шаблона),
  `run` (только явные значения), `defaults`, `steps`. Перед выгрузкой схема проверяется так же, как при Save и Import;
  если её нельзя показать на холсте, выгрузки нет, причина — в уведомлении.
- **Import schema** принимает:
  - файл с одной схемой (есть `schemaVersion` и `steps`, нет `pipelines`): имя pipeline предлагается из имени файла
    без `.json`, его можно изменить; имя шаблона занять нельзя; существующее имя спрашивает подтверждение замены;
    ошибки называют место (например, `steps[0].models[0].name`); после установки pipeline выбран;
  - файл прежнего общего экспорта (есть поле `pipelines`): **добавляет** записи, у которых есть `schema`, под их
    именами. При совпадении с существующим именем или с именем шаблона к имени добавляется « (2)», « (3)» и т. д.;
    запись, чьё имя совпадает с именем шаблона, пропускается. Остальные записи пропускаются, ничего не заменяется.
    Итог — в уведомлении: «Добавлено схем: N, пропущено: M»;
  - не JSON: «Файл не JSON.»; JSON, который не схема и не прежний экспорт: «Файл не похож на схему Basic.».
- Режима «заменить все pipelines» нет.
- Загрузка pipeline из списка не изменилась: страница читает запись и показывает холст. Запись всегда согласована
  со схемой, потому что строится только из неё.
- Хранение не менялось: одна запись `llmComparatorPipelines` в `chrome.storage.local`. Шаблоны не хранятся,
  они собираются из кода.

## Следствия

- Номер раунда берётся из id стадии `canvas-rN`, а не из порядка стадий плана: пустой раунд не сдвигает номера.
- Модель, у которой Send выключен во всех раундах, после перезагрузки с холста пропадает. В схеме от неё остаётся
  запись `enabled: false`, только если у неё есть настройки.
- Порядок моделей в параллельном раунде — порядок холста.

## Одна сборка конфигурации

Basic + схема → итоговая конфигурация → проверка → запуск.

Сборка выполняется одной функцией (`BasicSchema.assemble`, на странице — `buildBasicRun`). Канва,
предпросмотр запроса и запуск используют её, значения Basic по умолчанию лежат только в
`BasicSchema.DEFAULTS`. При запуске итоговая конфигурация фиксируется на весь прогон.

## Проверка перед запуском

До первой отправки проверяются версия формата, типы шагов и допустимость значений.
При ошибке запуск останавливается с указанием места ошибки; запросы не отправляются.
Схема не исправляется молча: `BasicSchema.validate` проверяет её до `normalizeSteps` движка, который
по-прежнему подменяет неизвестное (после проверки подменять уже нечего).
Намеренно выключенные элементы допустимы.

## Происхождение схемы

Поле `origin` в схеме:

| `origin` | Кто создаёт | Свойства |
| --- | --- | --- |
| `builtin` | Мы | Поставляется с кодом, не перезаписывается пользователем |
| `user` | Пользователь | Хранится у пользователя, мы её не перезаписываем |

Встроенную схему можно настраивать на канве как рабочий вариант. Save создаёт схему `user` с
переопределениями рабочего варианта; встроенная остаётся прежней. Схема `user` накладывается
прямо на Basic и не зависит от последующих изменений встроенной.

## Совместимость

1. **Движок не знает о конкретных схемах.** Если схеме нужна новая возможность, она
   добавляется в Basic как общее поле или вариант значения и доступна всем схемам.
2. **В пределах поддерживаемого `schemaVersion` не меняются:** смысл существующих полей,
   их допустимые значения, поведение при отсутствии поля, порядок исполнения и передачи данных.
3. **Новое поле по умолчанию сохраняет прежнее поведение.** Новое поведение схема включает явно.
4. **Обновление Basic сохраняет поддержку всех ранее выпущенных версий формата схем.**
   Повышение `schemaVersion` не является основанием отключать существующие схемы.
5. Отказ при неподдерживаемой версии — для схемы, созданной более новым Basic, чем установлен
   у пользователя (см. «Проверка перед запуском»). Механизм перехода между версиями формата
   определяется, когда формат действительно понадобится менять.

## Переименование Custom → Basic

Версия хранилища pipelines — 8 (`migrateBasicTemplateName`, `results.js`):
- запись шаблона «Custom» удаляется; шаблон «Basic» собирается из кода заново;
- отметки активного и последнего сохранённого pipeline, стоявшие на «Custom», переходят на «Basic»;
- собственный pipeline пользователя с именем «Basic» (если был) сохраняется под первым свободным «Basic N» со всеми данными, вместе с отметками, которые на нём стояли;
- внутренние id и ключи (`CUSTOM`, `disput/custom-engine.js`, `customDefaults` в старых записях) не менялись; пункт «Custom» в списке ролей остался: это роль, а не движок.

## Критерии готовности

Проверяются тестовым транспортом, без реальных вызовов моделей:
- сохранение и повторная загрузка сохраняют настройки и план (тесты Save: настройки и шаги запуска совпадают до и после перезагрузки);
- выключенный синтез не включается обратно;
- новое необязательное поле не меняет поведение старой схемы;
- изменение встроенной схемы не меняет пользовательскую;
- неподдерживаемая схема не отправляет запросы.

Вместе с форматом пишется **справочник формата схемы** и обновляется в том же коммите, что и поле:
- описывает сохраняемую схему, а не внутреннюю конфигурацию движка: поля, смысл, ограничения, наследование;
- если значение зависит от контекста (например, от типа шага), описывается правило, а не одно значение;
- содержит минимальный пример схемы, проходящий проверку Basic.

## Чего не делаем

Старые pipelines (Polishing, Delta, Test, Research, Architecture и ранее сохранённые копии)
не чиним и не переносим. При необходимости их заново описывают как схемы на Basic.
