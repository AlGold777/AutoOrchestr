# Движок Basic и схемы pipeline

Статус: **концепция согласована 9 октября 2026**. Реализовано в 2.81.671–2.81.674: формат (включая политику запуска
и общий предел), единая сборка, проверка перед запуском и **Save схемы**
([`disput/basic-schema.js`](../../disput/basic-schema.js), справочник —
[basic-schema-reference.md](basic-schema-reference.md)).

**Что хранит запись Basic-pipeline (2.81.674).** Поле `schema` — единственное место настроек Basic: карточки моделей,
▶, политика запуска и общий предел, `origin`, `basedOn`, `schemaVersion`. Прежние члены записи
(`customModelSettings`, `customDefaults`) у такого pipeline больше не пишутся; запись, сохранённая раньше, читается
как раньше и переходит на схему при первом сохранении настроек (Save или сохранение карточки). Структуру холста
(раунды, включённые модели, роли, синтезы) загрузка по-прежнему берёт из атомов холста в той же записи
(`modelStacks`, план, `protocol.synthesizer`); `steps` в схеме перезаписываются при Save и при сохранении карточки и пока
не служат источником для холста.

**Ещё не сделано:**
- схема без атомов холста (например, написанная моделью) не разворачивается в холст;
- карточка по-прежнему удаляет значение, совпавшее со значением ▶, вместо того чтобы сохранить его явным;
- явный выбор значения, равного Basic, на новом pipeline не запоминается (интерфейс не отличает его от значения по умолчанию).
Текущая реализация движка описана в [basic-pipeline.md](basic-pipeline.md).

## Термины

- **Basic** — универсальный движок pipeline (до 2.81.670 назывался Custom). Basic — это код движка вместе с его
  значениями по умолчанию. Это единственный pipeline, который исполняется.
- **Схема** — pipeline, созданный на базе Basic. Схема не содержит кода и не является копией
  pipeline. Это слой поверх Basic: она хранит **явные переопределения** —
  значения, которые автор схемы задал сам (раунды, модели, роли, задания, входы, политика запуска,
  маркеры и другие элементы дисциплины ответа).

## Наложение схемы на Basic

| В схеме | Результат |
| --- | --- |
| Поля нет | Значение Basic |
| Задано значение, включая `false` и `0` | Значение схемы |
| Пустая строка `""` | Пустой текст: унаследованный текст убран |
| Список (шаги, модели) | Заменяет список Basic целиком, порядок сохраняется |

Наследование задаётся только отсутствием поля. Пустая строка — явное значение. Так работает схема
(`BasicSchema.resolveFields`); прежние сохранённые настройки очищаются от пустых строк на границе
(`basicSchemaFromPage`), потому что карточка никогда не сохраняла пустое как значение.

## Save

- Сохраняет только явные переопределения. Явно заданное значение сохраняется, даже если оно
  совпадает со значением Basic. Возврат поля к наследованию удаляет переопределение.
- Открыть схему и нажать Save не превращает показанные значения Basic в явные. Политика запуска и предел длины записываются в `run` только если они различаются с Basic или были явными в загруженной схеме.
- Save шаблона создаёт схему `user` с `basedOn` = имя шаблона; повторный Save и сохранение карточки сохраняют `basedOn`.
- Настройки выключенной модели и шага, которого нет на холсте, остаются в схеме с `enabled: false`.
- Ответы, статусы и другие данные прогона в схему не попадают.
- В схеме записываются `schemaVersion` (с первого сохранения) и `origin`.

## Одна сборка конфигурации

Basic + схема → итоговая конфигурация → проверка → запуск.

Сборка выполняется одной функцией (`BasicSchema.assemble`, на странице — `buildBasicRun`). Канва,
предпросмотр запроса и запуск используют её, значения Basic по умолчанию лежат только в
`BasicSchema.DEFAULTS`. При запуске итоговая конфигурация фиксируется на весь прогон.

## Проверка перед запуском

До первой отправки проверяются версия формата, типы шагов и допустимость значений.
При ошибке запуск останавливается с указанием места ошибки; запросы не отправляются.
Схема не исправляется молча: `BasicSchema.validate` проверяет её до `normalizeSteps` движка, который
по-прежнему подменяет неизвестное (после проверки подменять уже нечего).
Намеренно выключенные элементы допустимы.

## Происхождение схемы

Поле `origin` в схеме:

| `origin` | Кто создаёт | Свойства |
| --- | --- | --- |
| `builtin` | Мы | Поставляется с кодом, не перезаписывается пользователем |
| `user` | Пользователь | Хранится у пользователя, мы её не перезаписываем |

Встроенную схему можно настраивать на канве как рабочий вариант. Save создаёт схему `user` с
переопределениями рабочего варианта; встроенная остаётся прежней. Схема `user` накладывается
прямо на Basic и не зависит от последующих изменений встроенной.

## Совместимость

1. **Движок не знает о конкретных схемах.** Если схеме нужна новая возможность, она
   добавляется в Basic как общее поле или вариант значения и доступна всем схемам.
2. **В пределах поддерживаемого `schemaVersion` не меняются:** смысл существующих полей,
   их допустимые значения, поведение при отсутствии поля, порядок исполнения и передачи данных.
3. **Новое поле по умолчанию сохраняет прежнее поведение.** Новое поведение схема включает явно.
4. **Обновление Basic сохраняет поддержку всех ранее выпущенных версий формата схем.**
   Повышение `schemaVersion` не является основанием отключать существующие схемы.
5. Отказ при неподдерживаемой версии — для схемы, созданной более новым Basic, чем установлен
   у пользователя (см. «Проверка перед запуском»). Механизм перехода между версиями формата
   определяется, когда формат действительно понадобится менять.

## Критерии готовности

Проверяются тестовым транспортом, без реальных вызовов моделей:
- сохранение и повторная загрузка сохраняют настройки и план (тесты Save: настройки и шаги запуска совпадают до и после перезагрузки);
- выключенный синтез не включается обратно;
- новое необязательное поле не меняет поведение старой схемы;
- изменение встроенной схемы не меняет пользовательскую;
- неподдерживаемая схема не отправляет запросы.

Вместе с форматом пишется **справочник формата схемы** и обновляется в том же коммите, что и поле:
- описывает сохраняемую схему, а не внутреннюю конфигурацию движка: поля, смысл, ограничения, наследование;
- если значение зависит от контекста (например, от типа шага), описывается правило, а не одно значение;
- содержит минимальный пример схемы, проходящий проверку Basic.

## Чего не делаем

Старые pipelines (Polishing, Delta, Test, Research, Architecture и ранее сохранённые копии)
не чиним и не переносим. При необходимости их заново описывают как схемы на Basic.
