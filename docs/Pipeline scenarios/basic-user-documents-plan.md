# Basic: документы для User и артефакты-файлы (план)

Статус: концепция согласована с User 24.10.2026 на версии 2.81.854. **Не реализовано.** Имена полей ниже — предложение для реализации. В действующий формат схемы (`basic-schema-guide.md`) они войдут только вместе с кодом.

## 1. Что решено

1. **Документ для User даёт одна модель.** Шаг User показывает документ, который выдал указанный в схеме раунд. У этого раунда ровно одна включённая модель.
2. **Документ всегда открывается в отдельном модальном окне** с кнопкой **OK/Send**. Ответ User после Send идёт дальше по схеме: следующий раунд по умолчанию получает его как вход `previous` (B-2, 2.81.854).
3. **Результат шага бывает двух видов:**
   - **файл** — физический артефакт;
   - **память** — запись о прогоне.

   Вид задаёт автор схемы. Приложение само не решает.
4. **Граница:** *файл — то, что нужно человеку после прогона; память — то, что нужно только самому прогону.* Если вид не указан, результат остаётся в памяти. Действующие схемы не меняются.
5. **Документы — тело ответа модели**, а не файлы, которые модель создаёт у себя в чате (скачиваемые файлы ChatGPT, артефакты Claude): у каждого провайдера они устроены по-своему, и надёжно их не забрать. Ответ забирается текстом со страницы, как сейчас.

## 2. Документ в окне User

**Схема.** Шаг User ссылается на раунд-источник, например `"document": "r3"`. Проверка схемы:
- источник — более ранний раунд;
- у раунда ровно одна включённая модель, иначе ошибка «документ для User даёт одна модель»;
- вид документа объявлен в выходе этого раунда.

**Виды документа:**

| Вид | Что выдаёт модель | Что видит User | Когда активна OK/Send |
|---|---|---|---|
| для чтения | текст или Markdown | документ для чтения | сразу |
| опросник | JSON в формате ниже | заполняемая форма | когда заполнены все обязательные пункты |

**Формат опросника (предложение):**

```json
{ "items": [
  { "id": "budget", "type": "one", "question": "Бюджет", "options": ["до 10k", "10–50k", "больше"], "required": true },
  { "id": "notes", "type": "text", "question": "Что ещё учесть", "required": false }
] }
```

Типы пунктов: `one` (выбор одного), `many` (выбор нескольких), `text` (поле), `yesno`. Опросник, нарушающий формат, движок отклоняет существующей проверкой ответа (`BasicOutput.checkAnswer`) и просит ту же модель исправить ответ.

**Ответ User** — текст «вопрос — ответ» по пунктам. Если выход шага User объявлен как `format: json`, ответ — JSON `{ id: значение }`.

Шаг User без `document` работает как сейчас (задание и поле текста, `provideOwnerResult` в `results.js`). Отличие одно: Send неактивна, пока поле пустое.

**Что переиспользовать:** отрисовку выбора из `results/owner-ask.js` и текст окна из `StageCard.ownerAskMessage`.

## 3. Артефакт-файл

**Схема.** У артефакта выхода появляется признак файла, например `output.artifacts: [{ "id": "spec", "name": "Спецификация", "file": "md" }]`, где `file` — `md` или `json`. Файлом становится весь ответ или его часть по указателю (`pointer`, как сейчас).

**Холст.** Рамка артефакта видна с загрузки схемы и сначала неактивна (пунктир). Когда файл записан, рамка становится обычной; клик открывает файл. Новая версия меняет подпись: «Спецификация v2». Если файл удалён или папка недоступна, рамка помечается «файл недоступен». На стенде зона артефактов уже есть (стенд v49).

**Где лежит.** В папке, которую User выбрал через File System Access, — так же стенд работает с `stand-templates.json`. Путь: `<папка>/<pipeline>/<дата-время прогона>/<имя> vN.<md|json>`.
- Доступ к папке запоминается.
- После перезапуска Chrome браузер просит подтвердить доступ. Это подтверждение спрашивается при нажатии старта ►, если схема объявляет файлы.
- User отказался — прогон идёт, а рамки показывают «файл не записан».

Папка выбрана вместо «Загрузок» (`chrome.downloads`) потому, что из «Загрузок» расширение не может прочитать файл обратно, и правка User вне окна потерялась бы.

**Главное хранилище — запись о прогоне** (`chrome.storage.local`, `CustomRunRecord`). Файл — её копия для человека. Прогон, продолжение после остановки и входы следующих шагов работают с текстом из записи.

**Правка вне окна.** Перед шагом, у которого этот артефакт во входе, расширение перечитывает файл:
- текст изменился — он записывается новой версией артефакта с автором User и идёт во вход;
- файла нет — берётся текст из записи.

## 4. Память

Короткие вопросы, выбор, одобрение, промежуточные ответы для следующего шага. Хранятся в записи о прогоне, как сейчас: тексты по отпечатку, реестр артефактов (`BasicArtifacts`), общий предел записей 4 МБ, самые старые прогоны вытесняются. Файла и рамки на холсте нет.

## 5. Граница для автора схемы

| Файл | Память |
|---|---|
| итоговый результат pipeline | выбор, одобрение, «да/нет» |
| документ, который User читает или правит вне окна | короткий ответ User в окне |
| то, на что ссылаются по имени позже или в другом прогоне | промежуточный ответ, который идёт только в следующий раунд |
| заполненный опросник, если нужна его копия | сам опросник как форма в окне |

Размер текста границу не определяет. Правило войдёт в `basic-schema-guide.md` и в запрос для моделей на стенде (`canvas-prototype/model-prompt.md`).

## 6. Связь с тем, что есть

- **Этап `file` стенда** при переносе в Basic становится признаком `file` у артефакта шага, а не отдельным видом шага. Это закрывает пункт onboarding «добавить в Basic `file`».
- **Файл User на странице (N03, `basic-developer.md`, раздел 5)** решается тем же путём: ответ User со своим файлом — артефакт-файл с автором User.
- **Экспорт ответов в HTML** остаётся как есть.

## 7. Порядок реализации

1. Окно User: модальное окно с документом от одной модели, опросник, OK/Send с условием активности; поле `document` и проверка «одна модель».
2. Артефакт-файл: признак `file`, выбор папки и подтверждение доступа при старте, запись, рамка на холсте.
3. Правка вне окна: перечитывание файла перед входом, новая версия артефакта с автором User.
4. Стенд: те же поля и рамки, Export/Import, запрос для моделей.

Каждый этап — отдельная поставка с тестами и правкой документов Basic, по [инструкции исправления](../agent-team-fix.md) в части «тест до правки, приёмка, интеграция».
