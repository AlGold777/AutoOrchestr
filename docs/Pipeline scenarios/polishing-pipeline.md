# Pipeline Polishing: сбор улучшений идеи

Версия: **2.81.629, 7 октября 2026**. До 2.81.625 pipeline назывался Delta; имя Delta свободно
для другого сценария, сохранённый pipeline «Delta» из прежних версий удаляется при загрузке.

**Polishing собирает только свежие улучшения исходной идеи.** Идея не меняется.
Слияния, дедупликации по смыслу, оценки и синтеза нет: результат — растущий
список строк. Всё это делается вне pipeline.

| Параметр | Значение |
| --- | --- |
| Идентификаторы | `presetId: POLISHING`, `runner: 'polishing'` |
| Круги | Раунды canvas; по умолчанию 3 (`roundLimit: "3"`) |
| Порядок вызова | Модели круга по очереди, в порядке на canvas |
| K | Не больше 3 улучшений на ответ (`polishingMaxIdeas`) |
| Длина ответа | Не более 300 слов (защитный предел) |
| Код | [`disput/polishing-pipeline.js`](../../disput/polishing-pipeline.js), `runPolishingFromPage` в [`results.js`](../../results.js) |

## Как работает

1. Идея — сообщение в поле ввода, иначе тема чата.
2. В каждом круге модели вызываются по одной. Промпт: идея, **весь** нумерованный
   список, собранный к этому моменту, и инструкция: «Предложи только новые улучшения
   по существу идеи, которых нет в списке выше… Каждое улучшение отдельной строкой,
   не больше K. Если новых нет, не пиши ничего, кроме метки.»
3. Ответ делится на строки: одна строка — одно улучшение. Убираются маркеры списка
   и нумерация, пустые строки, заголовки (`Улучшения:`, `## …`), ограждения кода,
   отказ вида «Новых улучшений нет» и точные повторы строк списка или самой идеи;
   выделение `**…**` вокруг всей строки снимается. Остальное сразу дописывается в конец списка с автором и кругом.
   K — жёсткий предел: берутся первые K строк ответа, остальные отбрасываются
   и считаются (`dropped`, «сверх K отброшено N» в итоговой карточке).
4. Ответ модели показывается в её карточке обычной лентой (привязан к прогону,
   кругу и запросу).
5. После остановки — по любой причине, включая Stop — в ленте появляется карточка
   **Polishing**: итоговый список, по каждому кругу строка «модель +N / пусто / сбой
   (причина)» и причина остановки. Собранное не теряется.

## Метка и сбои

Метку `[[AO-xxxxxx]]` и инструкцию «Последней строкой ответа напиши только метку»
добавляет общий транспорт ([`shared/message-delivery.js`](../../shared/message-delivery.js)).
Ответ с чужой меткой (устаревший) транспорт отбрасывает. Ответ без метки
**принимается**: даже часть предложений полезна.

Статус ответа в журнале прогона: `OK` — добавлены строки; `EMPTY` — ответ есть (в том числе одна метка: модель закончила
и сказала «новых нет»),
нового нет; `FAILED` — нет текста, ошибка или таймаут. Упавшая модель пропускается,
цепочка идёт дальше; отдельного повтора нет — модель снова вызывается в следующем круге.
Таймаут и повторы внутри вызова — общие значения транспорта.

В журнал доставки пишутся события `polishing_answer` (круг, модель, статус, добавлено
строк, всего) и `polishing_end` (причина остановки, итоги) — они видны в телеметрии.

Кнопка **Extract** (Transport) разбирает только этапы Debate. Для Polishing она скачивает
Disput Flow JSON и сообщает, что разбирать нечего; журнал доставки лежит внутри этого JSON.

## Остановка

- пройдены все круги canvas (`rounds_done`);
- круг не добавил ни одной строки, хотя модели ответили (`no_new_ideas`);
- два круга подряд без единого ответа (`all_failed`); один такой круг прогон переживает;
- следующий промпт со всем списком превысил бы бюджет контекста транспорта
  (52 000 символов) — `list_full`. Иначе транспорт обрезал бы хвост промпта вместе
  с инструкцией;
- Stop: пока идёт Polishing, кнопка запуска показывает Stop и прерывает прогон.

## Почему не движок Debate

Polishing вызывает `runModelBatch` напрямую, как судья и сообщение модератора.
План, StateMap, приёмка этапов и ContextBroker ему не нужны, а ContextBroker
отбирает контекст по бюджету — модель не увидела бы часть списка и повторяла бы
идеи. Новые вкладки, вложения (только в первом сообщении каждой модели), метка
и Stop — общие механизмы страницы. Анонимизация участников для Delta выключена:
настройка ранее выбранного пресета на промпт не влияет.

## Вне первой версии

Параллельные микрогруппы (параметр S), порог объёма, задаваемый пользователем,
повтор упавшей модели в конце того же круга, K в интерфейсе, обновление итоговой
карточки по ходу прогона.
