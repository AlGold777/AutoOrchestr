Не писать один огромный коммит на весь участок. Версии согласовать с интегратором; commit по правилам AGENTS.md.

## Назначение и зависимости

Пакеты P00/P01. Начинаете первым. Владеете `disput/basic-schema.js` на протяжении реализации; дальнейшие дополнения поступают от A02–A06 как запросы. Сначала читаются реальные validate/assemble/resolveFields/toSettings/toCanvas, затем расширяются. A02 получает ваш нормализованный план, A06 — модель холста.

## Порядок работ

1. **0.1: явное задание.** В assemble при input none проверять источник resolveFields.task: model/round сохранять, pipeline/basic подавлять. Проверить отдельно task модели и шага, явно пустой task, inherited task, запрос пользователя. Обновить basic-schema-guide и запись CHANGELOG.
2. **0.2: порядок.** В toCanvas enabled участники идут в порядке step.models, затем остальные выбранные модели. Не менять реальное исполнение последовательного движка. Проверить [B,A] → сохранение → загрузка, участника disabled и финальный синтез. A06 позже дополнит обратную сборку реальной страницы.
3. **Валидация входов.** Реализовать раздел 4.3: массив строк/объектов, адрес участника/артефакта, required, version. Ошибки указывать точным путём. Ссылки проверять по полной steps до фильтра; запрещать текущие/поздние обычные источники, duplicate address и неизвестный ID. Синтезам разрешить массив, none/all оставить запрещёнными.
4. **Участники.** Добавить models[].id и input. Уникальность внутри шага; согласованность name для одного явного ID между шагами. Схемы без ID остаются совместимыми. Assemble должен сохранить ID даже при одинаковом name.
5. **Выход.** Пропускать output без потерь; проверить типы name/form/sections/strictLength/format/requiredFields/artifacts. JSON Pointer проверять синтаксически и на запрещённые сегменты. Несколько artifacts без json — ошибка. RevisionOf проверять как входную artifact-ссылку и присутствие во входе соответствующего участника.
6. **Require/approve/chat.** Проверить типы и диапазоны из 4.2. У выключенного целиком шага сохранять N, проверять активный порог при включении. Gate pass и require не отождествлять.
7. **Новые виды.** Gate, route, owner не преобразовывать в round в normalize/assemble. Не удалять route/owner без моделей. Rule/owner route — models [], model route — ровно один enabled участник. Criteria и select валидировать по 6.1–6.2.
8. **Граф.** С A04 согласовать validate всех action, loop limits и return/resumeAt. Можно общий чистый helper графа; не делать независимые несовпадающие проверки в схеме и движке. Ошибка графа включает путь action. Удалить ограниченные рёбра и проверить отсутствие циклов в оставшемся графе.
9. **Проекция UI.** ToSettings хранит новые поля для каждого вида и участника; toCanvas сохраняет порядок control-steps и повторяющиеся modelName с разными ID. Старые rounds/stacks сохраняются для старой страницы. У control-step нет требования стоять между раундами. Не поднимать 50 до измерения A07.

## Готовность

Legacy fixtures принимаются без новых обязательных полей. Все новые примеры разделов 4–8 валидируются либо дают ожидаемую ошибку. Control-only схема не отвергается требованием round. Исполняемый план не теряет input синтеза, ID, output, refs и источники. Контракт передан A02/A03/A06; новые поля не объявлены работающими в руководстве раньше соответствующей интеграции.
