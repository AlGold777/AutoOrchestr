## Назначение и зависимости

Пакет P02 после P01. Владеете `disput/custom-engine.js` до передачи A04; затем не редактируете его параллельно. Допустимы небольшие чистые модули для input/output/artifacts. Новые скрипты нужно подключить в фактическую страницу через согласование с A06/A07, а не только require в тестах.

## Порядок работ

1. **Normalize.** Сохранить виды, ref, ID, массив input, model.input, output, require, owner, chat. Не удалять owner/route. Runtime address использует исходный ref, а не индекс отфильтрованной steps.
2. **Input resolver.** Раздел 4.3: порядок источников → порядок участников. Индивидуальный input заменяет общий. None пустой; all/previous старое поведение для legacy. Array не подставляет соседний шаг. Required missing — остановка до send, с адресом. Пока visit=1.
3. **Callback участников.** Добавить sendParticipants из раздела 7 с тестовым адаптером. Старый send работает как прежде для уникальных провайдеров; duplicate name без нового адаптера — participant_transport_required. Переименовать ключи outcome на participant ID, не потерять модель-провайдер в source.
4. **Output checker.** Реализовать точный порядок раздела 5.1, единый word counter и JSON Pointer reader. Нет coercion, eval, поиска JSON в произвольном тексте. Reasons содержат нужный pointer/heading. JSON object принимается только целиком либо из одного внешнего code fence.
5. **Require.** Подменить все accepted.length ветки завершения проверкой порога, включая manual-last и fallback invalid decision. Ниже порога нет continue. All не считает disabled. Retry не отправляет принятых заново; N после повторов учитывает уже принятые ответы.
6. **Approve.** После достаточного результата mandatory approve даже auto/last. Invalid/null decision — no_decision. Manual одна пауза; ASK отдельно; AbortSignal завершает ожидание, позднее разрешение окна не продолжает run.
7. **Artifacts.** Реализовать registry из раздела 5.3. Содержимое по answerRef+pointer через putText/getText callbacks раздела 7, список деклараций из output, атомарная регистрация после полной приёмки. Один missing artifact отклоняет весь ответ. Idempotent key lineage+source; rejected retry не создаёт версию. Legacy без artifacts не требует registry.
8. **RevisionOf.** Использовать только реально переданный исходный артефакт; новая версия получает ту же lineage и свой source. Different authors остаются разными линиями. Latest — порядок регистрации, не max visit.
9. **Передача.** Оставить A04 чистые интерфейсы resolveInput/checkOutput/registerArtifact/resolveArtifact и model outcome; конкретные имена согласовать и записать в отчёте. Snapshot hooks подготовить, но resume не реализовывать вместо A05.

## Проверки

`npm test -- --runInBand tests/custom-engine.test.js tests/basic-schema.test.js` плюс новые чистые тесты реестра/выхода. T02–T06, T19, T21. В fake send записывать prompts, чтобы доказать отсутствие чужого документа/участника; проверка только результата недостаточна.

## Готовность

S08 выдаёт два артефакта, S09/S10 получают разные документы. Недостаточный require и approve не обходятся. Output retry сохраняет успех соседнего участника. Registry не дублирует текст. Старые тесты движка остаются зелёными; поля не теряются до отправки.

- Какие части контракта реализованы, список тестов и фактические результаты.

- Нерешённые ограничения перечислить отдельно. Заглушку, silent fallback и тест только на mock не выдавать за реальную поддержку транспорта.
- Если нужен файл другого владельца, передать ему точный запрос с входом/ожидаемым выходом и тестом. Не редактировать параллельно его файл.
