## Назначение и зависимости

P04 допускает только чистые модели/fixtures без редактирования общих файлов. Полная интеграция P08 после A05. A01 владеет toCanvas/toSettings: направлять ему запросы, не править basic-schema.js одновременно.

## Порядок работ

1. **Инвентаризация.** Найти фактическую HTML-страницу и подключения скриптов, selectors окон, renderCustomBlockInspector, openStageCard, basicSchemaFromPage, recordFromSchema, installBasicSchema, buildBasicRun, import/export. Не предполагать наличие results.html: в корне его нет.
2. **Canonical steps.** Сохранить упорядоченные шаги с refs и participant IDs в данных редактирования; DOM — проекция. Старые stacks для legacy работают. Новая схема не превращается при Save в старый список одних round/synthesis.
3. **Участники.** Два блока одной модели с разными ID, стабильный ключ настройки ID+ref. Enabled B,A порядок сохранён. В ленте modelName и participant label различимы.
4. **Inputs.** Общий и индивидуальный input; источники step/participant/artifact с version и required. UI выбора зависит от объявленных ранних источников. Unknown ссылка видна как ошибка, не удаляется молча.
5. **Output.** Name/form/sections/strictLength/json/requiredFields/artifacts/revisionOf редактируются и сохраняются. Для JSON sections не показывать как активный одновременно. Не вводить отдельный конструктор JSON Schema сверх контракта ТЗ.
6. **Require/approve/chat.** Значения отсутствуют или явно заданы, enabled влияет на счётчик, авто/ручной режим не скрывает обязательный approve. New относится к visit, не попытке.
7. **Control nodes.** Gate, route, owner вставляются в любой допустимой позиции, в том числе подряд. Ref сохраняется. Gate criteria/pass, route cases/default/conflict/actions, feedback/invalidate/resumeAt, owner task/input/output имеют минимальные окна настроек.
8. **Route view.** Связь показывает условие/вариант и направление; бизнес-слова не заменяются служебным кодом во всей карточке. Достаточен компактный список case labels; полный графический DSL-редактор не нужен.
9. **Registry view.** По записи открыть нужный документ, показать автора/visit/актуальность. Содержимое не строится из нового ответа модели. History invalid доступна, актуальный вход ей не подменяется.
10. **Pause/resume.** Окна используют callbacks A05; хватает кнопок для всех заданных вариантов маршрута, а не фиксированных трёх для любого случая. Ошибки с адресом видны пользователю. Stop прерывает ожидание.
11. **Preview и export.** Отсутствующие runtime inputs показывать метками. Export schema отдельно от export run. Round-trip покрывает все явные поля и порядок. Import не игнорирует новые kind.

## Проверки

## Готовность

Все механизмы доступны через окна и сохраняются; два ID не схлопываются. Control nodes стоят в нужном порядке. View может открыть конкретный artifact. Старый UI не ухудшился; новый функционал не остаётся доступным только в JSON.
