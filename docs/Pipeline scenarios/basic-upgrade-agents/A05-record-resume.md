## Порядок работ

1. **Record version 2.** Привязать callbacks putText/getText к record.put/textOf до запуска и до resume. Сохранить чтение/export старой version 1, не обещать resume legacy без snapshot. Новый ключ попытки: ref+participant+visit+attempt+phase. Не менять завершённую попытку задним числом. Sent на revive становится unknown.
2. **Registry.** Записывать artifacts, dependencies, source, valid; content.answerRef указывает существующий текст, а не копию. Serialize.mark обязан учитывать все refs из artifacts/feedback/snapshot/files. Тест без этого обязан воспроизвести исчезновение текста после serialize.
3. **Full snapshot.** Все поля 8.2 без DOM/Promise/functions/живых Blob. Schema snapshot неизменяем с точки зрения текущего холста; сохранить resolved settings запуска. Artifact pointers и actual source version восстановить точно.
4. **Checkpoint.** Сохранение обязательное, await до внешнего действия. Ошибка checkpoint_failed, дальнейший send не выполняется. Не проглатывать storage error нынешним console.warn и не полагаться на debounce. Последовательная очередь сохранений не допускает, чтобы старый snapshot перезаписал новый.
5. **Owner result.** ProvideOwnerResult text/file, no models. Пустой результат не принят, cancel/Stop различаются по ТЗ. Output validation и registry используют helpers A02. File содержимое сохраняется надёжно; blob URL не единственная ссылка. Binary transport только через вложение.
6. **Resume.** По сохранённому pc/phase продолжить тот же visit, сохранить успех соседних участников. Сохранённые counters/stack/feedback/validity не обнулить. Отказаться от применения нынешней schema страницы.
7. **Unknown.** Окно проверить/resend/skip для конкретной попытки. Проверка через A03 handles и приёмку; resend новая попытка с retryOf; skip не уменьшает require. Принятый ранее ответ не отправить второй раз.
8. **Owner interactions.** Pending approve/route/owner-input сохраняется и снова открывается. Уже принятое решение не повторить. При Stop ожидающий callback завершается, поздний ответ игнорируется. OwnerAnswers ASK сохраняются отдельно от результата owner-step.
9. **Chat unavailable.** Решение восстановить/остановить, контекст из сохранённого прогона. Не привязать первого доступного провайдера. Не назвать «continue» новый пустой чат без восстановления.
10. **Export/import run.** У self-contained export реестр и тексты доступны, версии и состояния сохранены. Глобальная схема export не содержит run artifacts: это данные конкретного прогона, не шаблона.

## Проверки

`npm test -- --runInBand tests/custom-run-record.test.js tests/custom-engine.test.js` плюс storage/adapter fixtures. T13–T16/T20/T21. Fault injection перед send, после ответа, перед переходом, после invalidate; проверка duplicate attempts и text refs. Reload на pending owner и nested CHG.

## Готовность

Не потеряны содержимое артефактов/файлов и origin; resume не сбрасывает циклы и не пересылает принятые ответы; snapshot защищён от текущего холста. Старый run открыт как история. A06 получает callbacks и UI-состояния, A07 — fault-injection fixtures.
