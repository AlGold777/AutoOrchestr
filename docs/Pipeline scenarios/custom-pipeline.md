# Pipeline Custom и общий движок

Версия: **2.81.652, 8 октября 2026**. Движок [`disput/custom-engine.js`](../../disput/custom-engine.js)
(тесты [`tests/custom-engine.test.js`](../../tests/custom-engine.test.js)) подключён к странице:
Custom выбирается в списке так же, как остальные шаблоны, и запускается (`runCustomFromPage`
в [`results.js`](../../results.js)). Новый pipeline («+») и безымянный canvas без выбранного шаблона тоже работают на этом движке.
Они открывают тот же редактор модели; сохранённые старые pipelines сохраняют свой движок.

**Что уже работает на странице (2.81.633).** Шаги берутся из canvas в порядке плана: карточки
раундов (их модели), вставка синтеза между раундами (со своей моделью) и финальный синтез.
Раунды выполняются параллельно; раунд 1 получает задачу, следующие — задачу и принятые
ответы предыдущего шага с заданием «Учти ответы предыдущего шага и дай свой улучшенный ответ».
Авто или подтверждение — по переключателю политики запуска. Пауза — окно с кнопками
«Продолжить / Повторить без ответа / Stop» или, без принятых ответов, «Пропустить шаг /
Повторить / Stop». Вопросы `[[ASK]]` — диалог «Вопрос владельцу». Кнопка запуска во время
прогона — Stop. Итог — карточка **Custom** с принятыми ответами последнего шага и причиной
остановки. **Ещё не на карточке раунда:** выбор «параллельно / по очереди» и выбор входа —
следующий шаг; движок их уже поддерживает. Роль модели (мини-запрос) и «Роль для всех моделей
раунда» подключены (2.81.650); пункт «Custom» со своим текстом раунда — 2.81.652.

## Шаблоны

Custom, Polishing, Delta, Test, Research, Architecture — шаблоны. Пользователь может менять
их на canvas (добавлять раунды и другие элементы), но шаблон не перезаписывается:
изменённый вариант сохраняется только под новым именем через Save. Шаблон нельзя
переименовать или удалить, и ни один pipeline не может занять имя шаблона. Изменения
шаблона живут до перезагрузки страницы, затем шаблон возвращается к исходному виду.

Расположение встроенных pipelines:

| Левая колонка | Правая колонка |
| --- | --- |
| Custom | Test |
| Polishing | Research |
| Delta | Architecture |

Встроенный Red Team удалён из списка. Сохранённые пользователем копии можно просматривать,
но их запуск отключён.

**Custom — редактируемая заготовка pipeline по умолчанию.** Пользователь настраивает её
и сохраняет под своим именем; сохранённый pipeline хранит настройки сценария и работает
на том же общем движке. Смысловые операции (ответ, критика, улучшение, проверка, синтез)
задаются заданиями моделей; движок отвечает за исполнение и передачу данных.

## Карточка раунда

| Настройка | Значение |
| --- | --- |
| Модели | Список с галочкой «участвует»; порядок на карточке — порядок вызова |
| Дополнение модели | Необязательный мини-промпт у каждой модели (по умолчанию None); получает только эта модель. В Custom (R2+) его можно выбрать сразу для всех моделей раунда кнопкой «Роль для всех моделей раунда» в карточке раунда; выбор в блоке модели перекрывает общий. Смена при различающихся ролях спрашивает подтверждение. Раунд 1 таких блоков не имеет. Пункт **Custom** в списке ролей — см. ниже |
| Порядок работы | **Параллельно** — все получают одинаковый вход. **По очереди** — каждая модель получает выбранный вход и ответы моделей, ответивших до неё в этом раунде |
| Задание раунда | Общий текст для всех моделей раунда |
| Вход | Задача передаётся всегда. Дополнительно: **ничего**; **ответы предыдущего шага**; **всё принятое** за все предыдущие шаги |

Число раундов — число карточек. Настройки всего pipeline: Авто или подтверждение между
раундами, предел длины ответа.

## Синтез — обычный шаг

Для движка прогон — одна последовательность шагов; интерфейс сохраняет привычные элементы.
- Вставка `.pipeline-stage-insert` между раундами N и N+1 создаёт шаг синтеза: одна модель,
  задание «Сведи эти ответы в один итоговый ответ на задачу», вход — ответы раунда N.
  Модель сохраняется в самой вставке (первоначально подставляется выбранный синтезатор),
  поэтому смена финального синтезатора не меняет промежуточные шаги незаметно.
- Финальный синтез — такой же шаг после последнего раунда.
- Вход «ответы предыдущего шага» после синтеза получает только синтез; «всё принятое»
  сохраняет и исходные ответы раунда, и синтез.

## Дисциплина ответа

- Метка доставки и снятие метки — общий транспорт. Пустой текст, в том числе ответ одной
  меткой, **не принимается**: это технический исход, а не выполнение задания.
- Техническая проверка — общая приёмка ответа (обрыв, маркеры обрезки). Непринятый ответ
  получает повтор с запросом исправления в том же чате, всего до 2 попыток. Если шаг закрыт
  владельцем («дальше», Get it), повторов нет; в режиме «по очереди» закрытие закрывает весь
  шаг — следующие модели не вызываются (исход `closed_by_owner`).
- Перед отправкой каждый промпт сверяется с бюджетом; если не помещается — сообщение и
  остановка (`context_full`), без тихой обрезки транспортом.

## Переход к следующему шагу

Движок дожидается исхода каждой модели и выполняет разрешённые повторы.
- **Авто**: есть хотя бы один принятый ответ — следующий шаг; неполный состав виден на
  карточках и в журнале. Нет ни одного — пауза.
- **Подтверждение между раундами**: пауза после каждого шага.
- На паузе: при принятых ответах — «продолжить с имеющимся», «повторить проблемные» (если
  есть сбои), Stop; без принятых ответов — «повторить проблемные», «пропустить шаг», Stop.
  «Продолжить с имеющимся» без принятых ответов не предлагается.
- Пропущенный шаг ничего не передаёт: вход «ответы предыдущего шага» берёт последний шаг,
  у которого есть принятые ответы.
- Stop сохраняет собранное, в том числе принятые ответы шага, на котором прогон остановлен.
  Stop действует и во время ожидания владельца (решение на паузе, ответ на `[[ASK]]`):
  ожидание прерывается, прогон завершается как `cancelled` с собранным.
- Вопросы `[[ASK: …]]` из принятых ответов уходят владельцу; ответы получают следующие шаги.
  Инструкция о `[[ASK]]` автоматически не добавляется; поле удалено из обеих карточек Custom.

## Результат и история

Телеметрия Custom: транспортный уровень (отправка, доставка, метка, батчи) общий с остальными
pipelines; события Custom ниже входят в журнал доставки и в экспорт Disput Flow. Extract (Transport)
для прогона без этапов Debate разбирает последний прогон Custom: шаги — как этапы, только его
часть журнала, тот же сжатый формат. Отправки Custom помечены своим этапом `custom:<runId>:s<n>`.
Полные тексты прогона — `customRun` в JSON-экспорте Disput Flow.

Каждый запрос записан в истории прогона: шаг, модель, попытка, полный промпт, вход, исход
(принят / причина) и `transportRequestId`. В журнал доставки пишутся события
`custom_start` (план: шаги, порядок, вход, модели, режим), `custom_answer`, `custom_step`,
`custom_decision`, `owner_answer` (ответ на `[[ASK]]`), `custom_end` (в том числе `error` с текстом ошибки) — они связаны с диагностикой
отправки через `transportRequestId`. В конце известна причина остановки
(`steps_done`, `context_full`, `stopped`, `cancelled`, `no_decision`).

## Карточка модели (2.81.636)

Кнопка 📝 в Custom открывает компактный редактор: иконка и название модели, личный
предел длины и кнопка Save в шапке, раунд рядом с моделью. Ширина карточки — 889 px
(+17%); поле запроса увеличено. Подсказка находится справа от «Запрос», инструкции
транспорта идут в две колонки (на узком экране — в одну). Карточка помещается по высоте окна.

- Автоматический запрос можно изменить или заменить своим. Правка действует только для
  этой модели в этом шаге. «Вернуть автоматическую сборку» снимает замену.
- `{задача}` подставляет актуальную задачу при запуске, `{вход}` — принятые ответы
  предыдущих шагов согласно настройке входа. `{ответы до тебя}` — ответы предыдущих
  участников текущего шага при последовательном исполнении. Подстановка однократная:
  такие строки внутри полученных ответов не интерпретируются повторно.
- Роль модели (мини-запрос из блока) уходит в запрос этой модели как «Дополнительно для тебя».
  Персональный запрос заменяет сборку целиком, поэтому роль в нём не добавляется.
- Личная длина — положительное целое число слов; пустое поле наследует общий предел.
  Инструкция длины добавляется перед передачей в общий транспорт, в том числе при
  исправлении ответа. Это инструкция модели, а не обрезка ответа до числа слов.
- В блоке «Метки транспорта» показаны полные тексты инструкций доставки,
  длины и требований к содержанию. Инструкция исправления ответа
  показана отдельным редактируемым полем для повторов. Поля редактируются сразу. У каждой строки есть иконка копирования, красный крестик
  очистки и галочка сохранения. Правки хранятся в `customModelSettings[шаг][модель].discipline`
  и действуют только для этой модели в этом шаге, включая повторные попытки.
- Длина и требования к содержанию — отдельные персональные инструкции. По умолчанию при
  пределе 300 слов: `[RESPONSE_LIMIT] Объём ответа: 250-300 слов, не больше.`;
  требования к ясности, повторам и деталям идут следующей строкой отдельно. `{от}` — предел
  минус 50 (не меньше 1), `{слов}` — предел из шапки. Очистка каждого поля независима и возвращает его к общему значению.
  Прежняя метка `[DISPUT_RESPONSE_LIMIT]` (в запросе или в сохранённых настройках) распознаётся так же,
  как `[RESPONSE_LIMIT]`: лимит в запросе всегда один.
- `{слов}` в инструкции длины подставляет предел из шапки; `{метка}` в инструкции доставки —
  новую метку запроса. Пустое поле наследует инструкцию из ▶ или кода. Инструкция вопроса владельцу не отправляется. Уникальную метку доставки всегда создаёт транспорт.
- Метку доставки добавляет прежний транспорт. Карточка не объявляет отсутствие метки
  самостоятельным основанием отказа. Инструкция `[[ASK]]` автоматически не добавляется.
- «Сохранить» применяет настройки. У сохранённого пользовательского pipeline они записываются
  в `customModelSettings`; у встроенного шаблона остаются на странице и попадают в новую
  копию через Save. Во время исполнения редактор доступен только для чтения.
- Настройки безымянного pipeline сохраняют свою привязку при Run: отображение задачи
  в заголовке не меняет выбранный запрос и личную длину ответа.
- Копирование доступно у текстовых полей карточки: копируется текущее содержимое целиком,
  без изменений и без сохранения правок. У числовой длины иконки копирования нет.
- Поле длины сразу содержит действующее число (персональное или общее), которое можно
  править по цифрам. Сохранение неизменённого общего числа не создаёт персональный предел.
- Записи реальных попыток продолжают сохраняться отдельно; редактирование их не меняет.
  Старая подробная карточка истории заменена редактором, экспорт диагностики — Disput Flow.

### ▶ — общие значения Custom

Клик по ▶ в колонке In открывает общую карточку. В ней только задание раундов со входом
(R2+), задание синтеза и четыре инструкции дисциплины: длина как шаблон, требования к
содержанию, доставка, исправление. Задача и числовая длина здесь не
дублируются; порядок работы и выбор входа не добавлены.

Каждое поле разрешается одной функцией `CustomEngine.resolveSetting` через
`resolveCustomFields`: **модель в шаге → ▶ → код**. В функции уже есть место для будущего
уровня раунда: **модель → раунд → ▶ → код**; UI раунда пока нет. Этот же путь используется
для шагов исполнения, предпросмотра и карточки модели. R1 не получает задания R2+;
синтез получает своё задание. Общие значения не записываются в настройки моделей.

Пустое или отсутствующее поле означает наследование. Это заменяет прежнюю семантику
очистки (отключение инструкции): крестик очищает override, при сохранении применяется
уровень выше. Подписи источника под полями не показываются. Действие «Вернуть к общему»
доступно у своего поля. Введённое значение, равное унаследованному (включая отображённый шаблон
длины), не сохраняется как override. Изменение ▶ сразу учитывается во всех следующих
запросах без своего значения; начатый прогон использует снимок настроек и обе карточки
в нём доступны только для чтения. Копирование остаётся доступным.

Персональный `promptTemplate` — полная замена запроса. В карточке явно написано:
«Персональный запрос: общее задание не применяется; дисциплина применяется».
Дисциплина, включая повторы, продолжает наследоваться независимо. Сравнение с
автоматическим запросом использует предпросмотр уже с учётом ▶ и задания модели.

Общие значения хранятся в конфиге рядом с `customModelSettings`, в `customDefaults`:
`{ roundTask?, synthesisTask?, discipline?: { limit?, content?, delivery?, correction? } }`.
В модели задание хранится как `task`, дисциплина — только своими полями в `discipline`.
Сохранённый pipeline сохраняет ▶ и переносит её через Export/Import. Изменения встроенного
шаблона живут только на странице, не перезаписывают шаблон и после перезагрузки возвращаются
к коду; Save в новую копию сохраняет их отдельно. «+» начинает с пустой ▶.

### Custom в списке ролей (2.81.652)

На pipeline, который работает на движке Custom, список ролей (мини-запросов) раунда заканчивается пунктом
**Custom**: в блоке модели и в «Роль для всех моделей раунда». Пункт не появляется на других pipelines.

- Выбор **Custom** открывает в карточке раунда поле текста. Это единственное место ввода: в блоке модели
  Custom означает «использовать текст раунда». Поле видно только при выбранном Custom.
- Хранение: `customDefaults.roundPrompts[r2…]`, один текст на раунд; сохранение, копирование и Export/Import —
  как у остальных полей ▶. Встроенный шаблон теряет текст после перезагрузки, как и прочие его правки.
  Запись в сохранённый pipeline происходит сразу, как у Save в ▶.
- Применение: модель с ролью Custom получает текст своего раунда как «Дополнительно для тебя». Пустой текст —
  ничего не добавляется. Модель с другой ролью получает свою.
- Персональный запрос заменяет сборку целиком, поэтому роль в блоке при нём не применяется. В карточке модели
  появляется строка: «Роль не применяется: используется персональный запрос». Сборка от этого не меняется.

### Карточка промежуточного синтеза (2.81.655)

Промежуточный синтез не имеет блока модели: его вставка между раундами — вход в карточку. Одиночный клик
по вставке добавляет или убирает синтез (через 250 мс, чтобы двойной клик отменил это действие); кнопка
серая без синтеза и синяя с ним. Двойной клик открывает его Custom-карточку (персональный запрос, длина,
дисциплина) под ref `synth:planned-working-synthesis-after-<afterStageId>` и **не** добавляет и не убирает
этап: состояние кнопки не меняется. Если этапа ещё нет, карточка строится по виртуальной копии плана, которая
не сохраняется; сохранённый персональный текст применяется, когда одиночный клик добавит этап. Без выбранного
финального синтезатора двойной клик показывает предупреждение и ничего не делает. Пока персонального запроса
нет, карточка показывает и использует текст финального синтезатора; сохранённый персональный текст заменяет его.
Роль и пункт Custom синтезу не нужны. Во время прогона вставка неактивна, карточку открыть нельзя.

### Финальный синтез: бейдж Final (2.81.656)

Бейдж «Final» в последней колонке работает как вставка промежуточного синтеза. Одиночный клик (через 250 мс)
включает или выключает финальный синтез. Выключено: бейдж серый, блок модели скрыт, синтез не запускается
(синтезатор пустой). Включено: бейдж синий, синтезатор — последний выбранный (запоминается при выключении),
иначе первая выбранная модель; без выбранных моделей показывается предупреждение. Двойной клик открывает
Custom-карточку финального синтезатора и не переключает состояние; без синтезатора он показывает
предупреждение «Включите финальный синтез кликом по Final.». Во время прогона клик по бейджу ничего не делает.
Пункта «None» в списке синтезатора больше нет: выключение выражается бейджем.

### Особенности моделей (2.81.650)

В карточке ▶ блок «Особенности моделей»: по одному полю на каждую модель, которая стоит на холсте
(по имени, без дублей; синтезатор — только если выбран). Пустое поле ничего не добавляет.
Пример: GPT — «Без вступлений и пересказа вопроса, не раздувай ответ».

- Хранение: `customDefaults.modelNotes[имя]`; сохранение, копирование, Export/Import — как у
  остальных полей ▶. Встроенный шаблон после перезагрузки их теряет, как и прочие его правки.
  Заметки моделей, снятых с холста, при Save остаются в конфиге.
- Применение: текст уходит с каждым запросом этой модели во всех раундах и синтезах. Он добавляется
  отдельно **после** запроса и ответов владельца, **перед** лимитом; при персональном запросе тоже.
  Повторный запрос (исправление) особенность не получает.
- В карточке модели — строка только для чтения «Особенность модели (из ▶)», если заметка есть.

Порядок текста в запросе модели:

```
запрос (с ролью из блока, если выбрана)
ответы владельца
особенность модели (из ▶)
лимит
требования к содержанию
метка доставки
```

### Хранение записи прогона

[`disput/custom-run-record.js`](../../disput/custom-run-record.js), `chrome.storage.local`
(ключи `customRunRecords.index`, `customRunRecord.<runId>`):
- каждый текст хранится один раз под отпечатком, попытки ссылаются на него (вход одного шага —
  это ответы другого);
- предел — **объём** (4 МБ из общих ~10 МБ расширения); при превышении целиком удаляются самые
  старые прогоны, текущий прогон не удаляется;
- запись сохраняется по ходу прогона (с задержкой ~0,6 с) и в конце;
- **после перезагрузки** запись — только история: попытка, которая была отправлена, но не
  завершилась, помечается «исход неизвестен» и **никогда не отправляется повторно сама**.

Карточка показывает инструкции в порядке отправки: длина,
требования к содержанию, доставка. Инструкция исправления заменяет основной запрос
при повторе; `{причина}` подставляет причину непринятия. Она персональна для модели и шага.

Полный запрос проверяется по бюджету после добавления всех инструкций и новой метки,
включая повторы. Превышение завершает Custom с `context_full` до отправки всей пачки;
сокращение `compactPrompt` для Custom отключено. Уже принятые ответы сохраняются.

Изменения карточки применяются к следующему запуску; текущий прогон использует свой снимок настроек.
