# Pipeline Custom и общий движок

Версия: **2.81.633, 7 октября 2026**. Движок [`disput/custom-engine.js`](../../disput/custom-engine.js)
(тесты [`tests/custom-engine.test.js`](../../tests/custom-engine.test.js)) подключён к странице:
Custom выбирается в списке так же, как остальные шаблоны, и запускается (`runCustomFromPage`
в [`results.js`](../../results.js)). Новый pipeline («+») тоже работает на этом движке.

**Что уже работает на странице (2.81.633).** Шаги берутся из canvas в порядке плана: карточки
раундов (их модели), вставка синтеза между раундами (со своей моделью) и финальный синтез.
Раунды выполняются параллельно; раунд 1 получает задачу, следующие — задачу и принятые
ответы предыдущего шага с заданием «Учти ответы предыдущего шага и дай свой улучшенный ответ».
Авто или подтверждение — по переключателю политики запуска. Пауза — окно с кнопками
«Продолжить / Повторить без ответа / Stop» или, без принятых ответов, «Пропустить шаг /
Повторить / Stop». Вопросы `[[ASK]]` — диалог «Вопрос владельцу». Кнопка запуска во время
прогона — Stop. Итог — карточка **Custom** с принятыми ответами последнего шага и причиной
остановки. **Ещё не на карточке раунда:** выбор «параллельно / по очереди», поле задания,
выбор входа и дополнение модели (мини-промпт) — следующий шаг; движок их уже поддерживает.

## Шаблоны

Custom, Polishing, Delta, Test, Research, Architecture — шаблоны. Пользователь может менять
их на canvas (добавлять раунды и другие элементы), но шаблон не перезаписывается:
изменённый вариант сохраняется только под новым именем через Save. Шаблон нельзя
переименовать или удалить, и ни один pipeline не может занять имя шаблона. Изменения
шаблона живут до перезагрузки страницы, затем шаблон возвращается к исходному виду.

Расположение встроенных pipelines:

| Левая колонка | Правая колонка |
| --- | --- |
| Custom | Test |
| Polishing | Research |
| Delta | Architecture |

Встроенный Red Team удалён из списка. Сохранённые пользователем копии можно просматривать,
но их запуск отключён.

**Custom — редактируемая заготовка pipeline по умолчанию.** Пользователь настраивает её
и сохраняет под своим именем; сохранённый pipeline хранит настройки сценария и работает
на том же общем движке. Смысловые операции (ответ, критика, улучшение, проверка, синтез)
задаются заданиями моделей; движок отвечает за исполнение и передачу данных.

## Карточка раунда

| Настройка | Значение |
| --- | --- |
| Модели | Список с галочкой «участвует»; порядок на карточке — порядок вызова |
| Дополнение модели | Необязательный мини-промпт у каждой модели (по умолчанию None); получает только эта модель |
| Порядок работы | **Параллельно** — все получают одинаковый вход. **По очереди** — каждая модель получает выбранный вход и ответы моделей, ответивших до неё в этом раунде |
| Задание раунда | Общий текст для всех моделей раунда |
| Вход | Задача передаётся всегда. Дополнительно: **ничего**; **ответы предыдущего шага**; **всё принятое** за все предыдущие шаги |

Число раундов — число карточек. Настройки всего pipeline: Авто или подтверждение между
раундами, предел длины ответа.

## Синтез — обычный шаг

Для движка прогон — одна последовательность шагов; интерфейс сохраняет привычные элементы.
- Вставка `.pipeline-stage-insert` между раундами N и N+1 создаёт шаг синтеза: одна модель,
  задание «Сведи эти ответы в один итоговый ответ на задачу», вход — ответы раунда N.
  Модель сохраняется в самой вставке (первоначально подставляется выбранный синтезатор),
  поэтому смена финального синтезатора не меняет промежуточные шаги незаметно.
- Финальный синтез — такой же шаг после последнего раунда.
- Вход «ответы предыдущего шага» после синтеза получает только синтез; «всё принятое»
  сохраняет и исходные ответы раунда, и синтез.

## Дисциплина ответа

- Метка доставки и снятие метки — общий транспорт. Пустой текст, в том числе ответ одной
  меткой, **не принимается**: это технический исход, а не выполнение задания.
- Техническая проверка — общая приёмка ответа (обрыв, маркеры обрезки). Непринятый ответ
  получает повтор с запросом исправления в том же чате, всего до 2 попыток. Если шаг закрыт
  владельцем («дальше», Get it), повторов нет; в режиме «по очереди» закрытие закрывает весь
  шаг — следующие модели не вызываются (исход `closed_by_owner`).
- Перед отправкой каждый промпт сверяется с бюджетом; если не помещается — сообщение и
  остановка (`context_full`), без тихой обрезки транспортом.

## Переход к следующему шагу

Движок дожидается исхода каждой модели и выполняет разрешённые повторы.
- **Авто**: есть хотя бы один принятый ответ — следующий шаг; неполный состав виден на
  карточках и в журнале. Нет ни одного — пауза.
- **Подтверждение между раундами**: пауза после каждого шага.
- На паузе: при принятых ответах — «продолжить с имеющимся», «повторить проблемные» (если
  есть сбои), Stop; без принятых ответов — «повторить проблемные», «пропустить шаг», Stop.
  «Продолжить с имеющимся» без принятых ответов не предлагается.
- Пропущенный шаг ничего не передаёт: вход «ответы предыдущего шага» берёт последний шаг,
  у которого есть принятые ответы.
- Stop сохраняет собранное, в том числе принятые ответы шага, на котором прогон остановлен.
  Stop действует и во время ожидания владельца (решение на паузе, ответ на `[[ASK]]`):
  ожидание прерывается, прогон завершается как `cancelled` с собранным.
- Вопросы `[[ASK: …]]` из принятых ответов уходят владельцу; ответы получают следующие шаги.
  Инструкция о `[[ASK]]` добавляется в промпт только в режиме подтверждения.

## Результат и история

Каждый запрос записан в истории прогона: шаг, модель, попытка, полный промпт, вход, исход
(принят / причина) и `transportRequestId`. В журнал доставки пишутся события
`custom_answer`, `custom_step`, `custom_decision`, `custom_end` — они связаны с диагностикой
отправки через `transportRequestId`. В конце известна причина остановки
(`steps_done`, `context_full`, `stopped`, `cancelled`, `no_decision`).
