# Тренировочный прототип холста

Этот прототип и материалы в его папке сохранены для тренировок разработчиков. Они не входят в рабочий процесс создания и выполнения схем Basic. Актуальные инструкции: [запрос для модели](<../../Scheme create/basic-model-request.md>) и [формат схемы Basic](../basic-schema-guide.md).

Единый HTML-файл `canvas-prototype-vN.html` (N — версия стенда, номер в имени файла, заголовке вкладки, окне и первой строке блока замечаний). Это учебный прототип, не часть расширения: он ничего не запускает и не связан с кодом приложения.

## Зачем

Нейросети предлагают схемы сценариев из наших видов этапов (раунд, ответ User, запись файла). Стенд:
- проверяет, что предложенная схема записана в нашем формате и не нарушает правил движка (ссылки только вверх, без стрелок назад и т. д.);
- рисует её на холсте, похожем на настоящий (этапы открываются, у раундов настоящие окна настроек), чтобы было видно, как схема устроена;
- копит принятые схемы в каталоге черновиков — JSON-файле на компьютере. Из каталога схемы потом переносят в приложение по степени надобности.

Стенд служит только для проверки схемы под наш движок и для её понимания. Он не исполняет схему, не обращается к чатам моделей, не загружает исходные артефакты и не проверяет, существуют ли файлы, на которые ссылается схема.

## Как работать

1. Дать моделям запрос из [model-prompt.md](model-prompt.md) (и скриншоты холста). Каждая модель возвращает один JSON-объект и три коротких пункта комментария.
2. Открыть `canvas-prototype-vN.html` в Chrome (двойной клик или `open -a "Google Chrome" <путь>`). В панели приложений Claude и других просмотрщиках файл показывается без скриптов, поэтому открывать нужно именно в браузере.
3. Нажать кнопку **«i»** в шапке панели (или клавишу I), вставить ответ модели как есть и нажать **«Применить»**. Лишний текст и служебные строки расширения копирования стенд уберёт сам; комментарий модели останется в сворачиваемом блоке.
4. Прочитать замечания: ошибки (схема не применяется или нарушает правила) и предупреждения (исправлено автоматически или спорное место). Метка «!» на этапе показывает проблемный этап; двойной клик открывает окно с полями схемы («Из схемы»).
5. Понравившуюся схему сохранить иконкой дискеты в шапке: она появится в списке Pipelines. «×» (при наведении или долгом нажатии) удаляет шаблон. Все шаблоны лежат в файле `stand-templates.json`: при первом сохранении Chrome предложит выбрать место (удобно выбрать папку проекта).
6. «Сбросить» возвращает исходный холст и очищает поле; корзина очищает поле и комментарий модели.

## Обмен с Basic

Кнопка **Import** загружает файл каталога шаблонов или JSON-схему Basic и добавляет её на холст; кнопка **Export** скачивает текущую схему в формате Basic. Экспорт v66 переносит `round` и `owner`, делает источники обязательными и проверяет результат настоящим `BasicSchema.validate`. `in.Имя` становится входным файлом этапа: текст `content` переносится внутрь объявления файла, `attachment` требует выбрать реальный файл в Basic. Неподдерживаемый этап `file`, отсутствующий источник или неоднозначный адрес блокируют экспорт с причиной; файл с потерянным входом не создаётся.

Обычные артефакты переносятся в `output.artifacts`: выход задаётся JSON-полями с явным соответствием имени артефакта и JSON Pointer. Вход `s2.Имя` становится адресом конкретного артефакта участника, а не всем ответом этапа. Несколько моделей могут иметь собственные линии объявленных артефактов, но ссылка стенда без участника неоднозначна и требует исправления. Документ `read` сохраняет метки и отдельный адрес; ссылка на недоступный для точного выделения опросник `form` останавливает экспорт.

Обратный Import Basic → стенд остаётся ограниченным: необязательность, адрес участника/артефакта, индивидуальный вход и входные файлы могут потеряться с предупреждением. Не используйте обратный перенос как способ сохранить произвольную схему Basic без изменений. Подробности — [технический контракт](CONTRACT.md) и [входные файлы Basic](../basic-input-files.md).

## Что стенд понимает

Формат схемы — `{ "task", "steps": [ … ] }`, виды этапов и поля описаны в [model-prompt.md](model-prompt.md) (языком для моделей) и в [CONTRACT.md](CONTRACT.md) (технический контракт стенда: проверки, автоисправления, каталог, API).

Принятые решения:
- **Стрелок назад нет, ветвлений нет.** Все этапы выполняются по порядку: повтор работы — обычный этап ниже по списку, решение User — этап `owner`.
- **Исходные артефакты даёт модель.** Приложение само ничего не загружает и не ищет в интернете. Исходный артефакт (верхнеуровневое `artifacts`) несёт полный текст (`content`) или имя файла, приложенного к ответу в чате (`attachment`). Стенд имитирует файл ссылкой: это видимая ссылка в схеме независимо от того, выложила ли модель файл на самом деле.
- **Ошибки моделей ожидаются.** Стенд принимает то, что можно исправить однозначно (кавычки, запятые, обёртки, алиасы ключей), и всегда сообщает об этом; остальное отклоняет с пояснением, что просить у модели (формат `state.js`, Mermaid, оборванный JSON).
- **Черновая схема — не схема Basic.** Формат стенда проще и строже действующей схемы Basic (`disput/basic-schema.js`). В Basic есть шаги `round`, `owner` и реестр артефактов (волны 0–4 плана исполнены 11–12.10, см. [план доработки](../basic_upgrade_oct11.md)). Видов `synthesis`, `gate` и `route` нет ни на стенде, ни в Basic (из Basic `gate` и `route` удалены в 2.81.848, `synthesis` — в 2.81.849): синтез — `round` из одной модели с ролью «свести» (в Basic — роль `interaction_meta_synthesis`), проверка — обычный `round` с критериями в `task`, за которым при необходимости идёт `owner`; схема линейна, переходов нет. На стенде нет полей `optional_inputs` и `order` (из Basic `order` и `require` удалены в 2.81.850): раунд — один запрос всем его моделям, они отвечают независимо, а эстафета записывается раундами по одной модели подряд. Нет в Basic: вида `file`, верхнеуровневого `artifacts` и ссылок `in.Имя`. Возвратов назад нет ни там, ни там (из Basic убраны в 2.81.846). Перенос схемы в приложение — отдельная работа; несоответствие фиксируется здесь, а не подменяется.

- **Три паттерна — предупреждения, не ошибки.** Ответ User без этапа, который его читает; артефакт в раунде из нескольких моделей; личное задание модели при общем задании этапа. Схема применяется, замечания описывают сбой.
- **Документ и чат.** Артефакт этапа с `document: "read"` или `"form"` (только в раунде из одной модели), `owner.document` со ссылкой на такой раунд, `chat` у раунда (`new` | `continue`). Поля описаны в [CONTRACT.md](CONTRACT.md) и переносятся в Basic.

## Устройство и сборка

Показательная схема (исходные артефакты, раунды, в том числе синтез одной моделью, проверка с доработкой обычными этапами, ответ User, запись файла): [showcase-robot-vacuum v1.json](showcase-robot-vacuum%20v1.json) — вставить в окно «i». Она для просмотра возможностей стенда: в Basic уходит только часть видов этапов, и Export честно откажет, если файл получится недопустимым.

Исходники: `index.html`, `state.js`, `cards.js` (окна), `canvas.js` (холст), `stand.js` (стенд и каталог), `stand-examples.json` (примеры). Единый файл собирает `python3 build.py` в этой папке: он подтягивает настоящие стили проекта и иконки моделей, берёт номер из `STAND_VERSION` в `stand.js` и удаляет файл прежней версии. После любой правки исходников поднимайте `STAND_VERSION` и пересобирайте.

Видимая версия нужна, чтобы по сообщению об ошибке сразу понимать, на какой сборке оно получено.
