# Запрос для моделей: составить схему в формате стенда

Текст между линиями копируется целиком и отправляется моделям вместе со скриншотами холста (общий вид, окно раунда, окно модели). Ответ модели вставляется в стенд (кнопка «i» → «Применить»), см. [README.md](README.md). Формат проверяет `stand.js`; технический контракт — [CONTRACT.md](CONTRACT.md).

Запрос написан простым языком и ужесточён по результатам прогонов: модели путали форму ответа (присылали внутренний файл прототипа или Mermaid), уходили в повторы и возвраты, ссылались на пропускаемые этапы как на обязательные и просили приложение самому загрузить исходные данные. Каждое правило ниже закрывает конкретный наблюдавшийся сбой. При изменении формата стенда обновляйте запрос и поднимайте версию стенда.

---

````
Задание: собрать одну реальную схему из этапов и артефактов и записать её в строгом формате JSON.

О приложении.
Это расширение для браузера. Пользователь формулирует задачу, а приложение отправляет её сразу нескольким нейросетевым чатам (ChatGPT, Gemini, Claude и другим), собирает ответы и показывает вместе. Ответы можно пускать по кругу: модели видят ответы друг друга, критикуют, уточняют, одна из них сводит итог. Весь ход работы описан схемой: пользователь собирает её на экране, как конструктор, из этапов. На скриншотах показан наш холст: слева направо идут этапы, у раундов под значком стоят модели, под ними серые артефакты, справа финальный синтез.

Словарь (только два слова).
Этап — действие, у которого есть исполнитель: модель, человек или приложение.
Артефакт — любой документ или данные. Его производит этап, либо он дан с самого начала (бриф, образец, вложенный файл).
Правило проверки: если у этапа есть исполнитель (модель, человек, приложение), это этап; если нет — это артефакт.

Как устроена схема.
Схема — список этапов сверху вниз. Порядок в списке и есть порядок выполнения. Каждый этап берёт на вход артефакты более ранних этапов и исходные артефакты и выдаёт свои. Стрелок назад нет и быть не может: схема не содержит возвратов.

ВИДЫ ЭТАПОВ (значение `block`)
| Вид этапа | Исполнитель | Что делает | Поля |
| --- | --- | --- | --- |
| `round` | модели | несколько моделей отвечают одновременно или по очереди | `models` (список; у каждой `name`, можно `role`, `task`, `maxWords`), `order` (`parallel` — одновременно, `sequential` — по очереди: каждая видит ответы тех, кто ответил до неё), `task` (общее задание раунда), `inputs` |
| `synthesis` | модель | одна модель сводит ответы | `model`, `role` (свести, судья, жюри, отобрать идеи, сгруппировать, критический разбор), `task`, `inputs` |
| `route` | приложение или модель | выбор пути вперёд по ответу предыдущего этапа | `choices`: [{"when": "условие", "goes": ["id этапа НИЖЕ"]}] |
| `owner` | человек | этап ждёт ответа человека | `ask` |
| `file` | приложение | запись файла в папку пользователя | `file`, `mode` (`overwrite` / `append`), `inputs` |
| `assemble` | приложение | склейка артефактов в один документ без нейросети | `inputs`, `template` |

Проверка — не отдельный вид этапа. Это этап моделей (`synthesis` или `round`): критерии пишутся в `task`, а в задании просьба ответить «прошло» или «не прошло» с замечаниями. Затем `route` выбирает путь: «прошло» — дальше, «не прошло» — этап доработки ниже по списку.
Роль синтеза (свести, судья, жюри…) — просто текст запроса к модели, а не отдельный вид этапа.

ОБЩИЕ ПОЛЯ ЛЮБОГО ЭТАПА
`id` (уникальный: s1, s2, …), `block` (вид этапа), `title` (по-русски), `why` (ОБЯЗАТЕЛЬНО, одна строка), `inputs`, `optional_inputs`, `artifacts` (артефакты, которые этап производит).
У каждого артефакта в `artifacts` ОБЯЗАТЕЛЬНО описание, поэтому пишите его объектом: {"name": "Карта функций", "description": "что в нём лежит и кому он нужен, 1–2 фразы"}. Ссылки в `inputs` — по имени: "s2.Карта функций".
На верхнем уровне также `description` — презентация проекта для человека, который будет запускать эту схему. Не короткая строка: опишите проект целиком. На работу схемы не влияет.
Необязательные настройки: на верхнем уровне `defaults` {roundTask, synthesisTask, discipline: {lines: [строки]}, modelNotes: {"Claude": "текст"}} — общие правила для всех моделей; у модели и синтеза `maxWords` (целое число слов).

ИСХОДНЫЕ АРТЕФАКТЫ.
Исходный артефакт — не этап. Он записывается на верхнем уровне схемы списком `artifacts`: объекты с полями `name` (обязательно), `description` (желательно) и одним из полей `content` (полный текст) или `attachment` (точное имя файла с расширением, приложенного к ответу в чате).
Ссылка из этапа: в `inputs` строка "in.Имя" (например, "in.Бриф"). Этап для неё не нужен, ссылка допустима на любом месте списка.
Приложение само ничего не загружает и не ищет в интернете. Исходные данные даёте вы сами: полным текстом в `content` или файлом в `attachment`. Если реальный текст вставит пользователь, опишите в `content`, каким он должен быть: формат, объём, пример. Не рисуйте этапов вида «найти в интернете» или «прочитать ссылку».
Не путайте два поля `artifacts`: верхнеуровневое — исходные (объекты), у этапа — производимые (с описанием, см. выше).

ЖЁСТКИЕ ПРАВИЛА (нарушение = схема считается неверной)
1. `inputs` ссылаются только на этапы ВЫШЕ по списку. Конкретный артефакт: "s2.Название артефакта", артефакт должен быть в `artifacts` у s2. Исходный артефакт: "in.Название".
2. `route.goes` ссылается только на этапы НИЖЕ. Если этап читает результат этапа, который развилка могла пропустить, этот вход пишется в `optional_inputs`, а не в `inputs`.
3. Повтор и возврат. Возвратов в схеме нет. Если работу надо повторить после проверки, пишите ещё один обычный этап ниже по списку (своё `task`, свои `inputs`). `route` ведёт только вперёд: на этап доработки ниже по списку или к `owner`.
4. Имена моделей — только Claude, GPT, Gemini, Grok, Le Chat, Qwen, DeepSeek, Perplexity, Z.ai, Kimi. Не «ChatGPT».
5. У каждого этапа есть `id`, `block`, `title`, `why`. Все `id` в схеме уникальны.
6. Артефакт, который этап обновляет, называется так же (новая версия).
7. Артефакт — всегда документ (текст с названием и версией), а не запрос к модели и не обрывок ответа. Артефакт — не любой результат этапа. Обычный результат этапа следующий этап получает сам через `inputs: ["s1"]` (без точки и без артефакта). Объявляйте артефакт, только если он нужен не только соседнему этапу: его читают этапы дальше по схеме, он обновляется новыми версиями, или это документ для человека или для файла. Не объявляйте артефактом каждый результат.

ФОРМА ОТВЕТА (строго)
— Ответ: ОДИН JSON-объект и больше ничего до него. После него — только три коротких пункта (см. ниже).
— Только настоящий JSON: двойные кавычки, без комментариев, без запятой после последнего элемента, без «...», «…», «и т.д.», без многоточий вместо этапов.
— Не пишите Mermaid, JavaScript и не присылайте внутренние файлы приложения (никаких `window.ProtoState = …`).
— Если ответ не помещается: сокращайте тексты заданий до одной фразы, но НЕ убирайте этапы и НЕ обрывайте JSON.

ПРОВЕРЬТЕ ПЕРЕД ОТВЕТОМ (про себя, по списку)
 □ этапов верхнего уровня не меньше 8, разных видов этапов (`block`) не меньше 4;
 □ ни один `inputs` не ссылается на этап НИЖЕ по списку (и на сам этап), «стрелок назад» нет;
 □ у каждого этапа есть `why`; на верхнем уровне есть `description`;
 □ каждый «s2.Имя» ссылается на артефакт, объявленный в `artifacts` у s2; каждый "in.Имя" — на исходный артефакт верхнего уровня;
 □ у каждого артефакта этапа есть `description`; артефактами объявлены только документы, нужные не одному соседнему этапу (правило 7);
 □ после `route` все пропускаемые входы вынесены в `optional_inputs`;
 □ у каждого исходного артефакта есть `content` или `attachment`;
 □ имена моделей из списка;
 □ JSON закрыт до конца и разбирается без ошибок.

Что нужно от вас.
Выберите реальную задачу, которую человек действительно ставит перед нейросетями (подготовка большого документа, анализ множества документов, выбор решения, исследование). Не копируйте задачи из примера. Соберите схему и запишите её JSON. Затем тремя короткими пунктами:
— каких видов этапов не хватило или какой был непонятен («ничего», если всё ясно);
— какие виды этапов не использовали и почему;
— самое слабое место вашей схемы.
````

## Что стенд делает с нарушениями

| Нарушение в ответе | Реакция стенда |
| --- | --- |
| Лишний текст до и после JSON, служебные строки расширения копирования | Убирает, текст вне JSON сохраняет как «Комментарий модели» |
| Кавычки, запятые, комментарии, ключи без кавычек | Исправляет с предупреждением |
| Алиасы (`stages`, `type`, `name`, `input`), строка вместо списка, обёртки | Исправляет с предупреждением |
| Формат `state.js`, Mermaid, текст без JSON, оборванный JSON | Отклоняет с пояснением, что просить у модели |
| Ссылка вниз, `route` назад, нет `why` | Ошибка с названием этапа |
| Вид этапа `gate` (проверка) | Ошибка этапа: «Вид этапа «gate» не поддерживается. Проверка — обычный этап моделей: критерии запишите в task; результат читает route и выбирает путь вперёд.» |
| Удалённый вид этапа (перебор по пунктам, список, форма, источник, готовая часть, оценка баллами) | Ошибка этапа с пояснением, как выразить иначе |
| Вложенный `body` | Ошибка |
| Удалённые поля (повторы, основания, веса, запрос) | Предупреждение; значение игнорируется |
| Артефакт этапа без `description` | Замечание: «У артефакта «X» нет описания» |
| Пропускаемый вход вне `optional_inputs`, неизвестное имя модели, «...» вместо текста, исходный артефакт без `content` и `attachment` | Предупреждение |
