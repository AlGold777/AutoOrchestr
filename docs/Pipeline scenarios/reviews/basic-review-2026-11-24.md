## 2. Исправлено

**R-1 P1 — у участника-копии (`settingsMode: "explicit"`) пустые инструкция доставки и текст повтора.**
- Где: `disput/basic-schema.js`, `assemble`: ветка explicit брала `discipline[key]` или `''` и обходила правило `NEVER_EMPTY`.
- Что видел пользователь: копия модели («+» на карточке) получала запрос без строки «Последней строкой ответа напиши только метку…»; при отклонённом ответе повтор уходил пустым сообщением (`correctionPrompt(reason, '')` → `''`).
- Исправление: у explicit-участника `delivery` и `correction` при пустом значении наследуются; остальные поля по-прежнему пустые. Документы (`basic-schema-guide.md`, `basic-participants-schema-notes.md`) приведены к коду: прежнее исключение «пустое остаётся пустым» давало пустой повтор.

**R-7 P1 — кнопка Run «залипала» в Stop после отказа локальной модели.**
- Где: `results.js`, `runCustomFromPage`: три ранних выхода (у «Qwen 4B» есть файлы; выбрано «without LLM»; Ollama не отвечает) возвращали `false`, не сбросив `customAbortController`.
- Что видел пользователь: прогон не начат, но кнопка показывает «Остановить Basic»; нажатие только вызывает `abort()`. Run не работает до перезагрузки страницы.
- Исправление: `releaseAbort()` перед каждым выходом; исключение `loadChoice` и `ping` тоже освобождает контроллер.

**R-2 P2 — проверка отвергала правильную схему у explicit-участника со своим запросом.**
- Где: `validate`: для проверки `{вход}` брался вход шага, хотя `assemble` даёт explicit-участнику без своего `input` вход `none`.
- Что видел пользователь: «есть возможный вход из более раннего шага, но в запросе нет {вход}» на запросе, который получит пустой вход.
- Исправление: в проверке explicit без своего `input` — `none`, как в прогоне.

**R-5 P2 — метки документа считались словами ответа.**
- Где: `disput/basic-output.js`, `checkAnswer`: `countWords(answer)` при `strictLength`.
- Что видел пользователь: документ в пределах лимита получал повтор «слов 8 из 5».
- Исправление: слова считаются без меток `[[DOC: …]]`, `[[/DOC]]`.

**R-6 P2 — файлы прогонов в IndexedDB не удалялись.**
- Где: `disput/basic-input-files.js`, `putRun`: снимок файлов каждого прогона (base64) писался навсегда.
- Что видел пользователь: база расширения растёт без предела; при заполнении квоты новый прогон с файлами не сохраняется.
- Исправление: хранятся снимки 10 последних прогонов, старые удаляются в той же транзакции.

**R-8 P2 — после перезагрузки посреди прогона не было «Продолжить».**
- Где: `results.js`, `offerStoredResumeLine`: условие `record.stopReason && …`, а у прерванного прогона причина остановки пустая.
- Исправление: строку «Продолжить» получает и прогон без причины остановки, если запись пригодна к продолжению (`canResume`).

**R-9 P2 — «Сохранить» в окне End показывало успех без папки документов.**
- Где: `results.js`, `onSave` окна End: `saveDocumentCopy` молча выходил при `reason: 'none'`, кнопка мигала успехом.
- Исправление: `saveDocumentCopy` возвращает результат записи; без папки — уведомление «Документы не сохранены: папка документов не выбрана…», кнопка показывает ошибку.

**R-3 P3 — `ref` вида `__proto__` проходил проверку и писал в общий прототип объектов страницы** (`toSettings`). Исправление: `validate` отвергает `ref`, совпадающий с ключом `Object.prototype`.

**R-4 P3 — `addToRound` стирал личные настройки выключенного участника при включении без выбранного образца.** Исправление: без образца участник включается со своими настройками.

**R-10 — документы.** Раздел 5 `basic-developer.md`: снят V06 (не воспроизводится), REVIEW-2 и TEST-1 приведены к тестам, добавлен TEST-4 (текущие падения). Ссылка на `endless-pipeline.md` получила путь, «Export all schemas» → «Экспорт всех схем» (так в интерфейсе), «Пуск/Пауза» в окне → кнопка запуска.

## 3. Оставлено (P3)

1. Движок: ветка `prefetched` (ответы «найденные проверкой») никогда не получает данных — переменной ничего не присваивается; с ней мёртвы `viaCheck` и `attemptKey` (`custom-engine.js:515`, `:962-972`, `:1054`). Убирать вместе с решением о проверке неизвестной попытки.
2. Движок: после продолжения из снимка журнал запросов (`history`) пуст, поэтому чтение страницы перед повтором пропускается с причиной `no_sent_prompt`. Только чтение, не воспроизводилось.
3. Движок: комментарий «A skipped step passes nothing on» у `answersFor` (`:714`) читается как «следующий шаг ничего не получит». Поведение совпадает с `basic-schema-guide.md`: вход идёт от более раннего шага.
4. Повтор (`run.repeat`): между заходами, пока открыто окно User, панель визуально разблокирована (`setPipelineEditingEnabled(true)` в `endRunEarly`); обработчики правок проверяют `pipelineRunActive`.
5. Повтор: заход, который не начался, засчитывается в «Запросов израсходовано» (`requestsPerPass`).
6. Холст: переключение pipeline быстрее 150 мс после снятия Send теряет правку (таймер `persistBasicStructureSoon` сверяет текущий pipeline).
7. Холст: пока выключен раунд, на который ссылается `end.from`, правки не сохраняются; уведомление «Настройки не сохранены» показывается.
8. `extractDocument` берёт первый блок `[[DOC]]`, второй молча отбрасывается (так описано в комментарии).
9. Не вызываются из кода расширения: `BasicSpec` (`basic-spec.js`), `verify` цепочки прогонов (`basic-run-chain.js`), `snapshot.runSettings` (пишется, не читается).
10. Окно модели: если `previewPrompt` вернул `null` (шаг не проходит `unexecutedOf`), карточка не открывается, ошибка — в консоли. Такую схему `validate` не пропускает, в штатном пути не встречается.

## 4. Опровергнуто

- Пропущенный шаг передаёт следующему ответы более раннего — так описано в `basic-schema-guide.md` (вход `previous`).
- Ответ, пришедший во время Stop, теряется — страница передаёт ответы движку по волнам (`onWaveResult`), окно между ответом и Stop пренебрежимо мало.
- Stop не закрывает окно вопроса User — окно модальное, нажать Stop под ним нельзя.
- `toCanvas`/`toSettings` падают на `null` в шагах — перед ними стоит `validate`.
- Шаг User без `input` получает `previous` — шаги User собирает `assembleControl`, он вход по умолчанию не подставляет.
- Подписей «Оставить пустым», «Очистить — наследовать» нет в коде — есть, это подсказки (`title`) крестика.
