# Basic: старт здесь

Для модели или человека, который впервые пришёл в проект. После чтения вы понимаете, что такое Basic и схема, что происходит при прогоне, где что лежит в коде и на странице, и какой документ читать дальше.

## Что такое Basic (коротко)

- **Basic** — движок pipeline и его оболочка на странице. Это единственный pipeline, который развивается.
- Движок не знает про вкладки и DOM; страница отправляет запросы, принимает ответы и рисует карточки.
- **Pipeline = схема**: JSON с шагами (раунды и синтезы), моделями, заданиями, входами и политикой запуска.
- Схема, сохранённая пользователем, лежит в хранилище как **запись**: схема плюс данные холста, которые из неё выводятся.
- **Шаблон Basic** собирается из кода (`disput/pipeline-presets.js`) и в хранилище не лежит; правки шаблона живут до перезагрузки страницы.
- В коде Basic называется `custom` (`disput/custom-engine.js`, `runCustomFromPage`).

Пример схемы (шаблон A из `basic-schema-guide.md`): один раунд, где три модели отвечают независимо, затем итоговый синтез одной моделью; политика запуска `auto` (шаги идут без остановки):

```json
{
  "schemaVersion": 1,
  "origin": "user",
  "run": { "policy": "auto" },
  "steps": [
    { "ref": "r1", "kind": "round", "models": [{ "name": "Claude" }, { "name": "GPT" }, { "name": "Gemini" }] },
    { "ref": "final", "kind": "synthesis", "models": [{ "name": "Claude" }] }
  ]
}
```

## Что мы строим и зачем

- Движок можно менять и дополнять, не ломая уже созданные схемы.
- Поэтому схема хранит только явные отличия от умолчаний Basic; умолчания — контракт.
- Новое поле по умолчанию сохраняет прежнее поведение; старые схемы без него работают как раньше.
- Формат схемы версионируется (`schemaVersion`).
- Схему может написать человек или модель по самодостаточной инструкции: `basic-schema-guide.md`.
- Причины решений и правила — в `basic-engine-and-schemas.md` («Решения и причины»).

## Словарь

| Термин | Что это |
| --- | --- |
| Basic | Движок pipeline и его оболочка на странице. В коде — `custom`. |
| Схема | JSON, описывающий pipeline: шаги, модели, задания, вход, политику запуска, предел длины. |
| Запись | Pipeline в хранилище (`chrome.storage.local`, ключ `llmComparatorPipelines`): схема и данные холста. |
| Шаблон | Готовая схема из кода (`disput/pipeline-presets.js`), например Basic. В хранилище не лежит. |
| Шаг | Элемент схемы: раунд или синтез. |
| Раунд | Шаг, в котором модели отвечают на задачу (или на вход из предыдущих шагов). Ref: `r1`, `r2`… |
| Синтез | Шаг, в котором одна модель сводит ответы. Промежуточный — `synth:<id>`, финальный — `final`. |
| `ref` | Уникальный идентификатор шага в схеме: `r1`, `synth:<id>`, `final`. |
| Задача | Текст, который пользователь вводит в поле модератора при запуске. |
| Задание | Инструкция шага (поле `task`), которую получают все модели шага. Задание не равно задаче. |
| Принятый ответ | Ответ модели, который прошёл приёмку движка (`accept`): не пустой, не обрезан, не ошибка. |
| Запрос исправления | Повторный запрос в том же чате, если ответ не принят. Всего до 2 попыток. |
| Транспорт | Общая отправка запросов и приём ответов моделей через фон расширения и вкладки моделей. Одинаков для всех pipelines. |
| Метка доставки | Служебная метка, которую транспорт использует для подтверждения доставки. Ответ, состоящий только из неё, не принимается. |
| Журнал доставки | Журнал событий отправки (`MessageDelivery`). События Basic имеют имена `custom_*`. |
| Политика запуска | `run.policy`: `auto` — шаги идут без остановки; `manual` — владелец подтверждает каждый шаг. |
| Окно настроек | Окно редактирования: модели (двойной клик по блоку), раунда (клик по значку R1, R2…), ▶ (общие значения для всех шагов). |
| Карточка ответа | Блок в ленте: один ответ модели с подписью `Basic · Раунд N` или `Basic · Синтез после раунда N`. Итог — `Basic · итог`. |

## Имена: интерфейс и документы → код

В коде движок называется `custom`; ищите по таблице.

| В интерфейсе и документах | В коде |
| --- | --- |
| Движок Basic | `disput/custom-engine.js`, глобальный объект `CustomEngine` (`run`, `normalizeSteps`, `buildPrompt`, `previewPrompt`) |
| Формат схемы, значения по умолчанию, сборка | `disput/basic-schema.js`, глобальный объект `BasicSchema` (`validate`, `assemble`, `resolveFields`, `toCanvas`, `toSettings`, `resolveRun`, `DEFAULTS`) |
| Прогон Basic на странице | `results.js`: `runCustomFromPage` |
| Схема со страницы | `results.js`: `basicSchemaFromPage`, `buildBasicRun` |
| Запись из схемы | `results.js`: `recordFromSchema`, `installBasicSchema`, `persistBasicSettings` |
| Export / Import схемы | `results.js`: `buildBasicExport`, `exportBasicSchema`, `importBasicSchemaFile`, `importBasicBundle`, `handlePipelineImportFile` |
| Окно настроек модели | `results.js`: `renderCustomBlockInspector`, CSS-классы `custom-card-*` |
| Окно настроек раунда | `results/stage-card.js` (`StageCard`), открывается из `results.js`: `openStageCard` |
| Запись о прогоне | `disput/custom-run-record.js` (`CustomRunRecord`), в JSON-экспорте Disput Flow — поле `customRun` |
| События журнала | `custom_start`, `custom_answer`, `custom_step`, `custom_decision`, `custom_end` (движок), `owner_answer` (страница) |
| Пресет | `presetId: 'CUSTOM'`, `runner: 'custom'`, `isCustomEnginePipeline()` |
| Роль «Custom» в списке ролей | `CUSTOM_ROLE_ID = 'custom'` — **роль** (текст раунда), а не движок |
| Рабочие копии настроек на странице | `customCardSettings`, `customRoundSettings`, `customPipelineDefaults` (Map по имени pipeline) |

## Что где на странице

| Элемент | Что открывает или делает |
| --- | --- |
| ▶ (`#entryPoint`) | Окно настроек ▶: общие значения для всех шагов. |
| Значок раунда R1, R2… | Окно настроек раунда: роль для моделей раунда, порядок, вход, задание. |
| Двойной клик по блоку модели | Окно настроек модели: запрос, длина, дисциплина, свои строки «+». |
| Вставка между раундами | Клик добавляет или снимает промежуточный синтез; двойной клик открывает его окно настроек. |
| Значок «Final» | Клик включает или выключает финальный синтез; двойной клик открывает его окно настроек. |
| Save (`#pipeline-save-btn`) | Сохранить текущую схему как пользовательский pipeline (запись). |
| Export schema (`#pipeline-export-btn`) | Сохранить схему в файл. |
| Import schema (`#pipeline-import-btn`) | Загрузить файл схемы. |
| «+» (`#pipeline-add-btn`) | Новый пустой pipeline. |
| «+» у раундов (`#pipeline-add-round-btn`) | Добавить раунд. |
| «×» у раунда (`.pipeline-round-delete-btn`) | Удалить раунд. |
| Delete pipeline (в списке записей) | Удалить запись. |

Карточки ответа появляются в ленте: одна на каждый непустой ответ модели в шаге и одна `Basic · итог` в конце прогона. Итог собирает страница из принятых ответов, он не склеивается из карточек шагов.
