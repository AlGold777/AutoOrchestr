# Basic: окна настроек

Входные файлы любого участника (📎, поле `files`, доставка и продолжение): [описание](basic-input-files.md).

Для того, кто ищет, где на странице задаётся то или иное поле Basic и что оно делает. Окна: настроек раунда (клик по значку R1, R2…), модели (двойной клик по блоку), ▶ (общие значения), шага User. Отдельного окна синтеза нет: синтез — раунд из одной модели с ролью `interaction_meta_synthesis`, его настраивают окном раунда и окном модели. Прогон и карточки ответа — в `basic-start-here.md`; формат схемы — в `basic-schema-guide.md`. Значения из окон хранятся в схеме pipeline.

Переход кнопкой между Pipeline и основной страницей сохраняет выбранную схему, несохранённые правки её настроек, отдельный черновик prompt каждой страницы, вставленные тексты и вложения. Файлы восстанавливаются с содержимым; удалённые или отправленные вложения повторно не появляются. Избранное сохраняется между страницами. Переходы браузера «Назад/вперёд» также сохраняют черновики. Явная перезагрузка страницы сохраняет прежнее поведение очистки.

## Карточка раунда

| Настройка | Значение |
| --- | --- |
| Модели | Список с галочкой «участвует»; все включённые модели получают один запрос и отвечают независимо, раунд ждёт ответов всех |
| Дополнение модели | Необязательный мини-промпт у каждой модели (по умолчанию None); получает только эта модель. В Basic (R1 и R2+) его можно выбрать сразу для всех моделей раунда кнопкой «Роль для всех моделей раунда» в карточке раунда; выбор в блоке модели перекрывает общий. Смена при различающихся ролях спрашивает подтверждение. Блоки R1 имеют тот же список ролей, что и R2+. Пункт **Custom** в списке ролей — см. ниже |
| Задание раунда | Общий текст для всех моделей раунда |
| Вход | Задача передаётся всегда. Дополнительно: **ничего**; **ответы последнего этапа с принятым результатом**; **всё принятое** за все предыдущие шаги; **выбранные этапы** (список ранних шагов) |

**Окно раунда.** Клик по значку раунда (R1, R2…) открывает карточку раунда Basic: «Роль для всех моделей раунда»
(и текст «Custom»), **Вход раунда** и **Задание раунда**. У раунда, перед которым нет ни одного шага (шаг User тоже считается), нет входа (ему нечего
подавать), но задание есть. Поля: вход — «по умолчанию (ответы последнего этапа с принятым результатом)», «ничего», «ответы последнего этапа с принятым результатом», «всё принятое»; задание показывается при любом входе. При входе «ничего» отправляется
только задание, написанное в этом окне (общее задание из ▶ не отправляется); метка поля это говорит. При других входах пусто — общее задание
(▶, затем Basic, подсказка в поле показывает его). Выбранное и набранное — значение User, «по умолчанию» и пустое
задание возвращают наследование. Личное задание модели главнее задания раунда. Поля хранятся в схеме как `input`,
`task` шага и закрыты во время прогона. Поля User и выхода — в разделе «Поля шага» ниже. Выбора порядка
и числа нужных ответов нет: эстафета — раунды по одной модели подряд.

**Поля шага** (окно раунда). У раунда, до которого нет исполнимого шага (первый, который что-то делает), входа нет: он получает только задачу. Вход «выбранные этапы» — список ранних шагов с галочками; выключенные помечены «(выключен)», номер у галочки — место в списке входа (порядок выбора = порядок массива `input`). У каждого выбранного этапа есть отдельная галочка **Обязательный**: без принятого результата этот источник остановит прогон с `missing_input`. Вход `previous` выбирает ответы последнего этапа с принятым результатом и пропускает этапы без ответа. Обязательность задаётся явно для выбранного целого этапа. Пока ни один этап не отмечен, вход в схему не пишется. Ссылки на участников и артефакты, заданные в JSON, сохраняются и показываются строкой «заданы в JSON». **Спросить User после этапа** — `owner: "approve"`; в карточке раунда есть отметка «User: одобрение». **Выход этапа**: имя (`output.name`), форма (`output.form`), разделы по одному на строку (`output.sections`, недоступны при `format: json`) и строгая длина (`output.strictLength`). Поля `format`, `requiredFields`, `artifacts`, `revisionOf` окно не редактирует, но сохраняет. Поля сохраняются сразу, как «Задание раунда»; ошибка схемы при изменении сохранённого pipeline показывается уведомлением с путём. Предпросмотр запроса — в окне модели (двойной клик по блоку): вход «выбранные этапы» показан как «Ответы выбранных источников» с `{вход}`, выход шага — блоком «Формат ответа». Окно раунда само предпросмотр не показывает.

Число раундов — число карточек. Настройки всего pipeline: Авто или подтверждение между
раундами, предел длины ответа.

## Карточка модели

У модели есть компактная кнопка «+»: она создаёт нового участника с подписью `Модель 2`, затем `Модель 3` и новым ID. Новый участник виден в карточках раундов, изначально выключен и имеет пустые персональные настройки. Нажатие по подписи переименовывает участника; «×» убирает его только из текущего раунда. Если на участника ссылаются входы или артефакты последующих шагов, удаление блокируется с указанием зависимости. Двойной клик по карточке открывает настройки; **Default** заполняет поля значениями текущего раунда как черновик, **Save** сохраняет их. Эти действия не запускают модели. Save карточки пишет только её поля (подпись, режим, запрос, длину, файлы, задание, дисциплину); собственные `output` и `input` участника и прочие поля схемы остаются как были.

Двойной клик по пустому месту блока модели в Basic открывает компактный редактор (кнопки 📝 в блоке больше нет;
клики по чекбоксам, статусу, списку ролей и кнопкам блок не открывают): иконка и название модели, личный
предел длины и кнопка Save в шапке, раунд рядом с моделью. Ширина карточки — 889 px
(+17%); поле запроса увеличено. Подсказка находится справа от «Запрос», инструкции
транспорта идут в две колонки (на узком экране — в одну). Карточка помещается по высоте окна. Окно ▶ — 978 px (на 10% шире) и той же высоты, что карточка модели (`min(760px, 100dvh − 32px)`); тело прокручивается, шапка с Save остаётся видна.

- Автоматический запрос можно изменить или заменить своим. Правка действует только для
  этой модели в этом шаге. «Вернуть автоматическую сборку» снимает замену.
- `{задача}` подставляет актуальную задачу при запуске, `{вход}` — принятые ответы
  предыдущих шагов согласно настройке входа. Подстановка однократная:
  такие строки внутри полученных ответов не интерпретируются повторно.
- Роль модели (мини-запрос из блока) уходит в запрос этой модели как «Дополнительно для тебя».
  Персональный запрос заменяет сборку целиком, поэтому роль в нём не добавляется.
- R1 получает роль так же, как R2+: запрос содержит исходную задачу пользователя и текст роли. Роли R1 по умолчанию None;
  пресеты их не задают. Роль R1 применяется на движке Basic; на остальных движках роли ни в одном раунде
  не применяются к запросу.
- Личная длина — положительное целое число слов; пустое поле наследует общий предел.
  Инструкция длины добавляется перед передачей в общий транспорт, в том числе при
  исправлении ответа. Это инструкция модели, а не обрезка ответа до числа слов.
- В блоке «Метки транспорта» показаны полные тексты инструкций доставки,
  длины и требований к содержанию. Инструкция исправления ответа
  показана отдельным редактируемым полем для повторов. Поля редактируются сразу. У каждой строки есть иконка копирования, красный крестик
  («оставить пустым» у заданий, длины и содержания; «очистить — наследовать» у доставки и повтора) и галочка сохранения. Правки хранятся в схеме pipeline (`steps[].models[].discipline`)
  и действуют только для этой модели в этом шаге, включая повторные попытки.
- Кнопка «+» под строками блока «Метки транспорта» добавляет свою строку («Строка N»): текст
  уходит в запрос этой модели после требований к содержанию, каждая строка отдельным абзацем.
  «×» у своей строки удаляет её, «✓» сохраняет карточку; пустые строки не сохраняются.
  Строки хранятся в `discipline.lines` модели в схеме.
- «+» есть и в карточке ▶ («Общие задания и дисциплина»): её строки уходят в запрос каждой модели каждого шага
  перед собственными строками модели; оба списка складываются, не заменяют друг друга. Строки хранятся в `defaults.discipline.lines` схемы.
- Длина и требования к содержанию — отдельные персональные инструкции. По умолчанию при
  пределе 300 слов: `[RESPONSE_LIMIT] Объём ответа: 250-300 слов, не больше.`;
  требования к ясности, повторам и деталям идут следующей строкой отдельно. `{от}` — предел
  минус 50 (не меньше 1), `{слов}` — предел из шапки. Очистка каждого поля независима и возвращает его к общему значению.
  Прежняя метка `[DISPUT_RESPONSE_LIMIT]` (в запросе или в сохранённых настройках) распознаётся так же,
  как `[RESPONSE_LIMIT]`: лимит в запросе всегда один.
- `{слов}` в инструкции длины подставляет предел из шапки; `{метка}` в инструкции доставки —
  новую метку запроса. Пустое поле наследует инструкцию из ▶ или кода. Инструкция вопроса User не отправляется. Уникальную метку доставки всегда создаёт транспорт.
- Метку доставки добавляет прежний транспорт. Карточка не объявляет отсутствие метки
  самостоятельным основанием отказа. Инструкция `[[ASK]]` автоматически не добавляется.
- «Сохранить» применяет настройки. У сохранённого пользовательского pipeline они записываются
  в `schema` записи pipeline; у встроенного шаблона остаются на странице и попадают в новую
  копию через Save. Во время исполнения редактор доступен только для чтения.
- Настройки безымянного pipeline сохраняют свою привязку при Run: отображение задачи
  в заголовке не меняет выбранный запрос и личную длину ответа.
- Копирование доступно у текстовых полей карточки: копируется текущее содержимое целиком,
  без изменений и без сохранения правок. У числовой длины иконки копирования нет.
- Поле длины сразу содержит действующее число (персональное или общее), которое можно
  править по цифрам. Сохранение неизменённого общего числа не создаёт персональный предел.
- Записи реальных попыток продолжают сохраняться отдельно; редактирование их не меняет.
  Старая подробная карточка истории заменена редактором, экспорт диагностики — кнопка Basic на вкладке Disput.

## ▶ — общие значения Basic

Клик по ▶ в колонке In открывает общее окно настроек. Вверху окна — блок Description: презентация pipeline из поля `description` схемы (свёрнут до двух строк, ⤢ раскрывает на весь экран; нет поля — «Описание не задано»). Тот же текст (до 400 знаков) — подсказка при наведении на ▶. В нём задание раундов со входом
(R2+), четыре инструкции дисциплины (длина как шаблон, требования к
содержанию, доставка, исправление), свои строки «+» и особенности моделей. Задача и числовая
длина здесь не дублируются; порядок работы, вход и задание отдельного раунда задаются в окне раунда.
Строгая проверка длины (`run.strictLength`) окном не редактируется: она задаётся в схеме и сохраняется при Save и запуске.

Каждое поле разрешается одной функцией `BasicSchema.resolveFields` (на странице — через
`resolveCustomFields`): **модель → раунд → ▶ → Basic**. Этот же путь используется
для шагов исполнения, предпросмотра и окна настроек модели. R1 не получает задания R2+.
Общие значения не записываются в настройки моделей.

Отсутствующее поле означает наследование; **пустой текст, оставленный User, — это значение «ничего не отправлять»**.
У заданий (задание раунда, в ▶ и в карточке модели), инструкции длины и требований к содержанию «×» оставляет поле
пустым и не наследует: в схему пишется пустая строка (`task: ""`, `discipline.limit: ""`), и запрос уходит без этого текста. То же
происходит, если User стёр текст в поле и нажал «✓». Вернуть наследование — только «↶» («Вернуть к общему» / «Вернуть к коду»):
ключ из схемы убирается. Метка доставки и инструкция повторного запроса пустыми не бывают (они нужны транспорту): пустое поле там
по-прежнему означает наследование. Подписи источника под полями не показываются. Набранное User значение (задание, дисциплина, длина) сохраняется явным, даже если оно равно унаследованному; вернуть наследование — «↶». Введённая инструкция длины, совпавшая с показанной (с подставленными числами), записывается шаблоном и продолжает следовать пределу. Запрос, совпавший с автоматически собранным, остаётся унаследованным; длина, которой User не касался, сохраняется как была. Изменение ▶ сразу учитывается во всех следующих
запросах без своего значения; начатый прогон использует снимок настроек и обе карточки
в нём доступны только для чтения. Копирование остаётся доступным.

Персональный `promptTemplate` — полная замена запроса. В карточке явно написано:
«Персональный запрос: общее задание не применяется; дисциплина применяется».
Дисциплина, включая повторы, продолжает наследоваться независимо. Сравнение с
автоматическим запросом использует предпросмотр уже с учётом ▶ и задания модели.

Общие значения хранятся в схеме pipeline, в `schema.defaults`:
`{ roundTask?, discipline?: { limit?, content?, delivery?, correction?, lines? }, modelNotes?, roundPrompts? }`
(`synthesisTask` записи до 2.81.849 читается и при сохранении отбрасывается)
(поля — в [basic-schema-guide.md](basic-schema-guide.md)).
В модели задание хранится как `task` её шага (`schema.steps[].models[]`), дисциплина — в её `discipline`.
Сохранённый pipeline сохраняет ▶ и переносит её через Export/Import схемы. Запись, сохранённая до схем, читается как раньше и переходит на схему при первом сохранении карточки или ▶. Изменения встроенного
шаблона живут только на странице, не перезаписывают шаблон и после перезагрузки возвращаются
к коду; Save в новую копию сохраняет их отдельно. «+» начинает с пустой ▶.

Export схемы (`#pipeline-export-btn`) по умолчанию сохраняет файл в `Загрузки/Схемы`; Import открывает окно выбора файла, которое помнит последнюю папку и после первого выбора открывается в `Загрузки/Схемы`.

## Custom в списке ролей

На pipeline, который работает на движке Basic, список ролей (мини-запросов) раунда заканчивается пунктом
**Custom**: в блоке модели и в «Роль для всех моделей раунда». Пункт не появляется на других pipelines.

- Выбор **Custom** открывает в карточке раунда поле текста. Это единственное место ввода: в блоке модели
  Custom означает «использовать текст раунда». Поле видно только при выбранном Custom.
- Хранение: `defaults.roundPrompts` схемы, ключ — ref раунда (`r2`…), один текст на раунд; сохранение, копирование и Export/Import схемы —
  как у остальных полей ▶. Встроенный шаблон теряет текст после перезагрузки, как и прочие его правки.
  Запись в сохранённый pipeline происходит сразу, как у Save в ▶.
- Применение: модель с ролью Custom получает текст своего раунда как «Дополнительно для тебя». Пустой текст —
  ничего не добавляется. Модель с другой ролью получает свою.
- Персональный запрос заменяет сборку целиком, поэтому роль в блоке при нём не применяется. В карточке модели
  появляется строка: «Роль не применяется: используется персональный запрос». Сборка от этого не меняется.

## Синтез на холсте

Отдельной колонки синтеза, бейджа «Final» и кнопок вставки синтеза между раундами нет (с 2.81.849). Синтез — обычный
раунд из одной модели с ролью `interaction_meta_synthesis`: добавьте раунд, оставьте в нём одну включённую модель и выберите ей роль
(в блоке модели или «Роль для всех моделей раунда»); своё задание синтеза — «Задание раунда». Итоговый синтез — последний
такой раунд: результат прогона — принятые ответы последнего шага. Новый пустой pipeline и шаблон Default синтеза не содержат.

## Особенности моделей

В карточке ▶ блок «Особенности моделей»: по одному полю на каждую модель, которая стоит на холсте
(по имени, без дублей). Пустое поле ничего не добавляет.
Пример: GPT — «Без вступлений и пересказа вопроса, не раздувай ответ».

- Хранение: `defaults.modelNotes` схемы, ключ — имя модели; сохранение, копирование, Export/Import схемы — как у
  остальных полей ▶. Встроенный шаблон после перезагрузки их теряет, как и прочие его правки.
  Заметки моделей, снятых с холста, при Save остаются в схеме (`defaults.modelNotes`).
- Применение: текст уходит с каждым запросом этой модели во всех раундах. Он добавляется
  отдельно **после** запроса и ответов User, **перед** лимитом; при персональном запросе тоже.
  Повторный запрос (исправление) особенность не получает.
- В карточке модели — строка только для чтения «Особенность модели (из ▶)», если заметка есть.

Порядок текста в запросе модели:

```
запрос (с ролью из блока, если выбрана)
ответы User
особенность модели (из ▶)
лимит
требования к содержанию
метка доставки
```

## Проверок и развилок нет

Карточек проверки (`gate`) и маршрута (`route`) на холсте нет: шаги идут строго по порядку. Проверку делают обычным раундом (критерии — в задании раунда), решение — шагом User. Поле «Шаг после этого этапа» в окне раунда или карточки User добавляет только шаг User (подряд можно ставить несколько). Удалить шаг User — кнопка «×» в его карточке; шаг, который стоял после удалённого, встаёт после предыдущего.

## Карточка User (owner)

User — карточка на холсте (зелёная рамка), добавляется полем «Шаг после этого этапа»; карточка и её окно называются «User». Окно: «Назначение этапа» (`goal`, одна подсказка: для чего этот этап и что человек должен сделать — видит User в окне вопроса), «Что должен предоставить User» (`task`, обязательно) и «Выход этапа» (имя, форма, разделы, строгая длина), как в окнах раунда. Формат json: разделы не редактируются. Вход User (`input`) окно карточки не показывает и не меняет; он задаётся в схеме. Когда прогон доходит до шага, окно ответа User («Ответ User: …») показывает назначение (если задано), задание, переданные User ответы входа (подпись и текст; длинный текст урезан для показа, размер указан) и ожидаемый выход, затем поле ввода. Пустое задание в схему не пишется, и Save покажет ошибку с путём.

**Документ для User** (`document`) выбирается в окне шага User из списка: «нет» (поле текста) и раунды выше с одной моделью. Подпись раунда — «r1 · Claude»; если у выхода раунда не задан `output.document`, добавляется «(вид документа не объявлен)». Если схема ссылается на раунд, которого нет, значение показывается как «(недоступен)». Вид документа в окне раунда не выбирается: его пишет автор схемы в `output.document` выхода раунда.

**Окно ответа User с документом.** Документ для чтения: окно правки — заголовок «<имя>» (имя документа), текст документа в поле, который User может править; «Отправить» активна, пока текст не пуст. Ответ — утверждённый текст: изменённый текст становится новой версией (автор User), неизменённый утверждает текущую версию. Утверждённый текст идёт дальше по схеме. Опросник: переключатели для «один вариант», флажки для «несколько», «Да/Нет» для `yesno`, поле для `text`; обязательные пункты помечены «*»; «Отправить» активна, когда заполнены все обязательные. Шаг User без `document` — поле «Ответ User», «Отправить» активна, когда поле не пусто.

**Строка «Папка документов».** В окне ответа User с документом (шаг User с `document`) есть строка «Папка документов»: кнопка выбирает папку через File System Access (`showDirectoryPicker`), рядом показано имя папки или «не выбрана». Одна папка на все pipelines; дескриптор хранится в IndexedDB расширения и в схему не входит. При OK/Send утверждённый текст записывается в `<папка>/<pipeline>/<дата-время начала прогона YYYY-MM-DD_HH-mm-ss>/<имя документа>.md`; для опросника (`form`) — `.json` с ответом. Имя очищается: символы `\ / : * ? " < > |` и управляющие заменяются на `_`, пробелы и точки по краям убираются, длина до 80; пустое имя — «document». Повторное OK/Send перезаписывает тот же файл. Папка не выбрана — ничего не происходит. Нет доступа или ошибка записи — прогон не останавливается, одно уведомление за прогон: «Документ «…» не записан в папку: …. Прогон продолжается.» Доступ после перезапуска Chrome запрашивается на ▶ и на «Продолжить прогон», если папка выбрана; при отказе одно уведомление «Папка документов недоступна…», файлы не пишутся. Файл — копия для человека; главное хранилище — запись прогона.

**Рамка документа на холсте.** Рамка стоит в колонке раунда-источника, под моделями. До появления документа она неактивна (пунктир, подпись — имя артефакта); когда документ есть — «<имя>», после утверждения — «<имя> · утверждено» (зелёная рамка). Клик по активной рамке открывает окно «Документ: <имя>» только для чтения с кнопкой «Закрыть». Рамки строятся из записи прогона (реестр артефактов и утверждённая версия шага User), обновляются при каждом сохранении состояния и в конце прогона. После перезагрузки страницы они восстанавливаются из последней записи прогона этого pipeline; если текста в записи нет, User видит уведомление «Текст документа «…» не найден в записи прогона».

**Удаление раунда.** На холсте удаляется только последний раунд; номера остальных не меняются. Если удалён раунд, на который ссылается `document` шага User, поле сбрасывается, и страница пишет: «Документ шага User «<ref>»: раунд <rN> удалён, источник сброшен. Выберите документ заново.»

## Окна решений Basic

Общий компонент `results/choice-dialog.js` (`ChoiceDialog.ask`): окно с кнопками по выбору и, при необходимости, полем текста.
Отмена или Escape дают `null`. Окна открываются во время прогона: ответ User (текст), неизвестный запрос.
Что показывает каждое окно и что делает отмена — в `basic-start-here.md`, раздел «Окна решений».

## Окно «Вставить схему»

Открывается кнопкой «Вставить схему» (`#pipeline-profile-btn`, `openSchemaPasteWindow`, `results.js`). Принимает только формат Basic.

- Поле `#schema-paste-text`: вставляется ответ модели целиком. Текст читает `SchemaTextReader.read` (`disput/schema-text-reader.js`).
- Сворачиваемый блок «Комментарий модели» (`#schema-paste-comment`): текст вне JSON.
- Список проблем (`#schema-paste-problems`): путь и сообщение на каждую ошибку. Окно остаётся открытым, текст сохраняется.
- Оборванный ответ не применяется: сообщается, до какого шага (`ref`) JSON цел.
- Кнопки «Применить» и «Отмена» (Escape тоже). Объект с полем `basicCatalog` импортируется как каталог. Схема, которая прошла проверку, спрашивает имя pipeline, как при Import из файла; при отмене имени окно возвращается с тем же текстом. После установки окно закрывается.

## Лента прогона

Страница показывает то, что отдаёт движок (`CustomEngine.run`, `onEvent`). Новых полей в схеме нет.

- Подпись карточки ответа: `Basic · <этап>`, затем `участник <id>`, если id участника не совпадает с именем модели, затем `заход N` со второго захода. Строит её `StageCard.feed.role` (`results/stage-card.js`).
- Второй заход шага — отдельная карточка: в feed она получает `pipelineRoundId` вида `s<n>v<заход>`. Ответ предыдущего захода остаётся в ленте.
- Строки (`basic-run-line`, не карточки ответа, без одобрения): реестр артефактов (ниже) и предложение продолжить прогон (см. `basic-start-here.md`, «Продолжить прогон»). Строк проверки, маршрута и перехода нет.
- Устаревшая версия: в конце прогона карточка шага с `valid: false` получает метку «устарело». Ответ не удаляется и не становится входом (это решает движок).
- Реестр артефактов: если в прогоне есть артефакты, в конце ленты строка «Артефакты прогона: N» с кнопкой «Открыть». Окно `ChoiceDialog` (`results/choice-dialog.js`) показывает список (название · участник или User · заход · «устарело») и по выбору текст артефакта: весь ответ (`getText`, `CustomRunRecord.textOf`) или значение по указателю (`BasicOutput.readPointer`).
- Строки не сохраняются в записи сессии (`DebateRunStore`): после перезагрузки страницы их нет. Метка «устарело» ставится в конце прогона, в живой ленте её нет.
- Окна настроек реестра ещё не сделаны.

## Подсказки на холсте

Наведите курсор на элемент холста: появится подсказка. Название показано жирным, описание — строкой ниже.

- **In** — «In».
- **▶** — «▶ Общие значения» и описание схемы.
- **Бейдж раунда** (R1, R2…) — «R<n> · <название шага>» (или «R<n>») и цель шага.
- **Блок модели** — имя модели и её задание.
- **Карточка User** и её заголовок — «User · <ref> · <название>» и цель шага либо задание.
- **Рамка документа** — имя документа и его описание.
- **Пункт списка pipelines** — имя схемы.
- **Флажок блока модели** — «Участие в раунде» и пояснение: включённая модель входит в раунд, снятая — нет. Send у модели нет.

## Кнопка «Стрелки»

- В панели pipelines, перед «Export schema», есть кнопка «Стрелки»: она скрывает и показывает стрелки холста между колонками.
- Скрытие и показ плавные. Когда стрелки скрыты, кнопка приглушена.
- Состояние хранится в браузере и восстанавливается при открытии страницы. На схему, Save и прогон оно не влияет.

## Ошибки схемы

- При установке схемы (Import), если она не прошла проверку, кроме уведомления открывается окно «Схема не установлена» со всеми ошибками, по строке «путь: сообщение». Для файла прежнего формата, где установлена не вся часть схем, открывается «Не все схемы установлены» со строками «имя: путь: сообщение».
- Сохранённая схема, которая не проходит проверку при открытии, помечается на холсте красным значком «!» на шаге, к которому относится ошибка: в метке раунда или в карточке User. Значок есть только у ошибок с путём к шагу; ошибки без пути (например, схема новее Basic) видны в уведомлении.
- Подсказка значка — «Ошибки шага <ref>» и сообщения ошибок этого шага. Клик по значку открывает окно «Ошибки схемы» со всем списком.
- Отдельного различия «ошибка / замечание» нет: в Basic не блокирующих замечаний нет.
