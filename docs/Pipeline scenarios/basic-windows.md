# Basic: окна настроек

Для того, кто ищет, где на странице задаётся то или иное поле Basic и что оно делает. Окна: настроек раунда (клик по значку R1, R2…), модели (двойной клик по блоку), ▶ (общие значения), промежуточного и финального синтеза. Прогон и карточки ответа — в `basic-start-here.md`; формат схемы — в `basic-schema-guide.md`. Значения из окон хранятся в схеме pipeline.

## Карточка раунда

| Настройка | Значение |
| --- | --- |
| Модели | Список с галочкой «участвует»; порядок на карточке — порядок вызова |
| Дополнение модели | Необязательный мини-промпт у каждой модели (по умолчанию None); получает только эта модель. В Basic (R1 и R2+) его можно выбрать сразу для всех моделей раунда кнопкой «Роль для всех моделей раунда» в карточке раунда; выбор в блоке модели перекрывает общий. Смена при различающихся ролях спрашивает подтверждение. Блоки R1 имеют тот же список ролей, что и R2+. Пункт **Custom** в списке ролей — см. ниже |
| Порядок работы | **Параллельно** — все получают одинаковый вход. **По очереди** — каждая модель получает выбранный вход и ответы моделей, ответивших до неё в этом раунде |
| Задание раунда | Общий текст для всех моделей раунда |
| Вход | Задача передаётся всегда. Дополнительно: **ничего**; **ответы предыдущего шага**; **всё принятое** за все предыдущие шаги; **выбранные этапы** (список ранних шагов) |

**Окно раунда.** Клик по значку раунда (R1, R2…) открывает карточку раунда Basic: «Роль для всех моделей раунда»
(и текст «Custom»), **Порядок работы**, **Вход раунда** и **Задание раунда**. У первого раунда нет входа (ему нечего
подавать), но задание есть. Поля: порядок — «по умолчанию (параллельно)», «параллельно», «по очереди»; вход — «по умолчанию (ответы предыдущего
шага)», «ничего», «ответы предыдущего шага», «всё принятое»; задание показывается при любом входе. При входе «ничего» отправляется
только задание, написанное в этом окне (общее задание из ▶ не отправляется); метка поля это говорит. При других входах пусто — общее задание
(▶, затем Basic, подсказка в поле показывает его). Выбранное и набранное — значение владельца, «по умолчанию» и пустое
задание возвращают наследование. Личное задание модели главнее задания раунда. Поля хранятся в схеме как `order`, `input`,
`task` шага и закрыты во время прогона. Поля порога, владельца и выхода — в разделе «Поля шага» ниже.

**Поля шага** (окно раунда и окно синтеза: промежуточного и финального). Вход «выбранные этапы» — список ранних шагов с галочками; выключенные помечены «(выключен)», номер у галочки — место в списке входа (порядок выбора = порядок массива `input`). Пока ни один этап не отмечен, вход в схему не пишется. Ссылки на участников и артефакты, заданные в JSON, сохраняются и показываются строкой «заданы в JSON». **Сколько ответов нужно**: любой (по умолчанию), все включённые или число от 1 до числа включённых моделей шага (`require`); число не пишется, пока не введено. **Спросить владельца после этапа** — `owner: "approve"`; в карточке раунда есть отметка «владелец: одобрение». **Выход этапа**: имя (`output.name`), форма (`output.form`), разделы по одному на строку (`output.sections`, недоступны при `format: json`) и строгая длина (`output.strictLength`). Поля `format`, `requiredFields`, `artifacts`, `revisionOf` окно не редактирует, но сохраняет. Поля сохраняются сразу, как «Задание раунда»; ошибка схемы при изменении сохранённого pipeline показывается уведомлением с путём. Предпросмотр запроса пока не отличает вход «выбранные этапы» (следующее задание).

Число раундов — число карточек. Настройки всего pipeline: Авто или подтверждение между
раундами, предел длины ответа.

## Карточка модели

Двойной клик по пустому месту блока модели в Basic открывает компактный редактор (кнопки 📝 в блоке больше нет;
клики по чекбоксам, статусу, списку ролей и кнопкам блок не открывают): иконка и название модели, личный
предел длины и кнопка Save в шапке, раунд рядом с моделью. Ширина карточки — 889 px
(+17%); поле запроса увеличено. Подсказка находится справа от «Запрос», инструкции
транспорта идут в две колонки (на узком экране — в одну). Карточка помещается по высоте окна. Окно ▶ — 978 px (на 10% шире) и той же высоты, что карточка модели (`min(760px, 100dvh − 32px)`); тело прокручивается, шапка с Save остаётся видна.

- Автоматический запрос можно изменить или заменить своим. Правка действует только для
  этой модели в этом шаге. «Вернуть автоматическую сборку» снимает замену.
- `{задача}` подставляет актуальную задачу при запуске, `{вход}` — принятые ответы
  предыдущих шагов согласно настройке входа. `{ответы до тебя}` — ответы предыдущих
  участников текущего шага при последовательном исполнении. Подстановка однократная:
  такие строки внутри полученных ответов не интерпретируются повторно.
- Роль модели (мини-запрос из блока) уходит в запрос этой модели как «Дополнительно для тебя».
  Персональный запрос заменяет сборку целиком, поэтому роль в нём не добавляется.
- R1 получает роль так же, как R2+: запрос содержит исходную задачу пользователя и текст роли. Роли R1 по умолчанию None;
  пресеты их не задают. Роль R1 применяется на движке Basic; на остальных движках роли ни в одном раунде
  не применяются к запросу.
- Личная длина — положительное целое число слов; пустое поле наследует общий предел.
  Инструкция длины добавляется перед передачей в общий транспорт, в том числе при
  исправлении ответа. Это инструкция модели, а не обрезка ответа до числа слов.
- В блоке «Метки транспорта» показаны полные тексты инструкций доставки,
  длины и требований к содержанию. Инструкция исправления ответа
  показана отдельным редактируемым полем для повторов. Поля редактируются сразу. У каждой строки есть иконка копирования, красный крестик
  очистки и галочка сохранения. Правки хранятся в схеме pipeline (`steps[].models[].discipline`)
  и действуют только для этой модели в этом шаге, включая повторные попытки.
- Кнопка «+» под строками блока «Метки транспорта» добавляет свою строку («Строка N»): текст
  уходит в запрос этой модели после требований к содержанию, каждая строка отдельным абзацем.
  «×» у своей строки удаляет её, «✓» сохраняет карточку; пустые строки не сохраняются.
  Строки хранятся в `discipline.lines` модели в схеме.
- «+» есть и в карточке ▶ («Общие задания и дисциплина»): её строки уходят в запрос каждой модели каждого шага
  перед собственными строками модели; оба списка складываются, не заменяют друг друга. Строки хранятся в `defaults.discipline.lines` схемы.
- Длина и требования к содержанию — отдельные персональные инструкции. По умолчанию при
  пределе 300 слов: `[RESPONSE_LIMIT] Объём ответа: 250-300 слов, не больше.`;
  требования к ясности, повторам и деталям идут следующей строкой отдельно. `{от}` — предел
  минус 50 (не меньше 1), `{слов}` — предел из шапки. Очистка каждого поля независима и возвращает его к общему значению.
  Прежняя метка `[DISPUT_RESPONSE_LIMIT]` (в запросе или в сохранённых настройках) распознаётся так же,
  как `[RESPONSE_LIMIT]`: лимит в запросе всегда один.
- `{слов}` в инструкции длины подставляет предел из шапки; `{метка}` в инструкции доставки —
  новую метку запроса. Пустое поле наследует инструкцию из ▶ или кода. Инструкция вопроса владельцу не отправляется. Уникальную метку доставки всегда создаёт транспорт.
- Метку доставки добавляет прежний транспорт. Карточка не объявляет отсутствие метки
  самостоятельным основанием отказа. Инструкция `[[ASK]]` автоматически не добавляется.
- «Сохранить» применяет настройки. У сохранённого пользовательского pipeline они записываются
  в `schema` записи pipeline; у встроенного шаблона остаются на странице и попадают в новую
  копию через Save. Во время исполнения редактор доступен только для чтения.
- Настройки безымянного pipeline сохраняют свою привязку при Run: отображение задачи
  в заголовке не меняет выбранный запрос и личную длину ответа.
- Копирование доступно у текстовых полей карточки: копируется текущее содержимое целиком,
  без изменений и без сохранения правок. У числовой длины иконки копирования нет.
- Поле длины сразу содержит действующее число (персональное или общее), которое можно
  править по цифрам. Сохранение неизменённого общего числа не создаёт персональный предел.
- Записи реальных попыток продолжают сохраняться отдельно; редактирование их не меняет.
  Старая подробная карточка истории заменена редактором, экспорт диагностики — Disput Flow.

## ▶ — общие значения Basic

Клик по ▶ в колонке In открывает общее окно настроек. В нём задание раундов со входом
(R2+), задание синтеза, четыре инструкции дисциплины (длина как шаблон, требования к
содержанию, доставка, исправление), свои строки «+» и особенности моделей. Задача и числовая
длина здесь не дублируются; порядок работы, вход и задание отдельного раунда задаются в окне раунда.

Каждое поле разрешается одной функцией `BasicSchema.resolveFields` (на странице — через
`resolveCustomFields`): **модель → раунд → ▶ → Basic**. Этот же путь используется
для шагов исполнения, предпросмотра и окна настроек модели. R1 не получает задания R2+;
синтез получает своё задание. Общие значения не записываются в настройки моделей.

Пустое или отсутствующее поле означает наследование. Это заменяет прежнюю семантику
очистки (отключение инструкции): крестик очищает override, при сохранении применяется
уровень выше. Подписи источника под полями не показываются. Действие «Вернуть к общему»
доступно у своего поля. Набранное владельцем значение (задание, дисциплина, длина) сохраняется явным, даже если оно равно унаследованному; вернуть наследование — «↶» и «×» (для длины — очистить поле). Введённая инструкция длины, совпавшая с показанной (с подставленными числами), записывается шаблоном и продолжает следовать пределу. Запрос, совпавший с автоматически собранным, остаётся унаследованным; длина, которой владелец не касался, сохраняется как была. Изменение ▶ сразу учитывается во всех следующих
запросах без своего значения; начатый прогон использует снимок настроек и обе карточки
в нём доступны только для чтения. Копирование остаётся доступным.

Персональный `promptTemplate` — полная замена запроса. В карточке явно написано:
«Персональный запрос: общее задание не применяется; дисциплина применяется».
Дисциплина, включая повторы, продолжает наследоваться независимо. Сравнение с
автоматическим запросом использует предпросмотр уже с учётом ▶ и задания модели.

Общие значения хранятся в схеме pipeline, в `schema.defaults`:
`{ roundTask?, synthesisTask?, discipline?: { limit?, content?, delivery?, correction?, lines? }, modelNotes?, roundPrompts? }`
(поля — в [basic-schema-guide.md](basic-schema-guide.md)).
В модели задание хранится как `task` её шага (`schema.steps[].models[]`), дисциплина — в её `discipline`.
Сохранённый pipeline сохраняет ▶ и переносит её через Export/Import схемы. Запись, сохранённая до схем, читается как раньше и переходит на схему при первом сохранении карточки или ▶. Изменения встроенного
шаблона живут только на странице, не перезаписывают шаблон и после перезагрузки возвращаются
к коду; Save в новую копию сохраняет их отдельно. «+» начинает с пустой ▶.

## Custom в списке ролей

На pipeline, который работает на движке Basic, список ролей (мини-запросов) раунда заканчивается пунктом
**Custom**: в блоке модели и в «Роль для всех моделей раунда». Пункт не появляется на других pipelines.

- Выбор **Custom** открывает в карточке раунда поле текста. Это единственное место ввода: в блоке модели
  Custom означает «использовать текст раунда». Поле видно только при выбранном Custom.
- Хранение: `defaults.roundPrompts` схемы, ключ — ref раунда (`r2`…), один текст на раунд; сохранение, копирование и Export/Import схемы —
  как у остальных полей ▶. Встроенный шаблон теряет текст после перезагрузки, как и прочие его правки.
  Запись в сохранённый pipeline происходит сразу, как у Save в ▶.
- Применение: модель с ролью Custom получает текст своего раунда как «Дополнительно для тебя». Пустой текст —
  ничего не добавляется. Модель с другой ролью получает свою.
- Персональный запрос заменяет сборку целиком, поэтому роль в блоке при нём не применяется. В карточке модели
  появляется строка: «Роль не применяется: используется персональный запрос». Сборка от этого не меняется.

## Карточка промежуточного синтеза

В окне синтеза (промежуточного и финального) сверху — поля шага: вход «по умолчанию» (предыдущий шаг) или «выбранные этапы», порог, владелец, выход (см. «Поля шага» в карточке раунда). Промежуточный синтез показывает блок в том же виде, что финальный синтез: подпись «Synthesis» и список выбора модели
(по умолчанию — модель этапа); сама модель видна только в списке. Заголовка колонки нет; кнопка вставки переносится
в заголовок колонки синтеза, на её центральную линию, и возвращается к раунду при удалении этапа. Заголовок остаётся
на одной линии с бейджами раундов; центрируется по стекам раундов только стек блоков.
Выбор модели меняет модель этого этапа; список неактивен во время прогона и пока прогон на паузе.
Двойной клик по блоку открывает ту же карточку, что и двойной клик по вставке.
Вставка между раундами открывает карточку и переключает синтез. Одиночный клик
по вставке добавляет или убирает синтез (через 250 мс, чтобы двойной клик отменил это действие); кнопка
серая без синтеза и синяя с ним. Двойной клик открывает его Basic-карточку (персональный запрос, длина,
дисциплина) под ref `synth:planned-working-synthesis-after-<afterStageId>` и **не** добавляет и не убирает
этап: состояние кнопки не меняется. Если этапа ещё нет, карточка строится по виртуальной копии плана, которая
не сохраняется; сохранённый персональный текст применяется, когда одиночный клик добавит этап. Промежуточный синтез
не зависит от финального: вставка доступна и при выключенном финальном синтезе. Модель этапа — финальный синтезатор,
если он выбран, иначе модель по умолчанию Claude (или первая доступная модель, если Claude нет в списке).
Пока персонального запроса нет, карточка показывает и использует текст финального синтезатора; сохранённый
персональный текст заменяет его.
Роль и пункт Custom синтезу не нужны. Во время прогона вставка неактивна, карточку открыть нельзя.

## Финальный синтез: бейдж Final

Бейдж «Final» в последней колонке работает как вставка промежуточного синтеза. Одиночный клик (через 250 мс)
включает или выключает финальный синтез. Выключено: бейдж серый, блок финального синтеза остаётся на месте в неактивном виде (затемнён, список выбора
неактивен), синтез не запускается (синтезатор пустой). Связь от последнего раунда к блоку рисуется неактивной линией
к его центру. Включено: бейдж синий, синтезатор — последний выбранный (запоминается при выключении),
иначе Claude, если он выбран, иначе первая выбранная модель; без выбранных моделей показывается предупреждение.
Новый пустой pipeline стартует с включённым финальным синтезом на Claude. Выключенный синтез на несохранённом pipeline сохраняется и после перезагрузки. Блоки R1 получили список ролей. Сохранённый pipeline берёт
своё решение из сохранения, в том числе выключенный синтез; значение по умолчанию действует, только если решения
нет вовсе. Двойной клик открывает
Basic-карточку финального синтезатора и не переключает состояние; без синтезатора он показывает
предупреждение «Включите финальный синтез кликом по Final.». Во время прогона клик по бейджу ничего не делает.
Пункта «None» в списке синтезатора больше нет: выключение выражается бейджем. Блок финального синтеза подписан
«Synthesis»; модель видна только в списке выбора. Карточка открывается двойным кликом по его телу. Блок выглядит активным (зелёным) только при выбранном синтезаторе и выбранных моделях; блоки раундов синтезатором не помечаются и выглядят как обычные.

## Особенности моделей

В карточке ▶ блок «Особенности моделей»: по одному полю на каждую модель, которая стоит на холсте
(по имени, без дублей; синтезатор — только если выбран). Пустое поле ничего не добавляет.
Пример: GPT — «Без вступлений и пересказа вопроса, не раздувай ответ».

- Хранение: `defaults.modelNotes` схемы, ключ — имя модели; сохранение, копирование, Export/Import схемы — как у
  остальных полей ▶. Встроенный шаблон после перезагрузки их теряет, как и прочие его правки.
  Заметки моделей, снятых с холста, при Save остаются в схеме (`defaults.modelNotes`).
- Применение: текст уходит с каждым запросом этой модели во всех раундах и синтезах. Он добавляется
  отдельно **после** запроса и ответов владельца, **перед** лимитом; при персональном запросе тоже.
  Повторный запрос (исправление) особенность не получает.
- В карточке модели — строка только для чтения «Особенность модели (из ▶)», если заметка есть.

Порядок текста в запросе модели:

```
запрос (с ролью из блока, если выбрана)
ответы владельца
особенность модели (из ▶)
лимит
требования к содержанию
метка доставки
```

## Карточка проверки (gate)

Проверка — карточка на холсте после раунда или другого шага (кнопка «+ шаг» в заголовке раунда или карточки; подряд можно ставить несколько). Клик по карточке открывает окно. Между раундом и его промежуточным синтезом проверку не ставят: синтез стоит сразу после раунда, и при вставке синтеза либо проверке показывается пояснение.

| Настройка | Значение |
| --- | --- |
| Критерии | Список строк, по одной на строку. Пустые строки отбрасываются; пустой список в схему не пишется, и Save покажет ошибку с путём |
| Проверяющие | Модели из общего списка моделей. Снятая галочка оставляет модель в схеме с `enabled: false` |
| Проходит, если | «По умолчанию» (не пишется; все проверяющие), «Все проверяющие прошли» (`all`), «Достаточно одного» (`any`) |
| При провале | «Остановить прогон» (`stop`, по умолчанию не пишется), «Спросить владельца» (`ask`), «Перейти к шагу» (`goto`) |
| После успеха | «Следующий шаг» (по умолчанию, поле не пишется) или «Перейти к шагу» (`goto`) |
| Переход | Шаг (список шагов схемы) и лимит переходов 1–5 (`maxLoops`). Поля `feedback`, `invalidate`, `resumeAt` окно не редактирует и сохраняет |

Значения, которых окно не умеет показать (например переход другой формы), видны как «задан в JSON, сохраняется как есть» и не меняются при правке других полей. Удалить шаг — кнопка «×» в его карточке; шаг, который стоял после удалённого, встаёт после предыдущего.

## Окна решений Basic

Общий компонент `results/choice-dialog.js` (`ChoiceDialog.ask`): окно с кнопками по выбору и, при необходимости, полем текста.
Отмена или Escape дают `null`. Окна открываются во время прогона: выбор маршрута, ответ владельца (текст), неизвестный запрос.
Что показывает каждое окно и что делает отмена — в `basic-start-here.md`, раздел «Окна решений».

## Лента прогона

Страница показывает то, что отдаёт движок (`CustomEngine.run`, `onEvent`). Новых полей в схеме нет.

- Подпись карточки ответа: `Basic · <этап>`, затем `участник <id>`, если id участника не совпадает с именем модели, затем `заход N` со второго захода. Строит её `StageCard.feed.role` (`results/stage-card.js`).
- Второй заход шага — отдельная карточка: в feed она получает `pipelineRoundId` вида `s<n>v<заход>`. Ответ предыдущего захода остаётся в ленте.
- Строки (`basic-run-line`, не карточки ответа, без одобрения): `custom_gate` — «Проверка <ref>: пройдена / не пройдена» и невыполненные критерии; `custom_route` — «Маршрут <ref>: вариант «…», причина»; `custom_transition` — «Переход A → B, переход N из M», «Возврат …» или остановка с причиной. Тексты строит `StageCard.feed` (`gate`, `route`, `transition`).
- Устаревшая версия: в конце прогона карточка шага с `valid: false` получает метку «устарело». Ответ не удаляется и не становится входом (это решает движок).
- Реестр артефактов: если в прогоне есть артефакты, в конце ленты строка «Артефакты прогона: N» с кнопкой «Открыть». Окно `ChoiceDialog` (`results/choice-dialog.js`) показывает список (название · участник или владелец · заход · «устарело») и по выбору текст артефакта: весь ответ (`getText`, `CustomRunRecord.textOf`) или значение по указателю (`BasicOutput.readPointer`).
- Строки не сохраняются в записи сессии (`DebateRunStore`): после перезагрузки страницы их нет. Метка «устарело» ставится в конце прогона, в живой ленте её нет.
- Окна настроек для проверки, маршрута и реестра ещё не сделаны (следующее задание).
