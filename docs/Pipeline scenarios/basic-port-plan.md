# Basic: план переноса и доработок

Составлен 25.10.2026 на версии расширения 2.81.857. Стенд схем заморожен (v63, его правит отдельная сессия User); новые возможности стенда не разрабатываются, из стенда в Basic переносится только то, что User одобрил. Параллельно с этим идут реальные прогоны Basic на загруженном расширении.

## 1. Как работаем

- **Состав.** Две полосы. У каждой руководитель Sonnet в отдельной сессии (ставит задания, проверяет, ведёт документы и версии) и исполнители Haiku, не больше трёх одновременно. Порядок работ и приёмка — [инструкция исправления](../agent-team-fix.md). Третья Sonnet-сессия — менеджер: реальные прогоны с User, сведение полос, слияние в основной чекаут.
- **Почему две полосы, а не больше.** Пакеты полосы 1 правят один и тот же файл `results.js` (около 9000 строк, блок холста), поэтому идут по очереди, а не параллельно. Полоса 2 работает в другой части `results.js` (Save, Import, Export) и в других файлах, поэтому не мешает полосе 1. Третья полоса дала бы конфликты слияния и расход квоты без выигрыша по времени.
- **Основной чекаут защищён.** На нём идут реальные прогоны, а изменённые файлы расширения подхватываются при обновлении страницы. Полосы не вливают ничего в основной чекаут без сигнала менеджера: пакет коммитится в ветку полосы, в отчёте — ветка, коммит, версия. Слияние делает менеджер между прогонами и сообщает User, когда нужна перезагрузка расширения.
- **Версии.** Каждый пакет кода поднимает версию расширения в ветке полосы на единицу от её базы. При слиянии менеджер ставит единую следующую версию после основного чекаута. Документы Basic обновляются в коммите пакета.
- **Принцип.** Новый элемент вводится, только если назван существующий механизм Basic, которого недостаточно. Перед каждым пакетом — осмотр: что уже есть (с `файл:строка`).
- **Отчёт пакета** — 5–6 строк: версия, что сделано, тесты, живая проверка (что не проверено), вопросы.

## 3. Общий хвост

- **После всех пакетов.** Обновление `docs/agent-onboarding.md` (статус, что дальше) и карты документации — один Haiku по фактам руководителя.
- **Backlog реальных прогонов.** Сюда менеджер заносит находки прогонов (поведение моделей по меткам `[[DOC]]` и формату опросника, `chat: new`, закрытая вкладка участника, продолжение прогона и др.). Каждая находка — отдельный пакет по порядку серьёзности, в той полосе, которая правит нужный файл.
- **Открытые вопросы User.** Текст ответа документа для чтения при пустом комментарии («Документ прочитан, замечаний нет.»); вид документа (`read`/`form`) кнопкой в карточке раунда; нужны ли версии и рамка для опросника.

## 4. Не переносится

Автоисправление JSON ответов моделей, обязательное поле `why`, каталог шаблонов в файле стенда (`stand-templates.json`), этапы `foreach`, `list`, `score`, `assemble`, `gate`, `route`: стенд и Basic их не поддерживают. Раздел «Назначение этапа» в окне User и полноэкранное описание схемы в Basic уже есть.

## 5. Известные дефекты стенда (стенд заморожен, не исправляются)

- Import файла Basic на стенде не вызывает `BasicSchema.validate`: шаблон может попасть в каталог и потом не применяться (`stand.js` ~1335–1352).
- Комментарий в `stand.js` ~1011 («Новый pipeline — только на исходном холсте») расходится с кодом: кнопка сбрасывает стенд.

## 6. Перед архивированием стенда

Стенд временный. Здесь перечислено то, что живёт только на нём и исчезнет вместе с ним, если не перенести.

1. Правила для моделей, пишущих схему (запрос `canvas-prototype/model-prompt.md`: личное задание заменяет общее; после User идёт этап, который применяет правки; артефакт объявляется только в этапе из одной модели; повторная передача документа; что приложение добавляет само; пустое/умолчание входа) → перенести в `basic-schema-guide.md`, он и есть запрос для моделей по формату Basic.
2. Четыре предупреждения стенда (ответ User не читается; артефакт в раунде из нескольких моделей; личное и общее `task` вместе; повторная передача документа) → решить позже, переносить ли в Basic как подсказки автору.
3. Примеры схем (`showcase-robot-vacuum v1.json`, `coldstart-robot-vacuum v1.json`, `stand-examples.json`) → готовые шаблоны Basic (`basic-schema-guide.md` §9) после преобразования.
4. Терпимое чтение текста схемы → перенесено в пакете 2.2 (`disput/schema-text-reader.js`).
5. Тесты логики стенда (`tests/stand-*`) уходят вместе со стендом.
