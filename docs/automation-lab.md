# Automation Lab — стадии 1–5 Product→Architecture

Отдельная страница расширения `automation_lab.html`: иконка колбы в верхней панели Pipeline. Она исполняет первые пять стадий фреймворка из бандла `docs/Automation GPT комплект Документов/` (v2.2.4) через обычные веб-интерфейсы моделей. Debate-пайплайн и адаптеры провайдеров страница не меняет.

## Что происходит

| Стадия | Кто | Результат |
|---|---|---|
| 1. Product Idea & Decision Policy | основная модель | DPL (черновик), неизвестные (UNK), допущения (ASM) |
| — одобрение DPL | владелец | «Утвердить» → DPL ACTIVE; «Пересоздать» → стадия 1 заново |
| 2. Independent Concept Expansion | 2–4 модели, каждая в новом чате, без доступа к ответам друг друга | предложения (PRP), риски, вопросы |
| 3. Decision Closure Review | основная модель + Policy Engine | решения (PD); каждое PRP объединено, преобразовано, отклонено или сохранено; вопросы владельцу по решениям A2/A3 |
| — решения владельца | владелец | выбор вариантов → PD закрыты владельцем |
| 4. Product Concept Synthesis | основная модель | концепция продукта (PCON) |
| 5. Adversarial Concept Review | 2–4 модели независимо | находки (FND) против PCON |

После стадии 5 проект получает статус «Стадии 1–5 завершены». Концепцию и находки можно выгрузить кнопкой «Экспорт .md», полное состояние — кнопкой «Экспорт .json».

## Как запустить

1. Войдите в аккаунты выбранных моделей во вкладках браузера, как для Debate.
2. Откройте Automation Lab и выберите минимум 2 модели (стадии 2 и 5 требуют независимых ответов) и основную модель.
3. Опишите идею и нажмите «Создать и запустить». Вкладки моделей откроются автоматически.
4. Когда появится блок «Решение владельца», выберите варианты. Процесс продолжится сам.

Переключатель «Симулятор» проводит тот же процесс без веб-моделей, со встроенными ответами. Так удобно проверить механику и интерфейс.

## Гарантии

- Ответ модели принимается, только если он содержит рамку `PAF_RESPONSE_BEGIN/END` с токенами этого вызова и ровно один JSON AL-STRUCT-1. Кроме того, он должен повторить хеш входного снимка и пройти проверки ссылок, полномочий и диспозиций.
- Ошибка формата — один ремонт в той же беседе. Смысловая ошибка или таймаут — новая беседа, до 3 раз. Для одиночной стадии затем подключается следующая выбранная модель.
- Каждая фиксация — одна транзакция IndexedDB. Непринятый ответ ничего не меняет. Перезагрузка страницы не теряет состояние и не вызывает повторно модели, чей ответ уже принят. После перезагрузки нажмите «Продолжить».
- Модель не может активировать DPL, закрыть решение класса A2/A3, указать свой ID или изменить входные объекты напрямую.

## Если стадия не прошла

Во вкладке «Вызовы» для каждой попытки есть скомпилированный промпт, сырой ответ, режим извлечения и коды ошибок валидатора. «Повторить стадию» запускает её заново. Состояние проекта при сбое не меняется. Во вкладке «Телеметрия» — показатели по провайдерам: доля ответов, принятых с первого раза, успешность ремонта, сбои извлечения и схемы, медиана и p95 длительности.

## Для разработчика

- Спецификация: правки только в split-файлах бандла, затем `npm run spec:sync`. Скрипт пересобирает монолит и SHA-манифест и копирует рантайм-подмножество в `automation-spec/`.
- Тесты: `npm run test:automation` (jest), `npm run test:automation-e2e` (реальный Chromium с распакованным расширением, режим симулятора).
- Статический раннер бандла: `node "docs/Automation GPT комплект Документов/tests/automation-static-contracts.mjs"`.
