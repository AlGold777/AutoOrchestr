# Организация прогонов Basic: роли, протоколы, находки

Финишный документ папки `docs/Run/`. Процедура по шагам — [run-procedure.md](run-procedure.md), режимы моделей — [model-modes.md](model-modes.md), шаблон отчёта — [run-report-template.md](run-report-template.md). Здесь: кто что делает, по каким правилам, что создаётся и как находка доходит до проверенного исправления.

## 1. Цель и принципы

- **Цель прогона — устранить препятствия движка Basic**, а не провести прогон любой ценой. Полезный материал на выходе — вторичен.
- Один Chrome, один прогон одновременно. Новый прогон — только по явному разрешению владельца в чате на конкретную задачу (запрос уходит на сайты моделей). Чтение страниц без отправки прогоном не считается.
- Человек в прогон не вмешивается. Решения по ходу принимает ведущий; владельцу вопросов не задаёт. Отчёт краткий, по-русски: версия, что сломано, что сделано.
- Выбывшая модель не останавливает прогон. Необязательных участников пропускаем («Пропустить участника»), не ждём CAPTCHA и действий человека. Обязательную модель (опорную) сначала смотрим на странице сами (DOM без отправки: `document.hidden`, поле ввода, кнопки, узлы ответа).
- Не создаём сигналов живости своими действиями: не фокусируем, не прокручиваем и не «чиним» вкладки без нужды.
- Утверждаем только то, что видели в данных или на странице, с указанием источника; остальное — «не подтверждено».
- Расширение не перезагружаем и доставок не принимаем, пока идёт прогон. Данные при заблокированном экране недействительны.
- Доставка — это файл в основном чекауте (`ls`) и версия (`grep '"version"' manifest.json`), а не память о коммите.

## 2. Модели и режимы

Единственный источник — [model-modes.md](model-modes.md). Режимы владельца: **GPT — High; DeepSeek — DeepThink включён, поиск выключен; Qwen — 3.8, мышление; Perplexity — модель Kimi 3 «Рассуждение»**.

- **Gemini не используем** (слабая, наименее полезная).
- **Kimi.ai не вставляем отдельным участником**: Kimi задействован только как модель внутри Perplexity.
- Перед прогоном режимы читаем со страниц и сверяем с таблицей. Не совпало, а сами не переключаем — запись в отчёт («режим не подтверждён»), реестр L-38.
- Обязательна только опорная модель (GPT); остальные — `required: false`. Claude — автор свода, правки и итога в схемах, где он назначен.

## 3. Команда

| Роль | Кто | Что делает |
|---|---|---|
| Ведущий-наблюдатель | сессия «Прогоны Basic» (Sonnet 5.5) | единственный держатель Chrome и перезагрузки расширения; подготовка, запуск, наблюдение, решения по окнам, находки в реестр, отчёт, доставка документов |
| Аналитики разбора (4) | субагенты Haiku 5.5 | по направлениям: транспорт и завершение; логика, запросы и приёмка; интерфейс и окна; качество итога против «готово, когда» схемы. Каждый в своём worktree, первым шагом `git merge <актуальная ветка>` |
| Исполнитель коммитов | субагент Haiku 5.5 | `git add <пути>`, коммит, слияние `--ff-only` в основную линию |
| Независимый проверяющий исправлений | субагент Haiku 5.5 | сверяет дефект, тест и дифф доставленной версии |
| Разработчик движка | сессия «Реестр проблем Basic» | чинит, доставляет версии; перезагрузку расширения просит у ведущего |
| Методолог схем | сессия «Мастерство схем» | переносит уроки в `docs/Scheme create/`, ведёт пособие |

Иерархия: Sonnet и Haiku порождают только Haiku 5.5. Агентам отправку запросов в модели не поручаем.

## 5. Что создаётся во время работы

**Правило размещения (владелец, 2026-10-30).** Всё, что относится к прогонам, лежит в `docs/Run/Test_run/`. У каждого прогона там своя папка `docs/Run/Test_run/<имя>_<yyyy-mm-dd>[_HH-mm]/` (например `docs/Run/Test_run/Research_Instruction_2026-10-30_22-00/`) с подпапками `schema/`, `artefacts/`, `exports/`, `notes/`: в ней все документы этого прогона и созданные артефакты (`.../artefacts/`). Материалов прогонов в других папках (в том числе прежней `docs/pipelines/`) не держим; ссылки из других документов ведут в `Test_run`. Это правило заменяет общее правило `docs/pipelines/` из глобальных инструкций для этого проекта.

В папке прогона:
`schema/` (схема и `task.txt`), `exports/` (одна выгрузка «Basic»), `artefacts/` (итог и контроль), `notes/run-report.md` (по шаблону), `notes/action-log.md` (мои действия в Chrome с временем: кто нажал, а кто сделал движок), `notes/lessons-for-handbook.md` (уроки для схем), `notes/analysis-*.md` (разборы аналитиков).

Вне папки: строки реестра (ID продолжают нумерацию; перед записью проверить коллизии), дополнения в `docs/Platform specifics/<провайдер>.md`, правки `docs/Run/` при изменении процедуры.

## 6. Находка: от обнаружения до закрытия

1. **Обнаружение.** Наблюдатель каждые 20 секунд (любое видимое окно + состояние прогона); сверка карточек со страницами моделей; выгрузка «Basic»; разбор четырьмя аналитиками.
2. **Фиксация сразу, в тот же ход.** Строка реестра: что, где (положение в выгрузке, модель, время), доказательство со страницы. Одна строка сессии реестра (`local_a062c6df-59b5-4a8a-93b6-edc1b9e04c34`).
3. **Устранение.** Сессия реестра правит, тестирует, доставляет версию. Доставка принимается только после окончания прогона: ведущий получает «доставлено», проверяет `manifest.json`, перезагружает расширение и обновляет вкладки моделей.
4. **Проверка в два этапа.**
   - *Тест*: воспроизводит дефект по данным выгрузки, красный до правки, зелёный после; независимый проверяющий сверяет дифф с дефектом.
   - *Живая проверка*: узкий запуск именно этого места после доставки. Требует нового разрешения владельца; без него статус — «закрыто тестом, живая проверка не проведена».
5. **Закрытие** — когда сошлись оба этапа; отчёт фиксирует это в разделе «Что подтвердилось».

## 7. Окно или симптом → действие

| Что видно | Действие |
|---|---|
| Информационное «OK» (напр. «Схема установлена…») | `click-ok-modal.js` |
| «Another run is already in progress» | OK; сверить состояние прогона и страницы моделей; записать в `action-log.md` и реестр |
| «Ответ User» | ответить сам по заданию шага |
| Отчёт импорта «есть замечания» | «Закрыть» (10 известных предупреждений про личные задания в этой схеме намеренные) |
| Неполный раунд | сначала сверить с ответами на страницах (L-37). Необязательные модели — «Пропустить участника»; обязательная — смотреть страницу, при необходимости «Повторить» один раз |
| Раунд «нет принятых ответов» при полных ответах на страницах | не «Повторить» вслепую: зафиксировать находку с DOM-доказательством, затем решить по таблице выше |
| Лимит использования модели | пропуск участника |
| CAPTCHA / вход / не тот адрес | необязательная: пропуск; обязательная: смотрим страницу сами |
| Любое другое видимое окно | не гадать: прочитать текст и кнопки (`any-modal.js`), решить по смыслу, записать |
| Вкладки закрыты или расширение перезагружено посреди прогона (`NO TAB`) | прогон считается оборванным; выгрузку не ждём; после подготовки перезапуск — только с разрешением владельца |

## 8. Итог прогона

- **Успешный**: завершён, итоговый документ получен.
- **Частичный**: завершён с пропущенными необязательными участниками (причины в отчёте).
- **Недействительный**: заблокированный экран, перезагрузка расширения или потеря вкладок посреди прогона, оборван человеком. Данные годятся только для диагностики.
