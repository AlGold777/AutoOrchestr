## Проект прототипа v1 — Padel Smash Coach

**Принятые допущения (безопасные инженерные, где входные данные неполны):**

1. «Смэш (верхняя подача на отбой)» понят как базовый плоский смэш: атакующий удар над головой по высокому мячу. Это не подача. Виборa и бандеха не оцениваются.

2. Реальных видео тренера и спортсменов нет — не нашёл. Демо-видео заменяются заглушками: SVG-постер с таймером. Готовые ролики можно подставить позже без правки кода.

3. Один ракурс: сбоку (профиль), камера неподвижна, 2–3 м, в кадре всё тело, ракетка и зона удара. Игрок — правша. Съёмка предпочтительно горизонтальная, интерфейс остаётся вертикальным.

4. В подходе два удара (shotIndex 1 и 2). Один подход — одна запись 10–20 с.

5. Каталог ошибок редакционный. Тренер его не проверял, числовых порогов нет.

6. Оценки «72/100», углы и проценты из материалов в прототип не попадают: они выдуманные.

7. Аналоги и ссылки из материалов 1 и 3 мной не проверены и в документ не перенесены.

8. Данные лежат в `data.js` (JSON-объекты в JS-файле), потому что `fetch` JSON по `file://` блокируется браузером.

### 1. Задача

Кликабельный HTML-прототип: тренер записывает эталон смэша, спортсмен снимает подход, сохраняет видео и получает разбор. Анализ имитируется: ошибки и советы заранее прописаны для двух демо-попыток. Архитектура должна позволить заменить имитацию настоящим анализом позы без правки экранов.

Принципы:

- запись, сохранение и анализ — три отдельных статуса со своей обработкой ошибок;

- имитация везде помечена «Демо»;

- при нехватке данных показывается явное сообщение, случайные ошибки не подставляются;

- каждая ошибка привязана к удару и к временной метке.

### 2. Сквозной сценарий и экраны

**Тренер:** S01 (роль «Тренер») → «Записать эталон» → S02 → S03 «Сохранить эталон» → S01 («Эталон готов»).

**Спортсмен:** S01 (роль «Спортсмен») → «Снять подход» → S02 → S03 «Сохранить и анализировать» → S04 → S05 → выбор ошибки → «Повторить подход» → S02.

| ID | Экран | Переходы |
| --- | --- | --- |
| S01 | Упражнение «Смэш» | основная кнопка → S02; попытка из истории → S05; «Эталон» → окно плеера |
| S02 | Камера | «Остановить» → S03; «Отмена» → S01; ошибка камеры → импорт файла или демо-попытка |
| S03 | Просмотр и сохранение | «Переснять» → S02; тренер: сохранить → S01; спортсмен: сохранить → S04; ошибка записи остаётся на S03 |
| S04 | Анализ | успех → S05; «Отмена» → S01; ошибка → повтор S04 |
| S05 | Результат | «Повторить подход» → S02; «Все попытки» → S01 |

Модальные окна (экранами не считаются): плеер эталона, подтверждение замены эталона, увеличенный кадр, импорт файла.

### 3. Содержимое экранов

**S01.** Шапка «PADEL COACH · Прототип». Переключатель «Спортсмен / Тренер». Карточка эталона (миниатюра, «Эталон тренера доступен» или «Эталона нет»). Список «Мои попытки» с числом замечаний. В начальном состоянии уже есть демо-эталон и две демо-попытки.

- Основная кнопка у тренера: «Записать эталон» или «Заменить эталон». У спортсмена: «Снять подход».

- Без эталона спортсмену предлагается «Использовать демо-эталон».

- Замена эталона требует подтверждения. Старые попытки хранят ссылку на свою версию эталона.

**S02.** Живое изображение, а при отказе в доступе демо-кадр. Плашка роли: «Эталон тренера» или «Подход спортсмена». Сетка и силуэтная зона. Подсказка «Поместите в кадр всё тело, ракетку и зону удара». Кнопки «Начать», «Остановить», «Отмена». Таймер и индикатор REC. Состояния: подготовка, запись, остановлено, ошибка камеры. Камера работает только по HTTPS или localhost. Экран идентичен для обеих ролей, отличается только плашка.

**S03.** Плеер, длительность, метка «Эталон» или «Попытка N», кнопки «Переснять» и «Сохранить…» (подпись по роли). Переход дальше разрешён только после подтверждённой записи. Ошибка сохранения даёт «Повторить» и «Экспорт файла».

**S04.** Заголовок «Анализ смэша», бейдж «Демо», текст «Используются заранее подготовленные данные». Три шага по ~1 с: «Видео подготовлено» → «Эталон выбран» → «Формируется разбор». Для своего видео без данных показывается «Для этого видео нет демо-данных» с кнопками «Открыть демо-разбор 1» и «Открыть демо-разбор 2». Случайные ошибки не подставляются. Без валидного эталона анализ не стартует.

**S05 — главный экран.** Он отвечает на три вопроса: где ошибка, чем отличается от эталона, как исправить.

Верх: «Разбор смэша · Попытка N · Демо», «Найдено K замечаний». Если K = 0, выводится «В демо-данных замечаний нет», вывода об идеальной технике не делается.

Визуальный блок: два кадра рядом, слева спортсмен, справа тренер.

- На кадрах SVG-скелеты. Проблемные суставы спортсмена выделены контрастным цветом, у тренера подсвечены те же суставы в правильном положении.

- Под кадрами: фаза («Контакт»), метка спортсмена и метка тренера (могут различаться, например 00:02.40 и 00:02.10), сопоставление по фазе, а не по времени.

- Подпись «Схематические позы. Не результат анализа реального видео».

- Тап по кадру открывает увеличение. Режим «По одному» показывает кадры поочерёдно.

- Свободной покадровой перемотки нет, только переключение между заранее размеченными кадрами.

- «Смотреть момент» открывает плеер на нужной метке (для заглушки: постер с таймкодом).

Список ошибок: аккордеон. Карточка содержит название, «Удар N · метка», признак, совет одной фразой. Раскрыта одна выбранная, по умолчанию первая.

Выбор ошибки — одна атомарная операция: меняется `selectedErrorId`, подгружается пара поз, обновляются метки, подсветка суставов и совет, блок кадров прокручивается в видимую область.

Низ: «Повторить подход» (→ S02), «Все попытки» (→ S01).

### 6. Замена имитации настоящим анализом

**Граница слоя.** Интерфейс обращается только к одному вызову:

`AnalysisProvider.analyze({attemptId, referenceId, videoBlob}, onProgress) → Promise<AnalysisResult>`

Сейчас его реализует `MockAnalysisProvider`: он по `attemptId` отдаёт готовый объект `analysis` из `data.js`. Позже добавляется `PoseAnalysisProvider` с тем же контрактом. Выбор провайдера — одна строка конфигурации. S04 показывает прогресс через `onProgress`, S05 читает только `analysis`.

**Что должен делать настоящий провайдер:**

1. Декодировать кадры и проверить пригодность видео: полное тело, ракетка, освещение, смаз.

2. Найти ключевые точки позы с оценкой достоверности (например, MediaPipe Pose Landmarker — это из материала 3, мной не проверено), сгладить по времени.

3. Разбить подход на удары и выделить фазы `preparation`, `contact`, `follow`, `recovery`.

4. Выровнять фазы спортсмена и эталона (DTW или ключевые кадры), не предполагая одинаковых времён.

5. Посчитать только те признаки, которые надёжны при ракурсе «сбоку».

6. Применить правила и пороги, откалиброванные тренером по реальным записям. Сейчас порогов нет.

7. Вернуть ошибки в том же формате.

**Контракт расширяется только опциональными полями.** Новые поля: `confidence`, `analysisVersion`, `modelVersion`, `qualityWarnings`, `unassessablePhases`, `coordinateSystem` (нормализованные 0..1, ось Y вниз). `evidence.type` получает значение `keypoints` с массивами точек `{name, x, y, v}` для спортсмена и эталона. S05 выбирает отрисовку по `evidence.type`: `svg-preset` или `keypoints`. Низкая достоверность даёт «Недостаточно данных, переснимите», а не диагноз.

**Открытый риск.** Определение момента контакта мяча и ракетки по одному скелету может быть неточным. Может понадобиться трекинг ракетки или мяча либо ручная коррекция тренером. Это вне прототипа.

### 7. План сборки HTML-прототипа

Файлы: `index.html`, `styles.css`, `app.js` (hash-роутер, состояние), `data.js` (demo + catalog), `poses.js` (7 SVG-поз), `provider-mock.js`, `storage.js`. Внешних API нет, работает офлайн.

1. **Каркас.** Пять экранов как `<section>`, hash-навигация (`#s01`…`#s05`), состояние `role`, `attemptId`, `selectedErrorId`. Верстка mobile-first под 390×844, без горизонтальной прокрутки.

2. **Данные и позы.** `data.js` по разделам 4–5, `poses.js`, отрисовка скелета из ключей. Проверка ссылок скриптом при загрузке.

3. **S05 первым** (самая важная ценность): аккордеон, пара кадров, метки, подсветка суставов, «По одному», увеличение.

4. **S04 и MockProvider.** Три шага по ~1 с, состояния «нет данных» и «нет эталона».

5. **S01.** Роли, эталон, история, замена эталона, предзаполненные демо-данные.

6. **S02 и S03.** `getUserMedia` и `MediaRecorder`, MIME выбирается по поддержке браузера (MP4 не требуется). Фолбэки: импорт файла и демо-попытка. Видео в IndexedDB, метаданные и роль в localStorage, экспорт файла.

7. **Сквозная склейка.** Оба сценария, повтор подхода без перезаписи истории.

8. **Проверка.** Критерии из раздела 8 в Chrome desktop и Safari iOS. Публикация как статический сайт по HTTPS.
