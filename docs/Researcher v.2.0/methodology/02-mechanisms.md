# Механизмы

Механизм входит в состав, если назван отказ простого подхода, который он снимает, и если при его удалении что-то измеримо ломается. Простой подход для сравнения — перебор ответов с сильнейшим доступным проверяющим при том же бюджете.

Числа эффекта неизвестны до первых прогонов: все предсказания ниже — `[Г]` и проверяются удалением механизма на замороженной конфигурации ([../verification/04-evaluation.md](../verification/04-evaluation.md)).

## 1. Состав

| Код | Механизм | Сводится к «больше попыток и фильтр» |
| --- | --- | --- |
| М1 | Смена представления | нет |
| М2 | Порождение нового оператора поиска | нет |
| М3 | Работа с ложной предпосылкой | нет |
| М4 | Накопление отрицательных результатов | частично: фильтр, но растущий из неудач |
| М5 | Предсказание до проверки | нет, это условие проверяемости |
| М6 | Слепая калиброванная проверка | да, это сильный фильтр; включён как необходимое условие |
| М7 | Диагностика метода с плацебо | нет |
| М8 | Библиотека перестроек | нет |

Четыре кандидата задания v4.2 (М1–М4) включены: каждый адресует свой барьер из [01-methodology.md](01-methodology.md), §4, и остальные его не закрывают.

## 2. Карточки

### М1. Смена представления

| Поле | Содержание |
| --- | --- |
| Барьер и отказ | Б2, Б6. Простой подход: все ответы остаются в исходном языке задачи |
| Вход | Текущее представление, ямы и свидетельства, диагноз |
| Выход | Новое представление; что стало выразимым и проверяемым; правило перевода; что сохраняется |
| Оператор | Ход из каталога (§3), выбранный по признаку барьера |
| Вид переноса | Доказанная эквивалентность / ослабление / сужение / эвристическая аналогия — записывается явно. Без доказанной эквивалентности решение новой задачи не считается решением исходной |
| Почему лучше перебора | Перебор не выходит из языка, в котором задача не выражается `[И]` |
| Если убрать | На задачах полигона с удалённым понятием доля восстановленной выразимости падает до уровня перебора `[Г]` |
| Цена | 3–5 запросов на ход, одна проверка тройного теста |
| Типичный отказ | Переименование вместо понятия. Обнаруживается тестом редукции определения |
| Что видно в журнале | Кандидат в выразимость со сроком; смена ведущей валюты на В2 |
| Опровергающий опыт | Задачи с удалённым понятием: М1 против перебора при равном бюджете |
| Новизна | Комбинация известного: эвристики переформулировки плюс обязательный тест и срок |

### М2. Порождение нового оператора поиска

| Поле | Содержание |
| --- | --- |
| Барьер и отказ | Б1, Б3. Простой подход повторяет один способ порождения кандидатов |
| Пять шагов | 1) дефект текущего оператора по записям провалов; 2) требования к новому; 3) конструкция — новый приём роли; 4) испытание на отложенных задачах полигона; 5) принятие или откат |
| Вход и выход | Вход: ямы с одним кодом провала. Выход: приём с условиями применимости и правилом остановки |
| Почему лучше перебора | Меняет распределение кандидатов, а не их число `[И]` |
| Если убрать | Повторы одного кода провала не снижаются между циклами `[Г]` |
| Цена | Перестройка класса D: парные прогоны на полигоне |
| Типичный отказ | Новый оператор — старый с другим названием. Обнаруживается: признаки разнообразия гипотез не изменились |
| Что видно в журнале | Запись перестройки класса D с пятью шагами |
| Опровергающий опыт | Сравнение с плацебо класса D |
| Новизна | Известное: поиск в пространстве стратегий; здесь — с обязательным испытанием |

### М3. Работа с ложной предпосылкой

| Поле | Содержание |
| --- | --- |
| Барьер и отказ | Б3. Простой подход наследует предпосылки постановки |
| Оператор | 1) выписать допущения каждой прошлой попытки; 2) найти общее неявное; 3) проверить, что оно не необходимо: построить частный случай без него; 4) отличить продуктивный отказ от некорректной постановки: без предпосылки задача должна оставаться проверяемой |
| Вход и выход | Вход: история попыток из карточки и журнала отказов. Выход: предпосылка, статус «необходима / не необходима / неизвестно», задача без неё |
| Почему лучше перебора | Перебор не ставит под вопрос то, что не записано `[И]` |
| Если убрать | На задачах полигона с вживлённой ложной предпосылкой решений не больше, чем у перебора `[Г]` |
| Цена | 2–4 запроса и одна проверка |
| Типичный отказ | Отброшена необходимая предпосылка, задача стала другой. Обнаруживается проверкой обратного переноса |
| Что видно в журнале | Триггер T5, запись предпосылки, перестройка класса C |
| Новизна | Известное |

### М4. Накопление отрицательных результатов

| Поле | Содержание |
| --- | --- |
| Барьер и отказ | Б1. Простой подход повторяет тупики |
| Оператор | Неудача → вид → причина → яма-предикат с границами или свидетельство. Перед каждым планом цикла координатор сверяет шаг с ямами |
| Почему лучше перебора | Стоимость шага не растёт с историей, а пространство сужается `[И]` |
| Если убрать | Доля шагов, повторяющих записанный тупик, растёт `[Г]` |
| Цена | Один раздел в ответе секретаря журнала |
| Типичный отказ | Ложная блокировка: яма запрещает верное направление. Считается отдельно; яма без срабатываний уходит на пробную попытку |
| Режим «неудача ничего не даёт» | Три пустые неудачи подряд в одном направлении — направление приостанавливается, а не закрывается |
| Новизна | Известное |

### М5. Предсказание до проверки

Отказ: объяснение задним числом. Заявка с предсказанием записывается шагом раньше проверки ([../system/04-core.md](../system/04-core.md), §4). Если убрать: доля «подтверждений», не отличимых от наивного предсказания, не измерима вовсе. Типичный отказ: предсказание настолько широкое, что подтверждается всегда; закрыто требованием отличия от наивного. Новизна: комбинация предрегистрации и порядка шагов.

### М6. Слепая калиброванная проверка

Отказ: проверяющий соглашается с автором. Проверяющий — не модель автора и не модель исполнителя, в новом чате, без гипотезы и рассуждений автора, с двумя числами калибровки; судит только результат, полученный запуском; обязан назвать одно альтернативное объяснение и быстрейший тест против него — ответ «ошибок нет» не принимается. Если убрать: доля пропущенных посевов растёт `[Г]`. Типичный отказ: общая ошибка всех проверяющих; закрыто проверкой другим способом.

### М7. Диагностика метода с плацебо

| Поле | Содержание |
| --- | --- |
| Барьер и отказ | Любой. Простой подход не замечает, что мешает сам способ работы |
| Оператор | Диагност метода по записям цикла проверяет триггеры T1–T7, называет причину — какой приём, предпосылка или язык мешает — и конкурирующие причины с различающим тестом. Перестройка по диагнозу испытывается рядом с плацебо: изменением того же класса, выбранным без диагноза |
| Внешний канал | При T7 владелец прикладывает к задаче схемы перестройки взгляд извне: заметку о методе другой области — свою или модели вне состава. Сам диагност его не пишет: это был бы ещё один взгляд тех же моделей |
| Калибровка диагноста | На полигоне в конфигурацию вживляется известный дефект приёма; считается доля случаев, когда диагност назвал именно его |
| Почему лучше перебора | Отделяет «заметил, что мешает» от «поменял что-то» `[И]` |
| Если убрать | Перестройки не лучше плацебо `[Г]` — это и есть главный опыт системы |
| Цена | Один запрос в цикл; предложения — семь запросов схемы перестройки, только когда владелец решил перестраиваться; испытание — три плеча |
| Типичный отказ | Диагноз следует за последним провалом, а не за причиной. Обнаруживается калибровкой на вживлённых дефектах |
| Новизна | Кандидат на новое: плацебо-контроль перестройки метода |

### М8. Библиотека перестроек

Отказ: каждая задача учится перестраиваться заново. Запись: перестройка, класс, триггер, диагноз, предусловия, предсказание, исход, сравнение с плацебо, где сработала и где нет. Владелец вкладывает в задачу схемы перестройки записи с тем же триггером и барьером, а в задачу настройки новой задачи — записи с тем же типом барьера; роли обязаны назвать, что взяли. Взятое — гипотеза о переносе. Если убрать: доля бюджета на перестройки не падает от задачи к задаче `[Г]`. Типичный отказ: перенос перестройки туда, где предусловия не выполнены; закрыто полем предусловий и повторным испытанием. Заявление о переносе — только по правилу класса E.

## 3. Каталог ходов смены представления

Ход — заготовка для М1. Изобретатель перестроек выбирает ход по признаку и обязан назвать, что сохраняется при переносе.

| № | Ход | Когда пробовать | Что проверить |
| --- | --- | --- | --- |
| 1 | Частный случай | Общая задача не формулируется | Случай нетривиален и проверяем |
| 2 | Обобщение | Частные случаи решаются по-разному, общего нет | Обобщение не пусто |
| 3 | Ослабление условия | Условие слишком жёсткое для любого шага | Что из исходного следует из ослабленного |
| 4 | Усиление утверждения | Индукция или перенос не проходят для слабого | Усиленное не ложно на малых случаях |
| 5 | Двойственность | Объект труден, двойственный прост | Соответствие взаимно однозначно |
| 6 | Смена языка | Одни и те же формулы у всех попыток | Перевод сохраняет вопрос |
| 7 | Перенос из другой области | В другой области есть похожая структура | Аналогия или доказанное соответствие |
| 8 | Инвариант | Процесс или преобразование без видимого конца | Величина действительно сохраняется или монотонна |
| 9 | Движение от цели | Прямой вывод ветвится | Каждый обратный шаг обратим или помечен |
| 10 | Крайний объект | Общий объект необозрим | Крайний существует |
| 11 | Предел и асимптотика | Точный ответ недоступен | Какой вывод о точном следует из предельного |
| 12 | Симметрия | Задача симметрична, решение нет, или наоборот | Симметрия не добавлена искусственно |
| 13 | Разложение на локальное и общее | Локально всё решается, целиком нет | Условие склейки |
| 14 | Вспомогательный объект | Данные задачи не связываются напрямую | Объект не предполагает ответ |
| 15 | Смена аксиом или модели | Подозрение на независимость | В какой системе утверждение проверяемо |
| 16 | Подъём в большее пространство | В исходном пространстве нет места для манёвра | Проекция обратно корректна |
| 17 | Дискретное ↔ непрерывное | Один мир даёт инструменты, которых нет в другом | Что теряется при переходе |
| 18 | Отказ от предпосылки | Сработал T5 | Задача остаётся проверяемой |

Каталог пополняется из библиотеки перестроек: ход, подтвердившийся на трёх задачах, получает строку.
