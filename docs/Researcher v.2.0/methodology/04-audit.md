# Критический аудит и границы

Попытка опровергнуть собственную концепцию. Риски идут по убыванию тяжести.

## 1. Риски

| № | Риск | Чем закрыт или чем проверяется |
| --- | --- | --- |
| 1 | Самоперестройка — дорогой перебор конфигураций | Сравнение с плацебо: перестройка по диагнозу обязана быть лучше изменения той же цены без диагноза |
| 2 | Открытие подменено новыми названиями | Тройной тест выразимости, тест редукции определения, срок |
| 3 | Диагноз следует за последним провалом, а не за причиной | Калибровка диагноста на вживлённых дефектах метода |
| 4 | Общие заблуждения всех моделей проходят любую проверку | Независимость способом; расчёт и опыт первичны над текстом; внешний наблюдатель |
| 5 | Закрытые наборы выучиваются через испытания перестроек | Предел обращений, замена набора, финальный набор у наблюдателя |
| 6 | Владелец подгоняет ядро | Операция над ядром с записью и якорем; запечатанный тест; два числа владельца |
| 7 | Записи цикла расходятся с ответами моделей | Экспорт прогона первичен; контролёр сверяет; посев расхождений |
| 8 | Новый язык удорожает задачу | Аварийный порог и карантин; откат |
| 9 | Знание теряется при смене представления | Карта переноса; ямы без доказанных границ становятся свидетельствами, а не исчезают |
| 10 | Бесконечная перестройка без углубления | Минимальный срок жизни конфигурации; `k` перестроек без прироста — смена диагноза |
| 11 | Самообучение закрепляет неверные предпосылки | В постоянную память — только с тремя независимыми подтверждениями; перенос — только по классу E |
| 12 | Показатели перестроек накручиваются осторожными предсказаниями | Засчитывается только рискованное предсказание |
| 13 | Модель знает ответ из обучения | Проба знания; порождаемые задачи полигона |
| 14 | Внешний текст исполняется как инструкция | Правило в каждом запросе; контролёр; посев |

## 2. Когда фиксированная конфигурация лучше

- Задача класса Б1 с дешёвой точной проверкой и хорошим представлением: бюджет на диагностику и испытания перестроек не окупается.
- Малый бюджет: испытание с тремя плечами стоит втрое дороже цикла.
- Мало доступных моделей: при трёх моделях независимость проверки держится только на расчёте.

В этих случаях диагност метода должен отвечать «перестройка не требуется», а доля бюджета на перестройки — стремиться к нулю. Если она не стремится — это риск 1.

## 3. Сильнейший сценарий проигрыша

Одна сильная модель, перебор ответов и поиск по литературе выигрывают на задаче, где решение есть в литературе смежной области под другим названием. Простой подход находит его за десятки запросов; система тратит тот же бюджет на предполёт, диагноз и заявки. Проба знания ловит это только если модель воспроизводит решение на прямой вопрос. Контрмера частичная: искатель в первом же цикле обязан принести источники из смежных областей.

## 4. Три утверждения, в которых ошибка вероятнее всего

1. Модели разных поставщиков дают достаточно независимые ошибки, чтобы слепая проверка имела смысл.
2. Диагност метода способен назвать причину, а не симптом.
3. Задачи полигона с удалённым понятием похожи на настоящие концептуальные барьеры.

Каждое проверяется первым же прогоном: корпус порч, вживлённые дефекты, сравнение полигона с первой настоящей задачей.

## 5. Kill-критерии концепции

Записываются в ядро до первого прогона вместе с числом пар и порогом знакового критерия ([../verification/04-evaluation.md](../verification/04-evaluation.md), §4). Проект закрывается, если на записанном числе пар:

- полная система не выиграла у системы с контрольным изменением нужного числа пар;
- полная система не выиграла у системы без перестройки нужного числа пар при равном бюджете;
- доля ложных подтверждений на полигоне не ниже, чем у перебора с проверяющим;
- калибровка проверяющих не достигает порога ни на одном составе.

Любой из четырёх исходов записывается в итог как «не подтверждено» — без переопределения критериев и без увеличения числа пар задним числом. «Не подтверждено» — решение закрыть проект, а не доказательство, что метод бесполезен: малый набор не различает слабый перевес и его отсутствие. Исход «данных мало» проект не закрывает и ничего не подтверждает.

**Окупаемость.** `стоимость сборки ≤ 3 × число задач × (цена результата простого подхода − цена результата системы)`. При нулевой или отрицательной экономии система не окупается ни при каком числе задач.

## 6. Что нельзя надёжно сделать сегодня

- Создать понятие, которого нет ни у кого, и доказать это: проверки нет.
- Гарантировать независимость моделей.
- Исполнять проверки вне моделей без участия владельца.
- Повторить прогон с тем же случайным зерном.

## 7. Другие методологии

| Методология | Источник преимущества | Когда лучше этой | Какой отказ закрывает |
| --- | --- | --- | --- |
| Эволюционный поиск программ с автоматической оценкой | Массовый перебор с точной оценкой | Есть быстрая точная оценка, решение — программа | Комбинаторику при дешёвой проверке |
| Одна модель с формальным проверяющим | Формальная гарантия каждого шага | Задача формализуется целиком | Ложные подтверждения |
| Автоматический выбор экспериментов | Каждый опыт максимально сужает неопределённость | Барьер — дефицит данных, опыт дёшев | Б4 |

Эта система берёт у них проверку вне моделей и отсечение по неудачам; отвергает ставку на объём перебора.

## 8. Проверка честности

Для открытой проблемы уровня гипотезы Римана применимо: локализация барьера, перечень известных частичных результатов с пометкой «известно», проверяемые частные утверждения, ямы с границами. Бессильно: смена представления без способа проверки её пользы остаётся кандидатом в выразимость и сгорает в срок. Ожидаемый итог — `STOPPED` с записанными неопределённостями, без имитации продвижения.
