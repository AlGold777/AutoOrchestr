# Решения и допущения

Исходные документы писались отдельно и расходятся. Здесь записано, как каждое расхождение снято. При конфликте документов этой папки с исходниками права эта папка.

## 1. Решения по расхождениям

| № | Расхождение | Решение |
| --- | --- | --- |
| Р1 | Два входа: карта вопроса (V.2.1) и карточка из девяти полей (v1.1) | Вход один — карточка задачи. Карта вопроса — состояние, которое строится из карточки и журнала |
| Р2 | Две модели изменения: приём и меню методиста (V.2.1) против конфигурации с шестью полями и классами A–E (v4.2) | Одна модель. Конфигурация состоит из приёмов. Любое изменение — предложение с шестью полями и классом. Меню методиста — источник предложений классов A и B; ходы смены представления — источник классов C и D |
| Р3 | Три порядка сборки | Один план: [../operations/01-build-plan.md](../operations/01-build-plan.md) |
| Р4 | Меры прогресса: время до проверенного вывода против трёх валют | Прогресс — три валюты. Время и бюджет в трёх единицах — цена прогресса. Организационные показатели — здоровье системы, прогрессом не считаются |
| Р5 | Ссылки на «каркас 3A/3B/3C» и «уровни 0/2» без определения | Заменены тремя режимами: репетиция, по шагам, непрерывный |
| Р6 | Кто исполняет мета-уровень: «два мета-уровня» (v1.1) против методиста с турниром (V.3.2) | Одна машина. Первый мета-уровень — круг обучения: меняет конфигурацию. Второй — изменение самого оператора изменения, запросов и схем: только операцией владельца. Третьего нет |
| Р7 | «Проверяющий не предлагает гипотез» (v4.2) против экспериментатора, который пишет тест и предсказание (V.3.2) | Экспериментатор входит в число авторов. Он пишет заявку; проверяют её другие. Слепой проверяющий называет альтернативное объяснение результата — это не гипотеза о задаче, а довод против вывода |
| Р8 | «Координатор владеет очередью, а не записями» против шляпы ведущего задачи | Координатор предлагает план цикла. Записи и карту ведёт секретарь журнала, сверяет контролёр |
| Р9 | Запрет менять критерии (v4.2) против «пересмотреть критерии» по серии волевых решений (V.3.2) | Признак решения, способ проверки и kill-критерии внутри задачи не меняются: нужны другие — новая задача. Операцией над ядром меняются только временные пороги и среда исполнения |
| Р10 | «Среду исполнения пишет человек — она часть изменяемого слоя» (v1.1, не закрыто) | Запросы и схемы входят в `config_id` хешем. Их правка — операция владельца, а не перестройка системой |
| Р11 | Бюджет в токенах | В окне модели токенов не видно. Три единицы: запросы к моделям, запуски проверок, минуты владельца. Считает владелец по выгрузке |
| Р12 | «Журнал пишет код», «сводку считает скрипт» | На Basic кода нет. Первичная запись — экспорт прогона. Записи цикла и сводку пишут модели; контролёр сверяет их с ответами цикла. Это слабее и названо в §3 |
| Р13 | «Тот же seed» для теневого прогона | У моделей во вкладках его нет. Сравнение парное: тот же пакет, те же модели, новые чаты; отпечатки моделей записаны. Смена модели провайдером — смена конфигурации |
| Р14 | Проектные прогоны §15 задания v4.2 | Заменены исполняемыми прогонами на полигоне |
| Р15 | 12 полос, 4 семейства × 3 | Состав задаётся участниками схемы. Независимость — пары ролей, которые одна модель играть не может; их проверяет сборщик схем ([05-roles.md](05-roles.md), §1) |
| Р16 | Наёмный смотритель на этапе 9 | Внешний наблюдатель нужен с первого прогона, который претендует на статус выше S1: он держит финальный набор и получает хеши |
| Р17 | Свободная перестройка состава команд | Не вводится. Состав и порядок шагов — изменение схемы: операция владельца, а не перестройка |
| Р18 | Канал возражений, профили компетенций, абляция ролей | Вводятся после первого отработанного цикла: [../operations/01-build-plan.md](../operations/01-build-plan.md), этапы С6–С7 |

## 1а. Решения версии 2.0

Версию 1.0 отрецензировали семь моделей. Разбор каждой идеи — [../review-decisions.md](../review-decisions.md). Главное:

| № | Решение | Вместо чего |
| --- | --- | --- |
| Р19 | У сырого результата записано происхождение; без запуска статус не растёт, инструмент модели — не выше S1 | Исполнение проверки моделью без различения запуска и рассказа о запуске |
| Р20 | Предложения перестройки — в схеме `5-rebuild`; в цикле только диагност | Четыре шага предложений в каждом цикле |
| Р21 | Контрольное изменение и порядок плеч задаёт контрольная сумма последней строки журнала | Плацебо по номеру цикла, автор — модель с картой перед глазами |
| Р22 | Вердикт о перестройке — правило, записанное до испытания; счётчики не знают имён плеч | Суд одной модели свободным текстом |
| Р23 | Вердикт в задаче значит «принято в этой задаче»; довод о методе — знаковый критерий на полигоне | Одно понятие «подтверждено» для обоих |
| Р24 | Независимость — пары ролей, проверяемые сборщиком | «Три группы не пересекаются» |
| Р25 | Контроль записей — до карты, с сырым результатом на входе; контроль карты — после | Один контролёр после карты, без первичных ответов |
| Р26 | Замок после подписи не меняется; счётчики и числа калибровки — события журнала | Счётчик обращений и два числа в файле замка |
| Р27 | Документы задачи хранятся текстом; форматы — описание содержания; источник истины — выгрузки | «Карта пересобирается из журнала» |
| Р28 | Договор передачи с квитанциями убран | Протокол, встроенный в два запроса из семнадцати |
| Р29 | Сначала один полный цикл на учебной задаче, потом корпус порч, полигон и подпись порогов | Недели подготовки до первого цикла |

## 2. Допущения и чем они проверяются

| Допущение | Проверка | Если неверно |
| --- | --- | --- |
| Модели разных поставщиков ошибаются по-разному | Корпус порч: доля порч, пропущенных всеми проверяющими сразу | Независимость считается только по способу проверки: расчёт, другой набор данных, другой метод |
| Восемь моделей отвечают в одном прогоне | Сутки прогонов цикла, доля шагов без ответа | Сокращённый состав из [05-roles.md](05-roles.md), §4 |
| Пакет цикла умещается в 14 000 знаков | Счёт знаков в каждом цикле | Сжатие карты: [../methodology/01-methodology.md](../methodology/01-methodology.md), §9 |
| Модель действительно запускает код в своей среде, а не описывает вывод | Проверить нечем: текст запуска и текст о запуске неразличимы. Выборочный повтор запуска владельцем при аудите | Всё решающее запускает владелец; результат инструмента модели — не выше S1 |
| Ответы моделей не длиннее пределов слов больше чем на четверть | Длины ответов по выгрузке первого цикла | Пределы слов снижаются; у шагов-источников включается строгая длина |
| Правила сервисов разрешают такую работу с вкладками | Владелец читает условия каждого сервиса до первого прогона | Сервис исключается из состава |
| Владелец тратит не больше одного окна решений в день | Счёт минут с первого цикла | Реже окно, меньше параллельных веток |
| Данные задачи можно отправлять в облачные модели | Поле «незыблемые ограничения» карточки | Закрытые данные обрабатывает только владелец |

## 3. Что слабее, чем в исходниках

| Что | Почему | Чем прикрыто |
| --- | --- | --- |
| Записи цикла и сводку пишут модели | В Basic нет шагов приложения | Экспорт прогона первичен; контролёр сверяет; владелец сверяет выборочно |
| Замок держится на порядке шагов и ручном хеше | В Basic нет своего журнала с хешами | Цепочка хешей и внешний якорь: [04-core.md](04-core.md) |
| Авторство предложений видно приёмщику | Basic подписывает ответ участником | Приёмщик проверяет только форму предложения, выбор делает владелец |
| Нет песочницы | В Basic нет исполнения кода | Происхождение результата записывается и ограничивает статус; решающее запускает владелец |
| Бюджет считает владелец руками | В Basic нет счётчика запросов | Счёт по выгрузке; остаток — в разделе «ХОД» пакета |
| Проверка состава — только при сборке схем | В Basic нет понятия роли | Сборщик отказывает при нарушении пар независимости |
| Статистика испытания в задаче — два прогона на шум | Больше прогонов не по бюджету вкладок | Вердикт в задаче значит только «принято в этой задаче»; довод о методе — знаковый критерий на полигоне |

## 4. Не закрыто

- Полнота корпуса порч недоказуема.
- Проверка на полигоне с удалённым понятием показывает работу без понятия, а не создание понятия, которого не было ни у кого.
- Автор методологии и рецензенты — модели с общими данными обучения. Рецензия сужает ошибки, но не делает их независимыми.
- Владелец остаётся одним человеком на большинстве операций. Внешний наблюдатель закрывает только финальный набор и якорь журнала.
- Цепочка доказывает неизменность записанного, но не полноту: невыгруженный запуск в неё не попадёт.
- Ошибки трёх проверяющих могут совпадать. Третье число калибровки это измеряет, но не устраняет.
- Работа во вкладках упирается в суточные пределы сообщений и условия сервисов; аккаунт может быть ограничен посреди испытания.
- Контролёр карты видит раздел «ТЕСТ»; вслепую он проверяется только посевом.
