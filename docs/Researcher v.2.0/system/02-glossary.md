# Словарь

Один термин — одно значение во всех документах, запросах и форматах. Столбец «В исходниках» — прежние названия.

## 1. Термины

| Термин | Значение | В исходниках |
| --- | --- | --- |
| Карточка задачи | Девять полей о задаче, заполняет владелец | A0, `problem.md` |
| Предполёт | Пробы до настройки: знает ли модель ответ, работает ли проверка, где ломаются простые подходы | A0.5 |
| Журнал отказов | Точки отказа простых подходов, найденные в предполёте | `failure_logs.md` |
| Методология | Правила обоих кругов; папка `methodology/` | M, A1 |
| Конфигурация `C_n` | Версия изменяемого слоя: представление задачи, правило выбора шага, приёмы ролей, изменяемые пороги. Состава моделей и приёмов проверки в ней нет | K, `C_n`, набор приёмов |
| Приём | Раздел конфигурации для одной роли: что делать и по какому правилу | приём (V.2.1) |
| Ядро | Неизменяемый слой | неизменяемое ядро, `immutable.lock.json` |
| Замок | Способ, которым ядро и предсказания защищены от правки | `zero_floor.py`, замок реестра |
| Журнал | Выгрузки прогонов, события владельца и цепочка их контрольных сумм; источник истины | J, журнал событий |
| Карта вопроса | Состояние задачи; каждая строка ссылается на номер записи цикла | карта вопроса, `State/` |
| Пакет цикла | Выжимка ядра + раздел «ХОД» + конфигурация + карта вопроса | окно контекста |
| Раздел «ХОД» | Номер цикла, номер конфигурации и остаток бюджета; пишет владелец | — |
| Происхождение результата | Как получен сырой результат: запуск владельца, инструмент модели или запуска нет | — |
| Гипотеза | Одно проверяемое утверждение с основанием и альтернативой | гипотеза |
| Заявка на проверку `H#` | Три части, записанные до проверки: запись для проверяющих (условия и предсказание, без утверждения), процедура для исполнителя, заметка автора для записей | H#, реестр предсказаний |
| Вердикт `V#` | Отчёт о проверке по заявке | V#, отчёт о проверке |
| Факт | Утверждение с источником и классом надёжности | факт |
| Яма | Запись о провале с причиной и правилом обхода | яма, предикат-исключение |
| Пробел | Чего не хватает: данных, инструмента, понятия | пробел |
| Противоречие | Два утверждения, которые не могут быть верны вместе | дело о противоречии |
| Перестройка | Изменение конфигурации по сработавшему триггеру | перестройка, изменение приёма |
| Предложение изменения | Шесть полей + карта переноса | кортеж §2, предложение изменения |
| Контрольное изменение (плацебо) | Изменение того же класса, выбранное без диагноза: пункт каталога задаёт контрольная сумма последней строки журнала | — |
| Карта переноса | Что из накопленного сохраняет силу при перестройке, что устаревает, что выводится заново | `transfer_map.json` |
| Библиотека перестроек | Постоянная запись: перестройка, её условия, где сработала и где нет | — |
| Полигон | Задачи со скрытой структурой, порождённые по параметрам: ответ знает владелец, вспомнить его модель не может | полигон |
| Корпус порч | Верные утверждения и их испорченные копии для калибровки проверяющих | корпус порч §10 |
| Посев | Нарушение или ошибка, подложенные намеренно | посев |
| Сводка | Десять строк о цикле для владельца | D, дайджест |
| Окно решений | Шаг, где владелец читает сводку и решает | окно человека |
| Итог | Конечное состояние задачи и пакет воспроизведения | S |
| Пара независимости | Две роли, которые одна модель играть не может; проверяется при сборке схем | семейство, направление |
| Участник | Модель с постоянным ID в схеме Basic; свой чат | полоса |
| Внешний наблюдатель | Человек, не строивший систему; держит финальный набор | смотритель |

Не используются: «токены» (в окне модели их не видно; считаем запросы), «уровень 0/1/2» и «3A/3B/3C» (заменены режимами исполнения).

## 2. Валюты прогресса

| Код | Валюта | Когда засчитывается |
| --- | --- | --- |
| В1 | Исполнимое ограничение | Есть правило, отсекающее кандидатов, с доказанными границами |
| В2 | Новая выразимость | Тройной тест: новое следствие проверяемо; прошлые неудачи объяснимы в новом языке; определение не сводится к переименованию |
| В3 | Новая проверяемость | Появился способ проверки с двумя числами калибровки |

Концептуальный прогресс не измеряется валютой В1.

## 3. Статусы результата

| Код | Статус | Основание для повышения |
| --- | --- | --- |
| S0 | Гипотеза | — |
| S1 | Подтверждено одной проверкой | Не меньше двух совпавших вердиктов «подтверждено» по заявке с предсказанием; проверка годная; результат получен запуском — владельца или инструмента модели |
| S2 | Подтверждено независимо | Две проверки разными способами; хотя бы один результат получен запуском владельца или средством вне моделей |
| S3 | Формально доказано | Доказательство, принятое средством проверки вне моделей |
| S4 | Независимо воспроизведено | Повтор другим исполнителем на других данных или другим методом |

Повышает статус только запись вердикта. Автор свой результат не повышает. Результат без запуска статус не поднимает; результат, полученный только инструментом модели, — не выше S1, пока владелец не повторил запуск.

Новизна — отдельная отметка, статус её не содержит: новый результат может быть ошибочным, а известный — строго доказанным.

| Отметка новизны | Основание |
| --- | --- |
| Не проверялась | — |
| Известно | Найден первичный источник |
| Комбинация известного | Части известны, сочетание в поиске не найдено |
| Новизна подтверждена в пределах поиска | Проверка литературы и тест редукции; названо, где искали |

## 4. Метки утверждений

`[Ф]` — установленный результат с источником. `[И]` — инженерный вывод с посылками. `[Г]` — гипотеза с опровергающим опытом. Согласие моделей свидетельством не считается.

## 5. Классы надёжности факта

| Код | Класс | Может быть основанием вывода |
| --- | --- | --- |
| R1 | Проверено расчётом или опытом | да |
| R2 | Первичный источник | да |
| R3 | Пересказ | только вместе с R1 или R2 |
| R4 | Мнение модели | нет, только повод для проверки |
| R5 | Вклад человека без первичного артефакта | нет, регистрируется как гипотеза |

## 6. Классы перестроек

| Класс | Что меняется | Как доказывается польза |
| --- | --- | --- |
| A | Правило выбора шага, приёмы ролей, изменяемые пороги | Испытание тремя плечами в задаче |
| C | Представление задачи, язык, понятия | Испытание тремя плечами; тройной тест выразимости в срок |
| D | Оператор поиска, правила решений | Испытание тремя плечами в задаче или парные прогоны на полигоне |
| E | Улучшение, переносимое на другие задачи | Только на задачах, не участвовавших в настройке |

Состав ролей и порядок шагов — не перестройка, а изменение схемы: его делает владелец пересборкой. Вердикт испытания в задаче значит «изменение принято в этой задаче»; довод о методе даёт только парное сравнение на полигоне.

## 7. Триггеры перестройки

| Код | Наблюдается в журнале |
| --- | --- |
| T1 | Нет прироста ни в одной валюте `k` циклов подряд |
| T2 | Один код провала повторился `m` раз |
| T3 | Гипотезы последних `k` циклов используют один аппарат |
| T4 | Доля подтвердившихся предсказаний ниже порога или предсказания не отличаются от наивных |
| T5 | Найдена общая неявная предпосылка прошлых попыток |
| T6 | Доля бюджета на перестройки растёт без прироста валют |
| T7 | Один и тот же диагноз метода трижды подряд |

Состояние, не покрытое триггером: донесение владельцу; перестройка без триггера не начинается.

## 8. Коды шагов и провалов

Ключ ямы — пара `STEP_*` + `FAIL_*`. Новый код добавляет только владелец.

| Шаг | | Провал | |
| --- | --- | --- | --- |
| `STEP_SEARCH` | поиск | `FAIL_WRONG_PLACE` | искали не там |
| `STEP_SOURCE` | обработка источника | `FAIL_WEAK_EVIDENCE` | принято слабое доказательство |
| `STEP_HYPOTHESIS` | гипотеза | `FAIL_WRONG_HYPOTHESIS` | гипотеза опровергнута |
| `STEP_CLAIM` | заявка на проверку | `FAIL_UNTESTABLE` | заявку нельзя проверить |
| `STEP_EXEC` | исполнение проверки | `FAIL_EXEC_BUG` | ошибка исполнения, а не гипотезы |
| `STEP_VERDICT` | вердикт | `FAIL_SLOW_CHECK` | проверка слишком дорогая |
| `STEP_PLAN` | план цикла | `FAIL_REPEAT` | повтор известной ошибки |
| `STEP_REBUILD` | перестройка | `FAIL_CONTEXT_LOST` | потерян контекст |
| `STEP_RECORD` | запись и карта | `FAIL_TOO_COMPLEX` | шаг слишком сложен |
| | | `FAIL_EARLY_STOP` | преждевременный останов |
| | | `FAIL_PREDICTION_MISS` | предсказание перестройки не подтвердилось |
| | | `FAIL_FALSE_PREMISE` | ложная предпосылка |

## 9. Нарушения

Жёсткие (ветка замораживается, донесение идёт владельцу напрямую):

| Код | Нарушение |
| --- | --- |
| `V_LATE_PREDICTION` | Предсказание записано после запуска проверки |
| `V_LEAK_TO_CHECKER` | Проверяющий знает гипотезу или рассуждения автора |
| `V_VERDICT_EDIT` | Вердикт в записях или карте отличается от слова проверяющего |
| `V_RESULT_EDIT` | Число или исход в записях отличается от сырого результата |
| `V_NO_RUN` | Статус поднят без запуска, без годной проверки или при числе вердиктов меньше двух |
| `V_EXTERNAL_AS_INSTRUCTION` | Внешний текст исполнен как инструкция |
| `V_OVERREACH` | Выход за полномочия роли |
| `V_NO_POSTMORTEM` | Ветка закрыта без записи итогов |
| `V_CORE_WRITE` | Попытка изменить ядро |

Мягкие (запись и накопление): `V_GOAL_DRIFT` — подмена цели; `V_SOFTENING` — смягчение формулировки; `V_FORMAL_COMPLIANCE` — формально законный обход смысла задания; `V_UNMARKED_CLAIM` — утверждение без метки.

Часть правил контроля агентам не объявляется и меняется ([../verification/03-control.md](../verification/03-control.md)).

## 10. Конечные состояния задачи

`SOLVED` — проверенное решение. `PARTIAL` — подтверждённый частный результат. `COUNTEREXAMPLE` — контрпример. `LIMIT` — строгое ограничение или невозможность в конкретной формализации. `EXPRESSIBLE` — восстановленная выразимость или проверяемость. `STOPPED` — остановка без решения с записанными неопределённостями.

«Решение не найдено», «метод неизвестен» и «невозможность доказана» — три разных исхода; смешивать их нельзя.
