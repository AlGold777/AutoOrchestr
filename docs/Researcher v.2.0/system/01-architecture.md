# Архитектура

Система ведёт научное исследование и одновременно улучшает способ, которым его ведёт. Она работает на AutoOrchestr Basic: агенты — модели во вкладках браузера, этапы — схемы Basic, решения о маршруте принимает владелец.

Статус: версия 2.0, проект. Полный цикл не запускался ни разу; единственный живой прогон — рецензия одного документа методологии v.1.0. Что изменено против v.1.0 и почему — [../review-decisions.md](../review-decisions.md).

## 1. Части системы

| Часть | Что делает | Документы |
| --- | --- | --- |
| Ядро | Хранит то, что система менять не вправе: задачу, критерии, пороги, правила проверки, закрытые наборы, журнал | [04-core.md](04-core.md) |
| Круг исследования | Ищет, выдвигает гипотезы, проверяет, записывает | [../process/02-cycle.md](../process/02-cycle.md) |
| Круг обучения | Замечает, что мешает сам метод, меняет его и доказывает, что изменение помогло | [../methodology/03-change-operator.md](../methodology/03-change-operator.md) |
| Проверка системы | Полигон, корпус порч, контроль, оценка | [../verification/](../verification/) |
| Человек | Владелец, исполнитель ручных заданий, внешний наблюдатель | [06-human.md](06-human.md) |

Методология ([../methodology/](../methodology/)) задаёт правила для обоих кругов. Роли и состав — [05-roles.md](05-roles.md).

## 2. Два слоя

**Неизменяемый слой** — ядро. Агенты его читают, но не пишут. Меняет только владелец отдельной операцией с записью в журнал.

**Изменяемый слой** — конфигурация `C_n`: представление задачи, правило выбора шага, приёмы ролей, изменяемые пороги. Круг обучения меняет только её. Состав моделей и порядок шагов в неё не входят: их задаёт схема, и меняет их владелец пересборкой. Приёмы исполнителя проверки, проверяющих, секретарей и контролёров — ядро.

Запросы агентам и схемы Basic в этой папке — среда исполнения. Они постоянны: агент получает общий запрос роли и действует по разделу конфигурации для своей роли. Перестройка метода — это новая версия конфигурации, а не новая схема. Правка самих запросов и схем — операция владельца, она меняет `config_id` (см. [03-decisions.md](03-decisions.md), Р10).

## 3. Что переходит из цикла в цикл

Запросы цикла получают **пакет цикла** — один текст из четырёх частей. Исключение — исполнитель проверки, проверяющие, секретарь расхождений и контролёр записей: у них только свой вход.

| Документ | Слой | Кто меняет |
| --- | --- | --- |
| Выжимка ядра: цель, признак решения, запреты, пороги | неизменяемый | никто; сумма файла — в замке |
| Раздел «ХОД»: номер цикла, номер конфигурации, остаток бюджета | счёт владельца | владелец перед каждым циклом |
| Конфигурация `C_n` | изменяемый | круг обучения, с подписью владельца |
| Карта вопроса: что известно, гипотезы, ямы, пробелы, противоречия, триггеры, очередь владельца | указатель к журналу | секретарь журнала; контролёр карты сверяет; владелец правит в окне |

Пакет не длиннее 14 000 знаков: запрос Basic ограничен 52 000 знаков вместе с входом.

Журнал — источник истины. На Basic это экспорты прогонов и цепочка их хешей ([04-core.md](04-core.md), §3). Записи секретаря и карта — указатель к журналу: каждая строка карты ссылается на номер записи, при расхождении права выгрузка.

## 4. Жизненный цикл

```
Э0 карточка задачи → Э1 предполёт → Э2 настройка и ратификация
        → Э3 исследование (циклы) ⇄ Э4 перестройка
        → Э6 выход
Э5 периодика идёт параллельно Э3: калибровка, аудит, красная команда
```

Подробно — [../process/01-lifecycle.md](../process/01-lifecycle.md).

## 5. Режимы исполнения

| Режим | Как идёт | Ограничение |
| --- | --- | --- |
| Репетиция | Цепочка хешей не ведётся или в пакете есть раздел «ТЕСТ» | Статусы по такому прогону не меняются |
| По шагам | Один запуск схемы — один цикл; в конце окно решений владельца | — |
| Непрерывный | Цикл повторяется, пока владелец не остановит; окно решений — раз в N циклов | В Basic пока нет: [../process/04-endless-mode.md](../process/04-endless-mode.md) |

## 6. Схема

```
                      ВЛАДЕЛЕЦ
      окно решений · ручные задания · операции над ядром · Stop
            ▲ сводка                    ▲ донесения напрямую
        ДОКЛАДЧИК                    КОНТРОЛЁР
            ▲                           ▲
   ┌────────┴───────────────────────────┴─────────┐
   │ КРУГ ИССЛЕДОВАНИЯ (один цикл)                 │
   │ координатор → поиск → гипотезы → заявка       │
   │ → исполнение проверки → слепая проверка       │
   │ → расхождения → диагноз метода → записи       │
   │ → контроль записей → карта → контроль карты   │
   └────────┬──────────────────────────────────────┘
            │ триггер и решение владельца
   ┌────────▼──────────────────────────────────────┐
   │ КРУГ ОБУЧЕНИЯ (схемы перестройки)             │
   │ предложения → приёмка → выбор владельца       │
   │ → контрольное изменение → две конфигурации    │
   │ → испытание в три плеча → счёт → вердикт      │
   │ по правилу → библиотека                       │
   └───────────────────────────────────────────────┘

   ЯДРО: карточка задачи · пороги · правила проверки ·
         закрытые наборы · журнал и цепочка хешей
   ПЛАТФОРМА: AutoOrchestr Basic — вкладки моделей, схемы, запись прогона
```
