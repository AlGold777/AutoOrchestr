# Исполнение на Basic

Каждый этап — схема в [schemas/](schemas/). Схемы собираются из запросов папки [../prompts/](../prompts/README.md). Запуск из корня проекта:

```bash
node "docs/Researcher v.2.0/basic/build-schemas.mjs"
```

Сборка делает четыре проверки и при любой неудаче схемы не выдаёт:

1. Каждая схема проходит валидатор Basic.
2. Каждый запрос вошёл хотя бы в одну схему.
3. Наибольший запрос каждого шага помещается в предел 52 000 знаков. Считается с запасом: слово — 8 знаков, ответы длиннее своих пределов на четверть.
4. Пары независимости из [../system/05-roles.md](../system/05-roles.md), §1 не нарушены: одна модель не стоит по обе стороны пары.

Файлы схем руками не правятся.

## 1. Схемы

| Схема | Этап | Шагов моделей | Запросов | Шагов владельца | Что вводить как задачу |
| --- | --- | --- | --- | --- | --- |
| `1-task-card` | Э0 | 3 | 3 | 2 | Описание проблемы |
| `2-preflight` | Э1 | 7 | 17 | 1 | Карточка задачи |
| `3-setup` | Э2 | 7 | 9 | 1 | Карточка задачи, журнал отказов, выдержка библиотеки |
| `4-cycle` | Э3 | 16 | 20 | 2 | Пакет цикла |
| `4-cycle-endless` | Э3, непрерывный режим | 16 | 20 | 0 | Пакет цикла |
| `5-rebuild` | Э4 | 7 | 7 | 2 | Пакет цикла, ответ диагноста, выдержка библиотеки |
| `6-rebuild-verdict` | Э4 | 2 | 3 | 2 | Предсказание, сводки плеч А, Б, В, шум |
| `7-calibration` | Э5 | 2 | 4 | 2 | Выборка корпуса порч без ответов |
| `8-audit` | Э5 | 2 | 2 | 1 | Пакет цикла и выборка выводов |
| `9-exit` | Э6 | 4 | 5 | 1 | Пакет последнего цикла и перечень вердиктов |
| `10-polygon` | Э5 | 2 | 2 | 1 | Заказ задач |
| `11-methodology-review` | наладка | 2 | 5 | 1 | Текст одного документа методологии |

Схемы `7-calibration`, `10-polygon` и `11-methodology-review` нужны и при наладке, до первой задачи.

Установка: на странице pipeline — Import schema, выбрать файл. Имя pipeline — имя файла.

## 2. Как правила системы выражены в схеме

| Правило | Чем выражено |
| --- | --- |
| Предсказание до проверки | Заявка — шаг `r6`, проверка — `r7`, вердикты — `r8`. Порядок шагов в Basic не меняется |
| Исполнитель не знает гипотезы | Шаг `r6` отвечает JSON из трёх частей; `r7` получает только часть «процедура» и собственный запрос без текста задачи |
| Проверяющий не видит гипотезы и рассуждений автора | `r8` получает часть «запись заявки» — без утверждения — и сырой результат; текста задачи у него нет |
| Контроль раньше карты | Контроль записей — шаг `r13`, карта — `r14` и получает его донесение |
| Контролёр видит первичное | `r13` получает запись заявки, сырой результат, вердикты и записи проверки |
| Независимость ролей | Проверка пар при сборке |
| Новый чат на каждый шаг | `chat: "new"` |
| Обязательные поля заявки | `format: "json"` и `requiredFields`: ответ без полей Basic возвращает на исправление |
| Документ для владельца | `output.document: "read"`; владелец правит текст в окне, отправленный текст — утверждённая версия |
| Общие правила в каждом запросе | `defaults.discipline.content`; их получают и участники с собственным запросом |
| Условные шаги | Условие записано в запросе: роль, которой нечего делать, отвечает одной строкой |
| Остановка по метке | `run.stopMarks`: `4-cycle` — «ЦИКЛ НЕ ВЫПОЛНЯЕТСЯ»; `4-cycle-endless` — плюс «ТРЕВОГА:» и «СТОП:» |
| Пропуск без вопроса | `run.onNoAnswer: "skip"` только в `4-cycle-endless`; в `4-cycle` — `ask` (по умолчанию) |
| Повтор захода | `run.repeat` только в `4-cycle-endless`: перенос артефакта `map` шага `r14` после строки «=== КАРТА ВОПРОСА ===», пределы 10 заходов и 250 запросов, окно владельца раз в 5 заходов, карта не длиннее 7 500 знаков. Заход — обычный прогон схемы |

Участник с собственным запросом получает только свой вход: текст задачи попадает в запрос лишь через подстановку `{задача}`, а её в этих запросах нет. Так устроены `r7`, `r8`, `r9`, `r13` цикла, автор контрольного изменения и проверяющий изменение в `5-rebuild`, счётчик в `7-calibration`. Это свойство движка проверено по коду (`disput/custom-engine.js`, сборка запроса) и проверяется приёмочным тестом 7 по выгрузке.

Участники одной модели с разными ID ведут разные чаты: Claude-координатор не видит чата Claude-генератора.

## 3. Пределы

| Предел Basic | Что из него следует |
| --- | --- |
| 52 000 знаков на запрос вместе с входом | Пакет цикла — до 14 000 знаков: выжимка ядра до 1 500, раздел «ХОД» до 300, конфигурация до 4 500, карта до 7 500. Секретарь журнала разбит на три шага |
| Предел слов ответа Basic не принуждает | Длинный ответ принимается; поэтому размер считается с запасом. Строгая длина включена только у рецензентов методологии |
| Шаги строго по порядку, без ветвлений и повторов | Условия — в запросах. Маршрут между схемами выбирает владелец |
| Не больше двух шагов владельца без замечания | В цикле два: ручное задание и окно решений |
| Нет исполнения кода | Код запускает владелец или модель в своей среде; происхождение результата записывается и ограничивает статус |
| Нет шагов приложения | Записи, карту и сводку пишут модели; выгрузка прогона — первичная запись; бюджет считает владелец |

На шагах с собственным запросом проверка схемы показывает замечание «у раунда нет task»: это намеренно.

Наибольшие запросы по оценке сборки: записи проверки и контроль карты в цикле — 88% предела; журнал отказов в предполёте — 90%.

## 4. Чего в Basic пока нет

Для непрерывного режима — [../process/04-endless-mode.md](../process/04-endless-mode.md), §5.

Кроме того:

| Чего нет | Чем заменяется |
| --- | --- |
| Скрытия имени участника во входе | Приёмщик судит форму; счётчики испытания получают плечи под именами А, Б, В |
| Случайного выбора | Пункт контрольного изменения и порядок плеч задаёт контрольная сумма последней строки журнала |
| Импорта файла как текста задачи | Владелец вставляет пакет в поле задачи |
| Проверки ответа по JSON Schema | `requiredFields` шага и сверка контролёром; форматы в [../data/](../data/README.md) описывают содержание документов |
| Счётчика запросов | Владелец считает по выгрузке |

## 5. Замена моделей

Состав по умолчанию — восемь моделей: Claude, DeepSeek, GPT, Qwen, Grok, Z.ai, Perplexity, Le Chat. Замена делается в `build-schemas.mjs` и пересборкой, а не правкой JSON. Сборка откажет, если замена нарушает пары независимости. Искателем может быть только модель с поиском по сети. Смена проверяющего требует новой калибровки.
