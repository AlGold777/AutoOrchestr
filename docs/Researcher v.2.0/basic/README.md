# Исполнение на Basic

Каждый этап — схема в [schemas/](schemas/). Схемы собираются из запросов папки [../prompts/](../prompts/README.md):

```bash
node docs/Researcher/basic/build-schemas.mjs
```

Сборка проверяет каждую схему валидатором Basic, сверяет, что каждый запрос вошёл в схему, и оценивает размер запросов против предела в 52 000 знаков. Файлы схем руками не правятся.

## 1. Схемы

| Схема | Этап | Шагов моделей | Шагов владельца | Что вводить как задачу |
| --- | --- | --- | --- | --- |
| `1-task-card` | Э0 | 3 | 2 | Описание проблемы |
| `2-preflight` | Э1 | 7 | 1 | Карточка задачи |
| `3-setup` | Э2 | 7 | 1 | Карточка задачи и журнал отказов |
| `4-cycle` | Э3 | 19 | 2 | Пакет цикла |
| `4-cycle-endless` | Э3, непрерывный режим | 19 | 0 | Пакет цикла |
| `5-rebuild` | Э4 | 2 | 1 | Пакет цикла и выбранное предложение |
| `6-rebuild-verdict` | Э4 | 2 | 1 | Предложение, итоги плеч, шум |
| `7-calibration` | Э5 | 2 | 2 | Выборка корпуса порч без ответов |
| `8-audit` | Э5 | 2 | 1 | Пакет цикла и выборка выводов |
| `9-exit` | Э6 | 4 | 1 | Пакет последнего цикла и перечень вердиктов |
| `10-polygon` | Э5 | 2 | 1 | Заказ задач |
| `11-methodology-review` | до Э0 | 2 | 1 | Текст одного документа методологии |

Установка: на странице pipeline — Import schema, выбрать файл. Имя pipeline — имя файла.

## 2. Как правила системы выражены в схеме

| Правило | Чем выражено |
| --- | --- |
| Предсказание до проверки | Заявка — шаг `r6`, проверка — `r7`, вердикты — `r8`. Порядок шагов в Basic не меняется |
| Исполнитель не знает гипотезы | Шаг `r6` отвечает JSON с двумя артефактами; `r7` получает только артефакт «процедура» и собственный запрос без текста задачи |
| Проверяющий не видит рассуждений автора | `r8` получает артефакт «запись заявки», сырой результат и собственный запрос без текста задачи |
| Автор и проверяющий из разных групп | Состав участников схемы |
| Новый чат на каждый шаг | `chat: "new"` |
| Обязательные поля заявки | `format: "json"` и `requiredFields`: ответ без полей Basic возвращает на исправление |
| Документ для владельца | `output.document: "read"`; владелец правит текст в окне, отправленный текст — утверждённая версия |
| Общие правила в каждом запросе | `defaults.discipline.content` |
| Условные шаги | Условие записано в запросе: роль, которой нечего делать, отвечает одной строкой |

Участники одной модели с разными ID ведут разные чаты: Claude-координатор не видит чата Claude-генератора.

## 3. Пределы

| Предел Basic | Что из него следует |
| --- | --- |
| 52 000 знаков на запрос вместе с входом | Пакет цикла — до 12 000 знаков, карта — до 8 000. Секретарь журнала разбит на два шага. Пределы слов у ролей подобраны так, чтобы запрос помещался; сборка это считает |
| Шаги строго по порядку, без ветвлений и повторов | Условия — в запросах. Маршрут между схемами выбирает владелец |
| Не больше двух шагов владельца без замечания | В цикле два: ручное задание и окно решений |
| Нет исполнения кода | Проверку исполняет модель в своей среде или владелец |
| Нет шагов приложения | Записи, карту и сводку пишут модели; экспорт прогона — первичная запись |

На шагах `r7` и `r8` цикла проверка схемы показывает замечание «у раунда нет task»: у этих участников собственный запрос, это намеренно.

## 4. Чего в Basic пока нет

Для непрерывного режима — [../process/04-endless-mode.md](../process/04-endless-mode.md), §4: повтор схемы, перенос карты в задачу следующего захода, чекпоинт раз в N заходов, цепочка хешей экспортов, остановка по метке в ответе, пропуск не ответившего участника.

Кроме того:

| Чего нет | Чем заменяется |
| --- | --- |
| Скрытия имени участника во входе | Приёмщик и судья судят форму и числа, а не автора |
| Случайного выбора | Плацебо выбирается по номеру цикла |
| Импорта файла как текста задачи | Владелец вставляет пакет в поле задачи |
| Проверки ответа по JSON Schema | `requiredFields` шага и сверка контролёром |

## 5. Замена моделей

Состав по умолчанию — восемь моделей: Claude, DeepSeek, GPT, Qwen, Grok, Z.ai, Perplexity, Le Chat. Замена делается в `build-schemas.mjs` и пересборкой, а не правкой JSON. Правила замены — [../system/05-roles.md](../system/05-roles.md), §1 и §4: автор и проверяющий остаются в разных группах.
