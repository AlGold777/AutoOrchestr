# Корпус порч и калибровка

Корпус — верные утверждения с выводом и их копии, в которые внесена ошибка. Один корпус служит двум целям: калибровке проверяющих и проверке самих процедур проверки.

## 1. Состав

Элемент — [../data/schemas/corpus-item.schema.json](../data/schemas/corpus-item.schema.json). Верных и испорченных примерно поровну.

| Вид порчи | Критическая |
| --- | --- |
| Подмена квантора: «для всех» ↔ «существует» | да |
| Потеря условия | да |
| Циклическая ссылка: вывод опирается на себя | да |
| Сдвиг на единицу | нет |
| Неверная база индукции | да |
| Подстановка целевого числа: результат вписан, а не получен | да |
| Смена единиц | нет |
| Ложная ссылка: источник не содержит утверждения | да |
| Вывод шире данных | нет |
| Смешение корреляции и причины | нет |

Критическая порча обязана ловиться всегда. Доля прочих задаётся порогом до калибровки.

Половина корпуса — общая, половина — из области задачи. Общая половина собирается при наладке, до первой задачи; областная — при настройке каждой задачи, после чего калибровка повторяется. Корпус собирает владелец и внешний наблюдатель; модели, которые будут калиброваться, в составлении не участвуют. Пока областной половины нет, проверка в этой области не поднимает статус выше S1.

## 2. Хранение

`sealed/corpus/`: утверждения и ключ лежат в разных файлах. В прогон калибровки идёт только выборка утверждений; ключ владелец вставляет после ответов проверяющих. Выборка, прошедшая через прогон, повторно тем же моделям не даётся.

Корпус пополняется: каждая порча, пропущенная всеми, каждый посев, который никто не поймал, каждый вывод, отозванный аудитом, даёт новый вид или новый пример. Пополнение — операция над ядром; после неё калибровка повторяется на выборке с новыми элементами. Корпус только растёт: элемент, который проверяющие не ловят, из него не убирается — иначе число проверяющего росло бы от изъятия трудного.

## 3. Калибровка проверяющего

Схема `7-calibration`. Счётчик сверяет ответы с ключом построчно; числа по его таблице пересчитывает владелец и записывает событием журнала вместе с размером выборки, версией корпуса и отпечатками моделей. В файл замка они не идут.

Итог — два числа каждому проверяющему и третье на всех:

- доля найденных порч = найдено испорченных / всего испорченных;
- доля ложных срабатываний = верные, названные испорченными / всего верных;
- доля порч, пропущенных всеми сразу.

Числа записываются с размером выборки: на двадцати порчах доля известна с точностью около пятнадцати–двадцати пунктов, и порог, пройденный на пункт, ничего не значит. Проверяющий допущен, если прошёл порог с запасом на этот разброс либо на выборке вдвое большей.

Порча, названная без верного места, считается пропуском.

Пороги `checker_detect_min` и `checker_false_max` владелец записывает до калибровки исходя из цены пропуска ложного вывода. После калибровки меняется проверяющий, а не порог. Проверяющий без двух чисел подтверждать не вправе; его вердикты записываются, но статус не поднимают.

Калибровка повторяется при смене модели провайдером, при новой версии корпуса и раз в период из карточки. Владелец проходит ту же разметку ([../system/06-human.md](../system/06-human.md), §5).

**Общая слепая зона.** Порча, пропущенная всеми проверяющими сразу, — мера зависимости их ошибок. Будь ошибки независимы, все сразу пропускали бы долю, равную произведению долей пропуска каждого. Если пропущенных всеми заметно больше, три проверяющих работают как один; независимость тогда считается только по способу проверки, а не по числу моделей.

## 4. Проверка процедуры проверки

В каждой заявке экспериментатор задаёт холостой прогон и порчу ([../prompts/4-cycle.md](../prompts/4-cycle.md), C06). Исполнитель обязан показать, что процедура отказала на пустых данных и поймала порчу. Не показано — вердикт «повторить».

Выжившая порча — приговор процедуре проверки, а не гипотезе. Процедуру исправляют; гипотезу не вычёркивают.

## 5. Чего корпус не даёт

Корпус содержит известные виды ошибок. Заблуждение, общее для всех моделей и для составителей корпуса, он не ловит. Корпус показывает, что проверяющий что-то ловит, а не что он ловит нужное.
