# Протокол оценки

Как доказывается, что система работает, а не изображает работу. Всё, что здесь задаётся, записывается до прогонов и после получения результатов не меняется.

## 1. Что проверяется

Одно центральное утверждение: **перестройка метода по диагнозу даёт больше проверенных результатов, чем то же самое без перестройки и чем перестройка без диагноза, при равном бюджете.**

Это утверждение о методе, а не об одной перестройке. Испытание в задаче ([../methodology/03-change-operator.md](../methodology/03-change-operator.md), §6–7) решает, принять ли одно изменение в одной задаче. Утверждение о методе проверяется только здесь: на задачах полигона, с числом пар и порогом, записанными заранее. Сколько бы перестроек ни подтвердилось в задачах, без этого сравнения сказать «метод работает» нельзя: считаются все попытки, а не только удачные.

Три вспомогательных: проверка ловит ложное; неудачи сужают поиск; диагност называет настоящую причину.

## 2. С чем сравнивается

Бюджет равный во всех трёх единицах: запросы к моделям, запуски проверок, минуты владельца.

| Плечо | Что это |
| --- | --- |
| Одиночное рассуждение | Одна сильнейшая модель, один длинный ответ |
| Перебор с проверяющим | Несколько независимых ответов и отбор способом проверки |
| Стандартный метод области | Без изобретательности |
| Система без перестройки | Та же конфигурация `C0`; схема `5-rebuild` не запускается |
| Система с контрольным изменением | При триггере применяется контрольное изменение: пункт каталога по контрольной сумме, без диагноза |
| Система | Полная |

Сравнение только по запросам к моделям недействительно: выигрыш, оплаченный минутами владельца, не выигрыш.

## 3. Два ряда задач

- **Ряд А** — управление: задачи с дешёвой точной проверкой (скрытый закон, двойники, негативные). Показывает выигрыш от выбора шага, отсечения, остановки, проверки.
- **Ряд Б** — понятия: задачи с удалённым понятием и ложной предпосылкой. Показывает выигрыш от смены представления.

Один ряд не заменяет другой: отбор только по ряду А убивает методы, которые нужны для ряда Б.

## 4. Правило решения

Сравнение парное: одна и та же задача полигона проходится в двух плечах при равном бюджете. Пара — одна задача. Плечо выиграло пару, если дало на ней больше проверенных результатов; на задаче со скрытым ответом — если решило её, а другое нет. Равный исход — ничья.

Число пар `trial_pairs` и порог записываются в ядро до первого прогона. Решает знаковый критерий: ничьи отбрасываются; утверждение подтверждено, если из оставшихся пар полное плечо выиграло не меньше порога.

| Пар без ничьих | Побед нужно | Вероятность такого счёта при равных плечах |
| --- | --- | --- |
| 8 | 7 | 0,035 |
| 10 | 9 | 0,011 |
| 12 | 10 | 0,019 |
| 15 | 12 | 0,018 |
| 20 | 15 | 0,021 |

Правила:

1. Пар без ничьих осталось меньше восьми — исход «данных мало»: сравнение продолжается на новых задачах, вывода нет.
2. Число пар не увеличивается после того, как виден счёт. Досрочная остановка — только по бюджету, с исходом «данных мало».
3. Сравнений два: полная система против контрольного изменения и полная против системы без перестройки. Подтверждено — когда порог пройден в обоих.
4. Исходов три: «подтверждено», «не подтверждено», «данных мало». «Не подтверждено» значит: при записанном числе пар преимущество не показано. Это не доказательство, что преимущества нет; но проект по этому исходу закрывается — так записано заранее ([../methodology/04-audit.md](../methodology/04-audit.md), §5).
5. Какой наименьший перевес критерий способен заметить, видно из таблицы: при десяти парах нужно девять побед. Метод, который выигрывает две пары из трёх, такой набор обычно не подтвердит. Если интересен меньший перевес — число пар увеличивается до прогонов, а не после.

Шум в единицах показателя этому правилу не нужен. Он нужен только испытанию одной перестройки в задаче: там он измеряется двумя прогонами действующей конфигурации.

## 5. Удаление частей

Вклад механизма измеряется его удалением на замороженной конфигурации: живая конфигурация, которая перестраивается, для этого не годится.

| Что удаляется | Что должно ухудшиться |
| --- | --- |
| Диагност и перестройка | Доля решённых задач ряда Б |
| Плацебо-сравнение | Ничего в результатах; исчезает возможность приписать выигрыш диагнозу |
| Ямы | Доля шагов, повторяющих тупик |
| Слепая проверка | Доля ложных подтверждений |
| Альтернативщик | Разнообразие гипотез по четырём признакам |
| Предсказание до проверки | Доля подтверждений, не отличимых от наивных |
| Роль | Время до результата, качество, минуты владельца |

Механизм, удаление которого ничего не меняет, декоративен и убирается владельцем изменением схемы. Слепая проверка, предсказание до проверки и контролёр удалению по полезности не подлежат: это ядро.

## 6. Что записывается заранее

В `core/thresholds.txt` и на странице ратификации, до первого цикла:

- какой исход подтверждает центральное утверждение;
- какой означает частичный выигрыш: только ряд А или только ряд Б;
- какой опровергает: система не лучше плацебо; система не лучше себя без перестройки;
- kill-критерии концепции ([../methodology/04-audit.md](../methodology/04-audit.md), §5);
- сколько испытаний допускается до вывода.

Полный реестр со способами накрутки — [../operations/04-metrics.md](../operations/04-metrics.md). Главные:

| Показатель | Источник |
| --- | --- |
| Цена проверенного результата | Расход по выгрузкам / число результатов S1 и выше |

| Два числа проверяющих | Калибровка |
| Перенос на новые задачи | Следующий проект |

## 8. Наименьшая версия

То, что проверяет центральное утверждение за наименьшую цену:

1. Двадцать задач ряда А и десять ряда Б, порождённых параметрически.
2. Корпус порч из сорока элементов; калибровка трёх проверяющих.
3. Схема `4-cycle` на задачах полигона в трёх плечах: без перестройки, с контрольным изменением, полная. Бюджет на задачу одинаков.
4. Одно утверждение и правило решения из §4: полная система выигрывает у обоих других плеч не меньше порога пар.
5. Исход записывается одним из трёх слов: «подтверждено», «не подтверждено», «данных мало».

Цена наименьшей версии при трёх циклах на задачу: 30 задач × 3 плеча × 3 цикла × 20 запросов — около 5 400 запросов и 270 запусков проверок, не считая перестроек. Это много для вкладок браузера. Поэтому первой проходится половина: ряд А, десять задач, два плеча — полная и с контрольным изменением; исход «данных мало» по ней законен.

В наименьшую версию не входят: непрерывный режим, аудит, красная команда, библиотека перестроек, перенос между задачами.
