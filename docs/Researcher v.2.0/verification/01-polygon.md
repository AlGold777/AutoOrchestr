# Полигон

Задачи с известным владельцу ответом. На них проверяется сама система: работает ли проверка, отличается ли перестройка по диагнозу от плацебо, называет ли диагност настоящую причину. Настоящая задача этого не покажет: она одна и её ответ неизвестен.

## 1. Семейства задач

| Семейство | Что проверяет | Как строится |
| --- | --- | --- |
| Скрытый закон | Поиск с дешёвой проверкой; ловушки | Данные порождены правилом; в данных есть закономерность-ловушка |
| Удалённое понятие | Смену представления | Известная задача переписана без ключевого понятия и его синонимов; проверка частных случаев сохранена |
| Ложная предпосылка | Работу с предпосылкой | В условие вживлено неявное допущение, без отказа от которого решения нет |
| Двойник | Заученное против выведенного | Задача с изменёнными числами и обозначениями |
| Негативная | Честное «решить нельзя» | Данных мало, источники противоречат или вопрос некорректен |
| Вживлённый дефект метода | Диагноста метода | В конфигурацию вносится известная ошибка приёма; верный итог — диагноз называет её |

Задачи строит генератор миров (схема `10-polygon`) и владелец. Модель, построившая задачу, её не решает. Лучший источник — параметрическое порождение: условие строится по параметрам, которых модель не видела. Формат — [../data/schemas/polygon-task.schema.json](../data/schemas/polygon-task.schema.json).

Чего полигон не показывает: задача с удалённым понятием проверяет работу без понятия, а не создание понятия, которого не было ни у кого.

## 2. Наборы

| Набор | Где хранится | Для чего | Доступ |
| --- | --- | --- | --- |
| Отладочный | `polygon/` | Наладка схем и запросов | Свободный |
| Зачётный | `sealed/scored/` | Испытания перестроек, сравнение с простыми подходами | С записью в журнал; предел обращений |
| Финальный | У внешнего наблюдателя | Итоговая оценка системы | Один раз |

Наборы делятся по семействам и по способу порождения, а не случайно: задачи одного порождения не попадают в разные наборы.

Расхождение результата на зачётном и финальном наборе — признак того, что зачётный набор выучен.

## 3. Расход закрытых наборов

Каждое испытание перестройки сообщает системе немного о зачётном наборе. Поэтому:

1. Обращение — запись журнала `closed_set_access`: какое испытание, какие задачи.
2. Счётчик обращений — в `core/lock.json`; предел — порог `closed_set_access_limit`.
3. Исчерпанный набор переводится в отладочные; генератор миров строит новый.
4. Задача, условие которой попало в ответ модели вне прогона по ней, сгорает сразу.

## 4. Прогон на задаче полигона

Схема `4-cycle`, пакет собран из задачи: в ядре — условие и способ проверки. Скрытая часть остаётся у владельца; исход проверки по ней владелец возвращает на шаге ручного задания одним словом или числом.

Для задачи с вживлённым дефектом метода владелец вносит дефект в раздел конфигурации пакета и смотрит ответ диагноста метода на шаге `r10`.

## 5. Что считается на полигоне

| Показатель | Как |
| --- | --- |
| Доля решённых задач при равном бюджете | Система против трёх простых подходов |
| Доля ложных подтверждений | Вердикт «подтверждено» при неверном скрытом ответе |
| Доля честных отказов | На негативных задачах |
| Доля залипших ответов | На двойниках: ответ исходной задачи вместо нового |
| Доля восстановленной выразимости | На задачах с удалённым понятием |
| Точность диагноста | Доля вживлённых дефектов, названных причиной |
| Перестройка против плацебо | Разница плеч в единицах шума |

Перед первым сравнением измеряется шум: одна и та же конфигурация дважды на одних и тех же задачах.
