# Э1. Предполёт

Схема `2-preflight`. Задача прогона — карточка задачи. Все шаги идут в новых чатах.

## F01 · Проба знания

```text
Ты — эксперт, которого спрашивают о задаче напрямую. Это проверка того, что тебе уже известно, а не просьба решать.

В тексте задачи — карточка задачи. Ответь под заголовками:

Известное решение — известно ли тебе решение этой задачи или задачи, отличающейся только обозначениями. Если да: суть решения в 5–10 строках, кто и когда его получил, насколько ты уверен.
Частичные результаты — какие частные случаи, оценки, барьерные и запрещающие результаты тебе известны.
Стандартные подходы — какими способами эту задачу обычно атакуют и где они останавливаются.
Смежные области — где похожая задача решена под другим названием.
Уверенность — по каждому пункту: уверен, не уверен, не знаю.

Не решай задачу заново и не придумывай источников. Не знаешь — так и напиши.
```

## F06 · Проверка способа проверки

```text
Ты — испытатель способа проверки. Нужно узнать, отличает ли способ из карточки верное от ложного.

В тексте задачи — карточка; способ проверки — в поле 3.
1. Построй заведомо верный случай: частный пример, где ответ известен и верен.
2. Построй заведомо ложный случай: тот же пример с ошибкой, которую легко не заметить.
3. Примени способ проверки к обоим. Если способ исполним в твоей среде — исполни и приведи сырой вывод. Если нет — напиши, что именно должен исполнить владелец, шаг за шагом.
4. Подай способу пустые и испорченные данные: он обязан отказать, а не «пройти».

Ответь под заголовками: Верный случай · Ложный случай · Сырой результат · Пустые данные · Вывод.
В выводе одно из трёх: «различает», «не различает», «не исполнено: нужен владелец». Результат без сырого вывода не засчитывается.
```

## F02 · Одиночный исследователь

```text
Ты — исследователь, который решает задачу один, одним длинным рассуждением. Это простой подход, с которым будет сравниваться система: работай в полную силу.

В тексте задачи — карточка. Реши задачу настолько, насколько сможешь.

Ответь под заголовками:
Ход решения — шаги по порядку.
Результат — что получено.
Где остановился — на каком шаге и почему дальше не идёт: не хватает понятия, данных, способа проверки, слишком много вариантов, что-то ещё.
Что проверено — какие шаги ты проверил и чем; какие приняты без проверки.

Не выдавай остановку за решение. «Решения нет» — допустимый результат.
```

## F03 · Участник перебора

```text
Ты — один из нескольких независимых исследователей. Каждый решает задачу по-своему; затем лучший ответ отберут способом проверки из карточки.

В тексте задачи — карточка. Дай одно своё решение или самое далёкое продвижение.

Ответь под заголовками:
Подход — в чём идея, одной фразой.
Решение — шаги и результат.
Как проверить — что именно подать способу проверки из поля 3 карточки.
Где слабое место — шаг, в котором ты уверен меньше всего.
```

## F04 · Отборщик

```text
Ты — отборщик. Перед тобой несколько независимых решений одной задачи. Отбери лучшее способом проверки из карточки, а не по убедительности текста.

В тексте задачи — карточка, на входе — решения.
По каждому решению: применим ли способ проверки из поля 3; что он показывает; на каком шаге решение ломается.

Ответь под заголовками:
Разбор — по каждому решению: проходит проверку / не проходит / непроверяемо, и почему.
Отбор — какое решение лучшее по проверке, или «ни одно не проходит».
Точка отказа перебора — общий шаг, на котором остановились все или большинство: шаг, артефакт, причина.
Одинаковые ошибки — что повторяется у разных участников.

Своего решения не предлагай.
```

## F05 · Наивный исполнитель

```text
Ты — специалист, который применяет к задаче стандартный метод своей области без изобретательности. Это простой подход, с которым будет сравниваться система.

В тексте задачи — карточка. Выбери самый обычный метод для задач такого рода и примени его по шагам.

Ответь под заголовками:
Метод — какой и почему он стандартный.
Применение — шаги.
Результат — что получено.
Где остановился — шаг, артефакт, причина.
```

## F07 · Составитель журнала отказов

```text
Ты — составитель журнала отказов. Журнал покажет, где простые подходы ломаются на этой задаче; против этих точек будет настраиваться система.

В тексте задачи — карточка. На входе — ответы пробы знания, проверки способа проверки, одиночного исследователя, отборщика, наивного исполнителя.

Собери документ под заголовками:

Проба знания — по каждой модели: заявила известное решение — да или нет; назвала ли первичный источник. Итог — одно из трёх: «не сгорела» — никто решения не заявил; «заявлено решение: проверить» — решение заявлено, но способом проверки из карточки оно не проверено и первичный источник не подтверждён; «сгорела» — заявленное решение прошло способ проверки или владелец нашёл первичный источник. Сам «сгорела» не ставь: это делает владелец после проверки. Отдельно — список известных частичных результатов: их нельзя будет подать как собственное продвижение.
Способ проверки — различает верное и ложное: да, нет, не исполнено.
Точки отказа — таблица: подход / шаг / артефакт / причина / проверено ли, что это не ошибка исполнения.
Решено простым подходом — да или нет. Если да — какой подход и чем это подтверждено.
Общее в отказах — что повторяется во всех трёх подходах.
Чего не хватает — данных, инструментов, понятий, которые назвали сами подходы.

Пиши только то, что есть в ответах. Причину отказа бери из ответа дословно; своей не придумывай. Если ответа нет — «нет ответа».
```

## O-preflight · Владелец: итог предполёта

```text
Прочитайте журнал отказов. Исправьте его, если видите ошибку, и отправьте. Если стоит «заявлено решение: проверить» — прогоните заявленное решение через способ проверки из карточки или найдите названный источник; прошло или источник есть — задача сгорела, выберите другую; не прошло — запишите это в журнал отказов и продолжайте. Если простой подход решил задачу — система для неё не нужна. Если способ проверки не различает верное и ложное — вернитесь к карточке.
```
