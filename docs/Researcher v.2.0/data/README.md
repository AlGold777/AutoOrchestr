# Форматы данных

Файлы в [schemas/](schemas/) — JSON Schema (draft 2020-12). Они описывают, какие поля обязан содержать каждый документ. Описание каждого поля — в самом файле.

Программой по этим форматам проверяется немногое: Basic проверяет обязательные поля заявки, остальное приходит текстом под заголовками. Поэтому форматы — описание содержания, по которому пишутся запросы ролей и по которому сверяют секретарь, контролёры и владелец. Документы владелец хранит текстом, как их выдал Basic.

## 1. Форматы

| Формат | Файл | Кто пишет | Где живёт | Чем проверяется |
| --- | --- | --- | --- | --- |
| Карточка задачи | `task-card` | владелец | `core/task-card.txt` | Проверяющий карточку; сумма в замке |
| Пороги ядра | `thresholds` | владелец на этапе Э2 | `core/thresholds.txt` | Сумма в замке |
| Замок ядра | `core-lock` | владелец | `core/lock.json` | Первая строка цепочки |
| Конфигурация | `config` | сборщик конфигурации, подпись владельца | `config/C<n>.txt` | Проверяющий изменение; сумма в журнале |
| Карта вопроса | `question-map` | секретарь журнала | `state/map.txt` | Контролёр карты; владелец в окне |
| Заявка на проверку | `claim` | экспериментатор | выгрузка цикла | Basic: три обязательные части |
| Гипотеза | `hypothesis` | генератор | запись цикла | Секретарь |
| Вердикт | `verdict` | секретарь журнала по ответам проверяющих | запись цикла | Контролёр записей |
| Факт | `fact` | обработчик источников | запись цикла | Секретарь |
| Противоречие | `conflict` | секретарь расхождений | запись цикла | Секретарь |
| Пробел | `gap` | координатор, исполнитель проверки | запись цикла | Секретарь |
| Яма | `pit` | секретарь журнала | запись цикла, `library/pits/` | Контролёр карты |
| Предложение изменения | `change-proposal` | методист, изобретатель, автор контрольного изменения | выгрузка `5-rebuild` | Приёмщик |
| Запись библиотеки перестроек | `rebuild-record` | библиотекарь | `library/rebuilds/` | Владелец |

| Решение владельца | `owner-decision` | владелец | событие журнала | — |
| Итоги ветки | `branch-summary` | секретарь журнала | запись цикла | Контролёр карты |
| Сводка | `digest` | докладчик | `state/digest.txt` | Владелец |
| Элемент корпуса порч | `corpus-item` | владелец, наблюдатель | `sealed/corpus/` | — |
| Задача полигона | `polygon-task` | генератор миров, владелец | `polygon/`, `sealed/` | Basic: поле `tasks`; проверяющий мир |
| Итог задачи | `final-report` | составитель итога | `out/final.txt` | Проверяющий итог |

Имя файла схемы: `schemas/<файл>.schema.json`.

## 2. Правила

1. Номера объектов: `F` факт, `G` гипотеза, `H` заявка, `V` вердикт, `K` противоречие, `P` пробел, `Y` яма, `X` предложение изменения, `L` запись библиотеки. Нумерация сквозная по задаче; номер не переиспользуется.
2. Номер записи цикла: `<цикл>.<а или б>.<порядковый>` — «а» для записей поиска, «б» для записей проверки. Каждая новая строка карты ссылается на номер записи.
3. Запись не правится. Исправление — новая запись со ссылкой на исправляемую.
4. Каждая запись несёт номер конфигурации. Записи разных конфигураций напрямую не сравниваются; при перестройке их судьбу определяет карта переноса.
5. Шаг, который отвечает в формате JSON, Basic проверяет сам: обязательные поля заданы в схеме шага. Ответ без них возвращается модели на исправление.
6. Шаг, который отвечает текстом, обязан содержать заголовки из запроса.
7. Источник истины — выгрузки прогонов в цепочке журнала. Записи секретаря и карта — указатель к ним: при споре права выгрузка. Карта из записей заново не выводится: её последняя утверждённая версия лежит в выгрузке цикла.

## 3. Папка задачи

Одна папка на задачу. Место выбирает владелец; модели к папке доступа не имеют.

```
<задача>/
  core/          task-card.txt · thresholds.txt · extract.txt · lock.json · sealed-test.txt
  config/        C0.txt · C1.txt · C1к.txt · …    все версии, ни одна не удаляется
  state/         map.txt · map-archive.txt · digest.txt · package.txt
  journal/       NNNN_<схема>_<дата>.json · NNNN_<событие>_<дата>.txt · chain.txt · records/
  runs/          <схема>_<дата>/{schema,artefacts,exports,notes}
  polygon/       открытые задачи полигона
  sealed/        corpus/ · scored/ · seeds/       закрытые наборы
  out/           final.txt · пакет воспроизведения · пост-мортем
```

`core/extract.txt` — выжимка ядра: поля карточки и пороги дословно. Его сумма записана в замке; в пакет он входит без изменений.

`state/map-archive.txt` — то, что свёрнуто из карты при сжатии: полные тексты закрытых гипотез и фактов по номерам. Моделям не отправляется; запись из него владелец вкладывает в пакет, когда её запросил координатор.

`core/lock.json` после подписи не меняется. Всё, что меняется по ходу работы, — события журнала: обращения к закрытым наборам, числа калибровки, запись перед испытанием, решения владельца.

Постоянная память хранится отдельно от задач: `library/pits/`, `library/rebuilds/`, `library/techniques/`. Запись из неё в новой задаче — гипотеза о переносе ([../methodology/03-change-operator.md](../methodology/03-change-operator.md), §10).

Финальный набор в папке задачи не хранится: он у внешнего наблюдателя.

## 4. Пакет цикла

`state/package.txt` собирает владелец перед запуском цикла из четырёх частей в таком порядке:

```
=== ЯДРО (версия N, только чтение) ===
файл core/extract.txt без изменений:
Задача · Признак решения · Чем проверяем · Чем не проверяем · Ограничения ·
Kill-критерии · Пороги

=== ХОД ===
Цикл N · Конфигурация C<n> · Остаток: запросов N, запусков проверок N, минут владельца N
Запрошенные записи: <номер> — <текст записи>

=== КОНФИГУРАЦИЯ C<n> ===
Диагноз барьера · Ведущая валюта · Представление задачи · Правило выбора шага ·
Приёмы ролей (по коду роли) · Изменяемые пороги

=== КАРТА ВОПРОСА ===
документ «Карта вопроса» последнего цикла, утверждённый в окне решений
```

| Часть | Предел, знаков | Кто пишет |
| --- | --- | --- |
| ЯДРО | 1 500 | Владелец один раз; дальше не меняется |
| ХОД | 300, с запрошенными записями — до 1 000 | Владелец перед каждым циклом |
| КОНФИГУРАЦИЯ | 4 500 | Сборщик конфигурации; подпись владельца |
| КАРТА ВОПРОСА | 7 500 | Секретарь журнала; правка владельца в окне |

Предел пакета — 14 000 знаков. Ядро и конфигурация входят целиком; если пакет длиннее, сжимается карта, а не они. Пакет длиннее предела не запускается.

Раздел «ТЕСТ» вставляется после раздела «ХОД» только в приёмочных прогонах ([../verification/05-acceptance.md](../verification/05-acceptance.md), §1).
