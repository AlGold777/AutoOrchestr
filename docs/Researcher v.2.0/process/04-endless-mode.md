# Непрерывный режим

Агенты работают цикл за циклом, пока владелец не остановит их своим решением. В Basic такого режима нет: схема идёт от первого шага до последнего один раз. Здесь описано, как режим устроен и что для него нужно от Basic. Это последний этап сборки: он ускоряет работу, но не делает её достовернее.

## 1. Как идёт

1. Владелец запускает схему `4-cycle-endless` с пакетом цикла и пределами: сколько заходов и сколько запросов разрешено.
2. Цикл проходит все шаги. Последние шаги выдают карту вопроса, донесения контролёров и сводку.
3. Приложение проверяет условия следующего захода (§3). Выполнены — собирает пакет: постоянная часть без изменений, карта новая — и запускает схему снова в новых чатах.
4. Через каждые `checkpoint_every` циклов открывается окно решений владельца.
5. Владелец останавливает работу кнопкой Stop в любой момент или решением «стоп» в окне.

Приложение при этом ничего не оценивает: оно повторяет, считает и сравнивает строки. Всё, что зависит от содержания, решают модели внутри запросов и владелец в окне.

## 2. Чем схема отличается от пошаговой

| | `4-cycle` | `4-cycle-endless` |
| --- | --- | --- |
| Ручное задание | шаг `owner:lane` | шага нет; «НУЖЕН ЧЕЛОВЕК» становится пробелом в карте, статус не повышается |
| Окно решений | после каждого цикла | раз в `checkpoint_every` циклов |
| Перестройка | по решению владельца после цикла | триггеры копятся в карте; решение и схема `5-rebuild` — на чекпоинте |
| Правка карты владельцем | до следующего цикла | на чекпоинте |
| Раздел «ХОД» | пишет владелец | номер цикла и остаток запросов подставляет приложение по своему счётчику |

Конфигурация между чекпоинтами не меняется: любая перестройка требует подписи владельца.

Без владельца нет и запуска проверок владельцем. Поэтому результаты непрерывного режима получены инструментом модели и не поднимаются выше S1, пока владелец не повторит запуск на чекпоинте.

## 3. Условия следующего захода

Приложение запускает следующий заход, только если выполнено всё. Каждое условие — счёт или сравнение строк.

| № | Условие | Не выполнено |
| --- | --- | --- |
| 1 | Счётчик заходов и счётчик запросов меньше пределов, заданных при запуске | Остановка «бюджет» |
| 2 | Контрольная сумма постоянной части пакета равна сумме при запуске | Остановка «ядро изменено» |
| 3 | Шаги секретаря журнала, обоих контролёров и докладчика получили принятый ответ | Остановка «нет записи» |
| 4 | Ни в одном ответе захода нет строки, которая после снятия разметки и пробелов начинается с «ТРЕВОГА:» или «СТОП:» | Остановка «тревога» |
| 5 | План координатора не начинается с «ЦИКЛ НЕ ВЫПОЛНЯЕТСЯ» | Остановка «ждём владельца» |
| 6 | Запись захода сохранена в файл, её сумма и сумма предыдущей записи записаны | Остановка «не сохранено» |
| 7 | Документ «Карта вопроса» шага r14 получен и не длиннее предела | Остановка «нет карты» |

Остановка — состояние, из которого новый заход запускает только владелец. Приложение показывает причину и последний заход. После перезапуска браузера режим не продолжается сам: владелец видит счётчики и последнюю сохранённую запись и запускает заново.

Метка тревоги — только один из семи тормозов. Модель может её не поставить; тогда остаются счётчики, сумма и обязательные ответы.

## 4. Что переносится

Задача захода делится на постоянную часть (ЯДРО, КОНФИГУРАЦИЯ) и переносимую. Постоянную приложение подставляет дословно, как при запуске. Переносимая:

- раздел «ХОД» — из счётчиков приложения;
- документ «Карта вопроса» шага r14 прошлого захода.

Донесение контролёра записей уже внутри карты: секретарь обязан перенести жёсткие нарушения в очередь владельца, контролёр карты это сверяет. Тревога контролёра карты останавливает режим по условию 4.

## 5. Что нужно от Basic

| № | Чего в Basic пока нет | Чем заменяется сейчас |
| --- | --- | --- |
| 1 | Повтор схемы: после последнего шага начать её заново | Сделано (T08): `run.repeat`, `runBasicRepeat`; заход = обычный прогон |
| 2 | Задача следующего захода из постоянной части, счётчиков и названного документа прошлого захода | Сделано (T07, T08): `BasicRepeat`; документ — артефакт `carry` |
| 3 | Новые чаты всех участников в начале каждого захода | Сделано (T08): каждый заход идёт с `forceNewTabs` |
| 4 | Шаг владельца раз в N заходов | Сделано (T08): окно «Повтор: заход N из M» раз в `ownerEvery` заходов |
| 5 | Счётчики заходов и запросов с пределами, заданными при запуске; видны всё время | Сделано (T08): пределы задаёт схема (не окно при запуске); строка ленты после каждого захода |
| 6 | Сумма постоянной части при запуске и сверка в каждом заходе | Не сделано: сумма разделов задачи пишется в запись захода (`taskSections`), сверки между заходами нет |
| 7 | Остановка по условиям §3, включая метку в любом шаге | Сделано для метки в ответе: `run.stopMarks` (T04), причина `stop_mark`. Остальные условия §3 — T05 и T08. Пока — холостое прохождение цикла и окно решений |
| 8 | Запись каждого захода в файл с его суммой и суммой предыдущей | Сделано: расширение пишет запись прогона и строку `chain.txt` в папку документов в конце каждого прогона (T03). Команды из [../operations/02-runbook.md](../operations/02-runbook.md), §3, — для запусков без выгрузки |
| 9 | Пропуск участника, не ответившего в срок, с пометкой в записи захода; для шагов из условия 3 пропуска нет | Сделано: `run.onNoAnswer: "skip"` (T05) пропускает участника без вопроса, а шаг без принятых ответов останавливает прогон (`no_answer`). Пометка в записи захода — за T08. Пока — владелец выбирает «пропустить» |

Пункты 1–4 дают повтор. Без пунктов 5–8 режим не включается: повтор без счётчиков и остановок — это работа без тормозов.

Запрос на 52 000 знаков остаётся пределом: пакет не длиннее 14 000 знаков, карта — 7 500.

## 6. Ворота включения режима

Непрерывный режим включается для задачи после того, как:

1. В режиме по шагам прошло не меньше `min_config_life` циклов без жёстких нарушений.
2. Проверяющие откалиброваны; посевы ловятся не хуже порога.
3. Подложенное расхождение записи с ответом найдено контролёром (приёмочный тест 17).
4. Пройдены тесты режима:

| Тест | Действие | Ожидаемое |
| --- | --- | --- |
| Н1 | Запустить с пределом запросов меньше одного цикла | Остановка «бюджет»; новых запросов нет |
| Н2 | Записать «СТОП» в карту | Остановка «ждём владельца» после первого шага; остальные шаги не идут |
| Н3 | Разделом «ТЕСТ» заставить секретаря исказить число | Тревога контролёра записей; остановка «тревога»; следующий заход не начат |
| Н4 | Остановить контролёра записей | Остановка «нет записи» |
| Н5 | Закрыть браузер посреди захода и открыть | Режим стоит; счётчики и последняя запись на месте; заход не продублирован |
| Н6 | Изменить знак в постоянной части между заходами | Остановка «ядро изменено» |
| Н7 | Остановить одного проверяющего из трёх | Заход помечен неполным; остальные идут |

5. Владелец записал в карточке `checkpoint_every`.
