# Рабочий цикл

Один запуск схемы `4-cycle` — один цикл. Шаги идут строго по порядку; условий приложение не проверяет, поэтому условная часть записана в самих запросах: роль, которой в этом цикле делать нечего, отвечает одной строкой.

## 1. Шаги

| Шаг | Роль | Вход | Выход |
| --- | --- | --- | --- |
| r1 | C01 Координатор | пакет | План цикла: вид цикла, активная гипотеза или вопрос, сверка с ямами, прогноз и наивный прогноз |
| r2 | C02 Искатели | r1 | Источники по вопросам плана или «поиска нет» |
| r3 | C03 Обработчик источников | r2 | Факты с классом надёжности |
| r4 | C04 Генераторы | r1, r3 | Гипотезы с основанием, признаками разнообразия, ценой проверки |
| r5 | C05 Альтернативщик | r4 | Конкурирующее объяснение каждой гипотезе |
| r6 | C06 Экспериментатор | r1, r4, r5 | Заявка `H#` из трёх частей: запись для проверяющих, процедура для исполнителя, заметка автора для записей |
| r7 | C07 Исполнитель проверки | только процедура | Сырой результат с происхождением, итог холостого прогона и прогона с порчей; или «НУЖЕН ЧЕЛОВЕК» |
| owner:lane | Владелец | r7 | Вывод запуска с пометкой «запуск владельца» или «нет» |
| r8 | C08 Слепые проверяющие | запись заявки, r7, owner:lane | Вердикт первой строкой, годность проверки, альтернативное объяснение, быстрейший тест |
| r9 | C09 Секретарь расхождений | запись заявки, r7, owner:lane, r8 | Число вердиктов; «расхождений нет» или точка спора и разрешающий тест |
| r10 | C10 Диагност метода | r1, r8, r9 | «Триггера нет» или «ТРИГГЕР: код» с причиной и конкурирующими причинами |
| r11 | C15a Секретарь журнала | r1, r3, r4, r5 | Записи цикла: поиск |
| r12 | C15c Секретарь журнала | r6, r7, owner:lane, r8, r9, r10 | Записи цикла: проверка |
| r13 | C16a Контролёр записей | запись заявки, r7, owner:lane, r8, r9, r12 | Донесение: нарушения, сверка чисел записей с сырым результатом |
| r14 | C15b Секретарь журнала | r11, r12, r13 | Обновлённая карта вопроса; донесение контролёра — в очереди владельца |
| r15 | C16b Контролёр карты | r11, r12, r13, r14 | Донесение: расхождения карты с записями и прежней картой |
| r16 | C17 Докладчик | r12, r14, r13, r15 | Сводка |
| owner:window | Владелец | карта r14, r13, r15, r16 | Исправленная карта и решение |

Шестнадцать шагов моделей, двадцать запросов, два шага владельца.

Пакет цикла получают все шаги, кроме r7, r8, r9 и r13: у них только свой вход. Запись заявки не содержит ни гипотезы, ни утверждения — проверяющий видит условия «за» и «против», способ измерения и наивное предсказание.

Предложений перестройки в цикле нет. Диагност называет триггер; предложения, контрольное изменение и сборка конфигураций — схема `5-rebuild` ([../methodology/03-change-operator.md](../methodology/03-change-operator.md)).

## 2. Виды цикла

Координатор выбирает один вид; остальные роли действуют соответственно.

| Вид | Когда | Что делают генераторы и экспериментатор |
| --- | --- | --- |
| Поиск | Мало фактов R1–R2 по активному вопросу | Генераторы выдвигают гипотезы; заявка — на самую дешёвую различающую проверку |
| Проверка | Есть гипотеза с ценой и различающей силой | Заявка на активную гипотезу |
| Разрешение | В карте открыто противоречие с разрешающим тестом | Заявка на разрешающий тест |
| Пробел | Закрытие пробела открывает больше путей, чем проверка | Заявка на проверку пользы от закрытия; задание владельцу — в очередь |
| Выразимость | Ведущая валюта В2, есть кандидат со сроком | Заявка на один из трёх пунктов тройного теста |
| Постройка проверки | Ведущая валюта В3 | Заявка на проверку самой проверки: холостой прогон и порча |

## 3. Что обязано произойти в каждом цикле

1. Ровно одна заявка `H#`. Цикл без заявки — неполный; координатор объясняет причину, секретарь записывает `incomplete_step`.
2. Вердикт ссылается на заявку этого цикла.
3. У сырого результата записано происхождение. Статус поднимается, только если результат получен запуском, проверка годная и совпали не меньше двух вердиктов «подтверждено».
4. Каждая неудача записана с видом и причиной.
5. Секретарь проверил сроки отложенных предсказаний: истёкшие закрыты как «не подтверждено».
6. У каждой новой строки карты стоит номер записи цикла. Карта не длиннее 7 500 знаков; ничто не удалено без номера.
7. Жёсткое нарушение, найденное контролёром записей, стоит в очереди владельца новой карты.

## 4. Происхождение результата

| Происхождение | Что это | Какой статус допускает |
| --- | --- | --- |
| Запуск владельца | Владелец запустил код или выполнил шаги у себя и вставил вывод | Любой по правилам статусов |
| Инструмент модели | Исполнитель запустил код в своей среде; код и вывод приложены | Не выше S1, пока владелец не повторил запуск при аудите |
| Запуска нет | Исполнитель рассуждал или описал ожидаемый вывод | Статус не меняется; вердикт — «повторить» |

Отличить настоящий запуск в инструменте модели от правдоподобного текста расширение не может. Поэтому результат, на котором держится решение — подтверждение перестройки, итог задачи, статус выше S1, — владелец запускает сам. Код для запуска исполнитель обязан приложить.

## 5. Расхождение проверяющих

Не голосование. Секретарь расхождений называет одну точку спора и один минимальный разрешающий тест с предсказанием. Противоречие попадает в карту; статус не меняется; следующий цикл — вида «Разрешение», и разрешающий тест исполняется в нём. Вердикты никто не меняет: добавляется доказательство. Не разрешилось за два цикла — в очередь владельца.

Вердиктов меньше двух — независимой проверки не было: статус не повышается, цикл записан как неполный.

## 6. После цикла

Владелец:

1. Принимает решение в окне; при необходимости правит карту.
2. Сохраняет выгрузку прогона, дописывает строку цепочки, коммитит её в репозиторий наблюдателя.
3. Считает расход по выгрузке: запросы — по числу карточек ответов, запуски проверок, свои минуты. Обновляет раздел «ХОД» пакета.
4. Собирает пакет следующего цикла: выжимка ядра без изменений, «ХОД», конфигурация, утверждённая карта; записи, которые запросил координатор.

Правка карты и решение — записи журнала с типом `owner_decision`. Записи секретаря — указатель к выгрузке, а не её замена: при споре права выгрузка.

## 7. Цикл на задаче полигона

Та же схема. Пакет собирается из задачи полигона: в ядре — её условие и способ проверки, скрытая часть остаётся у владельца. Шаг `owner:lane` владелец использует, чтобы вернуть результат проверки по скрытому ответу, не раскрывая его.
