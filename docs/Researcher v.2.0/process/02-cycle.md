# Рабочий цикл

Один запуск схемы `4-cycle` — один цикл. Все шаги получают пакет цикла как текст задачи. Шаги идут строго по порядку; условий приложение не проверяет, поэтому условная часть записана в самих запросах: роль, которой в этом цикле делать нечего, отвечает одной строкой.

## 1. Шаги

| Шаг | Роль | Вход | Выход |
| --- | --- | --- | --- |
| r1 | C01 Координатор | пакет | План цикла: вид цикла, активная гипотеза или вопрос, сверка с ямами, прогноз и наивный прогноз |
| r2 | C02 Искатели | r1 | Источники по вопросам плана |
| r3 | C03 Обработчик источников | r2 | Факты с классом надёжности |
| r4 | C04 Генераторы | r1, r3 | Гипотезы с основанием, признаками разнообразия, ценой проверки |
| r5 | C05 Альтернативщик | r4 | Конкурирующее объяснение каждой гипотезе |
| r6 | C06 Экспериментатор | r1, r4, r5 | Заявка `H#`: запись для проверяющих и процедура для исполнителя |
| r7 | C07 Исполнитель проверки | только процедура | Сырой результат, итог холостого прогона и прогона с порчей; или «НУЖЕН ЧЕЛОВЕК» |
| owner:lane | Владелец | r7 | Сырой результат ручного задания или «нет» |
| r8 | C08 Слепые проверяющие | запись заявки, r7, owner:lane | Вердикт, совпадение с предсказанием, альтернативное объяснение, быстрейший тест |
| r9 | C09 Секретарь расхождений | запись заявки, r7, r8 | «Расхождений нет» или точка спора и разрешающий тест |
| r10 | C10 Диагност метода | r1, r8, r9 | «Перестройка не требуется» или триггер и диагноз с конкурирующими причинами |
| r11 | C11 Методист | r10 | Предложение из меню или «Предложений нет» |
| r12 | C12 Изобретатель перестроек | r10 | Предложение по ходу из каталога или «Предложений нет» |
| r13 | C13 Плацебо | — | Изменение той же цены по номеру цикла или «Плацебо не требуется» |
| r14 | C14 Приёмщик | r11, r12, r13 | Проверка формы каждого предложения |
| r15 | C15 Секретарь журнала | r1, r3, r4, запись заявки, r7, owner:lane, r8, r9 | Записи цикла: исследование |
| r16 | C15 Секретарь журнала | r15, r10–r14 | Записи цикла: метод |
| r17 | C15 Секретарь журнала | r15, r16 | Обновлённая карта вопроса |
| r18 | C16 Контролёр | запись заявки, r8, r15, r16, r17 | Донесение: нарушения, расхождения записей с ответами |
| r19 | C17 Докладчик | r15, r16, r17, r18 | Сводка |
| owner:window | Владелец | карта r17, r18, r19 | Исправленная карта и решение |

Исполнитель проверки и слепые проверяющие не получают пакета цикла: только свой вход. Плацебо не получает диагноза: его вход — только пакет. Плацебо к триггеру появляется на цикл позже самого триггера.

## 2. Виды цикла

Координатор выбирает один вид; остальные роли действуют соответственно.

| Вид | Когда | Что делают генераторы и экспериментатор |
| --- | --- | --- |
| Поиск | Мало фактов R1–R2 по активному вопросу | Генераторы выдвигают гипотезы; заявка — на самую дешёвую различающую проверку |
| Проверка | Есть гипотеза с ценой и различающей силой | Заявка на активную гипотезу |
| Разрешение | В карте открыто противоречие с разрешающим тестом | Заявка на разрешающий тест |
| Пробел | Закрытие пробела открывает больше путей, чем проверка | Заявка на проверку пользы от закрытия; задание владельцу — в очередь |
| Выразимость | Ведущая валюта В2, есть кандидат со сроком | Заявка на один из трёх пунктов тройного теста |
| Постройка проверки | Ведущая валюта В3 | Заявка на проверку самой проверки: холостой прогон и порча |

## 3. Что обязано произойти в каждом цикле

1. Ровно одна заявка `H#`. Цикл без заявки — неполный; координатор объясняет причину, секретарь записывает `incomplete_step`.
2. Вердикт ссылается на заявку этого цикла.
3. Каждая неудача записана с видом и причиной.
4. Секретарь проверил сроки отложенных предсказаний: истёкшие закрыты как «не подтверждено».
5. Карта не длиннее 8 000 знаков; ничто не удалено без номера в журнале.
6. Расход цикла в четырёх единицах записан.

## 4. Передача между шагами

Генератор → экспериментатор, экспериментатор → исполнитель, исполнитель → проверяющие, проверяющие → секретарь расхождений: каждый ответ кончается блоком передачи, следующий начинается квитанцией ([../system/05-roles.md](../system/05-roles.md), §7). «Возвращено» в квитанции — запись `incomplete_step`; шаг повторяется в следующем цикле.

## 5. Расхождение проверяющих

Не голосование. Секретарь расхождений называет одну точку спора и один минимальный разрешающий тест с предсказанием. Противоречие попадает в карту; следующий цикл — вида «Разрешение». Вердикты никто не меняет: добавляется доказательство. Не разрешилось за два цикла — в очередь владельца.

## 6. После цикла

Владелец:

1. Сохраняет экспорт прогона, дописывает строку цепочки.
2. Переносит записи цикла в `journal/records.jsonl`, карту — в `state/map.json`.
3. Собирает пакет следующего цикла.
4. Принимает решение в окне.

В режиме по шагам владелец правит карту в окне решений до того, как она станет пакетом, и дописывает в неё строку решения. Правка и решение — записи журнала с типом `owner_decision`.

## 7. Цикл на задаче полигона

Та же схема. Пакет собирается из задачи полигона: в ядре — её условие и способ проверки, скрытая часть остаётся у владельца. Шаг `owner:lane` владелец использует, чтобы вернуть результат проверки по скрытому ответу, не раскрывая его.
