# План сборки

Этап не начат, пока не пройдены ворота предыдущего. Номера тестов — из [../verification/05-acceptance.md](../verification/05-acceptance.md).

Порядок построен вокруг одного правила: сначала один полный цикл, потом всё остальное. Полный цикл ещё не запускался ни разу; первый прогон покажет длины ответов, отказы моделей и цену — и по ним будут собираться корпус порч, полигон и пороги.

| Этап | Что собирается | Ворота |
| --- | --- | --- |
| С1 | Схемы установлены в Basic. Пробный прогон `2-preflight` на учебной задаче: какие модели получают запрос и отвечают | По каждой модели известно: получила запрос или нет, ответила или нет. Недоставка устранена в расширении; не отвечающие заменены в сборщике |
| С2 | Папка учебной задачи; цепочка; команды из руководства; внешний наблюдатель назначен | Тесты 1, 6; наблюдатель получил первую строку |
| С3 | **Первый полный цикл.** Учебная задача со счётной проверкой, ответ которой владелец знает. `1-task-card`, `2-preflight`, `3-setup`, два-три запуска `4-cycle`. Исполнитель проверки — владелец: код запускается у него | Все шестнадцать шагов получили ответ; тесты 7, 8; измерены: запросов на цикл, длины ответов против пределов, минуты владельца, доля шагов без ответа |
| С4 | Правка по замерам: пределы слов, размер пакета, запросы ролей, состав | Наибольший запрос по выгрузке — не больше 80% предела; цикл проходит без остановок |
| С5 | Контроль: тесты с разделом «ТЕСТ» и ручным заданием на той же учебной задаче | Тесты 2–5, 9–12, 14, 16–22, 32–36, 38 |
| С6 | Корпус порч: общая половина, двадцать элементов; калибровка (`7-calibration`) | Тест 13; пороги проверяющих записаны до калибровки вместе с размером выборки |
| С7 | Перестройка на учебной задаче: `5-rebuild`, замер шума, три плеча, `6-rebuild-verdict` | Тесты 23–31; одна перестройка прошла путь от триггера до записи библиотеки |
| С8 | Рецензия методологии (`11-methodology-review`) по четырём документам — уже с опытом прогонов | Ни одного незакрытого замечания, чья проверка показывает нарушение ядра |
| С9 | Первая настоящая задача: карточка, предполёт, настройка с подписью порогов; областная половина корпуса порч и повторная калибровка; аудит и красная команда (`8-audit`) | Тесты 15, 37, 39–41; бюджет подписан по измеренной цене цикла |
| С10 | Выход (`9-exit`) на первой задаче; пост-мортем; неделя работы | Тест 42; итог утверждён; финальный якорь отправлен |
| С11 | Полигон: десять задач ряда А (`10-polygon`), два плеча — полная система и с контрольным изменением | Исход наименьшей версии оценки записан: «подтверждено», «не подтверждено» или «данных мало» |
| С12 | Вторая задача: перенос приёмов и перестроек через выдержку библиотеки | Kill переноса проверен; итог записан как «подтверждено» или «не подтверждено» |
| С13 | Непрерывный режим — после появления в Basic пунктов 1–8 из [../process/04-endless-mode.md](../process/04-endless-mode.md), §5 | Ворота включения режима из §6 того же документа |

## Что делается первым

1. С1–С3: пробный прогон, папка, один полный цикл на учебной задаче. Цель — не результат, а первое полное прохождение и замер.
2. С5 и С6 идут параллельно: тесты контроля и корпус порч не зависят друг от друга.
3. Настоящая задача — не раньше С9. До исхода С11 каждый итог несёт пометку «метод не проверен».

## Что отложено и до какого признака

| Что | Признак, по которому вводится |
| --- | --- |
| Полный полигон: двадцать задач ряда А и десять ряда Б, три плеча | Половина С11 дала «данных мало» или «подтверждено» и бюджет позволяет |
| Профили моделей по измеренным исходам | Накоплено не меньше двадцати циклов; замена модели в роли обсуждается чаще раза в период |
| Удаление ролей по полезности | После С11: есть парные прогоны |
| Вторая активная задача | Одна задача стабильно проходит неделю без вмешательства |
| Расширение меню методиста | Архив отклонённых предложений накопил повторяющийся тип |
| Исполнение проверок вне моделей и вне владельца | Появление в Basic исполнения кода или отдельной программы проверки |
| Машинная проверка записей по форматам | Появление в Basic шагов приложения |

## Оценка цены

Запросы посчитаны по схемам; минуты владельца — предположение до С3.

| Что | Запросов к моделям | Запусков проверок | Минут владельца |
| --- | --- | --- | --- |
| Карточка задачи | 3 | 0 | 40 |
| Предполёт | 17 | 2 | 40 |
| Настройка | 9 | 0 | 90 |
| Один цикл | 20 | 1 | 30 |
| Калибровка | 4 | 0 | 30 |
| Замер шума: два прогона по три цикла | 120 | 6 | 120 |
| Перестройка: предложения и сборка | 7 | 0 | 30 |
| Испытание: три плеча по три цикла | 180 | 9 | 200 |
| Счёт и вердикт | 3 | 0 | 20 |
| Выход | 5 | 0 | 40 |
| Рецензия методологии, четыре документа | 20 | 0 | 90 |
| Половина полигона: 10 задач, 2 плеча, 3 цикла | 1 200 | 60 | 600 |

Самое дорогое в задаче — испытание перестройки; самое дорогое в проекте — полигон. Число запросов упирается не только в бюджет: сайты моделей ограничивают число сообщений в день, и автоматическая работа во вкладках может нарушать их условия. Суточный предел по каждой модели измеряется на С3 и входит в расчёт сроков.
