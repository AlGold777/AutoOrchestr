# T05 · Пропуск не ответившего участника без вопроса

Ты — исполнитель кода расширения AutoOrchestr. Твоя задача — добавить в схему настройку, при которой прогон не спрашивает User, что делать с участником без ответа: участник пропускается, если в шаге есть хотя бы один принятый ответ, и прогон останавливается, если нет ни одного.

Задание T04 должно быть сделано: в `results.js` есть `basicKeptRunFields`.

Сначала выполни «Общие правила» из `docs/Researcher v.2.0/basic-run-automation ( ТЗ на допиливание  схема V.2.0)/README.md`.

## Что есть сейчас

- После попыток шага движок проверяет ответы в основном цикле `run` в `disput/custom-engine.js` (строки 1398–1437). `accepted` — участники с принятым ответом, `failed` — без него, `enough` — все ответили.
- Если ответили не все, движок всегда спрашивает User через `decide` (строки 1414–1420): повторить, пропустить участника, пропустить шаг, остановить. Так и при `run.policy: "auto"`.
- Решение «пропустить участника» записывается как `state.decisions[decidedKey] = 'continue'` (строка 1427) и событием `custom_decision` (строка 1430).
- Окно вопроса на странице — `askCustomDecision` в `results.js` (строка 7061).

## Что сделать

### 1. Схема: поле `run.onNoAnswer`

`disput/basic-schema.js`:

- разрешённый ключ `onNoAnswer` в `run` (строка 333); значение — `"ask"` или `"skip"`, иначе ошибка `fail('run.onNoAnswer', …)`;
- `resolveRun` (строки 713–717): `onNoAnswer` из схемы или `"ask"`.

`"ask"` — нынешнее поведение. Схема без поля работает как раньше.

### 2. Движок

`disput/custom-engine.js`:

- `STOP_TEXT` (строки 78–86): `no_answer: 'шаг остался без принятых ответов'`;
- параметр `onNoAnswer = 'ask'` у `run` (строки 443–449);
- в цикле решения, после строк `if (enough && !semiAuto && !approve) break;` и следующей (строки 1410–1411), до вычисления `choices`: если `onNoAnswer === 'skip'` и `!enough`:
  - есть принятые ответы → записать решение так же, как при «пропустить участника»: `state.decisions[decidedKey] = 'continue'`, контрольная точка `checkpointNow('decision', { pendingOwner: null })`, событие `custom_decision` с `{ step, action: 'skip_participant', auto: true, skipped: failed }`, затем `break`;
  - принятых ответов нет → `throw new StopRun('no_answer', …)` с ref шага и списком участников без ответа.

Ветка работает одинаково с функцией `decide` и без неё. Исход пропущенного участника движок не меняет: в `outcome` он остаётся с `ok: false` и своей причиной. Следующие шаги получают на вход меньше ответов — это и есть пропуск; автор схемы включает настройку, зная это.

Попытки и повторы до этого места идут как раньше: пропуск наступает только после того, как движок исчерпал свои повторы. Шаг с подтверждением User (`approve`) и режим `manual` этой настройкой не меняются: вопрос о продолжении при всех ответах остаётся.

## Готово, когда

Схема с `"onNoAnswer": "skip"` проходит шаг с одним не ответившим участником без окна вопроса и останавливается, когда шаг остался совсем без ответов; схемы без поля работают как раньше.
