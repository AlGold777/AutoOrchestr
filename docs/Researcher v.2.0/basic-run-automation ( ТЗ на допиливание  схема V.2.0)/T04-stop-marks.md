# T04 · Остановка прогона по метке в ответе

Ты — исполнитель кода расширения AutoOrchestr. Твоя задача — научить Basic останавливать прогон, когда принятый ответ шага содержит строку, начинающуюся с метки из схемы. Это сравнение строк, а не оценка содержания: метку ставит модель, расширение её только находит.

Сначала выполни «Общие правила» из `docs/Pipeline scenarios/basic-run-automation/README.md`.

## Что есть сейчас

- Настройки прогона в схеме — объект `run` с полями `policy`, `maxWords`, `strictLength`. Проверка — `validate` в `disput/basic-schema.js` (строки 330–339, список разрешённых ключей в строке 333). Значения для прогона отдаёт `resolveRun` (строки 713–717).
- Движок — `run` в `disput/custom-engine.js` (строка 443). Причины остановки и их тексты — `STOP_TEXT` (строки 78–86). Остановка — `throw new StopRun(причина, подробность)` (класс в строке 510).
- Раунд заканчивается в основном цикле строками 1447–1451: событие `custom_step_end`, затем `results.push(entry); pos += 1; current = null;`. Принятые ответы шага лежат в `outcome[model.id]`: поле `ok` и текст `text`.
- Страница вызывает движок в `results.js` (строка 7697) и передаёт настройки `built.run`.
- После остановки с причиной не `steps_done` страница предлагает «Продолжить прогон» (`offerResumeLine`, строка 7159).

## Что сделать

### 1. Схема: поле `run.stopMarks`

`disput/basic-schema.js`:

- строка 333: добавь `stopMarks` в список разрешённых ключей `run`;
- проверка: массив от одной до десяти строк; каждая — непустая после обрезки пробелов, не длиннее 60 знаков, без перевода строки. Ошибки — через `fail('run.stopMarks', …)` и `fail('run.stopMarks[i]', …)`;
- `resolveRun`: поле `stopMarks` — копия массива из схемы или пустой массив;
- комментарий формата в строке 11 дополни полем.

Схема без поля работает как раньше.

### 2. Движок

`disput/custom-engine.js`:

- `STOP_TEXT`: добавь `stop_mark: 'остановлено по метке в ответе'`;
- чистая функция `findStopMark(text, marks)` на уровне модуля. Для каждой строки текста убирает в начале пробелы и знаки разметки (`>`, `*`, `_`, `#`, `` ` ``, `~`, `-`, `–`, `—`, `•`) и проверяет, начинается ли остаток с метки, с учётом регистра. Возвращает `{ mark, line }` для первой найденной строки или `null`. Добавь её в экспорт модуля (строка 1516);
- параметр `stopMarks = []` у `run` (строки 443–449);
- сразу после `current = null;` в конце раунда (строка 1451): если `stopMarks` не пуст и шаг не пропущен, проверь тексты принятых ответов шага — `step.models.filter((model) => outcome[model.id]?.ok)` — функцией `findStopMark`. Нашлась метка — `throw new StopRun('stop_mark', …)` с подробностью: ref шага, id участника, первые 120 знаков строки.

Проверка стоит после того, как шаг записан в `results` и указатель сдвинут. Так принятые ответы шага сохраняются, а «Продолжить прогон» начнёт со следующего шага. Шаги User не проверяются.

### 3. Страница

`results.js`:

- строка 7697, вызов `engine.run`: добавь `stopMarks: built.run.stopMarks`;
- сохранение поля при Save и запуске — по правилу 8 общих правил: замени `basicStrictLengthRun` (строка 6757) функцией `basicKeptRunFields`, которая переносит из исходной схемы поля `strictLength` и `stopMarks`, и используй её в `basicRunForSave` (строка 6761).

Уведомление в конце прогона менять не нужно: `basicRunNotice` берёт текст из `STOP_TEXT` и подробность из `stopDetail`.

## Проверка

- `tests/basic-schema.test.js`: верное поле проходит; не массив, пустой массив, пустая строка, строка длиннее 60 знаков, одиннадцать меток — ошибки с путём; `resolveRun` без поля даёт `[]`.
- `tests/custom-engine-flow.test.js`:
  - метка в начале строки ответа второго шага из трёх → `stopReason: 'stop_mark'`, третий шаг не отправлен, ответы двух шагов в результате;
  - метка внутри строки, а не в начале → прогон идёт до конца;
  - метка после разметки `**ТРЕВОГА:**` и после `> ` → остановка;
  - без `stopMarks` тот же ответ прогон не останавливает;
  - метка в отклонённом ответе → не останавливает;
  - продолжение из состояния остановленного прогона начинается со следующего шага.
- `findStopMark` — отдельные случаи: пустой текст, несколько меток, регистр.
- `tests/results-debate-favorites.test.js`: Save и Export схемы с `run.stopMarks` сохраняют поле.

## Готово, когда

Схема с `"stopMarks": ["ТРЕВОГА:"]` останавливает прогон после шага, чей принятый ответ содержит такую строку, и предлагает продолжение; схемы без поля работают как раньше.
