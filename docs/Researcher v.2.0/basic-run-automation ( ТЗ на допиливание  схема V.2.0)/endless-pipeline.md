# Бесконечный pipeline в Basic — техническое задание

Ты — исполнитель кода расширения AutoOrchestr. Твоя задача — научить Basic проходить одну схему заход за заходом без участия User: документ, созданный в конце захода, становится частью задачи следующего, а расширение само считает расход, сохраняет запись каждого захода и останавливается по заранее заданным условиям.

Это задание описывает режим целиком. Работа разбита на восемь этапов; у каждого есть свой файл с точными местами в коде и проверками в папке `docs/Researcher v.2.0/basic-run-automation ( ТЗ на допиливание  схема V.2.0)`. Сначала прочитай этот документ, затем `docs/Researcher v.2.0/basic-run-automation ( ТЗ на допиливание  схема V.2.0)/README.md`, раздел «Общие правила», затем файл этапа.

Номера строк даны на версию кода 2.81.1054. Ищи место по имени, номер — подсказка.

## 1. Главное правило

Расширение повторяет, считает, сравнивает строки и сохраняет. Оно не оценивает ответы и не выбирает путь по смыслу. Всё, что зависит от содержания, решают модели в своих ответах и User в окне. Любое условие остановки — либо число, либо совпадение строки, либо отсутствие обязательного результата.

## 2. Что должен увидеть User

1. User выбирает папку документов, открывает схему с полем повтора, вставляет задачу и нажимает запуск.
2. В ленте появляется строка: сколько заходов и запросов разрешено.
3. Схема проходит от первого шага до последнего. Это заход. Каждый заход — обычный прогон Basic: своя запись, свои карточки ответов, новые чаты у всех участников.
4. После захода в ленте строка «Заход 3 из 10 · запросов 60 из 250», а в папке документов — файл записи захода и новая строка в `chain.txt`.
5. Следующий заход начинается сам. Его задача — прежний текст, в котором обновлены счётчики и заменён документ после строки-маркера.
6. Раз в N заходов открывается окно: документ для следующего захода, который можно поправить, кнопка «Продолжить» и «Остановить повтор».
7. Повтор кончается сам с уведомлением о причине или по кнопке Stop.
8. После перезагрузки страницы повтор не продолжается: User видит записи пройденных заходов и запускает заново.

## 3. Формат в схеме

Три необязательных поля объекта `run`. Схема без них работает как раньше.

```json
"run": {
  "policy": "auto",
  "maxWords": 1000,
  "stopMarks": ["ТРЕВОГА:", "СТОП:", "ЦИКЛ НЕ ВЫПОЛНЯЕТСЯ"],
  "onNoAnswer": "skip",
  "repeat": {
    "carry": { "step": "r14", "participant": "map", "artifact": "map" },
    "carryMarker": "=== КАРТА ВОПРОСА ===",
    "maxPasses": 10,
    "maxRequests": 250,
    "ownerEvery": 5,
    "carryMaxChars": 7500
  }
}
```

| Поле | Что значит |
| --- | --- |
| `stopMarks` | Прогон останавливается после шага, в принятом ответе которого есть строка, начинающаяся с одной из меток |
| `onNoAnswer` | `ask` — спросить User, как сейчас; `skip` — пропустить не ответившего участника, а если в шаге нет ни одного ответа — остановить прогон |
| `repeat.carry` | Адрес артефакта, текст которого переходит в следующий заход |
| `repeat.carryMarker` | Строка задачи, после которой стоит переносимый документ |
| `repeat.maxPasses` | Предел заходов, обязателен |
| `repeat.maxRequests` | Предел отправленных запросов на все заходы |
| `repeat.ownerEvery` | Раз в сколько заходов открывать окно User |
| `repeat.carryMaxChars` | Предел длины переносимого документа |

В тексте задачи до маркера допустимы три метки: `{заход}` — номер захода; `{заход+N}` — номер захода плюс N; `{осталось запросов}` — остаток до предела или слова «без предела».

## 4. Как идёт повтор

```
запуск:
  политика не auto            → отказ, ничего не отправлено
  в задаче нет строки-маркера → отказ
  папка документов недоступна → отказ
  шаблон = текст задачи до конца строки-маркера; документ = текст после неё

заход N:
  задача = шаблон с подставленными счётчиками + документ
  обычный прогон Basic с новыми чатами
  запись прогона → файл в папке документов → строка цепочки
  запросов израсходовано += отправленные в заходе
       (нет точного числа → верхняя граница: все участники всех раундов)
  новый документ = последняя годная версия артефакта carry

после захода, первое сработавшее останавливает повтор:
  User нажал Stop
  прогон кончился не по «все шаги пройдены»   (сюда попадают метка, шаг без ответов, ошибка)
  запись захода не сохранена
  нового документа нет
  документ длиннее carryMaxChars
  N достиг maxPasses
  запросов израсходовано не меньше maxRequests

иначе:
  N кратно ownerEvery → окно User; отмена — остановка; текст из окна заменяет документ
  заход N+1
```

Состояние повтора живёт только в памяти страницы. Постоянная часть задачи никогда не берётся из ответов моделей.

## 7. Требования ко всему режиму

1. **Совместимость.** Схема без новых полей проходит так же, как до работы: те же запросы, те же окна, та же выгрузка с одним добавленным полем.
2. **Один заход — один прогон.** Повтор не меняет движок: он вызывает обычный прогон и читает его запись. Продолжение незавершённого захода кнопкой «Продолжить прогон» остаётся, но повтор после него не возобновляется.
3. **Запись обязательна.** Без доступа к папке документов повтор не начинается; заход, запись которого не сохранена, становится последним.
4. **Неизвестное считается потраченным.** Если число запросов захода неизвестно, прибавляется верхняя граница.
5. **Stop действует всегда:** во время захода, между заходами, при открытом окне User.
6. **Страница не зависает.** Исключение в любом месте повтора снимает состояние «идёт прогон».
7. **Никаких скрытых запусков.** Повтор начинается только по клику User и не переживает перезагрузку страницы.

## 8. Приёмка

Тесты страницы на поддельном транспорте и поддельной папке документов; все должны проходить после этапа 8.

| № | Действие | Ожидаемое |
| --- | --- | --- |
| 1 | Схема с `maxPasses: 3`, все отвечают | Три захода; задача второго содержит документ первого; `{заход}` равен 2; три файла записей и три строки цепочки; уведомление «достигнут предел заходов» |
| 2 | Ответ шага во втором заходе начинается с метки | Третий заход не начат; уведомление называет причину; запись второго захода сохранена |
| 3 | Единственный участник шага не ответил, `onNoAnswer: "skip"` | Заход остановлен, следующий не начат, окно вопроса не открывалось |
| 4 | Один из трёх участников шага не ответил | Заход дошёл до конца, повтор продолжается |
| 5 | `maxRequests` меньше расхода первого захода | Второй заход не начат |
| 6 | Папка документов недоступна | Ни одного запроса не отправлено |
| 7 | Запись после второго захода не удалась | Третий заход не начат |
| 8 | Шаг-источник документа не дал артефакт | Следующий заход не начат: «нет документа для переноса» |
| 9 | Документ длиннее `carryMaxChars` | Следующий заход не начат |
| 10 | Stop во время захода и Stop между заходами | Следующий заход не начат; страница свободна |
| 11 | `ownerEvery: 2`; в окне текст изменён | Третий заход получил изменённый текст; отмена окна останавливает повтор |
| 12 | Политика `manual` | Отказ до первого запроса |
| 13 | В задаче нет строки-маркера | Отказ до первого запроса |
| 14 | Исключение внутри захода | Повтор остановлен, страница свободна, новый запуск возможен |
| 15 | Перезагрузка страницы после второго захода | Повтор не продолжается; записи двух заходов на месте |
| 16 | Схема без `run.repeat` | Один прогон, как раньше |
| 17 | `chain.txt` после трёх заходов | Каждая строка со второй ссылается на сумму предыдущей; сумма файла равна четвёртому полю |

## 9. Живая проверка

После этапа 8 — один прогон в настоящем Chrome по `docs/Agents/agent-live-chrome.md` и `docs/Run Automation/run-procedure.md`: схема из двух раундов с одной моделью, `maxPasses: 2`, документ в один абзац. Отправка запроса на сайт модели требует разрешения User на конкретный тестовый запрос. Проверяется: второй заход открыл новый чат; в папке два файла записей и две строки цепочки; команда `shasum -a 256` от файла даёт четвёртое поле его строки.

## 10. Чего не делать

- Не оценивать содержание ответов: никаких условий «если ответ хороший».
- Не добавлять ветвлений и переходов между шагами.
- Не продолжать повтор после перезагрузки и не запускать его без клика User.
- Не вводить новое хранилище для состояния повтора.
- Не менять формат выгрузки, кроме добавления полей `usage` и `taskSections`.
- Не добавлять окно ввода пределов при запуске: пределы задаёт схема.
