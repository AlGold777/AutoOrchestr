# T06 · Поле повтора в формате схемы

Ты — исполнитель кода расширения AutoOrchestr. Твоя задача — добавить в формат схемы Basic описание повтора: схема проходится заход за заходом, и документ одного захода становится частью задачи следующего. В этом задании меняется только формат и его проверка; сам повтор — задания T07 и T08.

Задания T04 и T05 должны быть сделаны: в `results.js` есть `basicKeptRunFields`.

Сначала выполни «Общие правила» из `docs/Researcher v.2.0/basic-run-automation ( ТЗ на допиливание  схема V.2.0)/README.md`.

## Что есть сейчас

- Настройки прогона — объект `run`. Проверка — `validate` в `disput/basic-schema.js` (строки 330–339); значения для прогона — `resolveRun` (строки 713–717).
- Артефакт объявляется в `output.artifacts` шага: `{ id, name, pointer }`. Во входе шага на него ссылаются так: `{ artifact: { step, participant, id } }`; проверка этой ссылки — `disput/basic-schema.js`, строки 254–269. Функции `stepAt` и `participantAt` там — внутренние, снаружи недоступны.
- Шаги User имеют `kind: "owner"`.

## Что сделать

`disput/basic-schema.js`, одна строка в `results.js`, документы и тесты.

Добавь `repeat` в список разрешённых ключей `run` (строка 333). Проверку `repeat.carry` поставь в `validate` после проверки шагов, там, где список шагов уже разобран, и напиши для неё собственный поиск: шаг по `ref`, участник по `id` (а без `id` — по `name`), артефакт по `output.artifacts` участника, а если у участника нет своего `output` — шага. У `carry` свой вид адреса — `{ step, participant, artifact }`, без вложенного объекта.

### Поле `run.repeat`

```json
"run": {
  "policy": "auto",
  "repeat": {
    "carry": { "step": "r14", "participant": "map", "artifact": "map" },
    "carryMarker": "=== КАРТА ВОПРОСА ===",
    "maxPasses": 10,
    "maxRequests": 400,
    "ownerEvery": 5,
    "carryMaxChars": 7500
  }
}
```

| Поле | Обязательное | Значение | Проверка |
| --- | --- | --- | --- |
| `carry` | да | Адрес артефакта, текст которого переходит в следующий заход | Шаг существует и это раунд; участник есть в шаге и включён; артефакт с таким `id` объявлен в `output` участника или шага |
| `carryMarker` | да | Строка-заголовок в тексте задачи. Всё после неё заменяется текстом артефакта | Непустая строка без перевода строки, не длиннее 80 знаков |
| `maxPasses` | да | Сколько заходов разрешено | Целое от 1 до 500 |
| `maxRequests` | нет | Сколько запросов моделям разрешено на все заходы | Целое от 1 до 100 000 |
| `ownerEvery` | нет | Раз в сколько заходов открывается окно User | Целое от 1 до 500 |
| `carryMaxChars` | нет | Предел длины переносимого текста | Целое от 100 до 50 000 |

Дополнительные проверки схемы с `run.repeat`:

- в схеме не должно быть шагов `kind: "owner"`: окно User в повторе одно, раз в `ownerEvery` заходов. Ошибка с путём шага;
- неизвестные ключи внутри `repeat` и `carry` — ошибка, как у остальных объектов схемы (`unknownKeys`).

`resolveRun` отдаёт `repeat: null`, если поля нет, иначе — копию объекта.

Политику запуска `validate` не проверяет: на странице её задаёт шапка, а не схема. Повтор при политике `manual` отклоняет задание T08 в момент запуска.

Сохранение поля при Save и запуске — правило 8 общих правил: добавь `repeat` в `basicKeptRunFields` в `results.js`. Больше в `results.js` в этом задании ничего не меняй: запуск схемы с `run.repeat` до T08 идёт как обычный одиночный прогон.

## Проверка

- `tests/basic-schema.test.js`:
  - полное верное поле проходит; только обязательные поля — проходит;
  - нет `carry`, нет `carryMarker`, нет `maxPasses` — три разные ошибки с путём;
  - `carry` указывает на несуществующий шаг, на шаг User, на выключенного участника, на необъявленный артефакт — ошибки;
  - `maxPasses: 0`, `maxPasses: 501`, дробное число — ошибки;
  - шаг `kind: "owner"` вместе с `repeat` — ошибка;
  - `resolveRun` без поля даёт `repeat: null`; прежние тесты `resolveRun`, сравнивающие объект целиком, дополни этим полем.
- `tests/results-debate-favorites.test.js`: Save и Export схемы с `run.repeat` сохраняют поле без изменений.
- Схема `docs/Researcher v.2.0/basic/schemas/4-cycle-endless.json` с добавленным вручную полем из примера выше проходит `validate`.
