# Basic: счёт, запись и повтор прогона — технические задания

Девять заданий для исполнителя кода. Они дают Basic то, чего ему не хватает для системы `docs/Researcher v.2.0`: счёт запросов, запись прогона на диск с цепочкой контрольных сумм, остановку по метке, пропуск не ответившего участника без вопроса и повтор схемы.

Общее правило всех заданий: расширение считает, сравнивает строки, сохраняет и повторяет. Оно не оценивает содержание ответов и не выбирает путь по смыслу.

Номера строк даны на версию кода 2.81.1054. Код меняется: ищи место по имени функции, номер строки — подсказка.

## Общие правила

Они обязательны для каждого задания.

1. **Сначала прочитай:** `AGENTS.md` в корне проекта, `docs/Agents/agent-onboarding.md` (разделы 1, 2, 2а), `docs/Pipeline scenarios/basic-start-here.md`, раздел «1. Код» в `docs/Pipeline scenarios/basic-developer.md`.
2. **База.** Перед первой правкой выполни `grep '"version"' /Users/restart/Documents/GitHub/AutoOrchestr/manifest.json` и `git status --short`. Работай от ветки основного чекаута; чужие незакоммиченные файлы не трогай.
3. **Проверка раньше правки.** Сначала напиши тест, который падает без изменения; потом меняй код. Тест проверяет поведение, а не повторяет реализацию.
4. **Тесты.** Jest: `npx jest --config tests/jest.config.js tests/<файл>.test.js`. Перед сдачей — тесты затронутых модулей, затем `npm test`. Любое падение разбирается, «было раньше» не объяснение.
5. **Новый модуль** оформляется как `results/documents-folder.js`: самовызывающаяся функция, `root.Имя = api`, `module.exports` для тестов, без обращения к DOM. Его нужно подключить в трёх местах: тег `<script>` в `pipeline_panel.html` (рядом со строкой 880, раньше `results.js`), список `web_accessible_resources` в `manifest.json` (рядом со строкой 286) и строка в таблице «Файлы Basic» документа `basic-developer.md`.
6. **Версия.** После правки кода подними последнюю цифру версии на единицу в `manifest.json` (строка 4), `package.json` (строка 3) и `package-lock.json` (строки 3 и 9).
7. **Документы в том же коммите:**
   - `docs/Pipeline scenarios/basic-developer.md` — таблицы «Файлы Basic», «results.js: области и функции», «Тесты»: каждая новая функция и каждый новый файл тестов. Их сверяет `tests/basic-docs-refs.test.js`.
   - `docs/Pipeline scenarios/basic-schema-guide.md` — если меняется формат схемы. Сверяет `tests/basic-schema-guide.test.js`.
   - `docs/Pipeline scenarios/basic-start-here.md` — новые события журнала, причины остановки, то, что видит User.
   - `docs/CHANGELOG.md` — запись сверху по образцу соседних.
   - После правки документов прогони `tests/basic-docs-refs.test.js` и `tests/basic-schema-guide.test.js`.
8. **Поле схемы без элемента управления на странице.** Страница собирает схему заново из холста и теряет поля, которых не знает. Поле `run.strictLength` сохраняет функция `basicStrictLengthRun` в `results.js` (строка 6845). Она вызывается в трёх местах: строка 6809 (сборка схемы со страницы), строка 6854 (`basicRunForSave`, Save) и строка 6995 (`buildBasicRun`, запуск). Задание T04 заменяет её функцией `basicKeptRunFields`; каждое новое поле `run.*` добавляется в эту функцию, иначе оно пропадёт при Save и не дойдёт до движка.
9. **Чего не делать:** не менять поведение схем, в которых нового поля нет; не добавлять настроек и окон сверх задания; не заводить новое хранилище, не проверив запись прогона (`disput/custom-run-record.js`), выгрузку (`shared/basic-telemetry.js`) и папку документов (`results/documents-folder.js`).
10. **Сдача.** Коммит и доставка — по `AGENTS.md` и `docs/Agents/agent-onboarding.md`, разделы 1–2. В отчёте: версия из `manifest.json` основного чекаута, что изменилось, какие тесты прошли.

## Чего в заданиях нет

| Чего нет | Почему |
| --- | --- |
| Запуск кода проверки самим расширением | Отдельный большой проект: песочница исполнения, безопасность, данные. Пока код запускает User |
| Окно для ввода пределов при запуске | Пределы повтора задаются в схеме; окно добавляется, когда повтор заработает |
| Продолжение повтора после перезапуска браузера | Намеренно: после перезапуска User видит последнюю запись и запускает сам |
| Проверка ответов по JSON Schema | Не требуется ни одним из девяти заданий |
