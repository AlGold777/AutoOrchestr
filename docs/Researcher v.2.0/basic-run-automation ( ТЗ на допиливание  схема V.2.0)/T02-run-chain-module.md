# T02 · Модуль контрольных сумм и цепочки; чтение и запись файла в папке документов

Ты — исполнитель кода расширения AutoOrchestr. Твоя задача — написать модуль, который считает SHA-256, ведёт цепочку записей прогонов и записывает прогон в папку документов. Код страницы `results.js` в этом задании не меняй: вызовы — задание T03. Теги подключения модуля ставишь ты.

Сначала выполни «Общие правила» из `docs/Researcher v.2.0/basic-run-automation ( ТЗ на допиливание  схема V.2.0)/README.md`.

## Что есть сейчас

- `results/documents-folder.js` пишет копию документа в папку, которую выбрал User. Функция `create` (строка 43) возвращает `{ folderName, pick, ensureAccess, write }` (строка 107). `write` (строка 77) пишет только по пути `<pipeline>/<время старта>/<имя>.md` и не умеет читать.
- Цепочку контрольных сумм User ведёт командами из `docs/Researcher v.2.0/operations/02-runbook.md`, §3. Формат строки: `<номер> <время UTC> <путь файла> <SHA-256 файла> <SHA-256 предыдущей строки>`. Сумма предыдущей строки считается от текста строки вместе с символом перевода строки — так её считает команда `tail -n 1 chain.txt | shasum -a 256`.

## Что сделать

### 1. `results/documents-folder.js`: чтение и запись по пути

В `create` добавь две функции и верни их в объекте (строка 107):

- `readAt({ dirs = [], file })` → `{ ok: true, text }` или `{ ok: false, reason }`. Причины: `none` — папка не выбрана; `denied` — нет доступа; `missing` — папки или файла нет; `error` — другая ошибка, с полем `message`. Папки не создаёт.
- `writeAt({ dirs = [], file, text })` → `{ ok: true, path }` или `{ ok: false, reason }`. Создаёт папки, перезаписывает файл целиком. Те же проверки доступа, что в `write` (строки 78–80). Не бросает исключений.

Имена в `dirs` и `file` очищай функцией `sanitizeName` (строка 18); у `file` расширение сохраняй. В объект `api` модуля (строка 145) добавь `runDirs({ pipeline, startedAt })` — массив из двух имён папок, тот же, что строит `relativePath` (строка 36).

`writeAt` перезаписывает файл намеренно: в отличие от `write`, он не подбирает имя с «(2)».

### 2. Новый файл `disput/basic-run-chain.js`

Глобальное имя `BasicRunChain`. Функции:

| Функция | Что делает |
| --- | --- |
| `sha256Hex(text)` | Асинхронная. SHA-256 от байтов UTF-8 строки, 64 шестнадцатеричных знака в нижнем регистре. В браузере — `crypto.subtle.digest`; в Node — `require('crypto').webcrypto.subtle` |
| `sectionsOf(task)` | Делит текст на разделы по строкам вида `=== НАЗВАНИЕ ===`. Возвращает `[{ title, text }]`; `text` — точная подстрока от строки заголовка до начала следующего заголовка. Текст до первого заголовка, если он не пуст, идёт разделом с `title: ''` |
| `taskSections(task)` | Асинхронная. `[{ title, chars, sha256 }]` по результату `sectionsOf` |
| `chainLine({ number, at, file, fileSha256, prevSha256 })` | Строка цепочки из пяти полей через пробел. В `file` пробелы заменяются на `%20` |
| `lastLine(chainText)` | Последняя непустая строка или `null` |
| `append(chainText, { at, file, fileText })` | Асинхронная. Возвращает `{ line, text }`: новую строку и весь текст цепочки с ней. Номер — число непустых строк плюс один. `prevSha256` — `sha256Hex(последняя строка + '\n')`; для пустой цепочки — `-` |
| `verify(chainText)` | Асинхронная. `{ ok, brokenAt }`: сверяет пятое поле каждой строки, начиная со второй, с суммой предыдущей строки. `brokenAt` — номер первой несошедшейся строки или `null` |
| `saveRun({ folder, dirs, report, at })` | Асинхронная. Записывает прогон и строку цепочки; см. ниже |

`saveRun` получает `folder` — объект с функциями `ensureAccess`, `readAt`, `writeAt` (то, что возвращает `create`) — и `dirs`, папки прогона: их даёт вызывающий через `DocumentsFolder.runDirs`. Порядок:

1. `ensureAccess({ request: false })` не `granted` → вернуть `{ ok: false, reason: 'none' | 'denied' }`.
2. Текст файла — `JSON.stringify(report, null, 2)`. Имя файла — `run_<report.runId>.json`: два прогона, начатые в одну секунду, не затирают друг друга. Записать `writeAt({ dirs, file, text })`.
3. Прочитать `readAt({ dirs: [], file: 'chain.txt' })`. Причина `missing` — цепочка пустая. Любая другая неудача — вернуть её, строку не дописывать.
4. `append` с путём записанного файла и его текстом; записать `chain.txt` в корень папки целиком.
5. Вернуть `{ ok: true, path, line, number, fileSha256 }`.

Любая неудача записи возвращается как `{ ok: false, reason, message }`. Функция не бросает исключений.

Цепочка одна на папку документов и лежит в её корне: одна папка — одна задача. Путь файла в строке цепочки — относительно этой папки.

Если User начал `chain.txt` сам, модуль продолжает его. Пятое поле первой строки не проверяется и может быть любым: у User там сумма файла замка ядра, у модуля — `-`. `verify` сверяет строки начиная со второй.

## Проверка

- `tests/basic-run-chain.test.js` (новый):
  - `sha256Hex('abc')` равно `ba7816bf8f01cfea414140de5dae2223b00361a396177a9cb410ff61f20015ad`;
  - `sectionsOf`: три раздела; текст до первого заголовка; сумма длин разделов равна длине текста;
  - `append` к пустой цепочке даёт номер 1 и `-`; ко второй строке — сумму первой строки с переводом строки (сверь с `require('crypto').createHash('sha256')`);
  - `verify` верной цепочки — `ok: true`; с изменённым знаком во второй строке — `brokenAt: 3`;
  - `saveRun` на фейковой папке: записан `run_<runId>.json`, `chain.txt` вырос на строку, четвёртое поле строки равно сумме текста файла; без доступа — `ok: false` и ни одной записи; ошибка чтения цепочки — `ok: false`, `chain.txt` не тронут.
- `tests/documents-folder.test.js`: `readAt` и `writeAt` — успех, `none`, `denied`, `missing`, ошибка записи. Фейковому файлу добавь `getFile()`, возвращающий объект с `text()`.
