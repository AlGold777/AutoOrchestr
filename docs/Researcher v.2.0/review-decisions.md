# Разбор ревью: что принято в v.2.0

Семь моделей (GPT, Claude, Qwen, Z.ai, Gemini, DeepSeek, Perplexity) отрецензировали v.1.0. Здесь каждая их идея с решением: принята, принята частично или отклонена — и почему. Идеи сверены с файлами v.1.0 и с кодом движка Basic (`disput/custom-engine.js`, `disput/basic-schema.js`, `results.js`), которого у рецензентов не было.

Все решения внесены в документы, запросы и схемы этой папки. Проверено сборкой: 12 схем проходят валидатор Basic, оценку размера запросов с запасом и проверку пар независимости. Прогонов на версии 2.0 не было: ни одно решение ещё не испытано живым циклом.

## 1. Главные изменения v.2.0

Семь решений, каждое закрывает несколько замечаний сразу.

| № | Решение | Что закрывает |
| --- | --- | --- |
| 1 | **Происхождение результата.** У каждого сырого результата одно из трёх происхождений: запуск владельцем, запуск в инструменте модели (код и вывод приложены), рассуждение модели. Рассуждение статус не поднимает; инструмент модели — не выше S1, пока владелец не повторил запуск. Исполнитель обязан отвечать «НУЖЕН ЧЕЛОВЕК», если код не был реально запущен | «Исполнение моделью — вымысел» (GPT 4.1, Claude 1, Gemini 2.1) |
| 2 | **Предложения перестройки вынесены из цикла в схему `5-rebuild`.** В цикле остаётся только диагност. Методист, изобретатель, приёмщик и плацебо работают тогда, когда владелец решил перестраиваться. В задачу этой схемы владелец вкладывает выдержку библиотеки перестроек | Цикл дешевле: 20 запросов вместо 23 (GPT 7.1); плацебо опаздывает на цикл (Gemini 2, Z.ai В12); библиотека недоступна ролям (Z.ai В4, GPT 6.1); один запрос на два шага секретаря (Gemini 3); плацебо и протокол пишет одна модель (Z.ai Ж22); запас размера запроса (Z.ai К2) |
| 3 | **Плацебо выбирает не модель и не номер цикла, а контрольная сумма последней строки журнала.** Каталог контрольных изменений — по классам; пункт задаёт остаток от деления суммы. Заранее его не знает никто, выбрать его не может никто, проверить может наблюдатель. Плацебо того же класса, что и предложение; совпало с предложением — берётся следующий пункт | Плацебо предсказуемо и может совпасть с предложением (Qwen 9, DeepSeek 3, Claude); не случайная выборка (GPT 5.2); не выровнено по масштабу (Z.ai В7) |
| 4 | **Суд перестройки — счёт и правило, а не мнение.** Плечи приходят счётчикам под именами А, Б, В; два счётчика независимо заполняют таблицу; вердикт выносится по правилу, записанному до испытания: разница с плацебо и с прежним методом не меньше двух шумов и не меньше наименьшего интересного эффекта. Пограничный исход — одно продление, затем откат | Один судья свободным текстом (Perplexity R-3); нет решающего правила (Z.ai В8, Claude 2, Qwen 8, GPT 5.1); судья знает метки плеч (Z.ai В7) |
| 5 | **Два разных утверждения.** «Это изменение помогло этой задаче» решается испытанием в задаче. «Перестройка по диагнозу лучше перестройки без диагноза» решается только на полигоне: число пар и порог знакового критерия записаны заранее. Исход «не подтверждено» закрывает проект, но не называется «доказано, что не работает» | Локальный успех выдаётся за доказательство метода (GPT 5.4, 5.5); нет объёма данных и порогов в условиях отказа (Claude 12) |
| 6 | **Честное правило независимости вместо «три группы не пересекаются».** Названы пары ролей, которые одна модель играть не может: автор — исполнитель — проверяющий; секретарь — контролёр; секретарь — автор. Сборщик схем проверяет эти пары и не собирает схему при нарушении | Заявленный инвариант противоречит составу (Z.ai К3, Perplexity R-1, Qwen 3, GPT 8.1); группы нет в схеме (DeepSeek 6) |
| 7 | **Порядок наладки: сначала один полный цикл.** Первый шаг — цикл на учебной задаче с владельцем в роли исполнителя проверки и замером цены. Корпус порч, полигон и подпись порогов — после него, по измеренным числам. Непрерывный режим — последним | Недели подготовки до первого цикла (Claude 11); бюджет подписывается до замера (Qwen 19, Claude 13); автономность раньше доказательности (GPT P3) |

## 2. Что показал код Basic

| Вопрос рецензентов | Что в коде | Решение |
| --- | --- | --- |
| Получают ли слепые шаги текст задачи (Z.ai В11, Qwen 1) | Нет. У участника с собственным запросом задача попадает в запрос только через `{задача}`; в запросах исполнителя и проверяющих её нет | Qwen 1 отклонено: исполнитель пакета не получает. Тест слепоты по выгрузке прогона добавлен в приёмку — он дешёвый |
| Получают ли слепые шаги общие правила (Gemini 6, GPT К6) | Да. Общие правила и предел слов добавляются каждому участнику, с собственным запросом тоже | Замечание неверно. Но оценка размера в сборщике их не считала — исправлено |
| Принуждает ли Basic к пределу слов (Z.ai К2) | Нет, пока у шага не включена строгая длина. Длинный ответ принимается | Принято: оценка размера считает с запасом (8 знаков на слово, превышение на четверть); пределы слов снижены там, где запаса не хватало |

## 4. Проверка и доказательность

| Идея | Кто | Решение |
| --- | --- | --- |
| Проверяющим не нужен текст утверждения: достаточно условий «за» и «против» и способа измерения | Perplexity D-2, GPT 4.2 | Принято: запись заявки для проверяющих больше не содержит утверждения и гипотезы |
| Отдельная роль для наивного предсказания | GPT 5.3 | Отклонено: лишний запрос. Вместо этого проверяющие судят, не занижено ли наивное предсказание; занижено — подтверждение не засчитывается |
| Три ступени: получены ли данные, годны ли, подтверждают ли | GPT 4.2 | Принято частично: проверяющий сначала судит годность (холостой прогон, порча, происхождение) и только потом совпадение. Отдельных шагов не добавлено |
| Статусы смешивают доказанность и новизну | GPT 4.4 | Принято: новизна — отдельная отметка, статус её не содержит |
| Калибровка не говорит о зависимости ошибок проверяющих; сорок примеров дают разброс около пятнадцати пунктов | Claude 5, GPT 4.3 | Принято: при калибровке считается третье число — доля порч, пропущенных всеми сразу; пороги записываются с объёмом выборки |
| Два числа калибровки считает модель | Perplexity D-7 | Принято: модель строит построчную таблицу, итог считает владелец |
| Порогов нет в ключе калибровки | Z.ai Ж18 | Принято: допуск решает владелец по порогам ядра; из запроса счётчика допуск убран |
| «Задача сгорела» не проверяется способом проверки | Z.ai В5 | Принято: «сгорела» — только если заявленное решение прошло способ проверки из карточки или найден первичный источник |
| При трёх моделях исполнитель судит свой результат | Z.ai Ж17 | Принято: при одном проверяющем результат исполняет владелец |
| Нет правила для вердиктов 2:1; решающий опыт негде исполнить | Qwen 2 | Отклонено по факту: правило есть (рабочий цикл, §5) — статус не меняется, следующий цикл вида «Разрешение». В обзор добавлена строка |
| Нет кворума проверки | Qwen 15 | Принято: меньше двух вердиктов — статус не повышается, цикл помечается неполным |
| Три цикла подряд без настоящего запуска проходят незаметно | следствие решения 1 | Добавлено стоп-правило `STOP_NO_RUN` |
| Вердикт проверяющего — в формате с обязательными полями | Perplexity R-5 | Принято частично: первая строка ответа — одно слово вердикта; контролёр сверяет его с записью дословно. JSON не вводится: проверяющему нужен текст для доводов |
| Срок у предсказания не обязателен в формате заявки | Perplexity D-3 | Принято для качественных предсказаний |
| Искателю нужен настоящий поиск | Z.ai Ж21 | Принято: искатель без поиска отвечает «поиска нет» и ссылок не приводит; состав проверяется пробным прогоном |
| «Взгляд извне» диагност пишет сам | Z.ai Ж19 | Принято частично: обещание убрано из цикла; взгляд извне даёт владелец в задаче схемы перестройки |
| Нет способа проверки — нельзя начать, хотя есть барьер «нечем проверять» | GPT 8.6 | Отклонено по факту: жизненный цикл это разводит — тогда первой задачей становится постройка проверки. Формулировка обзора исправлена |

## 6. Память и перенос

| Идея | Кто | Решение |
| --- | --- | --- |
| Библиотека не участвует в новой задаче | GPT 6.1–6.3 | Принято: в настройке и в перестройке владелец вкладывает выдержку библиотеки; сборщик обязан назвать, что из неё взято. Взятое — гипотеза о переносе, а не факт |
| Запись библиотеки должна нести условия применимости | GPT 6.3 | Уже было («Предусловия» у библиотекаря); добавлено «где не сработало» |
| Тупик, «подтверждённый трижды», наследуется как запрет | Qwen 5 | Принято: в новую задачу тупик приходит свидетельством; запретом становится, только если его границы покрывают новую задачу |
| У записи карты нет ссылки на источник | Claude 6 | Принято: каждая запись карты несёт номер записи цикла; без номера — «не проверено» |
| Карта теряет детали; первичное недоступно | GPT 6.4, Qwen 14, Gemini 2.3 | Принято частично: закрытое уходит в архив карты у владельца; координатор может запросить первичную запись по номеру — владелец вложит её в следующий пакет |
| Предел карты словами выше предела знаками | Z.ai Ж14 | Принято |
| Пакет и карта делят один предел | Perplexity R-4 | Принято: ядро и конфигурация входят целиком, карта — в остаток; пакет длиннее предела не запускается |
| Журнал — не машинный источник истины; форматы JSON почти не используются | GPT К4, Gemini 2.2 | Принято честно: источник истины — выгрузки прогонов в цепочке. Записи секретаря — указатель к ним. Обещание «карта пересобирается из журнала один в один» снято; форматы, которые никто не проверяет программой, названы описанием содержания |
| Остаток бюджета ведётся в двух местах | Z.ai В10 | Принято: остаток считает владелец по выгрузке и пишет в пакет; модели остаток не считают |
| «Часы расчёта» нечем измерить | Z.ai Ж25 | Принято: единица убрана; остаются запросы, запуски проверок, минуты владельца |

## 7. Ядро, журнал, наблюдатель

| Предел обращений к закрытым наборам не задан | DeepSeek 8 | Отклонено по факту: порог `closed_set_access_limit` в ядре есть |

## 9. Непрерывный режим

Режим не построен; меняется только описание того, что нужно от расширения.

| Идея | Кто | Решение |
