# TheCycle — ревью контроллера и практический план реализации

**Дата:** 26.11.2026. **Статус:** проект, статический аудит; NO-GO для автономной эксплуатации.  
Связь: [архитектура v0.2](../../Architecture/TheCycle/README.md), [архитектурное ревью TC-R01–TC-R05](TheCycle-architecture-review.md).

## 1. Решение для собственника

Не писать ещё один движок pipeline. Создать небольшой внешний управляющий цикл, который получает от Basic полный результат одного прогона, сохраняет его, проверяет условия продолжения и запускает следующий прогон. Сначала доказать техническую надёжность на неизменной схеме, затем подключать математическое планирование и автоматическую смену стратегии.

В проверенном main имеется конечный Basic; расширенные функции в черновом PR №3 пока не приняты. Самостоятельный внешний контроллер TheCycle в проверенных исходниках не найден. Поэтому ниже — план реализации и интеграции, а не утверждение, что отдельный контроллер уже написан и исправлен.

## 3. Минимальный контроллер: контракты

Размещение ниже предложено; окончательно проверить структуру сборки и фактический вход в Basic перед изменением кода. Имена не являются существующим API.

- `disput/thecycle/controller.js`: один переход за вызов tick(researchId), программная FSM, никакой собственной отправки промптов.
- `disput/thecycle/basic-adapter.js`: validate, execute, cancel, reconcile; мост к текущему Basic/транспорту и нормализация результата.
- `disput/thecycle/state-store.js`: долговечное состояние, журнал, версии, ссылки на исходники и исключительное владение.
- `disput/thecycle/policy.js`: разрешённые переходы, ресурсы, остановка; чистые функции.
- Модуль семантического планирования и математические метрики — после рабочего технического цикла, не обязательны для первого MVP.

Предпочтительный кандидат хранилища — IndexedDB с транзакциями, проверкой доступности и квоты; это проектное решение, не подтверждённая существующая инфраструктура. chrome.storage допустим только при эквивалентном протоколе согласованности и восстановления. Не создавать отдельный сервер без необходимости.

```json
{
  "researchId": "r1",
  "stateVersion": 7,
  "phase": "READY",
  "nextCycle": 3,
  "activeRunId": null,
  "pipelineRef": "p1:v1",
  "lastCommittedPacket": "packet-2",
  "ownerEpoch": 9,
  "budget": {"remainingCalls": 20},
  "stopRequested": false
}
```

Числа в примере иллюстративны. Реальный бюджет устанавливает собственник. Все переходы используют compare-and-set stateVersion и ownerEpoch. Перед внешним запуском атомарно фиксируется INTENT с runId и резервом бюджета, затем выполняется внешний вызов. После получения результата транзакция фиксирует первичные материалы, манифест, расход и следующую фазу. Сбой между внешним эффектом и фиксацией переводит в RECONCILE; при отсутствии доказательства исхода — PAUSED_UNKNOWN. Автоматическая повторная отправка неизвестного запроса запрещена. Exactly-once внешнего вызова не обещается; требуется идемпотентная фиксация результата.

Фазы MVP: READY → INTENT → RUNNING → COMMIT → EVALUATE → READY/PAUSED/COMPLETED. Отдельно RECONCILE и FAILED. Один tick делает ограниченную работу, не бесконечный синхронный цикл. Планировщик событий будит контроллер; при остановке worker следующее пробуждение восстанавливает состояние. UI отображает состояние, но не является источником истины. Stop проверяется перед резервированием и перед каждым внешним действием; отмена текущего запроса best effort. Идентификаторы передаются в транспорт, поздние ответы старого владельца не запускают переходы.

Отдельно решить зависимость от PR3 по результатам C00. На MVP не добавлять автогенерацию схем, сложный интерфейс, распределённую БД или выбор десятков параметров.

## 6. Критерий готовности и ограничение аудита

Переход к адаптивному исследованию только после технического MVP; к автономной эксплуатации — после C07 и закрытия P0. Результаты проверок и ошибки фиксировать в датированном отчёте. Пороговые значения семантических метрик и бюджетов калибруются отдельно. Код контроллера не менялся: это реализационный план. Аудит основан на чтении конкретных исходников и тестовых файлов; весь репозиторий, фактическая браузерная связка и живые провайдеры не проверены.
