# Старт новой сессии: что нужно знать агенту

Документ для агента, который начинает работу в проекте с нуля, без памяти и без доступа к прежним разговорам. Правила процесса ниже записаны владельцем проекта в личных инструкциях и передаются здесь, чтобы не зависеть от аккаунта. Описание продукта — в [обзоре проекта](project-overview.md), навигация — в [карте документации](documentation-map.md).

## 1. Откуда загружено расширение и как доставлять правки

Расширение у владельца загружено из **основного чекаута** `/Users/restart/Documents/GitHub/AutoOrchestr`, а не из worktree. Коммит в ветке worktree до владельца не доходит.

- Ветку основного чекаута определяйте командой `git -C /Users/restart/Documents/GitHub/AutoOrchestr branch --show-current`. Это не обязательно `main`: на 22.10.2026 там `claude/gracious-mccarthy-fe9lrh`.
- **Перед первой строкой кода** определите версию, которая реально загружена: `grep '"version"' <основной чекаут>/manifest.json` (сверять с `extensionVersion` в последней телеметрии). Worktree может отставать от неё; правка на устаревшей базе потребует полного переноса.
- **Доставка.** Задача не завершена, пока правка не лежит в основном чекауте: после коммита `git -C <основной чекаут> merge --ff-only <ваша ветка>`. Если слияние не только вперёд — сначала подтянуть ветку основного чекаута в свою ветку (в worktree), разрешить конфликты, повторить.
- В основном чекауте могут лежать **чужие незакоммиченные правки**. Не затирать их: перед слиянием убедиться, что файлы, которые оно меняет, с ними не пересекаются (`git diff --name-only HEAD <ваша ветка>` против `git status --short`). При пересечении остановиться и сообщить владельцу.
- **Отчёт о доставке:** выполнить `grep '"version"' <основной чекаут>/manifest.json` и привести эту версию. Версия не совпала с заявленной — писать «НЕ доставлено», а не «Сделано». В конце одной строкой напомнить: chrome://extensions → Reload.
- Изменения только документации и стенда схем расширение не меняют: слияние их доставляет, перезагрузка расширения не нужна.

## 2. Версия, документация, git

- После **любых изменений кода** обновить версию в `manifest.json`, пакетном манифесте и версионных константах изменяемого файла (`ALGORITHM_VERSION`, `RULE_SET_VERSION` и т. п.). Изменение функционала — с правкой документации в том же коммите (документы Basic сверяются с кодом тестами `tests/basic-schema-guide.test.js` и `tests/basic-docs-refs.test.js`).
- **Правки только документации и стенда схем версию `manifest.json` не меняют** (практика этой работы): расширение они не затрагивают. У стенда своя версия — `STAND_VERSION` в `canvas-prototype/stand.js`, её поднимают при каждой правке стенда и пересобирают файл (`python3 build.py`).
- Каждое законченное самостоятельное изменение — отдельный коммит; стадировать выборочно (`git add <путь>`), не `git add -A` по умолчанию. Перед разрушающими операциями (`checkout .`, `reset --hard`, `clean`, `stash`) — `git status --short`.
- **Коммит поручают субагенту Haiku 5.5** (`model: haiku`, это записано в корневом `AGENTS.md`). В задании ему перечислять только git-команды и запрещать другие инструменты: однажды такой субагент по ошибке запустил отдельную сессию (`hand_off_to_session`). Образец задания: «В <путь worktree> выполни `git add <файлы>` и `git commit -m "<сообщение>" -m "Co-Authored-By: Claude Haiku 5.5 <noreply@anthropic.com>"`. Больше ничего не коммить, не вызывай hand_off_to_session и не запускай другие сессии, только git-команды. Верни короткий хеш и `git status --short`». После отчёта проверить результат самому: `git log --oneline -1`, `git show --stat --format= HEAD`, `git status --short`.
- Спрашивать владельца только о продукте и о действиях вовне (push в удалённый репозиторий, публикация). Ветками, слияниями и коммитами агент распоряжается сам; в отчётах — версия, что изменилось и где результат, без git-терминов.

## 2а. Тесты и телеметрия перед доставкой

- Тесты запускает Jest: `npm test` (то же, что `jest --config tests/jest.config.js`) или на отдельных файлах `npx jest --config tests/jest.config.js tests/<файл>.test.js`. В worktree может не быть `node_modules`: тогда `npm install` по `package.json` либо запуск Jest из основного чекаута на файлах worktree (`<основной чекаут>/node_modules/.bin/jest --config tests/jest.config.js <файлы>`, из каталога worktree).
- Изменили документацию Basic — обязательно прогнать `tests/basic-schema-guide.test.js` и `tests/basic-docs-refs.test.js` (на 22.10 — 19 тестов, все проходят). Изменили код — прогнать тесты затронутых модулей и перед доставкой, по возможности, весь набор.
- «Зелёным» считается набор без падений, кроме известных нестабильных: тест `false success: watcher completion guards` (`tests/false-success-watcher-guard.test.js`, зависит от времени; описан как TEST-2 в `Pipeline scenarios/basic-developer.md`, раздел 5). Падение любого другого теста до вашей правки — не повод его игнорировать: выяснить причину и сообщить.
- Загруженная версия расширения по телеметрии: поле `extensionVersion` в отчётах телеметрии; формат и разбор — [telemetry.md](Telemetry/telemetry.md) и [инструкция анализа отчёта](Telemetry/report-analysis-prompt.md). Если отчёта нет, версию берут из `manifest.json` основного чекаута.

## 2б. Слова, которые легко перепутать

- `assemble` в коде Basic — функция сборки запроса (`BasicSchema.assemble`, шаг `assemble` с явным заданием при `input: none`). Блок `assemble` в черновых схемах стенда — склейка документа без нейросети (пункт 1.11 плана); это другое. При переносе в Basic рассмотреть другое имя блока.
- «Компонент» — тип элемента схемы (раунд, синтез, проверка, источник и т. д.), «блок» в запросе для моделей — то же самое.
- «Кнопка i» — кнопка в шапке панели стенда; клавиша I делает то же.
- «Возврат» в Basic — действие `goto` / `return`; в черновой схеме — новый этап с `repeats` и `because`.

## 3. Как работать с владельцем

- Отвечать коротко и по существу; отчёт «Поломано / Сделано» — версия и статус тестов одной строкой.
- Технические решения принимает агент: выбирает по назначению и данным, делает и сообщает выбранное. Не предлагать владельцу меню «А или Б» там, где есть очевидный вариант.
- Когда владелец обсуждает концепцию, отвечать в чате; документы и коммиты — после согласования.
- Если владелец указал пробел, прямо признать его до исправления; не выдавать его идею за уже имевшуюся.
- Слово владельца может означать элемент интерфейса, а не клавишу (например, «кнопка I» — кнопка «i» в шапке панели). Если смысл не очевиден, проверить на экране, а не угадывать.
- «Компонент» в разговорах о схемах — тип элемента схемы (как «сохранённый артефакт»), а не метафоры из кино и театра.
- Минимально достаточное решение: не добавлять функции, поля и пояснения без практической необходимости (корневой `AGENTS.md`).

## 4. Браузер: что делать самому и что поручать владельцу

**Нужна проверка в настоящем Chrome с загруженным расширением (импорт, экспорт, кнопки страницы)? Это делается без участия владельца: рецепт с точными командами — [agent-live-chrome.md](agent-live-chrome.md) (CDP, `Extensions.loadUnpacked`). «Нет доступа к живому Chrome» — не причина остановиться; прогон поручайте субагенту Haiku по этому рецепту.**

У владельца в Chrome два собственных расширения, и доступность инструментов зависит от сессии, поэтому сначала проверьте, что есть у вас.

- **Claude-расширение (Claude in Chrome)** управляет реальным Chrome владельца: вкладки, переход по адресу, чтение страницы, консоль, выполнение JavaScript, скриншоты. Инструменты называются `mcp__claude-in-chrome__*` и могут быть отложенными: загружайте их одним запросом через поиск инструментов (набор: контекст вкладок, переход, чтение страницы, JavaScript, консоль, создание и закрытие вкладок). Если оно доступно, проверяйте страницы и DOM им сами, а не просите владельца. Наблюдавшиеся ограничения: адреса `file://` оно не открывает (подменяет схему на https), поэтому локальные HTML открывайте через временный сервер (`python3 -m http.server <свободный порт>` в нужной папке, остановить после проверки); созданные вами вкладки закрывайте.
- **Встроенный браузер приложения Claude** (`mcp__Claude_Browser__*`) тоже годится для проверки, но файлы по `file://` показывает статичным снимком без скриптов: для страниц со скриптами — тот же временный сервер.
- **Проверка `file://`-страницы в настоящем Chrome без окна:** запустить `/Applications/Google Chrome.app/Contents/MacOS/Google Chrome --headless=new --remote-debugging-port=<порт> --user-data-dir=<временная папка> <file://-адрес>` и управлять страницей по протоколу отладки (CDP; в Node 22 есть встроенный WebSocket). Так проверялось, что стенд схем работает по `file://` и что хранилище общее для всех `file://`-страниц.
- **GPT-расширение владельца** открывается на любой странице (страницы моделей и нашего расширения). Через владельца ему поручают сбор данных, которые агент не получит сам ни одним из способов выше: реальный DOM перед правкой селектора или детектора, состояние страницы при визуальном баге, сверка собранного ответа с видимым. Задание оформляется отдельным блоком (страница, момент, что собрать, формат вывода); просить **данные, а не выводы**: дословный текст, `outerHTML`, атрибуты, «не видно». Не просить того, что агент может получить сам (код, телеметрия в репозитории, браузер выше).
