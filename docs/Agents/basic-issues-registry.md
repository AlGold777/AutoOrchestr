# Реестр открытых проблем Basic

Один список для движка Basic. Цель работы — не прогоны, а устранение препятствий, которые мешают прогону. Новую проблему, найденную в любом прогоне (включая прогоны других задач, например «Ловушка для комаров»), ведущий вносит сюда в тот же ход, со ссылкой на экспорт. Закрытая проблема получает версию и тест; «не проверено вживую» остаётся открытым хвостом, пока живой прогон не подтвердит.

Статусы: **ОТКРЫТО** — не сделано; **ЗАКРЫТО-Н** — исправлено и покрыто тестами, живой проверки нет; **ЗАКРЫТО** — подтверждено живым прогоном; **ПРОВЕРИТЬ** — по плану закрыто, независимого подтверждения кодом нет (аудит AUD-1).

Источники: R — ревью 2026-10-30 (`docs/Run Automation/Test_run/Remote_Viewfinder_2026-10-30/notes/review.md`, пункты A–E); L — живые прогоны на 2.81.945–948 и прогон по комарам.

## 2. Открытые проблемы (в работе)

**ART-1 — повторная передача артефакта в тот же чат (ОТКРЫТО, 2026-10-31).** Согласовано с User: одна версия документа передаётся файлом или текстом один раз в каждый чат; дальше — ссылка по названию и версии. Свой документ автор уже имеет. Та же версия повторно передаётся только в чат без общей истории; новая версия учитывается отдельно. Сейчас движок повторно вставляет содержимое по каждому `input`, `revisionOf` требует вход даже для собственного документа, холст рисует повторные связи. Учёт входных файлов по ID в `BasicFileDelivery` не устраняет повторы текста артефактов. В этом изменении обновлена документация; исправление кода и живые проверки ещё не выполнены. Места изменения и сценарии проверки — [basic-developer.md, «Передача артефактов по истории чата»](<../Pipeline scenarios/basic-developer.md#передача-артефактов-по-истории-чата>).

## Находки 31.10.2026: восстановление холста

**MEM-1 — пустое место записывается как участник без имени.** `results.js:basicSchemaFromPage` включал `.pipeline-empty-slot` в `shownKeys`, хотя `PipelineRuntime.captureModelStackState` его исключал. Исправление 2.81.958 исключает placeholders и пустые ID при сборке схемы; сохранённые пользовательские схемы автоматически не исправляются. Изолированное воспроизведение и ограничения проверки — [basic-reload-state.md](<../Pipeline scenarios/basic-reload-state.md>).

**MEM-2 — уведомление при редактировании неисполняемого черновика (ОТКРЫТО, гипотеза по коду).** `applyParticipantSchemaEdit` допускает отсутствие исполнимого шага, но вложенный `applyPipelineConfig` снова вызывает строгую проверку и может оставить уведомление после очистки ошибки внешним вызовом. Требуется отдельное воспроизведение; не объясняет пустое имя и в 2.81.958 не исправляется.

**MEM-3 — после перезагрузки не очищена рабочая сессия (исправление 2.81.959).** User подтвердил требование пустой сессии. Прежний контракт сохранял телеметрию, а экспорт Basic выбирал последнюю архивную запись. Теперь сброс подтверждается фоном до hydration; старые UI-черновики, доставка, телеметрия и состояние прогона не восстанавливаются, архив и сохранённые схемы остаются. Подробности и проверки — [basic-reload-state.md](<../Pipeline scenarios/basic-reload-state.md>).

**MEM-4 — отложенное восстановление UI стирает пришедшую карточку (исправление 2.81.959).** `applyCrossViewUiState` отправлял `llm-selection-change`, хотя выбор провайдеров восстанавливается отдельно. Обработчик очищал ленту после поступления ответа во время загрузки. Восстановление отсутствующего снимка теперь пропускается; лишнее событие при восстановлении полей удалено. Обнаружено и воспроизведено тестом карточки участника, без изменения его ожиданий.

**MEM-5 — Reload расширения сохраняет телеметрию (исправление 2.81.961).** Правка MEM-3 охватывала обновление страницы, но не `background/index.js:resetVolatileRuntime`. В новый runtime переносились `__diagnostics_events__` и `messageDelivery.journal.v2.local`. Теперь оба ключа очищаются вместе с рабочим состоянием до hydration, сохраняется новая граница сессии; обычное пробуждение worker не очищает данные. Архив Basic и библиотека схем остаются. Проверки lifecycle исполняют фактический startup-код, а не только отдельный handler; [подробности](<../Pipeline scenarios/basic-reload-state.md>).
