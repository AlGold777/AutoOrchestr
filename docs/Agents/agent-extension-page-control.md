# Управление страницей расширения из браузера

Эта инструкция описывает практическое управление `pipeline_panel.html` через CDP/CUA и публичные методы `window`. Полная спецификация и инвентаризация элементов обеих страниц расширения (`pipeline_panel.html` и `result_new.html`) находятся в [agent-extension-pages-spec.md](agent-extension-pages-spec.md). Страница собрана в [pipeline_panel.html](../../pipeline_panel.html), её логика подключена из [results.js](../../results.js). При изменении HTML сначала сверяйте фактические `id`; при изменении поведения — обработчики и экспортируемые методы в `results.js`.

## 1. Подключение к правильной странице

- Для изолированной проверки расширения следуйте [инструкции по живому Chrome](agent-live-chrome.md): отдельный временный Chrome, CDP, загрузка распакованного расширения через `Extensions.loadUnpacked`.
- После загрузки расширения используйте `id`, который вернул CDP, и создайте цель `chrome-extension://${id}/pipeline_panel.html`. Не угадывайте ID: URL с чужим ID может показать пустую страницу.
- Обычный Chrome User’а используйте самостоятельно при наличии подходящего инструмента (например, CUA) и проверьте перед действием, что выбран правильный профиль, вкладка и URL. Не закрывайте чужие вкладки.
- Дождитесь загрузки страницы. `window.__RESULTS_PAGE_LOADED === true` означает, что `results.js` начал загрузку, но не гарантирует завершение асинхронной инициализации. Дополнительно проверьте `document.title`, `location.href`, наличие нужного контрола и глобального метода. При отсутствии признака прочитайте консоль/исключения и DOM; не вызывайте методы незагруженной страницы и не внедряйте `results.js` повторно: флаг защищает от двойной инициализации.

CDP-вызов выполняется в контексте прикреплённой вкладки:

```js
const r = await send('Runtime.evaluate', {
  expression: "({title: document.title, url: location.href, ready: window.__RESULTS_PAGE_LOADED === true})",
  returnByValue: true,
  awaitPromise: true
}, sessionId);
console.log(r.result.value);
```

Схема запуска, подключения, `sessionId`, ожидания, DOM, консоли и скриншотов описана в `agent-live-chrome.md`.

## 2. Способы взаимодействия

### Предпочтительный способ: настоящий ввод или клик

CUA работает с тем же интерфейсом, который видит человек. На первом вызове `mcp__cua_repl.js` и после сброса сессии выполните ровно один вызов инициализации, например `await cua.getState();`; документация CUA появится в ответе. Дальше получите инвентарь, найдите браузер и вкладку именно по URL, привяжите вкладку и запросите её состояние:

```js
const state = await cua.getState();
const browser = state.browsers.find((item) =>
  item.tabs.some((tab) => tab.url === 'chrome-extension://<id>/pipeline_panel.html')
);
const tabInfo = browser?.tabs.find((item) => item.url === 'chrome-extension://<id>/pipeline_panel.html');
if (!browser || !tabInfo) throw new Error('Вкладка pipeline_panel.html не найдена');
const tab = await cua.getTab(tabInfo.id, {browser: browser.id});
const ax = await tab.getAXState();
```

Если вкладки ещё нет, откройте её способом, который подходит текущему браузеру. Для изолированной проверки используйте отдельный Chrome и CDP из `agent-live-chrome.md`. В браузере User навигируйте самостоятельно в рамках задачи при наличии подходящего инструмента; сначала сохраните возможность вернуться к исходной вкладке.

После чтения `getAXState()` кликайте по индексу из **последнего** дерева и заново читайте состояние:

```js
await tab.click(45); // только если индекс 45 в последнем getAXState() — нужная кнопка
const after = await tab.getAXState();
```

Индекс `45` здесь пример, а не постоянный ID. После любого действия, навигации, открытия меню или изменения DOM индексы могут поменяться.

Если после действия CUA пишет, что дерево не изменилось, это может быть diff, а не подтверждение отсутствия эффекта. Один раз запросите полный снимок `getAXState({disableDiffing: true})` или screenshot и проверьте фактическое значение/выделение. Не повторяйте клик, пока не выяснили, сработало ли первое нажатие: многие кнопки являются переключателями.

CUA имеет два похожих, но разных интерфейса:

- **Окно приложения**: `const app = await cua.getApp("Google Chrome")`; `app.click(index)`, `app.paste(text, options)`, `app.typeText(text, index)` и `app.pressKey(key)`. Для адресной строки окна сначала сфокусируйте поле, затем используйте `app.paste(url, {format: "text"})` и `app.pressKey("Return")`. У `app.paste` **нет аргумента индекса**. Это системная вставка, на Mac аналог Cmd+V, на Windows/Linux Ctrl+V.
- **Вкладка браузера**: `tab.click(index)`, `tab.paste(indexOrNull, text, options)`, `tab.typeText(index, text)`, `tab.pressKey(indexOrNull, key)`. У `tab.paste` первым аргументом идёт индекс поля либо `null` для текущего фокуса. У `tab.goto(url)` есть только если этот метод присутствует у привязанной вкладки.
- Некоторые CUA-вкладки работают только через DOM/Playwright. Тогда нативные `click`/`paste`/`pressKey` могут сообщить, что ввод не поддерживается; используйте документированные Playwright locators этой вкладки. Не повторяйте тот же нативный ввод без изменения метода.

Если CUA вернул ошибку, сначала проверьте сигнатуру метода (App или Tab), текущий фокус, последний AX snapshot и выбранную вкладку. В частности, `app.paste(index, text)` неверен и возвращает `Invalid params`; для индекса используйте `tab.paste(index, text)`.

Проверенный шаблон вставки URL в **окне Chrome**:

```js
const app = await cua.getApp('Google Chrome');
const ax = await app.getAXState();
// По текущему ax найдите индекс поля «Адресная строка и строка поиска».
await app.click(<индекс адресной строки из ax>);
await app.paste('chrome-extension://<id>/pipeline_panel.html', {format: 'text'});
await app.pressKey('Return');
const after = await app.getAXState();
```

Подставляйте ID из фактического URL/результата CDP. На macOS не отправляйте Ctrl+V как клавиатурную комбинацию: используется Cmd+V, который выполняет `app.paste`. У `tab.paste` буфер обмена может не восстанавливаться после вставки; у нативного `app.paste` на macOS предыдущий буфер восстанавливается автоматически.

### CDP: выполнить действие на странице

Когда нужно работать по DOM, сначала прочитайте элемент, потом вызовите его штатный DOM-метод:

```js
const r = await send('Runtime.evaluate', {
  expression: `(() => {
    const el = document.querySelector('#llm-gpt');
    if (!el) return {found: false};
    const before = el.classList.contains('active');
    el.click();
    return {found: true, before, after: el.classList.contains('active')};
  })()`,
  returnByValue: true,
  awaitPromise: true
}, sessionId);
console.log(r.result.value);
```

`HTMLElement.click()` запускает обработчики страницы и обычно достаточен для проверки поведения, но событие синтетическое (`isTrusted === false`). Если код страницы или браузер требует настоящий жест, используйте CUA-клик или CDP `Input.dispatchMouseEvent` по координатам. Для `select`, `input` и `textarea` изменение `.value` само по себе не вызывает обработчики: отправьте `input` и/или `change` в зависимости от события, на которое подписан код. Например:

```js
const el = document.querySelector('#debate-round-value');
el.value = '4';
el.dispatchEvent(new Event('input', {bubbles: true}));
el.dispatchEvent(new Event('change', {bubbles: true}));
```

После действия дождитесь завершения синхронизации/сохранения (обычно 300–500 мс), затем заново прочитайте URL, значение контрола и видимое состояние. Успехом считается изменившееся состояние, а не только отсутствие ошибки у CDP.

### Кнопки и диалоги браузера

- HTML-кнопки вызывайте через `el.click()` или настоящий клик.
- Для `select` берите допустимые значения из `el.options`, не придумывайте их.
- Для `confirm`/`prompt`/`alert`, скрытых полей файлов и File System Access API используйте специальные инструкции из `agent-live-chrome.md`. Вызов `click()` не открывает системный диалог надёжным способом.
- Не подделывайте жесты, если проверяется API, который требует пользовательского жеста. Переключитесь на CUA/настоящий ввод и отдельно подтвердите результат.

## 3. Часто нужные элементы `pipeline_panel.html`

| Действие | Селектор / метод | Что проверить после действия |
|---|---|---|
| Выбрать или снять модель | `#llm-gpt`, `#llm-claude`, `#llm-qwen`, `#llm-zai`, `#llm-kimi`, `#llm-gemini`, `#llm-grok`, `#llm-deepseek`, `#llm-lechat`, `#llm-perplexity` | Класс `.active`; `window.ResultsShared.getSelectedLLMs()` |
| Ввести запрос | `#modTa` | `value`; ввод не запускает запрос сам по себе |
| Выбрать ведущую модель | `#judge-select` | `value` и выбранная подпись |
| Выбрать отправителя / получателя | `#mod-sender-select`, `#mod-receiver-select` | `value`; опции получайте из DOM после загрузки |
| Запустить, продолжить, подтвердить или остановить | `#debate-run-toggle-btn` | Сначала прочитайте `aria-label`, `title` и доступный текст: одна кнопка меняет действие во время прогона |
| Число раундов | `#debate-round-value`, кнопки `#debate-round-minus-btn`, `#pipeline-add-round-btn` | Значение и отображение раундов |
| Длина ответа | `#debate-length-select` | `value`, подпись и связанные мини-подсказки |
| Режим Auto | `#debate-auto-toggle-btn` (видимый) или `#debate-run-policy-select` (служебный select) | `checked`/`value`; после прямой установки значения отправьте `change` |
| Открывать ответы в новых вкладках | `#new-pages-checkbox` | `checked` |
| Переключить Tuning Control | `#pipeline-toggle-modifiers-btn` | `aria-pressed` и видимость панели |
| Панель Basic / выбор дефолтов | `#entryPoint` | Окно/панель Basic и видимое содержимое |
| Создать пустой pipeline | `#pipeline-add-btn` | Новая схема/пустой поток; действие меняет текущую схему |
| Сохранить текущий pipeline | `#pipeline-save-btn` | Название и карточка появились в `#pipelineItems` |
| Экспорт/импорт схем | `#pipeline-export-btn`, `#pipeline-export-all-btn`, `#pipeline-import-btn`, `#pipeline-profile-btn` | Диалог, скачивание или результат импорта; файловые диалоги требуют отдельного сценария |

**Это три разных действия:**

1. Кнопка вроде `#llm-gpt` включает/выключает провайдера в наборе выбранных моделей. Она синхронизирует и сохраняет выбор, но не запускает модельный запрос и не задаёт ведущую/отправляющую роль.
2. `#judge-select`, `#mod-sender-select` и `#mod-receiver-select` задают роли/маршрут. Их варианты формируются из текущего набора выбранных моделей. Сначала выберите провайдера, дождитесь обновления опций, затем задавайте роль.
3. `#debate-run-toggle-btn` отправляет prompt или управляет уже идущим прогоном. Клик по нему может взаимодействовать с внешними сайтами моделей.

В таблице доступности: Lead начинается с пустого значения `~ Lead ~`; Sender содержит `Moderator` (подпись User) и выбранные модели, но некоторые варианты могут быть `disabled` до подтверждения или во время последовательного хода; Receiver содержит пустое значение (All models), `__none__` и выбранные модели. Для User-инициированного запроса проверяйте доступность варианта, а не только наличие `<option>`.

Кнопка модели добавляет выбранную модель в подходящие раунды canvas. Если на странице три раунда, в каждом может появиться блок GPT; это три появления модели в последовательных раундах, а не три разных выбранных модели. Выбор провайдера сохраняется в локальном состоянии расширения. Не меняйте чужой набор моделей «для проверки», если не нужно оставить его изменённым.

Чтобы программно выбрать вариант `<select>`, сначала проверьте наличие и `disabled` у требуемой опции, затем установите точное `value` и отправьте `change`. Для sender/receiver обработчик сохраняет выбранную маршрутизацию; прямое изменение значения без события может остаться только визуальным:

```js
const select = document.querySelector('#judge-select');
const option = [...(select?.options || [])].find((item) => item.textContent.trim() === 'GPT');
if (!select || !option || option.disabled) throw new Error('Опция GPT недоступна');
select.value = option.value;
select.dispatchEvent(new Event('change', {bubbles: true}));
({value: select.value, label: option.textContent.trim()});
```

Или выберите вариант настоящим кликом/клавиатурой через CUA. Если список пуст, сначала выберите кнопку провайдера и снова прочитайте состояние. Метод `syncModeratorSelectors()` — внутренняя функция в замыкании, напрямую из `window` не вызывается; обработчик выбора моделей вызывает её сам.

Кнопка `#debate-run-toggle-btn` запускает отправку запроса и может взаимодействовать с внешними сайтами моделей. Не нажимайте её, если пользователь не просил запускать прогон. Во время работы эта же кнопка может означать остановку, паузу, продолжение, подтверждение или переход к следующему этапу — проверьте её текущее состояние перед кликом.

## 4. Внутренние методы, выставленные на `window`

Большинство функций `results.js` находятся внутри замыкания. Они **не вызываются напрямую** из CDP. Внешнему коду доступны только методы, явно записанные в `window`; наличие функции в исходнике само по себе не делает её публичной. Для остальных действий используйте DOM-контролы и их штатные обработчики.

| Метод | Аргументы / результат | Назначение и оговорки |
|---|---|---|
| `window.ResultsShared.getSelectedLLMs()` | без аргументов → массив имён моделей | Текущий набор выбранных кнопками моделей. Может отсутствовать до полной загрузки страницы. |
| `window.syncPipelineModelsFromSelectedLLMs(options = {})` | опции синхронизации → `boolean` «изменился ли pipeline» | Обновляет модели в раундах pipeline по текущему выбору моделей и сохраняет совместимые роли. Не выбирает сами модели за пользователя. `force: true` просит пересинхронизировать независимо от обычной проверки. |
| `window.syncDebateSchemeUi()` | без аргументов | Обновляет видимость и доступность UI-контролов, зависящих от схемы. Не выбирает схему. |
| `window.setDebateSchemeValue()` | объявлен без аргументов | Совместимый синхронизатор: вызывает `syncPipelineModelsFromSelectedLLMs({force:true})` и `syncDebateSchemeUi()`. Переданный аргумент игнорируется; не используйте его как setter значения схемы. |
| `window.getSelectedPipelinePresetId()` | без аргументов → ID пресета | Возвращает выбранный пресет pipeline. Проверяйте `typeof` перед вызовом. |
| `window.__getActivePipelineDraftPlan()` | без аргументов → план или пустое значение | Читает текущий черновой план для canvas. Внутренний диагностический интерфейс, не заменяет пользовательский редактор. |
| `window.__updatePipelineAll()` | без аргументов | Перерисовывает/синхронизирует pipeline после допустимых DOM-изменений. Обычно клик по контролу уже вызывает это сам. |
| `window.__persistActivePipelineDraftPlan()` | без аргументов → Promise/результат сохранения | Сохраняет текущий черновой план. Вызывать только если задача действительно требует сохранения. |
| `window.__syncPipelineRunStateVisuals(engineState)` | объект состояния движка | Синхронизирует только визуальное состояние запуска; не запускает и не останавливает pipeline. Используется кодом приложения. |
| `window.runPipeline(...args)` | параметры делегируются внутреннему `startDebateFromPage`; Promise/результат запуска | Реальный запуск. Может отправить prompt внешним моделям; вызывайте только при явном запросе пользователя на запуск. Не угадывайте аргументы: сначала изучите вызывающий код или UI-обработчик. |
| `window.cancelPipelineRun()` | без аргументов → Promise<boolean> | Отменяет активный запуск; если запуск не активен, возвращает `false`. |
| `window.approveDebateCheckbox(checkbox)` | DOM-элемент checkbox → результат подтверждения | Подтверждает ответ карточки. Передавайте настоящий `.debate-approval-check` текущей карточки; не выдуманный объект. |
| `window.patchDebateCardMessage(card, patch)` | карточка и объект изменений | Внутренне обновляет модель сообщения/карточку; применять только при отладке рендера, не вместо пользовательского действия. |
| `window.syncDebateCardOutputLayout()` | без аргументов | Пересчитывает раскладку карточек ответов; не меняет ответы. |
| `window.__getDiagnosticLogs()` | без аргументов → логи страницы | Читает диагностические записи текущей вкладки. Перед выводом проверяйте, не содержат ли они пользовательский prompt или другие чувствительные данные. |
| `window.__getSerialDebateState()` | без аргументов → объект состояния | Читает состояние протокольного прогона. Только для диагностики; не изменяет его. |
| `window.__setSerialDebateStateForTest(nextState = {})` | частичное состояние → объект состояния | Меняет состояние только в тестовой конфигурации. В обычной странице просто возвращает текущее состояние; не используйте для штатных действий. |
| `window.clearFavoriteEntriesOnLoad()` | без аргументов | Удаляет сохранённые избранные записи из локального хранилища и сбрасывает UI. Не вызывать при обычной проверке страницы. |
| `window.clearModifierSelectionsOnLoad()` | без аргументов | Удаляет сохранённые выборы модификаторов из локального хранилища. Не вызывать при обычной проверке страницы. |

`window.__pipelineLifecycleDebug` доступен только в тестовой конфигурации (`NODE_ENV=test` либо `window.__RESULTS_TEST_DEBUG__ === true`). Это тестовый объект с внутренними функциями и состоянием, не API обычной загруженной страницы. Не включайте этот флаг ради обычного UI-взаимодействия.

`window.__resultsExportDebug` также появляется только в тестовой конфигурации и содержит функции сборки экспорта и внутреннее состояние избранного. Это не интерфейс страницы. `window.__pipelineDraftPlanForCanvas` — объект текущего плана, а не метод; для чтения/сохранения используйте соответствующие методы из таблицы выше.

## 5. Надёжный сценарий «выбрать модель»

1. Уточните, что нужно изменить: набор провайдеров или роль Lead/Sender/Receiver. Для простого выбора провайдера прочитайте `#llm-gpt` и исходный набор:

   ```js
   ({active: document.querySelector('#llm-gpt')?.classList.contains('active'),
     selected: window.ResultsShared?.getSelectedLLMs?.()})
   ```

## 6. Почему действие могло не сработать

- Вызов отправлен в браузерный target, а не в `sessionId` нужной вкладки.
- Страница ещё не завершила загрузку, поэтому элемента/глобального метода пока нет.
- Использован устаревший AX-индекс после предыдущего изменения DOM.
- Выбран элемент с тем же названием, но не та кнопка (например, GPT в панели модели и GPT внутри уже созданной карточки).
- Значение формы установлено программно, но не отправлено ожидаемое событие `input`/`change`.
- Кнопка-модель является переключателем: повторный клик снимает выбор.
- Код вызывает private функцию внутри замыкания, а не экспорт на `window`.
- Синтетический клик не подходит для API, требующего настоящий пользовательский жест.
- Код успешно выполнился, но асинхронная перерисовка или сохранение ещё не завершились; прочитайте DOM ещё раз после небольшой паузы.
