# Долгие задачи: накопленный опыт

Ты — ведущий долгой задачи: несколько этапов, внешний агент-разработчик (например GPT в чате), живые прогоны на сайтах моделей, работа без User часами. Здесь собрано то, что уже сорвалось или стоило дорого. Перед стартом такой задачи прочитай файл целиком. Новый урок записывай в раздел «Журнал» в тот же ход.

Связанные документы: команда агентов — `docs/Agents/agent-team.md`; прогон — `docs/Run Automation/run-procedure.md`, режимы моделей — `docs/Run Automation/model-modes.md`; реестр проблем — `docs/Agents/basic-issues-registry.md`.

## 1. Расход контекста и лимитов

- Один этап — одна сессия. Состояние между этапами держать в плане задачи (например `docs/TheCycle-GLOBAL-PLAN.md`) и в памяти, а не в контексте. Сессия длиной в сутки стоила около $125: каждый ход перечитывал почти миллион токенов.
- Не будить себя по таймеру «посмотреть, нет ли новостей». Ждать фоновым наблюдателем (`Bash` с `run_in_background`, `Monitor`), который завершается только на событии: новый ответ, конец генерации, окно на странице.
- Без `sleep` в командах переднего плана.
- Механика, которая не требует понимания, — скриптом, а не агентом: тесты, коммит, доставка, сверка версии, чтение чата. Агент при большом контексте дороже и может пересказать итог вместо точного вывода.
- Haiku — поиск по списку, механический перенос, выжимка из длинного вывода. Sonnet — review, разбор причин, независимая проверка. Решения по плану — только ведущий.

## 2. Ведение внешнего агента-разработчика

- Первое сообщение задаёт жёсткие правила: только текущий шаг; без новых протоколов, метрик, документов и «улучшений»; следующий шаг — только после «шаг закрыт».
- Формат ответа: СДЕЛАНО / НУЖНО ОТ CLAUDE / БЛОКЕР. Мысли вне шага — строкой «В РЕЕСТР: …», несогласие — «ВОЗРАЖЕНИЕ: …». Решение по возражению принимает ведущий.
- Ответ с нарушением формата или шага не принимать, вернуть с одной фразой, что нарушено.
- Агент уходит в детализацию, если его не держать. Каждое задание ссылается на пункт плана.
- Заранее проверить, что агент реально может: доступ на запись к репозиторию заявлен, а на деле 404. Если не может — его код приходит текстом, вносит ведущий.
- Не удалять и не переделывать незаконченную работу другого агента. Переносить как есть, править только блокеры.

## 3. Проверка чужого кода

- Не верить отчёту на слово. Каждую поставку: независимый review (Sonnet), полный прогон тестов, свой взгляд на diff.
- «Тесты проходят» у агента без доступа к среде значит «тесты проходят у него в голове». Запускать самому.
- Живая проверка обязательна для всего, что касается страницы модели: модульные тесты не видят очистку текста, привязку вкладок, метку доставки.

## 4. Живые прогоны

- Любая живая отправка моделям — прогон, даже если слово не прозвучало. Вся дисциплина `run-procedure.md`.
- До отправки: список вкладок моделей и флажок «новые страницы». Запрос однажды ушёл в собственный чат User. Отправлять только в новые вкладки.
- `caffeinate -d -i` на всё время прогона. Заблокированный экран прячет вкладки, прогон стоит.
- После перезагрузки расширения пропадает доступ к папке копий. Восстанавливать самому настоящим кликом (`docs/Agents/agent-real-chrome-control.md`), не просить User.
- Блокер, который можно снять, снимать сразу. Повторять «ничего не изменилось» в каждом тике — срыв: однажды так прошло 30 минут, эксперимент был потерян.
- Окна подтверждения во время работы без User недопустимы. Действие, которое вызывает окно (например push во внешний репозиторий), отложить до User.
- Пустой или оборванный ответ: сначала прочитать вкладку модели (лимит, вход, ошибка), потом делать выводы. Поверхностное «модель молчит» уже приводило к неверным решениям.
- Пока страница генерирует — ждать, не принимать и не повторять.
- Модель выбыла — прогон идёт без неё.
- Нужен ли прогон вообще: если вопрос уже закрыт данными, прогон не делать.

## 5. Модели и лимиты

- Состав и режимы — только по `docs/Run Automation/model-modes.md`.
- Claude как участник — считанные запросы за всю задачу; вторым участником ставить DeepSeek DeepThink.
- Медленную модель в роли проверяющего заменить быстрой (Qwen → Gemini).
- Лимит может кончиться у любой модели в любой момент. Знак — сообщение на её странице. Смена аккаунта — дело User; дальше прогон идёт без этой модели.

## 6. Доставка и GitHub

- Каждая законченная правка — коммит, версия, `CHANGELOG`, ff в основной чекаут, сверка `manifest.json`. Чужие незакоммиченные файлы основного чекаута не трогать.
- Перед push в публичный репозиторий проверить, что в файлах нет ссылок на чаты User и других личных данных. Однажды пришлось переписывать историю.

## 7. Общение с User

- Всё по-русски, коротко: версия, что изменилось, что не проверено.
- Вопрос User — только о продукте или действии вовне; технические решения ведущий принимает сам.
- Ошибку, которую заметил User, признать прямо и исправить.
