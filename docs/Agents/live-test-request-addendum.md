# Что добавить в запрос на живое тестирование

Дополняет [agent-live-test.md](agent-live-test.md). Поручение на подобное тестирование (прогон схемы Basic в обычном Chrome) должно содержать пункты ниже. Часть из них я (ведущий) обязан подставлять сам, если владелец их не назвал.

## 1. Что добавить в запрос

1. **Критерий остановки.** Работа заканчивается только когда получен нужный результат (например, готовый документ) или владелец сказал «стоп». Отчёт о неудачном прогоне — не остановка: после него сразу следующая попытка.
2. **Что считается сбоем, который чинится сразу.** Модель не ответила, ответ обрезан или собран из промежуточного блока, шаг не завершён, молчание дольше 120 с. Каждый такой случай: причина → правка → версия → повтор.
3. **Что можно без вопросов.** Перезагружать расширение, закрывать и открывать вкладки прогона, менять и коммитить код, повторять прогон, вставлять окна User, чьи ответы владелец уже дал.
4. **Что нельзя без слова владельца.** Закрывать вкладки, которые не открывал прогон; закрывать страницу расширения; отправлять от имени владельца то, что он не поручал.
5. **Какие вкладки считать тестовыми.** Перед закрытием перечислить вкладки, закрывать только те, что открыл прогон; страницу расширения после перезагрузки сразу открыть заново.
6. **Состав моделей и роль каждой** (кто отвечает, кто проверяет, кто глубоко разбирает), и что делать, если модель не отвечает: пропустить и записать в журнал, а не ждать.
7. **Предел ожидания.** На каждом ожидании — срок (например, 10 минут), после него диагностика, а не простой.
8. **Где фиксируются результаты:** журнал, экспорт «Basic», отчёт наблюдателя интерфейса; без доказательства запись не закрывается.
9. **Формат отчёта владельцу:** «Поломано / Сделано», версия, статус тестов, одной строкой; перезагрузка расширения.
10. **Немедленная реакция и порядок коммитов.** Каждая обнаруженная проблема сразу получает агента; коммиты и перезагрузка расширения — только после остановки прогона. Модель, явно мешающая процессу, исключается из тестового прогона с записью причины.
11. **Перед отчётом** — проверка офис-менеджера по журналу.

## 2. Почему я остановился (и как исключить)

| Причина | Что произошло | Как исключить |
|---|---|---|
| Отчёт принят за конец | Итог прогона не получен, я описал сбои и ждал реакции | Правило 1: отчёт без результата допустим только вместе со следующим действием; перед отчётом спросить себя «получен ли результат?» |
| Нет критерия остановки | В запросе не было сказано, когда работа закончена | Пункт 1 запроса |

| Ожидание согласования там, где оно не нужно | Окно owner:ok: я не отправил без согласования, хотя владелец велел не спрашивать | Пункт 3 запроса: окна User, чьи ответы владелец дал, заполняются самостоятельно |
| Перерыв из-за лимита | Сессия оборвалась, продолжение шло через сводку | Состояние держать в журнале (что делается, следующий шаг), а не в голове; по возвращении начинать с журнала |
| Уборка среды стёрла рабочее | Закрыл все вкладки и потерял страницу расширения | Пункты 4–5 запроса |
| Нет параллельной работы | Пока прогон стоял, остальное не делалось | Пока ждёт прогон — работают исполнитель и расследователь по найденным причинам (не более трёх агентов) |

## 3. Первый отчёт инженера по интерфейсу

Основание: экспорты «Basic» за 30.10 (версии 2.81.934–935) и журнал. **Живой проверки интерфейса при этом не было**: страницы закрыты, поэтому отчёт состоит из зафиксированного, а не из свежих наблюдений. Формат: видимое — ожидаемое — доказательство.
