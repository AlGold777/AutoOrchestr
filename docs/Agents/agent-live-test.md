# Живое тестирование Basic: система работы ведущего

Для прогонов схем Basic на странице расширения в обычном Chrome (см. [agent-real-chrome-control.md](agent-real-chrome-control.md)) и для работы над результатом схемы (первый такой продукт — архитектура MVP «Remote Viewfinder»). Протокол заданий и ответов, роли исполнителя и проверяющего — [agent-team.md](agent-team.md); здесь только то, что добавляет живое тестирование. Модели агентов задаёт корневой `AGENTS.md` (Haiku 5.5).

## 1. Принцип

Ведущий (основная сессия) не выполняет рутину сам и не держит в голове список обещаний. Рутина — у агентов, память о процессе — у **журнала задач** и **офис-менеджера**. Новый агент создаётся, когда появляется переменная, которой нет у существующих (раздел 4), и закрывается отчётом.

## 2. Постоянные роли

| Роль | Делает | Не делает |
|---|---|---|
| Ведущий | ставит задачи, решает, принимает, говорит с владельцем | не пишет код сам, если можно поручить; не задаёт технических вопросов владельцу |
| Оператор прогона | по схеме и версии: вставляет схему, запускает прогон кнопкой прогона (`#debate-run-toggle-btn`, не `#start-button`), заполняет окна User, снимает экспорт «Basic», чистит среду | не чинит код, не интерпретирует причины |
| Наблюдатель интерфейса | сверяет видимое с реальным: карточка и текст в чате модели, строки Basic и журнал, окна User, холст, блокировки; записывает «видимое — ожидаемое — доказательство» | не чинит, не объясняет причины; не видит исправлений ведущего |
| Аналитик провайдера | собирает живой DOM и поведение одного провайдера (через GPT-расширение владельца или скрипты), таблица «провайдер × проверка» | не меняет селекторы |
| Офис-менеджер | перед каждым этапом и перед отчётом сверяет журнал с правилами раздела 5 и возвращает короткий список напоминаний | не принимает решений и не меняет файлы кроме журнала |
| Исполнитель, проверяющий, расследователь | как в `agent-team.md` (2.2, раздел 4, раздел 5) | — |

## 3. Журнал задач

Файл `.claude/plans/live-test-ledger.md`: список задач (id, статус, агент, доказательство), **обещания владельцу** (что просил, что сказано), открытые находки, ожидающие напоминания. Ведёт ведущий; офис-менеджер читает. Запись о задаче закрывается только с доказательством (версия, коммит, вывод команды, файл).

## 4. Динамическое добавление агентов

Перед тем как делать самому, ведущий смотрит таблицу. Новая переменная → новый агент по шаблону задания из `agent-team.md`, одним заданием; закрывается после отчёта, запись остаётся в журнале.

| Появилась переменная | Новый агент | Что получает |
|---|---|---|
| Сбой у конкретного провайдера | Аналитик провайдера X | страницу, момент, что собрать (DOM, строки журнала) |
| Причина сбоя неясна | Расследователь (agent-team, раздел 5) | симптом, версия, наблюдения |
| Причина доказана | Исполнитель + Проверяющий (agent-team, 2.2) | причина как требование, файлы |
| Расхождение интерфейса | Наблюдатель интерфейса | версия, схема, список проверок |
| Новая область знаний в продукте (WebRTC, разрешения iOS и т. п.) | Эксперт области | узкий вопрос; возвращает данные и источники, не вывод о продукте |
| Схему пишет модель | Оценщик схем | запрос, ответы моделей, число принятых «Вставить схему» |
| Новый класс отрицательного сценария | Оператор отрицательных сценариев | сценарий (стоп, перезагрузка, закрытая вкладка…) |
| Накопились обещания и риск забыть | Офис-менеджер (уже есть) | журнал |

Ограничения: не больше трёх агентов одновременно; общая среда (один живой Chrome) — только последовательно; агент без нового знания дважды подряд — меняем подход, а не повторяем.

## 5. Напоминания офис-менеджера (контрольный список)

Он проверяет по журналу и по состоянию репозитория и возвращает только нарушенные пункты:

1. Каждое обещание владельцу имеет статус и доказательство.
2. Менялся код → версия поднята, документация и CHANGELOG обновлены, тесты прогнаны, коммит сделан агентом Haiku, правка лежит в основном чекауте, в отчёте версия из `grep '"version"' manifest.json`.
3. После доставки расширение перезагружено (разрешено владельцем); перезагрузка стирает ответы текущего прогона — отметить.
4. Среда прогона чистая: тестовые вкладки закрыты, старый прогон остановлен, версия и схема записаны.
5. Запуск прогона только кнопкой прогона.
6. В разговоре нет слова «стенд»; отчёт короткий («Поломано / Сделано»); владельцу задаются только продуктовые вопросы, с вариантами.
7. Решения по концепции без согласования не оформляются документами.
8. Открытые находки без владельца.
9. Чужие неотслеживаемые файлы не тронуты.
