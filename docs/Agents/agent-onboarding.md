# Старт новой сессии: что нужно знать агенту

Документ для агента, который начинает работу в проекте с нуля, без памяти и без доступа к прежним разговорам. Правила процесса ниже записаны User в личных инструкциях и передаются здесь, чтобы не зависеть от аккаунта. Описание продукта — в [обзоре проекта](../project-overview.md), навигация — в [карте документации](../documentation-map.md).

## 0. Смысл работы и словарь

- **Схема** — список этапов сверху вниз. Порядок в списке — порядок выполнения. Стрелок назад нет, ветвлений нет: все этапы выполняются по порядку.
- **Словарь — два слова.** **Этап** — действие с исполнителем: модель, User или приложение. **Артефакт** — документ или данные: его производит этап, либо он дан с самого начала (бриф, образец, вложенный файл).
- **Правило проверки:** если у этапа есть исполнитель (модель, User, приложение) — это этап; если нет — артефакт.

## 1. Откуда загружено расширение и как доставлять правки

Расширение у User загружено из **основного чекаута** `/Users/restart/Documents/GitHub/AutoOrchestr`, а не из worktree. Коммит в ветке worktree до User не доходит.

- Ветку основного чекаута определяйте командой `git -C /Users/restart/Documents/GitHub/AutoOrchestr branch --show-current`. Это не обязательно `main`: на 22.10.2026 там `claude/gracious-mccarthy-fe9lrh`.
- **Перед первой строкой кода** определите версию, которая реально загружена: `grep '"version"' <основной чекаут>/manifest.json` (сверять с `extensionVersion` в последней телеметрии). Worktree может отставать от неё; правка на устаревшей базе потребует полного переноса.
- **Доставка.** Задача не завершена, пока правка не лежит в основном чекауте: после коммита `git -C <основной чекаут> merge --ff-only <ваша ветка>`. Если слияние не только вперёд — сначала подтянуть ветку основного чекаута в свою ветку (в worktree), разрешить конфликты, повторить.
- В основном чекауте могут лежать **чужие незакоммиченные правки**. Не затирать их: перед слиянием убедиться, что файлы, которые оно меняет, с ними не пересекаются (`git diff --name-only HEAD <ваша ветка>` против `git status --short`). При пересечении остановиться и сообщить User.
- **Отчёт о доставке:** выполнить `grep '"version"' <основной чекаут>/manifest.json` и привести эту версию. Версия не совпала с заявленной — писать «НЕ доставлено», а не «Сделано». В конце одной строкой напомнить: chrome://extensions → Reload.
- Изменения только документации расширение не меняют: слияние их доставляет, перезагрузка расширения не нужна.

## 2. Версия, документация, git

- После **любых изменений кода** обновить версию в `manifest.json`, пакетном манифесте и версионных константах изменяемого файла (`ALGORITHM_VERSION`, `RULE_SET_VERSION` и т. п.). Изменение функционала — с правкой документации в том же коммите (документы Basic сверяются с кодом тестами `tests/basic-schema-guide.test.js` и `tests/basic-docs-refs.test.js`).
- **Правки только документации версию `manifest.json` не меняют**: расширение они не затрагивают.
- Каждое законченное самостоятельное изменение — отдельный коммит; стадировать выборочно (`git add <путь>`), не `git add -A` по умолчанию. Перед разрушающими операциями (`checkout .`, `reset --hard`, `clean`, `stash`) — `git status --short`.
- **Коммит поручают субагенту своей платформы: GPT Codex — GPT-6 Luna (`model: gpt-6-luna`, `reasoning_effort: high`); Claude — Haiku 5.5 (`model: haiku`)**, согласно корневому `AGENTS.md`. В задании ему перечислять только git-команды и запрещать другие инструменты: однажды такой субагент по ошибке запустил отдельную сессию (`hand_off_to_session`). Образец задания: «В <путь worktree> выполни `git add <файлы>` и `git commit -m "<сообщение>"`. Больше ничего не коммить, не вызывай hand_off_to_session и не запускай другие сессии, только git-команды. Верни короткий хеш и `git status --short`». После отчёта проверить результат самому: `git log --oneline -1`, `git show --stat --format= HEAD`, `git status --short`.
- Вопросов и запросов разрешения User не задавать: решать самому (корневой `AGENTS.md`, «Самостоятельность агентов»). Ветками, слияниями, коммитами и push агент распоряжается сам; в отчётах — версия, что изменилось и где результат, без git-терминов.

## 2а. Тесты и телеметрия перед доставкой

- Запуск тестов, проверку сценариев и анализ результатов обязательно делегировать по правилу корневого `AGENTS.md`: GPT Codex — GPT-6 Luna high; Claude — запуск тестов Haiku 5.5, разбор результатов и проверка сценариев Sonnet 5.5. Ведущий координирует проверки и разбирает результаты.

- Тесты запускает Jest: `npm test` (то же, что `jest --config tests/jest.config.js`) или на отдельных файлах `npx jest --config tests/jest.config.js tests/<файл>.test.js`. В worktree может не быть `node_modules`: тогда `npm install` по `package.json` либо запуск Jest из основного чекаута на файлах worktree (`<основной чекаут>/node_modules/.bin/jest --config tests/jest.config.js <файлы>`, из каталога worktree).
- Изменили документацию Basic — обязательно прогнать `tests/basic-schema-guide.test.js` и `tests/basic-docs-refs.test.js` (на 22.10 — 19 тестов, все проходят). Изменили код — прогнать тесты затронутых модулей и перед доставкой, по возможности, весь набор.
- «Зелёным» считается набор без падений. Известные и ранее существовавшие ошибки не являются исключением. Нестабильные часы теста `false success: watcher completion guards` исправлены в 2.81.920 (TEST-2 в `Pipeline scenarios/basic-developer.md`); любое падение требует выяснения причины.
- Загруженная версия расширения по телеметрии: поле `extensionVersion` в отчётах телеметрии; формат и разбор — [telemetry.md](../Telemetry/telemetry.md) и [инструкция анализа отчёта](../Telemetry/report-analysis-prompt.md). Если отчёта нет, версию берут из `manifest.json` основного чекаута.

## 2б. Слова, которые легко перепутать

- Склейка — не отдельный вид этапа, а обычный запрос, дающий новый артефакт. Не путать с функцией `BasicSchema.assemble` в коде Basic.
- Этап и артефакт — два слова словаря (раздел 0). «Блок», «компонент», «карточка», «колонка», «материал», «источник» синонимами этапа не являются; поле JSON `block` — имя поля.
- «Возврат» назад ни в черновой схеме, ни в Basic не поддерживается (с 2.81.846): повтор — обычный этап ниже по списку. Переходов (`goto`, `stop`), проверок (`gate`) и развилок (`route`) в Basic нет (с 2.81.848).
- Синтез, судья, жюри, проверяющий — роли в тексте запроса, а не виды этапов. В Basic синтез — раунд из одной модели с ролью `interaction_meta_synthesis` (вид `synthesis` удалён в 2.81.849).

## 3. Как работать с User

- Долгая задача с внешним агентом и живыми прогонами — сначала [опыт долгих задач](long-task-playbook.md).
- Отчёты сессий этапов архитектору — [доска архитектора](architect-board.md), «Как архитектор получает информацию».
- Отвечать коротко и по существу; отчёт «Поломано / Сделано» — версия и статус тестов одной строкой.
- Технические решения принимает агент: выбирает по назначению и данным, делает и сообщает выбранное. Не предлагать User меню «А или Б» там, где есть очевидный вариант.
- Когда User обсуждает концепцию, отвечать в чате; документы и коммиты — после согласования.
- Если User указал пробел, прямо признать его до исправления; не выдавать его идею за уже имевшуюся.
- Слово User’а может означать элемент интерфейса, а не клавишу (например, «кнопка I» — кнопка «i» в шапке панели). Если смысл не очевиден, проверить на экране, а не угадывать.
- В разговорах о схемах говорим «этап» и «артефакт» (раздел 0), а не «компонент».
- Минимально достаточное решение: не добавлять функции, поля и пояснения без практической необходимости (корневой `AGENTS.md`).

## 4. Браузер: что делать самому и что поручать User

Для поиска, обхода и сохранения страниц Notion используйте [инструкцию по Notion](agent-notion.md).

**Нужна проверка страницы расширения? Полная спецификация элементов и поведения обеих страниц (`pipeline_panel.html` и `result_new.html`) — [agent-extension-pages-spec.md](agent-extension-pages-spec.md). Рецепт отдельного Chrome с расширением — [agent-live-chrome.md](agent-live-chrome.md) (CDP, `Extensions.loadUnpacked`). Для CUA, селекторов и публичных методов `pipeline_panel.html` — [agent-extension-page-control.md](agent-extension-page-control.md). Если нужно взаимодействовать именно с обычным Chrome User’а — [agent-real-chrome-control.md](agent-real-chrome-control.md). Для теста с реальными сайтами моделей нужны авторизованные model tabs, тестовый prompt и отдельное разрешение на отправку.**

Обычный Chrome User’а используйте самостоятельно при наличии подходящего инструмента, в рамках задачи. Отдельный профиль нужен для изолированных проверок; авторизация моделей в новом профиле обычно отсутствует.

У User в Chrome два собственных расширения, и доступность инструментов зависит от сессии, поэтому сначала проверьте, что есть у вас.

- **Claude-расширение (Claude in Chrome)** управляет реальным Chrome User’а: вкладки, переход по адресу, чтение страницы, консоль, выполнение JavaScript, скриншоты. Инструменты называются `mcp__claude-in-chrome__*` и могут быть отложенными: загружайте их одним запросом через поиск инструментов (набор: контекст вкладок, переход, чтение страницы, JavaScript, консоль, создание и закрытие вкладок). Если оно доступно, проверяйте страницы и DOM им сами, а не просите User’а. Наблюдавшиеся ограничения: адреса `file://` оно не открывает (подменяет схему на https), поэтому локальные HTML открывайте через временный сервер (`python3 -m http.server <свободный порт>` в нужной папке, остановить после проверки); созданные вами вкладки закрывайте.
- **Встроенный браузер приложения Claude** (`mcp__Claude_Browser__*`) тоже годится для проверки, но файлы по `file://` показывает статичным снимком без скриптов: для страниц со скриптами — тот же временный сервер.
- **GPT-расширение User** открывается на любой странице (страницы моделей и нашего расширения). Через User ему поручают сбор данных, которые агент не получит сам ни одним из способов выше: реальный DOM перед правкой селектора или детектора, состояние страницы при визуальном баге, сверка собранного ответа с видимым. Задание оформляется отдельным блоком (страница, момент, что собрать, формат вывода); просить **данные, а не выводы**: дословный текст, `outerHTML`, атрибуты, «не видно». Не просить того, что агент может получить сам (код, телеметрия в репозитории, браузер выше).

## 5. Текущий статус работ над схемами (23.10.2026)

Формат Basic 2 поддерживает отдельных участников одного provider: постоянные ID, подписи, явно пустые настройки, собственные чаты и действия добавления/переименования/удаления на холсте. Формат 1 остаётся совместимым. Тесты страницы проверяют round-trip схемы и блокировку удаления при зависимостях следующих входов; транспортные проверки используют заглушки и не отправляют запросы моделям.

Цель: собирать схемы сценариев из этапов; человек или модель создаёт схему непосредственно в формате Basic. Инструкция для модели — [запрос для создания схемы](../Scheme%20create/basic-model-request.md), формат — [руководство по схеме](../Pipeline%20scenarios/basic-schema-guide.md), общая картина — [Basic: старт здесь](../Pipeline%20scenarios/basic-start-here.md).

**Виды этапов в движке Basic** (по `disput/basic-schema.js` и `disput/custom-engine.js`, 2.81.849): `round`, `owner`; реестр артефактов; шаги идут строго по порядку. `synthesis` удалён в 2.81.849 (схема с ним отклоняется проверкой: «тип шага: допустимо round, owner; синтез — роль: раунд из одной модели с role»; итог прогона — принятые ответы последнего шага), `gate` и `route` удалены в 2.81.848 (текст ошибки: «…; проверка — обычный раунд: критерии в task; решение принимает User шагом owner»), переходов (`goto`, `stop`) нет, возвраты убраны в 2.81.846. Поля `require` и `order` удалены в 2.81.850: раунд — один запрос всем его моделям, они отвечают независимо, раунд ждёт ответов всех; эстафета — раунды по одной модели подряд. **Нет в движке:** `file`; поле `optional_inputs`, верхнеуровневое `artifacts` и ссылки `in.Имя`.



**Что дальше:** развивать Basic и схемы по актуальным планам проекта и проверять их на реальных задачах.
