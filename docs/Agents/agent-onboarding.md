## 0. Смысл работы и словарь

- **Схема** — список этапов сверху вниз. Порядок в списке — порядок выполнения. Стрелок назад нет, ветвлений нет: все этапы выполняются по порядку.
- **Словарь — два слова.** **Этап** — действие с исполнителем: модель, User или приложение. **Артефакт** — документ или данные: его производит этап, либо он дан с самого начала (бриф, образец, вложенный файл).
- **Правило проверки:** если у этапа есть исполнитель (модель, User, приложение) — это этап; если нет — артефакт.

## 2. Версия, документы, git

- После **любых правок кода** — новая версия (`manifest.json`, `package.json`, версионные константы изменяемого файла: `ALGORITHM_VERSION`, `RULE_SET_VERSION` и т. п.) и запись в `docs/CHANGELOG.md`.
- **Только документы — версия не меняется.** Не пиши в них номер, который выпущен не будет.
- Изменилось поведение — документы в том же коммите.
- Каждое законченное изменение — отдельный коммит, только названные пути. Не `git add -A`.
- Не используй `git stash` без метки: стек общий для всех сессий.
- Перед риском — тег или отдельная ветка. Перед откатом или заменой файлов — `git status --short`.
- Коммит и доставку делает `scripts/agent/deliver.sh` (раздел 6). Если без скрипта и субагентом — Haiku (GPT Codex: GPT-6 Luna high) с точным списком команд и запретом других инструментов: однажды такой субагент сам запустил отдельную сессию. Результат проверь сам.
- Изменения только документов расширение не меняют, перезагрузка не нужна.

### Как писать документы

- Короткие естественные фразы. Не пересказывать очевидное.
- Сначала проверить, что уже есть. Лучше дополнить существующий документ, чем завести новый.
- Документ, который прикладывают модели, начинается с её роли («Ты — …»), содержит полные пути от корня и не содержит указаний человеку.
- HTML — только в светлой теме.
- Файлы для User называть полным путём в основном чекауте.
- Результаты прогона — в папку прогона с подпапками `schema/`, `artefacts/`, `exports/`, `notes/`, сразу после прогона. Basic: `docs/Run Automation/Test_run/<имя>_<yyyy-mm-dd>/`; TheCycle: `docs/TheCycle/runs/<имя>_<дата>/`.

## 2б. Слова, которые легко перепутать

- Склейка — не отдельный вид этапа, а обычный запрос, дающий новый артефакт. Не путать с функцией `BasicSchema.assemble` в коде Basic.
- Этап и артефакт — два слова словаря (раздел 0). «Блок», «компонент», «карточка», «колонка», «материал», «источник» синонимами этапа не являются; поле JSON `block` — имя поля.
- «Возврат» назад ни в черновой схеме, ни в Basic не поддерживается (с 2.81.846): повтор — обычный этап ниже по списку. Переходов (`goto`, `stop`), проверок (`gate`) и развилок (`route`) в Basic нет (с 2.81.848).
- Синтез, судья, жюри, проверяющий — роли в тексте запроса, а не виды этапов. В Basic синтез — раунд из одной модели с ролью `interaction_meta_synthesis` (вид `synthesis` удалён в 2.81.849).
- Слово User может означать элемент интерфейса («кнопка I» — кнопка «i» в шапке панели). Неясно — посмотри на экране.
- Слово «стенд» User не говорить: всё относится к Basic; чего нет — «в Basic пока нет».

## 3. Как работать с User

- Права постоянные: терминал, прогоны, перезагрузка расширения, новые вкладки, клики, push рабочей линии (`AGENTS.md`, «Самостоятельность агентов»).
- Границы: запросы моделям — только в новых вкладках; чужие вкладки, чаты и файлы не трогать; пароли и платёжные данные не вводить; настройки разрешений и защитные хуки не менять; в окнах подтверждения за User не нажимать.
- Отклонённый шаг сделай другим способом. Другого нет — отложи только его, остальное доведи.
- User не знает про ветки и коммиты и не должен знать. В отчёте: что изменилось, версия, что не проверено, где результат. Строка про chrome://extensions → Reload, если менялся код.
- Отвечать коротко; отчёт «Поломано / Сделано», версия и тесты одной строкой.
- Спрашивать только о продукте. Технические решения принимать самому: выбрать, сделать, сообщить.
- Идёт обсуждение замысла — отвечать в чате; документы и коммиты после согласия.
- User указал пробел — прямо признать. Не выдавать идею User за уже имевшуюся.
- Не добавлять функции, поля и пояснения без практической нужды.
- Не писать «нужно решение владельца»: назвать конкретное действие.
- Telegram — только по прямой просьбе, по инструкции `/Users/restart/.codex/instructions/telegram-notifications.md`.

## 5. Статус работ

Версия и этапы меняются часто: верь `manifest.json`, доске задачи и реестру, а не этому разделу.

**TheCycle / Circle** — `docs/TheCycle/TheCycle-board.md`: статус этапов и следующий шаг.

**Basic, схемы (сведения на 23.10.2026, 2.81.849–2.81.850).** Формат Basic 2 поддерживает отдельных участников одного provider: постоянные ID, подписи, явно пустые настройки, собственные чаты и действия добавления/переименования/удаления на холсте. Формат 1 остаётся совместимым. Тесты страницы проверяют round-trip схемы и блокировку удаления при зависимостях следующих входов; транспортные проверки используют заглушки и не отправляют запросы моделям.

Цель: собирать схемы сценариев из этапов; человек или модель создаёт схему непосредственно в формате Basic. Инструкция для модели — `docs/Scheme create/basic-model-request.md`, формат — `docs/Pipeline scenarios/basic-schema-guide.md`, общая картина — `docs/Pipeline scenarios/basic-start-here.md`.

**Виды этапов в движке Basic** (по `disput/basic-schema.js` и `disput/custom-engine.js`): `round`, `owner`; реестр артефактов; шаги идут строго по порядку. `synthesis` удалён в 2.81.849 (схема с ним отклоняется проверкой: «тип шага: допустимо round, owner; синтез — роль: раунд из одной модели с role»; итог прогона — принятые ответы последнего шага), `gate` и `route` удалены в 2.81.848 (текст ошибки: «…; проверка — обычный раунд: критерии в task; решение принимает User шагом owner»), переходов (`goto`, `stop`) нет, возвраты убраны в 2.81.846. Поля `require` и `order` удалены в 2.81.850: раунд — один запрос всем его моделям, они отвечают независимо, раунд ждёт ответов всех; эстафета — раунды по одной модели подряд. **Нет в движке:** `file`; поле `optional_inputs`, верхнеуровневое `artifacts` и ссылки `in.Имя`.

### Подводные камни скриптов и терминала

- `tab-js.sh` при отсутствии вкладки печатает `NO_TAB` и выходит с кодом 0. Проверяй текст.
- `tab-js.sh` берёт первую подходящую вкладку, `docs/Run Automation/tools/js.sh` — последнюю. Давай точную часть адреса.
- `gpt-send.sh`: коды 1 — не ушло, 3 — нет вкладки, 5 — идёт генерация (поверх не слать). После «НЕ УШЛО» сначала посмотри чат: повторная отправка задвоит сообщение.
- `gpt-watch.sh` запускай в фоне (`run_in_background`): он разбудит тебя сам. Не проверяй чат по таймеру.
- Команды `timeout` в этой оболочке нет. `sleep` на переднем плане не использовать.
- «Permission denied» у `.sh` — запусти через `zsh <скрипт>`.
- `sed` с классами вроде `[а-я]` портит UTF-8.
- Временные файлы — в scratchpad сессии, не удалять. Чужие скачанные данные разбирать через `python3 -I`.
- Команды дольше пары минут — в фоне.

## 7. Живые проверки и прогоны

Любая отправка запроса моделям — прогон, даже если это «быстрая проверка».

**До отправки**

1. Экран не заблокирован и не уснёт: `caffeinate -dimsu -t <секунд>` в фоне. После прогона остановить.
2. Версия на странице расширения равна доставленной. Перезагрузил расширение — обнови страницу панели.
3. Модели получат запрос в новых вкладках: проверь флажок «новые страницы» и список вкладок. Однажды запрос ушёл в собственный чат User.
4. Не запускай `docs/Run Automation/tools/refresh-model-tabs.applescript`, если среди вкладок моделей есть не твои: он обновляет все.
5. Никто другой в это время не прогоняет и не доставляет версии.
6. Состав и режимы моделей — только по `docs/Run Automation/model-modes.md`. Claude — считанные запросы за задачу (3–4); вместо него DeepSeek DeepThink. Claude исчерпал лимит в роли синтезатора — GPT High.


**Во время**

- Следи за **любым** видимым окном на странице (`docs/Run Automation/tools/any-modal.js`), не за списком известных; реагируй сразу.
- Страница модели генерирует — жди. Не принимай, не повторяй, не пропускай.
- Пустой или оборванный ответ — сначала прочитай вкладку модели (лимит, вход, ошибка), потом делай выводы.
- Модель выбыла — прогон идёт без неё, User не привлекать.
- Блокер, который можно снять, снимай сразу. Не повторяй «ничего не изменилось».
- Расширение не перезагружать (прогон пропадёт).

**Клики**

- Перед кликом активируй нужную вкладку и сверь передний процесс и адрес; после — снимок. Успех — видимое изменение, а не ответ команды.
- Во время отправки расширение выводит вперёд вкладку модели: активируй панель прямо перед кликом.
- Координаты бери со свежего снимка. По старым клик уже открывал чужой выпадающий список.

**После перезагрузки расширения**: скрипты в открытых вкладках моделей мертвы (открывай новые); пропадает доступ к папке копий — восстанови сам настоящим кликом; страницу открывай через `open -a` (вкладка из AppleScript даёт `ERR_BLOCKED_BY_CLIENT`).

**После**: выгрузка и итоги в папку прогона; дефект — в `docs/Agents/basic-issues-registry.md` сразу; поведение платформы — в `docs/Platform specifics/`.

**Что тесты не поймали, а живая проверка поймала** (27.11.2026): ключ модели в журнале другим регистром; фон забывал прогон после Stop; подпись на странице DeepSeek длиннее предела очистки; время в списке по UTC вместо местного. Заглушки повторяют твои же предположения.

## 8. Внешний агент GPT

- Адрес чата — только в памяти (`thecycle-gpt-supervision.md`). В репозиторий, коммиты и отчёты его не писать, даже частично.
- GPT — оппонент и соавтор; окончательное решение твоё.
- Правила ему: только текущий шаг; без новых протоколов, документов и «улучшений»; следующий шаг после «шаг закрыт»; ответ в виде СДЕЛАНО / НУЖНО ОТ CLAUDE / БЛОКЕР; мысли вне шага — «В РЕЕСТР: …», несогласие — «ВОЗРАЖЕНИЕ: …».
- Локальные файлы GPT не видит: сначала push, потом проси проверить названный коммит.
- Отчёт об этапе — сразу абсолютно детальный: паспорт этапа, коммиты и версии, как устроено, найденные дефекты, тесты, живая приёмка, что не проверено.
- Порядок: написать сообщение в файл → `gpt-send.sh` → `gpt-watch.sh … --append <файл отчёта>` в фоне → прочитать ответ, проверить замечания по коду, не принимать на слово.

## 9. Расход лимитов, субагенты, сессии

Каждый вызов инструмента заново читает весь контекст (в длинной сессии — около 145 тыс. токенов за вызов).

- Объединяй команды, читай только нужные части, длинный вывод фильтруй.
- Передавай путь к файлу, а не вставляй его текст.
- Ожидание фоновым скриптом ничего не стоит; проверки по таймеру стоят каждый раз.
- Оценки одного обмена: GPT через скрипты ≈35 тыс. входных токенов; другая сессия ≈65 тыс. с тёплым кешем и ≈200 тыс. с холодным; руками через браузер ≈130 тыс.
- Один этап — одна сессия. Состояние держать в плане и доске, не в контексте.
- Субагент стартует примерно с 60 тыс. токенов: давать кусок работы, а не команду.
- Модели: анализ, review, разбор сбоев — Sonnet; тесты и механика — Haiku. Haiku создаёт только Haiku, Sonnet — только Haiku.
- Ведущий на Opus только анализирует и ставит задачи; `.claude/hooks/lead-guard.sh` не даёт ему Bash и правки.
- Независимая проверка чужими глазами окупается: на первой версии возобновления она нашла 6 дефектов при зелёных тестах.
- Задание субагенту или сессии: цель, папка и базовый коммит, установленные факты, что менять, что сохранить, «готово, когда», команды проверки. Образец — `docs/Agents/agent-team.md`.
- Сессия этапа в конце пишет отчёт файлом (`docs/<Задача>/reports/<этап>.md`: ГИПОТЕЗА, ДАННЫЕ, ВЛИЯНИЕ НА ПЛАН, НЕ ПРОВЕРЕНО) и строку на доске. Родительская сессия видит из чата только начало ответа — результат ставь первым.
