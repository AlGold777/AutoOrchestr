# Отдел TheCycle: как работает без остановок

Цель отдела — чтобы живой прогон шёл всё время, а остановка устранялась за 15 минут.

## Участники

| Роль | Кто | Работает | Инструкция |
|---|---|---|---|
| Сторож | скрипт `scripts/agent/watchdog.sh` под launchd | всегда, сам | ниже |
| Оператор | Claude (Sonnet), основная сессия | ведёт этап, запускает прогоны, принимает результат | `roles/operator.md` |
| Дежурный | Haiku 5.5, по вызову оператора | разбирает остановку, пишет диагноз | `roles/duty.md` |
| Инженер | Sonnet, отдельная сессия | чинит по диагнозу, тесты, доставка | `roles/engineer.md` |
| Архитектор | GPT (чат) | решения по спорному, задания этапа | `roles/architect.md` |

## Файлы (вне репозитория: `~/Documents/TheCycle-ops/`)

- `status.md` — сторож обновляет каждые 30 с: идёт ли прогон, фаза, сколько минут без изменений, ход чата архитектора. Старше 2 минут — сторож умер, перезапустить.
- `ALERT.md` — журнал срабатываний (виды ниже). `ALERT.current` — его копия для чтения.
- Очередь прогонов — `docs/TheCycle/ops/queue.json`; запуск — `scripts/agent/ops-start.sh <id|next|auto>`.

## Виды срабатываний сторожа

| Вид | Значит | Что делать (кто) |
|---|---|---|
| PAUSED | Circle встал на паузу | Оператор вызывает дежурного; по диагнозу — инженер или Resume |
| STALL | прогон идёт, но 15 мин без изменений | Оператор: открыть вкладки моделей, найти, что ждёт (модальное окно, Continue, лимит) |
| DEAD | фаза RUNNING, прогон не идёт | Оператор: перезагрузка вкладки панели, затем Resume |
| MODAL | на панели открыто окно | Оператор: прочитать и закрыть по `docs/Agents/agent-live-test.md` |
| GPT_REPLY | архитектор ответил | Оператор: прочитать `gpt-last.js`, выполнить |
| DONE | исследование завершено | Оператор: приёмка по `docs/TheCycle/runs/<прогон>/`; сторож сам запускает следующее только если у него `autostart:true` |

## Правила

1. Остановка живого прогона важнее любой другой работы. Начать с неё.
2. Оператор читает `status.md` и `ALERT.current` первым действием каждого хода.
3. Срок: от срабатывания до диагноза 5 минут, до исправления или обхода 15. Не получилось — обход: урезать схему или запустить без неисправного участника (правило «модель выбыла — прогон идёт дальше»).
4. Каждый участник пишет отчёт в файл своего этапа не реже раза в 10 минут; молчит дольше — оператор возобновляет его сессию и требует отчёт.
5. Новый запуск — только из очереди (`queue.json`), состояние пишется в неё.
6. Адрес чата архитектора не пишется в репозиторий: он лежит в `~/Documents/TheCycle-ops/architect-needle`.
7. Метрика отдела — доля времени, когда прогон шёл. Оператор считает её по `ALERT.md` и пишет в отчёт этапа.

## Запуск и остановка сторожа

```bash
launchctl load ~/Library/LaunchAgents/com.autoorch.watchdog.plist
launchctl unload ~/Library/LaunchAgents/com.autoorch.watchdog.plist
```
