## 2. Изоляция проверяющего (интерфейс Basic/TheCycle)

Есть:
- Проверка идёт отдельным циклом и новым запуском Basic с `forceNewTabs: true` (`results.js:7761`), то есть по коду — в новой вкладке (`job-orchestrator.js:6214–6217`).
- Независимая модель выбирается автоматически: исключаются авторы ссылок, модели аналитика и рабочих циклов; если свободной нет — `independence='UNPROVEN'` (`circle-policy.js:313–330`). `VERIFIED` без `FRESH_TAB_OTHER_MODEL` понижается до `INSUFFICIENT` (`:209`).
- В журнал пишется `DISPATCH_PROMPT` (полный текст отправленного, `state-store.js:233`), ответ по модели (`status`, `completion`, `attribution`, длина).

Нет:
1. `verifierModel` — назначенная модель, а не ответившая (`circle-policy.js:248`); сверки с отчётом нет.
2. `independence` — вывод из имён моделей, не наблюдение; факт новой вкладки/чата не записывается; идентификатор вкладки, URL чата, пустота чата в пакет не попадают.
3. Схема Basic не задаёт «независимую модель» и «слепую проверку»; выбор — неявный (`results.js:7731–7737`).
4. В схему проверки копируются `defaults` и `modelNotes` рабочей схемы (`circle-policy.js:53–65`); попадают ли заметки в запрос проверяющего — не проверено.
5. В отчётах нет живого доказательства новой вкладки/чата для VERIFY, только тесты.

Вывод: изоляция реализована, но подтверждается именами моделей, не наблюдаемыми данными. Это требование §3.4; закрывается в P6 записью `IsolationObservation` (контракт §6). Узкий эксперимент: цикл VERIFY при двух выбранных моделях — снять `DISPATCH_PROMPT`, список вкладок до/после, ответившую модель; повторить с одной моделью, чтобы увидеть `UNPROVEN`.

## 3. Границы платформы (A1/A2)

| Вопрос | Доказано | Не доказано | Узкий эксперимент |
|---|---|---|---|
| A1: продолжение без клика | Циклы 1→2→3 без кликов при открытой странице (G3-live-verify). Переход делает страница, не фон (`circle-runtime.js:315`) | Скрытая вкладка/троттлинг, блокировка экрана, сон; продолжение после падения — только ручное (`results.js:9163`) | Исследование из трёх циклов при скрытой вкладке и закрытом экране 30+ минут: переходы, интервалы heartbeat, сорванные отправки |
| Alarms | Один alarm `thecycle-backup-interval`, 10 минут, копия из service worker (live-checks: `BACKUP_READBACK_VERIFIED`). Он же обновляет значок | Исследовательского alarm нет; будит ли спящий worker после долгого простоя | Тот же alarm при простое > 30 минут |
| Перезапуск | Состояние в IDB и `chrome.storage`; тесты resume/stop/restore; живьём Stop → «Продолжить», восстановление из копии (2.81.1149–1152) | Перезагрузка расширения во время запроса; закрытие страницы во время ответа; чистый профиль (только имитирован) | Закрыть страницу/перезагрузить расширение при идущем запросе; проверить `RECONCILE`, число вызовов, отсутствие повторной отправки |
| Каталог копий после перезапуска | Дескриптор в IDB; `queryPermission`/`requestPermission` — только по клику (`directory-handle-manager.js`); в SW запись при выданном разрешении работает | Сохраняется ли `granted` после перезапуска Chrome; видит ли SW то же разрешение (в live-checks прямо записано «не проверялось») | Закрыть Chrome полностью, открыть, в SW и странице вызвать `queryPermission`, затем `requestPermission` без клика и с кликом |
| A2: среда без нажатий | В проекте есть `alarms`, SW, `windows.create` (только окно просмотра). Нет `offscreen`, автозапуска страницы Circle | Всё: мост живёт в странице (`results.js:7720`), права на каталог без жеста не выдаются, `recover` нужен до продолжения | 1) alarm в SW открывает страницу через `windows.create` без жеста — поднимается ли мост; 2) `chrome.offscreen.createDocument` — доступны ли IDB и `FileSystemDirectoryHandle`; 3) автозапуск `recover('resume')` при выданном разрешении |

Итог: A1 при открытой странице доказан, A2 не доказан и не назначен. Ручное возобновление автономностью не считается (§4.1). Эксперименты выше требуют реального Chrome без изменения production Basic; в этой сессии не выполнялись — отдельный блокер для A2, независимые работы G3 он не блокирует.
