## 1. Вопрос и область заявления

Вопрос: даёт ли TheCycle (управляемый длинный цикл над Basic) более полные и верные решения, чем простые способы, при сопоставимых ресурсах?

Область пользы (GP-23): задачи, где нужны удержание результатов, разрешение противоречий, перебор альтернатив, проверка обязательств на длинном горизонте. Заявление ограничено классами задач, на которых реально прошло сравнение. Превосходство «вообще» не заявляется; причинность по одному прогону не заявляется.

Не отменяется решение владельца о снятии G2.2. Техническая приёмка P9 не пересматривается.

## 2. Руки сравнения (контроли)

| Рука | Что это |
|---|---|
| T | TheCycle: схема цикла, аналитик + участник + проверяющий, лимит вызовов L |
| B | Фиксированный Basic: те же модели и режимы, один проход схемы без управляющего слоя |
| S | Сильная одиночная модель: один чат, тот же текст задачи, бюджет вызовов/времени как у T (допускается «продолжай» в пределах бюджета) |
| V | Независимые прогоны: k прогонов S, итог выбирается заранее заданным правилом (§5). Голосование — контроль, не доказательство |

Одинаково для всех рук: тот же текст задачи, те же режимы моделей (`docs/Run Automation/model-modes.md`), те же запреты инструментов (расчёты — рассуждением, без кода), новые вкладки, не чаты владельца. Для каждого прогона фиксируются: модель и доступная версия/режим (GP-31; неизвестное — «неизвестно»), дата-время, версия расширения и SHA, дрейф среды (смена UI, лимиты, отказы).

## 3. Классы задач и эталоны

Эталон хранится в `notes/`, исследовательским моделям не передаётся; проверка — скриптом (по образцу `check.py`) либо ограниченной экспертной оценкой.

| Класс | Что проверяет | Задачи (предложение) | Эталон |
|---|---|---|---|
| K1 удержание | верный промежуточный результат не теряется на следующих раундах | дискретная оптимизация P7 (task1/task2) | детерминированный, скрипт |
| K2 противоречия | два источника/расчёта расходятся, надо разрешить | задача с конфликтующими данными (новая) | детерминированный |
| K3 альтернативы | несколько допустимых методов, нужно выбрать и обосновать | задача с несколькими методами разной точности (новая) | по итоговому ответу |
| K4 покрытие | закрыты все обязательства задачи | многотребовательная задача (12+ пунктов) | чек-лист пунктов |

Открытые задачи в первичную конечную точку не входят; если добавляются — только вторичные, с ограниченной силой оценки (две модели-оценщика вне рук сравнения, слепая оценка, вывод только «не хуже / не лучше»).

Задачи P7 использовались при отладке системы: для зачётного сравнения брать их новые параметризованные варианты (другие веса/стоимости, пересчитанный эталон). Нужно ≥2 варианта на класс.

## 4. Предзарегистрированные гипотезы

- **H1 (первичная).** На задачах K1–K4 доля прогонов T, прошедших все проверки эталона («полностью верно»), выше, чем у S при сопоставимом бюджете.
- **H2.** T не хуже B по той же доле.
- **H3 (сохранность).** Если на раунде r получен верный результат, T сохраняет его в финале не реже, чем S/B (доля прогонов с верным промежуточным и верным финальным).
- **H4 (цена).** Полная цена T на один верный итог не более m× цены S (m — для согласования; предложение 3).
- Нулевая гипотеза: разницы нет. Заключения «подтверждено» без H1 не бывает.

## 5. Метрики и решающее правило

**Первичная конечная точка (до результатов, не менять):** доля «полностью верно» (все проверки эталона) на задачу-вариант, T против S, парное сравнение по одним и тем же задачам-вариантам.

Вторичные: частичная правильность (доля пройденных проверок); сохранность (H3); полная цена — вызовы (включая служебные и управляющие), время, символы/токены где известны; отказы/паузы/ручные вмешательства (прогон с вмешательством помечается).

Выбор в руке V (заранее): из k независимых ответов — мажоритарный по ключевому итоговому ответу; при ничьей — первый по времени. Эталон выбор не использует.

Решающее правило (предложение):
- **Подтверждено в области [классы]:** T выигрывает по первичной в ≥ 2/3 пар, ни в одном классе не уступает S более чем на 1 пару, H4 выполнена.
- **Опровергнута:** S лучше T в ≥ 2/3 пар.
- **Недостаточно данных:** завершено < N пар из-за лимитов/блокеров провайдера (BLOCKED, не FAIL).
- **Не доказана:** все прочие случаи при достаточных данных.
- Заявление ограничивается классами, где правило выполнено отдельно по каждому классу; остальные — «не установлено».

## 6. Выборка, повторы, бюджет (предложение)

- 4 класса × 2 варианта = 8 задач-вариантов.
- Повторы на вариант: T — 2, S — 2, B — 1, V — k=3 (S-прогоны переиспользуются). До ≈ 6–8 прогонов на вариант, всего ≈ 50–64.
- Порядок рук рандомизируется и фиксируется до старта; новые вкладки; одна параллельная сессия на сайт модели.
- Бюджет: у T лимит L=25 вызовов (как в P7), у S — эквивалент по числу вызовов/времени. Общий расход по провайдерам — решение ведущего. Claude как участник — не более 3–4 вызовов (`feedback-claude-participant-budget`); участники: Gemini, DeepSeek, GPT.
- Минимум для решения: N=6 завершённых пар из 8 (предложение).
- Дополнительные прогоны — только по правилу, записанному до старта; «повторять до успеха» нельзя.
