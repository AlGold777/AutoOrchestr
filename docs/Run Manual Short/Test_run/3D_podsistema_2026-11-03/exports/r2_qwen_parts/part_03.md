12.10. Заменить эвристические пороги, раздельное сглаживание координат и некалиброванную надёжность; сохранить мобильный базовый движок до доказательства преимущества альтернативы.
4. Самая сильная идея
View-Invariance Certificate: для каждой метрики система хранит калиброванную область ракурсов и условий видимости, при которых ошибка допустима. Показывать DEVIATION только внутри этой области; за её пределами — UNCERTAIN.

Публичная документация Onform описывает 2D-наложения и скелетный трекинг, а Sportsbox — сравнение двух 3D-аватаров. Аналогичный сертификат качества там не документирован; его фактическое отсутствие у конкурентов не подтверждено.

7. Итог: приоритеты и ограничения
1. Межракурсная достоверность — главный риск: ошибка реконструкции превышает полезное различие техники.
2. Калиброванная неопределённость — риск: слишком много результатов UNCERTAIN.
3. Кинематическая оптимизация — риск: подавление реального быстрого движения.
4. Единый мобильный движок — риск: скорость и память слабых Android.
5. Вращаемый 3D-скелет — риск: пользователь воспринимает оценку как измеренную реальность.
Главный компромисс: лучше три проверенные метрики, чем полный цифровой двойник с недоказанной точностью.

Худшие свойства: невозможность восстановить скрытые суставы достоверно при некоторых ракурсах; отсутствие точной ориентации ракетки и момента контакта; условный метрический масштаб; возможное отсутствие диагностического результата.

Непроверено: производительность на целевых устройствах, межракурсная точность на паделе, калибровка вероятностей, соответствие координатных систем, окончательная совместимость и лицензирование поставляемых бинарных артефактов.

Решение: запускать этап 0 до основной мобильной реализации. Если M1–M3 не проходят межракурсные критерии, диагностические статусы не выпускать. 3D-визуализация сама по себе не заменяет доказанную измерительную точность.

Допущения (приняты вместо встречных вопросов)
А1. Единственный проверенный мной on-device детектор позы с допустимой для приложения лицензией — MediaPipe Pose Landmarker. RTMPose, RTMW, Apple Vision 3D и ML Kit мной не проверены (не подтверждено) и нужны только для сверки в фазе 0.
А2. Подсказки по съёмке и проверка кадра запрещены владельцем. Съёмка настраивается автоматически, а качество оценивается только постфактум статусами метрик.
А3. Метрики — M1–M3 автора, M4 и M5 скрыты до прохождения калибровки.
А4. Все скорости и размеры собственных компонентов — цели проектирования, не измерения. Измеренные данные приведены только там, где есть ссылка.
А5. Мокапа нет. «Эталон истины» — триангуляция 3 телефонов (как в разделе 9 материала).
1. Решение
Выбор подхода
П1 (автор): MediaPipe worldLandmarks, поворот по гравитации, углы. Быстро и реализуемо, но глубина берётся из одного выхода сети без проверки. Оставлен как путь слабых устройств (уровень C).
П2: тяжёлая сеть-сетка (SAM 3D Body, ноябрь 2025). Её чекпойнт весит 2,11 ГБ плюс 696 МБ модель тела [S2]. На телефоне она невозможна. Используется только офлайн как учитель и для сверки. Допустимость использования её выходов для обучения продукта по лицензии SAM — не подтверждено.
П3 (выбран): MediaPipe 2D + world как вход, гравитация и параметры камеры из датчиков, пакетная оптимизация позы на устройстве с физическими ограничениями, неопределённость в виде распределения, статусы по вероятности. Это единственный вариант, где независимость от ракурса проверяется числом (K2, K5) и всё работает локально (K1).
Отказ от MotionBERT (ICCV 2023, облегчённая версия 61 МБ [S4]). Это метод 2023 года, обучен на H36M в 17-точечном формате. Лицензия весов с учётом ограничений датасета — не подтверждено.

Честная оговорка по K4. Базовый детектор (BlazePose/GHUM) — решение 2020–2022 годов [S1]. Я оставляю его, потому что это единственный проверенный мной вариант, работающий на телефоне с допустимой лицензией. Новизна лежит выше слоя детектора:

слияние с датчиком и оптимизация по батчу вместо покадровых чисел;
ковариация и калибровка неопределённости по межракурсным данным;
проверка вероятностью, а не пороговым флагом;
перенос углов эталона на пропорции ученика.
