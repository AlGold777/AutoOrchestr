Причины:

Единственное, где независимость от ракурса переведена в число (σ_view, покрытие интервалов, тест «один удар с двух ракурсов»), а не в утверждение.

Б.1 Захват
1080p, 60 к/с (120, где устройство даёт при 1080p), 30 к/с допускается с флагом LOW_FPS. Фиксированный объектив 1×, ультраширокий не используется, выдержка ограничена. Никаких подсказок и предварительной проверки кадра (решения владельца); качество оценивается постфактум.
Электронная стабилизация выключена там, где API позволяет. Имена параметров (на iOS режим стабилизации соединения AVCaptureConnection, на Android CONTROL_VIDEO_STABILIZATION_MODE_OFF) NEEDS FACT: сверить с документацией Apple и Android.
Метки времени каждого кадра (PTS), без предположения о постоянном интервале.
Файл-спутник: вектор гравитации, гироскоп, кватернион ориентации, 100 Гц, ≈ 16 КБ на 4 с (400 × 10 float32). Источник часов камеры и датчика: если одинаков, привязка по времени точная; если неизвестен, статус SYNC_APPROX. Домены часов на iOS и Android NEEDS FACT.
Исправление (замечание C-06). Рассинхрон Δt даёт ошибку ориентации ω·Δt. При ручной съёмке 30°/с и 50 мс это 1,5°, то есть не пренебрежимо. Поэтому оценка сдвига по корреляции гироскопа с вращением фона — задача фазы 0, бюджет ≤ 1°. На штативе ω ≈ 0 и ошибка мала.
Intrinsics: покадрово, где устройство их даёт. Исправление: иначе номинальное поле зрения устройства и флаг INTRINSICS_NOMINAL (σ растёт).
Исправление (C-03, D-04). Движение камеры: признаки фона отслеживаются, при смещении выше порога ставится CAMERA_MOVING и интервалы расширяются. Трансляцию камеры не компенсируем: метрики — углы в системе гравитации, и она на них влияет только через перспективу.
Импортированное видео без датчиков: вертикаль ESTIMATED (см. 12.6).

Уровень C: lite на всех кадрах в окне удара (±300 мс вокруг tA), в остальной части клипа каждый второй кадр, без пакетной оптимизации. Метрики M2 и M3 (последняя только при вертикали от датчика) показываются как интервалы; вердикт — только если собственная калибровка уровня C пройдена. Коэффициент «σ×2» (Perplexity) не берём.
Выбор спортсмена касанием; трек по рамке. Модель с num_poses > 1: поведение проверить воспроизведением в фазе 0 (спор об issue не разрешён [8]). Смена личности определяется скачком отношений длин костей или потерей перекрытия рамки; тогда SUBJECT_LOST (из GPT-2).
Фронтир-модели (SAM 3D Body, ноябрь 2025: чекпойнт ≈ 2,1 ГБ + MHR 696 МБ [6]; RTMW3D) только офлайн, как дополнительный «судья» при проверке, не как эталон. Допустимость использования выходов SAM по лицензии NEEDS FACT; до прочтения лицензии судья не запускается.
Проход по зеркальному кадру на уровне A: выигрыш измерить в фазе 0, решать по снижению σ_view.
Б.3 Реконструкция

Конвейер: сырые данные → перевод координат → отбраковка выбросов (visibility, предел скорости) → пакетная оптимизация по окну удара (±1,5 с) → ковариация → метрики.

Ось и вертикаль. Конвенция осей worldLandmarks (по вторичному источнику [5] y вниз, z к камере) проверяется в фазе 0 обратной проекцией и тестом «человек стоит прямо, телефон вертикален». До проверки правило «d > 0,8 → LOW» не применяется; вместо него действует запасной критерий: видимость сегмента < 60% и σ > порога.

Параметры. Положения 19 суставов на кадр в системе «вертикаль — гравитация» и длины костей на клип (старт — медиана).

Стоимость. E = Σ w·ρ_Huber(reproj) + α‖X − X_mp‖² + β(‖bone‖ − L)² + γ·joint_limits + δ(t)‖∇²X‖², где X_mp — оценка world MediaPipe как слабый приор.

δ(t) ослабляется в момент удара (по скорости запястья), чтобы не срезать пик.
joint_limits: числовые диапазоны NEEDS FACT (взять из биомеханического справочника).
stance_foot — экспериментальный, по умолчанию выключен (замечание C-08, K-9: в прыжковом смэше контакта может не быть). Включается лишь при подтверждённом контакте и неподвижности лодыжки несколько кадров; фаза полёта определяется подъёмом обеих лодыжек над плоскостью пола, и тогда ограничения нет.

Исправление ковариации (C-03, G-C04). Cov = κ·σ̂²·(JᵀWJ)⁻¹, где σ̂² = RSS/(n − p) — оценка дисперсии остатка, W — веса Хьюбера, невырожденность даёт приор X_mp и ограничения костей, κ подгоняется по покрытию на данных. Расчёт блочно-ленточный по окну. Для углов дельта-метод σ²_θ = gᵀΣg, Монте-Карло только для нелинейных метрик и с n = 512 (64 мало для хвостов).

Масштаб. World MediaPipe — оценка модели в метрах, не измеренная глубина [1]. Метрическая шкала скелета даётся как оценка с неопределённостью масштаба σ_s (медианные кости против антропометрической модели, NEEDS FACT: источник пропорций). Рост пользователя необязателен; если введён, σ_s падает. Скорости показываются в длинах корпуса в секунду. Углы масштаба не требуют.

Сглаживание — внутри оптимизации (δ(t)); для показа отдельный фильтр с нулевой фазой; частота среза подбирается в фазе 0 по минимуму σ_view при ограничении на срезание пика (фиксированные 6 Гц или 8–15 Гц не принимаются).

События. tA — максимум высоты запястья, подтверждаемый пиком скорости запястья в окне ±100 мс (из Qwen); σ_t входит в сравнение как неопределённость времени.

Реализуемость. Решатель сначала на Kotlin с ленточной факторизацией. Ворота в конце фазы 1: > 20 с на 240 кадров на среднем устройстве → окно ±0,75 с или ядро на C++ (лицензия библиотеки линейной алгебры NEEDS FACT).

Б.4 Хранение (.p3d v2)
Заголовок: схема, профиль, SHA-256 модели, версия решателя и ограничений, уровень, источник intrinsics, статус синхронизации, источник вертикали, конвенция осей.
Исправление формата (Q-02). Координаты не float16. World и fitted хранятся как int16 с шагом 0,1 мм (диапазон ±3,27 м от таза); 2D — uint16 нормированных; visibility/presence — uint8.
Размер: сырой слой на кадр 33 × (2×2 + 3×2) + 66 = 396 Б, на 240 кадров ≈ 95 КБ; расчётный слой 19×3×2 + 19 = 133 Б на кадр ≈ 32 КБ; итого ≈ 127 КБ до сжатия плюс спутник ≈ 16 КБ. Степень сжатия zstd NEEDS FACT.
Сырой слой не перезаписывается. Пересчёт метрик из сырого слоя без видео, если модель та же; при смене бандла только из видео (если видео удалено, старый результат остаётся, но помечается как не пересчитываемый). Сравнение результатов разных бандлов без пересчёта запрещено (из GPT-2).
Б.5 Сравнение
Система тела. Вертикаль покадрово по гравитации; азимут корпуса один раз на клип по стойке до замаха; вращения таза относительно корпуса покадрово, иначе вращение в ударе «съедается».
Метрики. M1 подъём плеча, M2 сгиб локтя, M3 наклон корпуса к гравитации. M4, M5 скрыты до калибровки. Пронация, кисть, ракетка, осевые вращения костей не измеряются.
Перенос на тело ученика. Эталонный «призрак» строится по углам тренера на длинах костей ученика. Различия пропорций не дают ложного рассогласования; различия подвижности остаются, поэтому статус звучит «отличается от эталона», а не «ошибка» (из GPT-2).
Время. Три якоря, линейная деформация между ними, DTW в полосе Сакое–Чиба внутри сегментов. Тайминги (длительности фаз) считаются по якорям до деформации и показываются отдельно, чтобы DTW не стирал временные ошибки (C-09).
Вердикт (исправление C-01, C-02, C-05). Δ = θ_you − θ_ref. Неопределённость u = √(σ_you² + σ_ref²), где каждый σ_i уже включает межракурсный член σ_view(d, az) из калибровки (отдельного σ_retest в u нет). T — порог практического значимого различия на метрику, не зависящий от σ; старт 15° (число автора, PROVISIONAL), уточняется серией с намеренными ошибками. κ = 1,645. Порядок проверки, условия не пересекаются:
видимость < 60% или метрика UNAVAILABLE → UNDETERMINED;
|Δ| − κu > 2T → STRONG_DEVIATION;
|Δ| − κu > T → DEVIATION;
|Δ| + κu ≤ T → IN_RANGE;
иначе UNCERTAIN.
Односторонний κ уместен: DEVIATION — проверка «|Δ| превышает T», и при корректном u ложные срабатывания не выше ≈ 5%. Это допущение проверяется тестами Т1–Т2.
Зоны метрики по σ_view: ≤ 5° режим вердикта; 5–10° режим «только интервал» (без вердикта); > 10° метрика скрыта. Ворота фазы 0: хотя бы две из M1–M3 достигают режима вердикта, иначе остаются режим «с собой» и прошедшие метрики.
Критерии приёмки (все PROVISIONAL): покрытие 90%-интервалов на независимых игроках 85–95%; ложные DEVIATION в тесте «один удар, два ракурса» ≤ 5%; доля пар с вердиктом, отличным от UNCERTAIN, ≥ 60% на штатных клипах (остальным показываются интервалы без вердикта); чувствительность к намеренным ошибкам ≥ 80%. Прежнее «σ ≤ 7° и ≤ 5% ложных» несовместимо: при σ = 7° SD разности ≈ 9,9°, а 5% достигается лишь при T ≈ 16–19°.
Левша: зеркалирование эталона.
Б.6 Показ
Общая проекция в ядре, холсты SwiftUI Canvas и Compose Canvas. SceneKit мягко объявлен устаревшим [2], поэтому выбор Canvas остаётся; если понадобится настоящий 3D-движок, рекомендованный Apple путь — RealityKit [2].
Кости капсулами с сортировкой по глубине; неуверенные точки пунктиром; проекция 1σ-эллипсоида ковариации у сустава.
Орбитальная камера с инерцией, поворот 360°, кнопки Front / Side / Back / Top, «Match camera» (камера орбиты в азимут съёмки).
Наложение: два скелета в одном нормированном масштабе и общем деформированном времени, рядом или поверх; призрак эталона; покадровый шаг, замедление 0,25×; видео синхронно со своим 2D-скелетом.
Постоянная подпись: «Estimated 3D from a single camera». Цель отрисовки ≤ 4 мс/кадр и 60 к/с не подтверждена, измеряется в фазе 4. 360° не создаёт скрытых частей тела.
Б.7 Проверка качества

Оборудование: три обычных телефона на штативах.

Протокол. 15–30 игроков × 10 смэшей × 3 ракурса. Калибровка камер доской ChArUco в OpenCV (4.14.0 от 19.07.2026 заявлен GPT-2 и подтверждён критиком, мной не проверен). Синхронизация по вспышке/хлопку плюс подбор подкадрового сдвига по эпиполярной невязке. Шаг кадра 16,7 мс; для плеча, локтя и таза (M1–M3) скорость ниже, чем у запястья, поэтому ошибка триангуляции для них меньше (численный бюджет NEEDS FACT: измерить скорости суставов).
Выборки. Игроки калибровочной и контрольной групп не пересекаются (из GPT-1/GPT-2). В выборке игроки разного роста и сложения.
Тесты. Т1 межракурсное согласие, σ_view и пределы согласия Бланда–Альтмана, кластерный бутстреп по игрокам. Т2 тест «один удар с двух ракурсов» как «ученик и тренер», доля ложных DEVIATION. Т3 10 обычных и 10 намеренно ошибочных ударов. Т4 покрытие интервалов. Т5 ручная разметка независимой части кадров двумя разметчиками (доля кадров и сроки задаются в фазе 0), оценка систематики σ_bias(d, az), которая добавляется в σ_i: триангуляция берёт те же 2D-точки, поэтому сама истиной не является. Т6 вертикаль без датчика (датчик скрывается): медиана ≤ 3°, P95 ≤ 8°. Т7 паритет iOS/Android на одном видеофайле: медиана ≤ 2°, P95 ≤ 5° (цель 1° из GPT-1 ничем не обоснована). Т8 «10 ударов подряд» используется для оценки вариативности игрока и выбора T, но не как тест системы.

Б.9 Ответы на 12.1–12.10
12.1. Лучший способ на устройстве — связка: детектор MediaPipe, гравитация и параметры камеры из датчиков, пакетная оптимизация с ограничениями. Тяжёлые сети-сетки точнее по вращениям, но по размеру не для телефона [6]. Абсолютная метрическая точность не гарантирована.
12.2. Надёжно (после прохождения Т1): сгиб локтя; наклон корпуса к гравитации при вертикали от датчика. Условно: подъём плеча, сгиб колена опорной ноги. Не измеряются: пронация, кисть, ракетка, осевые вращения, разворот корпуса вокруг вертикали.
12.3. Азимут корпуса один раз на клип по стойке; вертикаль и вращения таза относительно корпуса покадрово.
12.4. Надёжность — число: σ метрики = Лаплас-ковариация с оценкой σ̂², поправка σ_view(d, az) и σ_bias из Т5. Дискретный статус получается по Б.5; корректность проверяется покрытием.
12.5. Ворота: σ_view ≤ 5° режим вердикта, 5–10° режим интервала, > 10° метрика скрыта; пороги фиксируются до прогона; плюс приёмка по Б.5.
12.6. Без датчика: вертикаль из стойки (середина стоп → середина плеч) и вертикальных линий сцены; корректность по Т6; при неудаче vertical = ESTIMATED, M3 и риск-паттерн UNDETERMINED.
12.7. Выбросы отбрасываются до оптимизации; сглаживание внутри оптимизации (δ(t)); отдельный фильтр с нулевой фазой только для показа; срез по данным фазы 0.
12.8. Canvas с капсулами, сортировкой по глубине, эллипсами неопределённости, наложением; движок не нужен.
12.9. Т1–Т8 из Б.7, без дорогого оборудования.
12.10. Заменить: порог σ ≤ 7° (несовместим с 5% ложных); фиксированный max(15°, 2σ) на T независимый от σ и κ·u; метрики-числа на метрики-распределения; покадровое сглаживание на оптимизацию с приором; тезис «M1–M3 не зависят от азимута» на проверяемый σ_view; правило d > 0,8 до проверки осей на запасной критерий.
