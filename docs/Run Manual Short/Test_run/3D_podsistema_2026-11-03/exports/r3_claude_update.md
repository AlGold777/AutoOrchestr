4. Обновлённый черновик (часть Б)

Черновик изменён. Правки: подтверждены версии OpenCV и Kotlin; SAM 3D Body привязан к [10]; вертикаль по сцене сделана вторичной; убраны числа входов моделей; уточнён статус калибровки ковариации.

padel.smash.v2 — 3D-подсистема анализа смэша (основа: решение Claude Sonnet 5.5, с правками).

Принцип. Продукт измеряет углы и фазы, а не метры. 3D — оценка по одной камере. Каждая метрика получает интервал, статус выдаётся только по откалиброванным данным. Все числа — PROVISIONAL до фазы 0.

Заимствования. Трёхзначный вердикт и запрет сравнения разных бандлов — из GPT-2. Раздельные игроки калибровки и проверки — из GPT-1/GPT-2. Ручная разметка независимой части кадров — из GPT-2 и критики DeepSeek D-03. Проверка tA по пику скорости запястья — из Qwen (разбор §5.6). Остальное — исправления дефектов базы по критике.

Б.1 Захват
1080p, 60 к/с (120, где устройство даёт при 1080p), 30 к/с допускается с флагом LOW_FPS. Объектив 1×, ультраширокий не используется, выдержка ограничена. Подсказок и предварительной проверки кадра нет (решения владельца); качество оценивается постфактум.
Электронная стабилизация выключена там, где API позволяет. Имена параметров NEEDS FACT.
Метки времени каждого кадра (PTS), без предположения о постоянном интервале.
Файл-спутник: гравитация, гироскоп, кватернион, 100 Гц, ≈ 16 КБ на 4 с. Если часы камеры и датчика совпадают, привязка точная; иначе SYNC_APPROX. Домены часов NEEDS FACT.
Рассинхрон Δt даёт ошибку ориентации ω·Δt: при 30°/с и 50 мс это 1,5°. Поэтому сдвиг оценивается по корреляции гироскопа с вращением фона (задача фазы 0), бюджет ≤ 1°. На штативе ω ≈ 0.
Intrinsics покадрово, где доступны; иначе номинальное поле зрения и флаг INTRINSICS_NOMINAL (σ растёт).
Движение камеры: признаки фона отслеживаются; при смещении выше порога ставится CAMERA_MOVING и интервалы расширяются. Трансляцию камеры не компенсируем.
Импорт видео без датчиков: вертикаль ESTIMATED (см. 12.6).
Б.2 Распознавание
MediaPipe Pose Landmarker, Tasks API, режим VIDEO, один бандл на обеих платформах. Выход: 33 точки 2D, 33 worldLandmarks (метры, начало в тазу [1]), visibility и presence без отсечения при записи. Размеры входа моделей берутся из бандла, не из документов.
Версия: MediaPipe 1.1.0 от 06.10.2026 подтверждена вторично [4]; 1.2.0 NEEDS FACT (проверить тег релиза на GitHub). Размеры .task ≈ 3 / 6 / 27 МБ (lite/full/heavy), вторично [5].
Уровни по замеру (20 кадров на первом запуске): A — heavy при ≤ 40 мс/кадр; B — full при ≤ 100 мс; C — lite. Делегат CPU/GPU/NPU выбирается замером: GPU не всегда быстрее CPU [8]. NNAPI не планируем (устарел с Android 15 [3]). Core ML в Tasks — NEEDS FACT.
Нижняя граница: если lite не укладывается в ≈ 250 мс/кадр или по памяти, 3D-режима нет, остаются видео и 2D-скелет без вердиктов.
Уровень C: lite на всех кадрах окна удара (±300 мс вокруг tA), вне его каждый второй кадр; без пакетной оптимизации. M2 и M3 (последняя только при вертикали от датчика) показываются интервалом; вердикт только при пройденной калибровке уровня C.
Выбор спортсмена касанием, трек по рамке. Поведение num_poses > 1 проверяется воспроизведением в фазе 0. Смена личности определяется скачком отношений длин костей или потерей перекрытия рамки, тогда SUBJECT_LOST.
Фронтир-модели (SAM 3D Body — Meta, 19.11.2025, лицензия SAM, GitHub facebookresearch/sam-3d-body [10]; чекпойнт ≈ 2,1 ГБ + MHR 696 МБ, вторично [6]; RTMW3D) только офлайн, как дополнительный «судья». Допустимость использования выходов SAM по лицензии NEEDS FACT; до её прочтения судья не запускается.
Проход по зеркальному кадру на уровне A: выигрыш измерить в фазе 0.
Б.3 Реконструкция

Конвейер: сырые данные → перевод координат → отбраковка выбросов → пакетная оптимизация по окну удара (±1,5 с) → ковариация → метрики.

Оси и вертикаль. Конвенция осей worldLandmarks (по вторичному источнику [5] y вниз, z к камере) проверяется в фазе 0 обратной проекцией и тестом «человек стоит прямо, телефон вертикален». До проверки правило «d > 0,8 → LOW» не применяется; действует запасной критерий: видимость сегмента < 60% и σ выше порога.

Параметры. Положения 19 суставов на кадр в системе «вертикаль — гравитация» и длины костей на клип (старт — медиана).

Стоимость. E = Σ w·ρ_Huber(reproj) + α‖X − X_mp‖² + β(‖bone‖ − L)² + γ·joint_limits + δ(t)‖∇²X‖², где X_mp — оценка world MediaPipe как слабый приор.

δ(t) ослабляется в момент удара по скорости запястья, чтобы не срезать пик.
joint_limits: числовые диапазоны NEEDS FACT.
stance_foot — экспериментальный, по умолчанию выключен. Включается только при подтверждённом контакте; фаза полёта определяется подъёмом обеих лодыжек над плоскостью пола, тогда ограничения нет.

Ковариация. Cov = κ·σ̂²·(JᵀWJ)⁻¹, где σ̂² = RSS/(n − p) — оценка дисперсии остатка, W — веса Хьюбера, невырожденность даёт приор X_mp и ограничения костей. Множитель κ — эмпирическая пересчётная калибровка, а не свойство метода Лапласа; корректность проверяется покрытием на независимых игроках. Если покрытие не достигается, метрика переводится в режим «только интервал». Для углов используется дельта-метод σ²_θ = gᵀΣg; Монте-Карло только для нелинейных метрик и с n = 512.

Масштаб. World MediaPipe — оценка модели в метрах, не измеренная глубина [1]. Скелет получает оценку масштаба с неопределённостью σ_s (медианные кости против антропометрической модели, пропорции NEEDS FACT). Рост пользователя необязателен; если введён, σ_s падает. Скорости показываются в длинах корпуса в секунду. Углы масштаба не требуют, поэтому для сравнения с тренером масштаб не нужен.

Сглаживание внутри оптимизации (δ(t)); для показа отдельный фильтр с нулевой фазой, срез подбирается в фазе 0 по минимуму σ_view при ограничении на срезание пика.

События. tA — максимум высоты запястья, подтверждаемый пиком скорости запястья в окне ±100 мс; σ_t входит в сравнение.

Реализуемость. Решатель сначала на Kotlin (2.4.20 [9]) с ленточной факторизацией. Ворота в конце фазы 1: > 20 с на 240 кадров на среднем устройстве → окно ±0,75 с или ядро на C++ (лицензия библиотеки NEEDS FACT). Скорость Kotlin/Native NEEDS FACT.

Б.4 Хранение (.p3d v2)
Заголовок: схема, профиль, SHA-256 модели, версии решателя и ограничений, уровень, источник intrinsics, статус синхронизации, источник вертикали, конвенция осей.
Координаты не float16 (шаг ≈ 0,98 мм на [1; 2) м, ≈ 0,49 мм на [0,5; 1) м). World и fitted — int16 с шагом 0,1 мм (±3,27 м от таза); 2D — uint16; visibility/presence — uint8.
Размер: сырой слой 33 × (2×2 + 3×2) + 66 = 396 Б/кадр, на 240 кадров ≈ 95 КБ; расчётный слой 19×3×2 + 19 = 133 Б/кадр ≈ 32 КБ; итого ≈ 127 КБ + спутник ≈ 16 КБ. Сжатие zstd NEEDS FACT.
Сырой слой не перезаписывается. Пересчёт метрик из него без видео, если модель та же; при смене бандла только из видео; без видео старый результат помечается как не пересчитываемый. Сравнение результатов разных бандлов без пересчёта запрещено.
Б.5 Сравнение
Система тела. Вертикаль покадрово по гравитации; азимут корпуса один раз на клип по стойке; вращения таза относительно корпуса покадрово.
Метрики. M1 подъём плеча, M2 сгиб локтя, M3 наклон корпуса. M4, M5 скрыты до калибровки. Пронация, кисть, ракетка, осевые вращения не измеряются.
Перенос на ученика. «Призрак» эталона строится по углам тренера на длинах костей ученика. Различия подвижности остаются, поэтому статус звучит «отличается от эталона», а не «ошибка».
Время. Три якоря, линейная деформация, DTW (полоса Сакое–Чиба) внутри сегментов. Тайминги считаются по якорям до деформации и показываются отдельно.
Вердикт. Δ = θ_you − θ_ref; u = √(σ_you² + σ_ref²), где σ_i уже включает межракурсный член σ_view(d, az). T — порог практической значимости на метрику, не зависящий от σ; старт 15° (число автора), уточняется серией с намеренными ошибками. κ = 1,645. Порядок проверки:
видимость < 60% или метрика UNAVAILABLE → UNDETERMINED;
|Δ| − κu > 2T → STRONG_DEVIATION;
|Δ| − κu > T → DEVIATION;
|Δ| + κu ≤ T → IN_RANGE;
иначе UNCERTAIN.
При корректном u ложные DEVIATION не выше ≈ 5% (проверяется Т1–Т2).
Зоны по σ_view: ≤ 5° режим вердикта; 5–10° только интервал; > 10° метрика скрыта. Ворота фазы 0: минимум две из M1–M3 достигают режима вердикта, иначе остаются режим «с собой» и прошедшие метрики.
Приёмка: покрытие 90%-интервалов на независимых игроках 85–95%; ложные DEVIATION в тесте «один удар, два ракурса» ≤ 5%; доля пар с вердиктом, отличным от UNCERTAIN, ≥ 60%; чувствительность к намеренным ошибкам ≥ 80%. Прежнее «σ ≤ 7° и ≤ 5% ложных» несовместимо: при σ = 7° SD разности ≈ 9,9°, а 5% достигается лишь при T ≈ 16–19°.
Левша: зеркалирование эталона.
Б.6 Показ
Общая проекция в ядре, холсты SwiftUI Canvas и Compose Canvas. SceneKit мягко объявлен устаревшим [2], поэтому выбор Canvas сохраняется; если понадобится 3D-движок, Apple рекомендует RealityKit [2].
Кости капсулами с сортировкой по глубине; неуверенные точки пунктиром; 1σ-эллипсоид у сустава.
Орбитальная камера с инерцией, 360°, Front / Side / Back / Top, «Match camera».
Наложение: два скелета в одном нормированном масштабе и общем деформированном времени, рядом или поверх; покадровый шаг, замедление 0,25×; видео синхронно со своим 2D-скелетом.
Подпись: «Estimated 3D from a single camera». Цель ≤ 4 мс/кадр и 60 к/с не подтверждена, измеряется в фазе 4. 360° не создаёт скрытых частей тела.
Б.7 Проверка качества

Три обычных телефона на штативах.

Протокол. 15–30 игроков × 10 смэшей × 3 ракурса. Калибровка ChArUco в OpenCV 4.14.0 [7]. Синхронизация по вспышке/хлопку плюс подбор подкадрового сдвига по эпиполярной невязке; шаг кадра 16,7 мс. Для плеча, локтя и таза (M1–M3) скорость ниже, чем у запястья, поэтому ошибка триангуляции меньше (численный бюджет NEEDS FACT).

Тесты. Т1 межракурсное согласие, пределы Бланда–Альтмана, кластерный бутстреп по игрокам. Т2 «один удар, два ракурса» как «ученик и тренер», доля ложных DEVIATION. Т5 ручная разметка независимой части кадров двумя разметчиками (доля кадров и сроки задаются в фазе 0), оценка систематики σ_bias(d, az), входящей в σ_i. Б.9 Ответы на 12.1–12.10
12.1. Лучший способ на устройстве — связка: детектор MediaPipe, гравитация и параметры камеры из датчиков, пакетная оптимизация с ограничениями. Тяжёлые сети-сетки точнее по вращениям, но по размеру не для телефона [6]. Абсолютная метрическая точность не гарантирована.
12.2. Надёжно (после Т1): сгиб локтя; наклон корпуса к гравитации при вертикали от датчика. Условно: подъём плеча, сгиб колена опорной ноги. Не измеряются: пронация, кисть, ракетка, осевые вращения, разворот корпуса вокруг вертикали.
12.3. Азимут корпуса один раз на клип по стойке; вертикаль и вращения таза относительно корпуса покадрово.
12.4. Надёжность — число: σ метрики = ковариация с оценкой σ̂² и калибровкой κ, поправка σ_view(d, az) и σ_bias из Т5. Статус по Б.5; корректность проверяется покрытием.
12.5. Ворота: σ_view ≤ 5° режим вердикта, 5–10° режим интервала, > 10° метрика скрыта; пороги фиксируются до прогона; плюс приёмка по Б.5.
12.6. Без датчика вертикаль берётся из стойки (середина стоп → середина плеч). Вертикальные линии сцены (стойки, стены) используются только как вторичная оценка и только если не менее двух почти вертикальных линий согласуются между собой; сетки и наклонные стёкла корта делают эту оценку ненадёжной. Корректность проверяет Т6; при неудаче vertical = ESTIMATED, M3 и риск-паттерн UNDETERMINED.
12.7. Выбросы отбрасываются до оптимизации; сглаживание внутри оптимизации (δ(t)); отдельный фильтр с нулевой фазой только для показа; срез по данным фазы 0.
12.8. Canvas с капсулами, сортировкой по глубине, эллипсами неопределённости и наложением; движок не нужен.
12.9. Т1–Т8 из Б.7, без дорогого оборудования.
12.10. Заменить: порог σ ≤ 7°; фиксированный max(15°, 2σ) на T независимый от σ и κ·u; метрики-числа на метрики-распределения; покадровое сглаживание на оптимизацию с приором; тезис «M1–M3 не зависят от азимута» на проверяемый σ_view; правило d > 0,8 до проверки осей на запасной критерий.
