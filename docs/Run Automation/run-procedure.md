# Процедура прогона

Требуются: macOS, Chrome с включённым «Разрешить JavaScript из Apple Events» (Вид → Для разработчиков), расширение загружено из основного чекаута. Все команды — из каталога репозитория; `T=docs/Run Automation/tools`.

## 0. Допуск

1. Разрешение владельца в чате на этот прогон и эту задачу (текст задачи отправится моделям). Один Chrome — один прогон одновременно; другие сессии на время прогона ничего не доставляют и не трогают Chrome.
2. Схема валидна (ошибок нет), закоммичена. Папка прогона создана: `docs/Run Automation/Test_run/<имя>_<yyyy-mm-dd>[_HH-mm]/` с `schema/`, `artefacts/`, `exports/`, `notes/`; схема и `task.txt` лежат в `schema/`.

## 1. Подготовка (чек-лист)

| № | Что | Как | Критерий |
|---|---|---|---|
| 1 | Экран не заблокирован, не уснёт | `caffeinate -dimsu -t 7200 &`; `bash $T/preflight.sh` | `IOConsoleLocked = No`, PreventUserIdleDisplaySleep = 1 |
| 2 | Версия доставлена | `grep '"version"' manifest.json` в основном чекауте | равна заявленной |
| 3 | Расширение перезагружено | JS `reload-extension.js` на `chrome://extensions` (`bash $T/js.sh $T/reload-extension.js chrome://extensions`) | `reloaded` |
| 4 | Вкладки моделей обновлены | `osascript $T/refresh-model-tabs.applescript` (скрипты осиротевших вкладок мёртвы до обновления) | N вкладок обновлено |
| 5 | Страница панели открыта и свежая | `open -a "Google Chrome" chrome-extension://<id>/pipeline_panel.html`; если `ERR_BLOCKED_BY_CLIENT` — обновить вкладку | `extension-version.js` возвращает версию |
| 6 | Окон нет, прогон не идёт | `any-modal.js` → `[]`; `run-state.js` → кнопка не «Остановить Basic» | |
| 7 | Модели доступны | Claude: `claude-page-state.js` (`limit:false`), `claude-composer-state.js` (поле пусто); баннеров лимита нет; вход выполнен | |
| 8 | Нет посторонних вкладок входа | закрыть лишние `login/popup…` | |

`bash $T/preflight.sh` печатает пункты 1, 2, 5, 6, 7 одним запуском.

## 2. Импорт схемы и запуск

```bash
python3 $T/make-import-scripts.py <schema.json> <task.txt> "<имя pipeline>" /tmp/run-scripts
bash $T/js.sh /tmp/run-scripts/paste.js        # вставка схемы
bash $T/js.sh /tmp/run-scripts/name.js         # имя + «OK»
bash $T/js.sh $T/click-ok-modal.js             # информационное окно «Схема установлена… OK»
bash $T/js.sh $T/close-choice-dialog.js        # отчёт «есть замечания» → «Закрыть», если появился
bash $T/js.sh /tmp/run-scripts/select.js       # выбрать pipeline
bash $T/js.sh /tmp/run-scripts/task.js         # текст задачи
bash $T/js.sh $T/any-modal.js                  # окон не должно быть
bash $T/js.sh /tmp/run-scripts/run-click.js    # запуск; время старта записать
```

## 3. Во время прогона

- **Наблюдатель**: каждые 20 секунд `any-modal.js` (любое видимое окно) и `run-state.js`; при окне — немедленная реакция. Виды окон — раздел «Окна страницы расширения» в [agent-live-test.md](../Agents/agent-live-test.md).
- **Ход**: `model-cards.js` — статусы и длины ответов карточек без выгрузки. Выгрузка «Basic» скачивает файл 4–5 МБ: 2–3 раза за прогон и в конце.
- **Решения ведущего**: окно «Ответ User» — отвечать самому по заданию шага; неполный раунд — «Skip member» для необязательной модели, молчащей 15 минут при принятых обязательных; лимит использования модели — пропуск участника.
- **Неясная причина сбоя** — смотреть страницу самому (`document.hidden`, поле ввода, кнопки, узлы ответа; без отправки запроса), не ждать выгрузки; находку — в `docs/Platform specifics/<провайдер>.md` и реестр.
- Расширение не перезагружать и не доставлять новую версию, пока идёт прогон.

## 4. После прогона

1. Одна выгрузка «Basic» (кнопка на странице; файл из `~/Downloads`) → `exports/`; итоговые документы → `artefacts/`. **Сразу после выгрузки:** закрыть окно телеметрии (`bash $T/js.sh $T/close-devtools-modal.js`) и панель загрузок Chrome (`bash $T/dismiss-downloads-bubble.sh` из вкладки Terminal приложения (`mcp__terminal__run_in_terminal`; из Bash и через клавишу Escape не работает) и проверить снимком, что список загрузок закрыт): оставленное открытым окно телеметрии показывается при каждом возвращении на страницу расширения.
   Ответы проверить скриптом: `node scripts/agent/check-run.js --flagged "<выгрузка>"`. Читать только отмеченные «ПРОВЕРИТЬ»: пустой, намного короче других, оборванный, без обязательных разделов, лимит или ошибка вместо ответа, повтор запроса, потерянные номера идей в карте. «ок» не значит, что ответ верен по смыслу; ответ, оборванный на слове без знака, скрипт может пропустить.
2. `notes/run-report.md` по [шаблону](run-report-template.md): что прошло, что нет, находки (по строке: что, где в экспорте, какая модель), оговорки среды.
3. Находки — в единый реестр `docs/Agents/basic-issues-registry.md` (те же сутки), наблюдения платформ — в `docs/Platform specifics/`, уроки схемы — в журнал пособия `docs/Scheme create/schema-craft-handbook.md` (§12).
4. Разбор по направлениям агентами Haiku: транспорт и завершение; логика, запросы и приёмка; интерфейс и окна; качество итога против «готово, когда» схемы.
5. Коммит папки прогона. Файлы, созданные мною в `~/Downloads`, чужие не трогать.

## 5. Правила

- Не запускать прогон при заблокированном экране (данные недействительны для транспорта, см. [environment.md](<../Platform specifics/environment.md>)).
- После перезагрузки расширения обновлять вкладки моделей до прогона.
- Не засорять `~/Downloads` снимками; не открывать вкладку телеметрии без нужды.
