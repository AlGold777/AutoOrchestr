## Основа: JS во вкладке через osascript

Работает, пока в Chrome включено View → Developer → Allow JavaScript from Apple Events. Сам не включай: если выключено, открой пользователю это меню и попроси поставить галочку.

1. Найти нужную вкладку: окно и номер.

```bash
osascript -e 'tell application "Google Chrome"
set o to ""
repeat with w in windows
repeat with i from 1 to count of tabs of w
set o to o & (id of w as text) & " " & i & " " & (URL of tab i of w as text) & linefeed
end repeat
end repeat
return o
end tell'
```

2. Выполнить JS-файл во вкладке: `bash "docs/Run Automation/tools/js.sh" <файл.js> <часть адреса>` (берётся последняя подходящая вкладка). Для точной вкладки: `execute (tab N of window id W) javascript js`, где `js` читается из файла (`do shell script "cat файл"`).
3. Номера вкладок сдвигаются, когда вкладки закрываются. Перед каждым действием заново найди номер; не используй номер из прошлого шага.
4. Во вкладке возвращай данные, а не выводы: текст, атрибуты, число узлов. Скрипты клади в scratchpad, не в репозиторий.

Команды `timeout` на этом Mac нет. Долгий вызов запускай в фоне.

## Что делать на страницах

- **Прочитать страницу модели.** JS возвращает `innerText`, список узлов ответа, их `getBoundingClientRect`, маркеры `[[AO-xxxxxx]]`. Сначала смотри реальный DOM, потом правь селектор.
- **Нажать индикатор или кнопку на странице расширения.** Событие из JS: `el.dispatchEvent(new MouseEvent('dblclick',{bubbles:true,cancelable:true,view:window}))` (для двойного клика) или `el.click()`. Обработчик двойного клика индикатора слушает `document` в фазе захвата, события из JS он принимает. Индикатор: `.status-indicator[data-llm-name="Qwen"]`. Если нужен настоящий клик мышью — `tools/realclick.js x y` (CGEvent), только из вкладки терминала приложения, предварительно активировав Chrome.
- **Проверить результат.** Прочитай карточку и подсказку индикатора (`title`): было → стало. Ответ команды не доказательство.

## Перезагрузка расширения после правки

1. Версия в `manifest.json` основного чекаута поднята, правка там закоммичена (расширение грузится из основного чекаута, не из worktree).
2. Нужна вкладка `chrome://extensions`. Нажми Reload: `bash tools/js.sh tools/reload-extension.js chrome://extensions`. В скрипте зашит id основного расширения `egfijmjjpedpikkfmfaekjbhjjjlhlgo` (`_Opus`); для копии `_Local_Qwen` подставь её id (`dpnajmofhnhhikfbefjbhlbfidejcnkk`). Список расширений и id: JS в `extensions-manager` → `extensions-item-list` → `extensions-item`.
3. После Reload расширение закрывает свои страницы (`result_new.html`, `pipeline_panel.html`) и очищает состояние текущего прогона. Страницы модели нужно перезагрузить: content-script подхватывается только при новой загрузке. Задай адрес вкладки заново и подожди 8–10 секунд.
4. Проверка версии: `tools/extension-version.js` на вкладке расширения.

Пользователь разрешил перезагружать расширение и его страницы. Другие вкладки не закрывай и не трогай.

## Где ошибаются

- Номер вкладки из прошлого шага после перезагрузки указывает на другую вкладку. Не задавай адрес «по номеру» вслепую: сначала сверь URL.
- Страница модели сразу после загрузки может открыться гостевой («Войти»). Подожди и проверь `innerText`; не делай выводов о выходе из аккаунта по первой секунде.
- Две копии расширения (`_Opus`, `_Local_Qwen`) работают одновременно. Правка нужна в обеих, перезагрузка тоже в обеих.
- Экран заблокирован — вкладки скрыты, JS возвращает пустое. Проверь `ioreg -n Root -d1 | grep IOConsoleLocked`.
- Не вводи пароли, не жми кнопки отправки запросов моделям без разрешения владельца на конкретный прогон.
