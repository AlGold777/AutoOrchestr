По замечаниям ведущего: 1) существование ClickNovaShutter, BLE_HID_EXAMPLE/APK v2.7.0 и jameellzx/iphone-cam-remote я не могу проверить без доступа к GitHub — **не знаю**, не опровергаю. 2) Clak — **не знаю/не подтверждаю**. 3) Прямую цитату Apple Accessory Design Guidelines R18 о запрете стороннему iOS-приложению публиковать BLE HID **не нашёл**; без раздела и цитаты это остаётся неподтверждённым. 4) Разночтение по ww24/remote-shutter — **не знаю**. 5) Замечание Qwen, что связка Android → iOS 26 не проверена, **подтверждаю как отсутствие доказательств**, а не как опровержение возможности.

Оценка решения: концепция BLE HOGP как первого эксперимента корректна и лучше, чем утверждение о готовом решении. Но это гипотеза, а не рабочий путь. Ключевой незакрытый факт: Apple документирует спуск физическими кнопками громкости в штатной Camera iOS 26, но не документирует, что произвольный HID Consumer Control Volume Increment (0xE9) будет обработан так же. ClickNova на ESP32 подтверждает лишь конкретный аппаратный прецедент, не Android-периферию и не все сборки iOS 26. Android `BluetoothGattServer.addService()` с API 18 и разрешениями Android 12+ существуют, но публикация HOGP зависит от контроллера/прошивки; HOGP 1.2 требует HID Service, Battery, Device Information, Report Map, Report Reference и bonding/шифрование. Это нормативно для профиля, но не матрица совместимости Apple Camera.

Возражения и дешёвые проверки:

1. «Достаточно отправить Volume Up» — неверно без проверки состояния: bonded, encrypted, Input Report подписан, press/release доставлены. Проверка: nRF Connect/GATT-лог, затем один press/release при закрытой Camera — должна меняться только громкость.
2. «ClickNova доказывает Android → iOS» — неверно: там ESP32. Проверка: тот же однобитный дескриптор из Android APK, Camera foreground, 10 команд → 10 новых PHAsset.
3. «Любой HID Consumer Control сработает» — не подтверждено; нужен точный Report Map, Report ID 1, release 00, пауза ~20 мс. Проверка: смена дескриптора только после удаления устройства из Bluetooth iPhone, иначе кэш GATT даст ложный отказ.
4. «PhotoKit/фоновая передача решены» — частично: `PHAssetResourceManager` документирован, но `PHBackgroundResourceUploadExtension` для iOS 26.1 я не подтверждаю; гарантий фоновой передачи при foreground Camera нет. Проверка: ручной экспорт после спуска.
5. Пропущено: нет публичного shutter API; iOS-приложение не может синтезировать нажатие штатной Camera. Вспомогательный компонент может лишь оркестрировать, но не гарантирует управление чужим Camera-процессом.
6. Протокол c03 в целом годен как эксперимент: APK v2.7.0/Basic, iOS 26 Camera foreground, 10 Volume Up, логи GATT, список новых Photos. Критерий успеха — 10 команд → 10 оригинальных снимков; иначе различать «нет HID», «нет bonding», «нет подписки», «только громкость», «снимок». После теста останутся неизвестны воспроизводимость на других Android/iPhone, режимы/HDR и автоматический возврат файла; тест сузит только причинность Android BLE HID → штатный затвор.
