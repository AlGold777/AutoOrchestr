## Короткий вывод

Публичного **программного** канала «приложение → штатная Камера → спуск» в iOS 26 нет. Но есть непубличный по смыслу, зато легальный **входной** канал: эмуляция Bluetooth-HID с Android-контроллера. Это не API Камеры, а ввод на уровне ОС — и он не запрещён платформой.

## Что запрещено и чем именно

- **Песочница / отсутствие IPC.** Стороннее приложение не может посылать события UI в чужой процесс. `UIApplication.open` умеет только запускать; публичной URL-схемы «сделай снимок» у Камеры нет (не документирована — не выдумываю).
- **Shortcuts / App Intents (iOS 16+).** Камера не публикует intent съёмки. Действие «Take Photo» — это собственный захват Shortcuts через AVFoundation, не конвейер приложения Камера. Автоматизации умеют «Open App Camera», но не «нажми спуск».
- **SiriKit.** Домена захвата фото нет; голосовое «сделай фото» лишь открывает приложение.
- **Bluetooth со стороны iPhone-контроллера.** CoreBluetooth не даёт роль HID/HOGP-периферии: iPhone не может притвориться клавиатурой/пультом. MFi External Accessory требует сертифицированного железа — исключено условием.
- **Wi-Fi/интернет.** В Камере нет слушающего сервиса управления; пуш не может инициировать съёмку, фон ограничен.
- **AVFoundation / UIImagePickerController** — исключены самой постановкой задачи.

## Единственный реалистичный путь

**Android-контроллер как BLE-клавиатура.** Android `BluetoothHidDevice` (API 28+) позволяет приложению зарегистрироваться HID-устройством и слать отчёты клавиш. iOS штатно принимает Bluetooth-клавиатуры; кнопка громкости «+» — известный спуск в Камере (на этом работают дешёвые BLE-пульты). Камера в foreground, снимок делает её конвейер (HDR/Deep Fusion/режимы), файл — в Photos.

Ограничения: контроллер **только Android** (iPhone так не умеет); сопряжение вручную в Настройках; Камеру открыть вручную или автоматизацией Shortcuts; возврат файла — iCloud/общий альбом/AirDrop, не мгновенный API.

**Уверенность:** высокая по механизму HID, средняя по тому, что именно Volume Up с HID-клавиатуры (а не с consumer-пульта) reliably спускает затвор на iOS 26. Это надо проверить, а не утверждать.

## Минимальные ослабления, если HID не сработает

1. Разрешить ввод как канал (HID/Switch Control/Voice Control) — уже почти разрешено условием «Bluetooth».
2. Разрешить MFi/BLE-пульт (снимает запрет «только телефоны»).
3. Разрешить helper с AVFoundation — теряется требование «конвейер штатной Камеры».
4. Jailbreak/приватные API — вне условий.

## Риски

Поведение HID-клавиш зависит от версии iOS и может меняться; спуск возможен только когда Камера уже в foreground и экран разблокирован; синхного возврата файла нет; App Store-приложение-«клавиатура» на Android легально, но iOS-сторона ничего не гарантирует.

## Самая дешёвая проверка (15–30 минут)

Android-телефон + готовое приложение Bluetooth-клавиатуры (или демо `BluetoothHidDevice`). Сопрячь с iPhone, открыть штатную Камеру, отправить Volume Up. Снимок появился — путь есть; нет — попробовать consumer-key/Enter и Voice Control («Tap Take Photo») как запасной.
