## Оценка решения

Сильно: физический спуск громкостью документирован Apple для актуальных iPhone («press either volume button to take a photo»); Android `BluetoothHidDevice` — API 28 с `registerApp()`/`sendReport()`, автоматическая дерегистрация при уходе из foreground — как в файле; `PHBackgroundResourceUploadExtension` действительно появился в iOS 26.1 (deprecated в iOS 27 в пользу Job-варианта).support.apple+3

## Возражения

1. **Пропущен главный прецедент**: массовые Bluetooth-селфи-пульты годами снимают штатную Camera iPhone именно через HID/AVRCP Volume Up — это делает BLE-гипотезу не «рискованной», а соизмеримой с успехом. Проверка: купить/взять любой пульт за 3–10 €, спарить, щёлкнуть.
2. **Экстраполяция Consumer Control → Camera не документирована Apple**: гарантировано только поведение физических кнопок. Исправление: в файле уже есть контроль «меняется только громкость» — оставить как точку отказа. Проверка: этап «закрытая Camera» из протокола.[support.apple](https://support.apple.com/guide/iphone/camera-basics-iph263472f78/ios)
3. **«HOGP 1.2 от 21.04.2026» не подтверждено** — нормативно действующий профиль; сверить с bluetooth.com. Проверка: одна справка по спецификации SIG.
4. **AirDrop/Quick Share — не автоматический возврат**: приём вручную, режим на 10 минут; для критерия «возврат файла» годится лишь как ручной. Исправление: зафиксировать в приёмке «ручная передача допустима на проходе 1» (в файле это есть, вынести в критерий).[store.google](https://store.google.com/in/magazine/pixel-quick-share-iphone?hl=en-IN)
5. **Опора на самоотчёт ESP32 как «подтверждено на устройстве»** — это отчёт автора, не независимый протокол. Исправление: понизить статус до «заявлено автором» до собственного прогона. Проверка: собственная серия 10/10.
