**Краткий вывод:** по состоянию на iOS 26 разрешённого платформой канала, которым обычное приложение на управляющем телефоне заставит **штатное приложение «Камера»** целевого iPhone сделать снимок, нет. Штатная «Камера» не имеет публичного API управления, URL-схемы, App Intent или Shortcuts-действия «нажать спуск». Внешняя команда может лишь доставить данные вспомогательному приложению на целевом iPhone, но оно не сможет синтезировать нажатие в чужом UI или запустить съёмку штатной «Камерой» без пользователя.

**Каналы и механизмы (iOS 26, Apple Developer Documentation):**

- **Bluetooth (CoreBluetooth):** приложение-приложение может передать команду, но это только GATT-обмен. Нет публичного API «нажать затвор» в штатной «Камере». Эмуляция HID-клавиатуры/кнопки громкости из обычного iOS-приложения для другого iPhone не документирована; MFi/ExternalAccessory — не «обычное приложение», требует аксессуар. Штатная «Камера» реагирует на аппаратную кнопку громкости как на спуск, но это физический HID/MFi-путь, не команда из приложения, и файл не возвращается управляющему телефону.
- **Wi‑Fi/интернет (Network, push):** можно передать сообщение на target-app. Push не запускает приложение и не открывает «Камеру»; background execution ограничен. Публичной URL-схемы `camera://` нет; открытие чужого приложения без документированной схемы невозможно.
- **Shortcuts/App Intents:** Shortcuts может иметь действие съёмки, но это не публичный «пульт» для штатной «Камеры» и не гарантирует её конвейер; удалённый запуск shortcut не даёт фонового нажатия спуска. App Intents не экспонируют управление штатной «Камерой».
- **UI-автоматизация/Accessibility:** synthetic events в другое приложение для App Store-приложений запрещены sandbox-моделью; приватные API недопустимы.
- **Apple Watch Camera Remote/Continuity:** это механизмы Apple, не публичный API для стороннего приложения.

**Что именно запрещает:** sandbox и отсутствие публичного API межприложенческого управления UI; запрет синтетических событий; ограничения background execution; отсутствие документированной URL-схемы/Intents у «Камеры»; ограничения CoreBluetooth на эмуляцию системного HID-ввода. `UIImagePickerController` и `AVFoundation` — это не штатное приложение «Камера», а собственный/системный capture-UI.

**Минимальные ослабления:** (1) физический MFi/Bluetooth-пульт, эмулирующий кнопку громкости, плюс target-app с доступом к Photos для выгрузки — но это не «команда из обычного приложения» и не автоматический возврат файла; (2) разрешить пользователю на целевом iPhone самому нажать спуск, а внешнему приложению — только уведомлять; (3) Apple должна добавить публичный remote-capture API/Intent с авторизацией; (4) отказаться от требования штатной «Камеры» и использовать AVFoundation. Приватные API/UI-автоматизация/jailbreak — вне условий.

**Рекомендация:** compliant-пути нет; для штатного конвейера нужен человек или MFi-пульт. Риски: отказ App Store, нестабильность, privacy/Photos-разрешения. **Дешёвая проверка:** спарить BLE/HID-пульт с целевым iPhone, открыть «Камеру», нажать кнопку — снимок появится; затем minimal target-app по BLE/Wi‑Fi пытается открыть `camera://`/нажать спуск — ожидаемо не работает.
