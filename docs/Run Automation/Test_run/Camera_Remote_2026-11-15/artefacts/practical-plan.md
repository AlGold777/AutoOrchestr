# Практический план: внешний спуск штатной Камеры iPhone

Обновлён после прохода c01. Порядок от дешёвого к дорогому. Каждая проба бинарная: снимок сделан штатной Камерой без касаний iPhone или нет.

Предусловия для всех проб: iPhone разблокирован, Камера на переднем плане, режим «Фото», Bluetooth сопряжён вручную. На iPhone: Настройки → Звуки и тактильные сигналы → выключить «Изменение кнопками». Записывать экран iPhone, модель iPhone, версию iOS, модель Android.

0. Контроль (5 минут). Нажать кнопку громкости на самом iPhone в Камере: должен получиться снимок. Нет — дальше идти нельзя.
1. Готовое Android-приложение с BLE HID без сборки (30–60 минут): APK v2.7.0 из релизов Aleksander-Drewnicki/BLE_HID_EXAMPLE на GitHub (есть также v2.6.0, v2.5.0). Перед установкой проверить, что APK из официальных релизов этого репозитория, и прочитать issues. Это сторонний код: ставить только на тестовый телефон. Если нужна сборка из исходников (1–2 часа, Android Studio) — тот же репозиторий или форк rkissell. Кандидаты: Aleksander-Drewnicki/BLE_HID_EXAMPLE и форк rkissell/BLE_HID_EXAMPLE (режим «Basic» — только consumer control), ww24/remote-shutter. Готовых релизов нет. Сопрячь с iPhone, отправить «Volume Up». Снимок есть — канал работает, дальше нужен только свой интерфейс. Перед сборкой проверить исходник: какой дескриптор и какие службы HOGP он публикует.
1а. Быстрая проверка без кода: nRF Connect для Android позволяет задать GATT-сервер; добавить службу HID (0x1812) и убедиться, что Android её принимает (спор Perplexity против DeepSeek).
2. Аппаратный контроль (если есть Bluetooth-пульт для селфи, 10 минут). Покажет, принимает ли именно эта версия iOS такой ввод. Не есть решение (нарушает «только телефоны»).
3. Свой минимальный Android-код, классический HID (BluetoothHidDevice, API 28): дескриптор Consumer Control, Volume Increment 0xE9, press и release. Приложение должно быть на переднем плане, иначе регистрацию снимет система. На Android 12+ нужно разрешение BLUETOOTH_CONNECT.
4. Если классический HID не сработал: BLE HID over GATT через BluetoothGattServer. Дескриптор и формат отчёта брать из рабочего примера (вопрос 2 прохода c02).
5. Только после первого воспроизводимого снимка: серия 100 команд и отдельная задача возврата файла (помощник на iPhone, PhotoKit, .readWrite).

Не считать успехом: громкость поменялась, а снимка нет; sendReport() вернул true; новый файл появился без записи экрана.
Как подтвердить: запись экрана, журнал отправки на Android, EXIF нового кадра, время. При отрицательном результате — NO-GO для проверенной конфигурации, без вывода о всей платформе.

Известные ограничения: Camera Control на iPhone 16 по HID не запускается; iPhone в роли управляющего HID-устройством быть не может (источник Apple по этому пункту ещё нужен — вопрос 4 прохода c02).

Статус проверок после c02 (2026-11-15): непроверены источниками утверждения GPT о «ClickNovaShutter», «APK v2.7.0», «uuidNotAllowed для 0x1812 на iPhone»; Perplexity: запрет службы 0x1812 в Android не подтверждён. Нужен дескриптор, работающий на iOS 17+: в доступных источниках его нет, брать из проверки на устройстве.

Проверено по первоисточникам после c03 (2026-11-15): tcholewa/ClickNovaShutter — ESP32 BLE HID Consumer Control (Volume Increment 0xE9 + release) снимает штатную Камеру iPhone 16 Pro (по описанию автора, Камера должна быть открыта). Это подтверждает сторону iOS для BLE; Android → iOS 26 ещё не проверен никем. Первый тест на двух телефонах: Камера открыта в режиме «Фото» → контроль с закрытой Камерой (меняется громкость) → 10 нажатий с Android → считать новые снимки.

Обновление после c04 (2026-11-15): актуальные версии по странице Apple Security Releases — iOS 27.2.1 (09.11.2026) и 26.7.3; записать точную сборку на своём iPhone (Настройки → Основные → Об этом устройстве). В BLE_HID_EXAMPLE v2.7.0 режима «basic» больше нет: использовать вкладку потребительского пульта (consumer), кнопку громкости вверх; Android 12 и выше. Перед основной серией отключить на iPhone «Use Volume Up for Burst», Live Photo и ProRAW, выбрать режим «Фото». Отрицательный контроль: при главном экране 10 нажатий не дают снимков, громкость меняется. Положительный контроль: физическая кнопка громкости на самом iPhone в Камере снимает. Возврат файла: iPhone → Android вручную через AirDrop ↔ Quick Share (только поддерживаемые модели, на iPhone «Все на 10 минут») или облако; это отдельная задача.

## Финальная редакция (после c05, 2026-11-16)

Что нужно владельцу для первого теста: Android 12+ и iPhone, оба ваши, без доп. оборудования.

1. Записать: модель iPhone, точную сборку iOS (Настройки → Основные → Об этом устройстве; актуальны iOS 27.2.1 и 26.7.3 от 9 ноября 2026), есть ли у модели Camera Control и Action, модель Android.
2. Приложение: готовый APK v2.7.0 из релизов Aleksander-Drewnicki/BLE_HID_EXAMPLE (ставить на тестовый телефон; записать SHA-256 файла). Вкладка потребительского пульта, кнопка «Volume UP». По исходникам: Report ID 3, поле Volume Up = usage 0xE9, нажатие даёт шестибайтный отчёт с первым байтом 0x80, отпускание — нули. Режима «basic» в этой версии нет.
3. На iPhone: выключить «Use Volume Up for Burst», Live Photo, ProRAW; убрать подключённые Bluetooth-аудиоустройства; выключить автоблокировку и уведомления («Не беспокоить»); разблокировать.
4. Положительный контроль: открыть Камеру вручную, режим «Фото», нажать физическую кнопку громкости на iPhone: должен получиться снимок.
5. Сопрячь Android с iPhone через Настройки Bluetooth, закрыть диалог сопряжения.
6. Отрицательный контроль: на главном экране iPhone нажать «Volume UP» в приложении: громкость меняется, снимка нет.
7. Основная проба: Камера открыта, режим «Фото»; один импульс; при успехе 10 отдельных нажатий с паузой. Критерий: 10 команд = 10 новых снимков, без лишних и поздних. Записывать экран iPhone и журнал Android.
8. Повторить после переподключения Bluetooth. После смены описания устройства забыть его в настройках iPhone и сопрячь заново.
9. Отказ классифицировать по этапу: нет обнаружения, нет сопряжения, нет подписки, на главном экране громкость меняется, а в Камере снимка нет, снимок сделан, но файла нет. Один отрицательный результат не доказывает невозможность: затем отдельно классический HID (BluetoothHidDevice, Android API 28, приложение должно оставаться на переднем плане).
10. Возврат файла отдельной задачей: вручную (AirDrop ↔ Quick Share на поддерживаемых Android, на iPhone «Все на 10 минут») или помощник на iPhone с доступом к Фото.

Что не доказано: работоспособность Android → iPhone ни на одной версии iOS. Подтверждён только аппаратный прецедент (ClickNovaShutter, ESP32, iPhone 16 Pro, отчёт автора).
Границы: Камеру программно открыть нельзя, режим «Фото» ставится вручную; iPhone в роли управляющего не поддерживается Apple.
