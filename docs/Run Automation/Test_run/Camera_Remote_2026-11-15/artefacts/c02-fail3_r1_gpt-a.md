Оценка: концепция HID обоснована, но выбор классического Bluetooth как основного пути преждевременен. BLE HOGP необходимо проверить первым или параллельно. Работоспособность Android → штатная Camera на iOS 26 пока не доказана.Замечания ведущего1. HID Volume Up — подтверждаю частично. Apple документирует спуск физической кнопкой громкости в iOS 26. Nordic DevZone подтверждает управление штатной Camera через BLE HID на iOS 15–16. Однако Apple не гарантирует эквивалентность любого внешнего HID-события физической кнопке. 2. BluetoothHidDevice — подтверждаю, с поправкой. API существует с Android 9 (API 28). Ограничение foreground подтверждено AOSP, но утверждение ведущего об отсутствии его в официальной документации неверно: оно прямо указано в registerApp(). 3. Camera Control и изменение громкости звонка — не знаю. Публичная документация Apple различает Camera Control и кнопки громкости, но не устанавливает поведение конкретных Bluetooth HID-дескрипторов на iOS 26. Упомянутые сообщения форумов недостаточны для универсального запрета. Возражения и исправления4. Пропущен BLE HOGP — существенная ошибка. Android предоставляет BluetoothManager.openGattServer() и BluetoothGattServer.addService() начиная с API 18. Публикация HID Service 0x1812 не запрещена этими API. Классический HID документирован через BluetoothHidDevice, BLE — через GATT Server. Последний имеет более близкий экспериментальный прецедент для iPhone. Но надёжность обоих путей на iOS 17–26 не установлена. 5. Дескриптор не валидирован. Nordic опубликовал рабочий для iOS 16 вариант с Consumer Control, Report ID 01, Volume Down EA и Volume Up E9, а также код press/release. Для iOS 17–26 подтверждённых точных байтов не найдено. Нельзя объявлять этот дескриптор универсальным. Дешёвая проверка: сравнить исходный Nordic report map и битовый вариант, регистрируя сопряжение, изменение громкости и факт снимка. 6. Готовый прототип существует. BLE_HID_EXAMPLE реализует Android BLE GATT HID с Consumer Control и Volume Up. rkissell/BLE_HID_EXAMPLE — форк этого проекта. Исходный код содержит BluetoothGattServer, HID-сервис и consumer reports. Но совместимость со штатной Camera iOS 26 не доказана. 7. Проверка за час. Установить APK из Releases, активировать BLE HID, выполнить сопряжение в настройках iPhone, открыть штатную Camera, отправить Volume Up. Проверить создание нового HEIC. Повторить десять раз. Затем сравнить с классическим HID, если имеется готовая реализация. Отдельно проверить блокировку экрана и повторное сопряжение.8. iPhone-контроллер и возврат файла. CBPeripheralManager позволяет iOS-приложению публиковать GATT-сервисы, но Apple не документирует превращение произвольного приложения в системно совместимый HOGP-пульт. Это экспериментальный путь, не доказанный запрет. Для возврата без помощника подходит iCloud Photos через браузер Android; AirDrop напрямую на Android не является универсальным каналом. Для автоматического возврата — PhotoKit с разрешением .readWrite, PHAssetResourceManager и передача оригинальных байтов по Wi-Fi. Итог: штатная Camera сохраняется, но HID-спуск остаётся экспериментальным.
