Итог: концепция HID технически обоснована, но приоритет классического Bluetooth ошибочен. Обнаружены новые свидетельства работоспособности BLE на iOS 26. Полная связка Android → iPhone → возврат оригинала пока не подтверждена.Замечания ведущего1. Android BLE HID — подтверждаю частично. BLE_HID_EXAMPLE и форк rkissell существуют. Android предоставляет публичный BluetoothGattServer; запрет службы 0x1812 документацией не установлен. У rkissell готовых релизов нет. Однако ww24/remote-shutter использует M5Stack, а не Android-приложение. 2. Свидетельства iOS 17–26 — прежний вывод опровергаю частично. Для iOS 17/18 подтверждённых испытаний не нашёл. Зато ClickNovaShutter документирует аппаратный тест 18–19 июля 2026 года: iPhone 16 Pro, iOS 26.5.2, штатная Camera, десять снимков от десяти BLE-команд. Это отчёт разработчика, не независимая сертификация. 3. Требования HOGP — подтверждаю спецификацией Bluetooth SIG v1.2. Необходимы HID Service 0x1812, Battery Service, Device Information с PnP ID, HID Information, Report Map, Input Report, Report Reference 0x2908, bonding и шифрование. Protocol Mode зависит от используемого режима. Apple не гарантирует совместимость любого корректного дескриптора. 4. ClickNovaShutter и Clak — существование подтверждаю. ClickNova содержит отчёт об успешном iOS 26-тесте. Clak реализует HOGP через CoreBluetooth, включая iPhone → Mac. Автор описывает uuidNotAllowed для короткого 1812 и обход посредством 128-битной записи того же UUID. Поддержка Apple этого обхода не гарантирована. 5. Возврат файлов — подтверждаю частично. AirDrop ↔ Quick поддерживается на перечисленных Google совместимых Android-устройствах, с пользовательским подтверждением. PhotoKit допускает экспорт оригинальных ресурсов при разрешённом доступе. Общие альбомы iCloud на iOS 26 уменьшают фотографии до 2048 пикселей: для оригинала непригодны. Возражения и исправления1. Приоритет транспорта. BLE HOGP должен быть первым, Classic HID — резервным. Проверка: собрать rkissell, установить соединение и отправить Volume Increment 0xE9 с последующим release. Зафиксировать факт появления фотографии.2. Дескриптор. Неподтверждённый набор байтов нельзя объявлять рабочим. Использовать исходную реализацию ClickNova как проверенный разработчиком образец для iOS 26, но не как гарантию для Android. Проверка: сравнить GATT-структуры и повторить десять спусков. 3. Управляющий iPhone. Полностью исключать его ошибочно: Clak демонстрирует работающую HOGP-периферию. Проверка: адаптировать передачу Consumer Control и испытать iPhone → iPhone. Статус — экспериментальный.4. Возврат файла. PhotoKit не гарантирует непрерывную работу помощника, пока Camera находится foreground. Проверка: измерить получение события Photos и передачу оригинала без переключения приложений.5. Критерий успеха. iOS 26 документирует спуск клавишей громкости, но не API удалённого управления Camera. HID обходит отсутствие shutter API посредством штатного системного ввода, не нарушая sandbox. Проверка обязательна на целевой версии. Минимальное ослабление: ручной экспорт снимка устраняет неопределённость возврата. Если HID на двух телефонах не заработает, отдельный BLE-пульт устраняет неопределённость источника команды, но нарушает аппаратное ограничение.Вердикт: согласен с правками
