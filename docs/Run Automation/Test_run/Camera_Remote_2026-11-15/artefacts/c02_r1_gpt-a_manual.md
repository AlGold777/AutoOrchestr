Независимая оценка

Основная ошибка: классический Bluetooth HID выбран приоритетным без сравнительных испытаний с BLE HOGP. Документированность Android API не доказывает совместимость с Camera на iOS 26.

Замечания ведущего и возражения

1. HID Volume Up — подтверждаю частично. Nordic документирует спуск штатной Camera через BLE Consumer Control 0xE9. Apple подтверждает спуск физическими кнопками громкости в iOS 26, но не гарантирует эквивалентность любого HID-события. 
Nordic DevZone
+1
 Проверка: снимок в штатной Camera без касания iPhone.

2. BluetoothHidDevice — подтверждаю. API 28, автоматическая отмена регистрации вне foreground. Исправление ведущего: это прямо указано и в текущей официальной документации Android. 
Android Developers
 Проверка: onAppStatusChanged() при сворачивании.

3. Camera Control через HID — не знаю. Публичного соответствия между HID Volume Up и отдельной кнопкой Camera Control Apple не документирует. 
Apple Developer
 Проверка: раздельно испытывать Volume Up и Camera Control.

4. Изменение громкости звонка — подтверждаю как возможный эффект, не как универсальное поведение. Проверка: Camera foreground, переключить «Изменение кнопками», наблюдать фото и индикатор громкости.

5. BLE HOGP — подтверждаю пропуск. Android BluetoothGattServer.addService() существует с API 18. Запрет публикации 0x1812 в Android SDK не обнаружен. 
Android Developers
 Исправление: BLE сделать первым экспериментальным кандидатом, классический HID — вторым.

6. Готовая реализация — подтверждаю. rkissell/BLE_HID_EXAMPLE — форк 04Alek04 с Consumer Control и Basic Mode. У оригинала есть готовый APK v2.7.0. Совместимость с iOS 26 не доказана. 
GitHub
+1

7. Дескриптор iOS 17–26 — не знаю. Проверенного для всего диапазона нет. Nordic публикует дескриптор, проверенный на iOS 16.1:

05 0C 09 01 A1 01 85 01 15 00 26 FF 03 19 00 2A FF 03 75 10 95 01 81 00 C0

Input Report: E9 00 — нажатие; 00 00 — отпускание; Report ID = 1. Подтверждено управление громкостью, не спуск на iOS 26. 
GitHub
+1

8. Сравнение транспортов. BLE имеет более релевантный прецедент. Проект ClickNovaShutter сообщает об успешном спуске штатной Camera на iPhone 16 Pro, но точная iOS не указана. 
GitHub
 Дешёвая проверка: APK, сопряжение, 20 нажатий, подсчёт фотографий.

9. iPhone как контроллер — частично подтверждаю. CBPeripheralManager публично предоставляет GATT. Проект Clak экспериментально реализует iPhone → Mac HID. Однако iPhone → iPhone не подтверждён; короткий UUID 1812 может возвращать uuidNotAllowed. 
Apple Developer Documentation
+1
 Проверка: публикация HID и подписка принимающего iPhone.

10. Возврат файла. Для автоматизации — PhotoKit (PHAssetResourceManager) плюс Wi-Fi. Без помощника — iCloud Photos либо ручной AirDrop → Quick Share на совместимом Android. Shared Albums в iOS 26 уменьшают разрешение. 
Apple Developer Documentation
+2

Итог: публичного API управления затвором чужого Camera.app нет. HID обходит необходимость такого API посредством системного ввода, но работоспособность Android → iOS 26 требует аппаратного теста.
