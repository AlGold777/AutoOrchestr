## Итог

`artefacts/final-solution.md`: Android BLE HID (Consumer Control, Volume Increment 0xE9) → штатная Камера iPhone; статус «проверяемая архитектура, не доказанное решение». Практический план для владельца: `artefacts/practical-plan.md`.

Что подтверждено источниками: аппаратный прецедент ClickNovaShutter (ESP32, iPhone 16 Pro); готовый APK BLE_HID_EXAMPLE v2.7.0 (Report ID 3, Volume UP = usage 0xE9); актуальные версии iOS 27.2.1 и 26.7.3; совместимость AirDrop ↔ Quick Share на части Android; запрет публиковать BLE HID Service стороннему iOS-приложению (формулировка в R7 «shall not», номер раздела в редакциях разный).
Что не доказано: работа связки Android → iPhone; таблица обязательных служб HOGP по первоисточнику SIG (не удалось прочитать); номер раздела Apple в текущей редакции R26.

## Что серия дала приложению (всё в копии, версия 2.81.1047)

Терпение: сроки ожидания и закрытие этапа больше не вердикты, пока страница модели генерирует; детектор лимита знает дневной лимит Qwen; повтор принимает готовый ответ по метке в ответе; отправка длинного запроса в ChatGPT (кнопка «Отправить», время слота); ограничение ревизий карточки в записи прогона; платформенный режим Qwen = Qwen4-Max-Preview. Перенос в основной проект не делался.

## Ошибки ведущего, найденные по ходу

Решение в задаче резалось по 7500 знаков (c02, c03); условия задачи называли iOS 26 вместо актуальной 27; Qwen стоял на Qwen3.8-Max; ручные шаги иногда объявляли конец раньше времени. Всё исправлено и записано в `notes/decisions.md`.
