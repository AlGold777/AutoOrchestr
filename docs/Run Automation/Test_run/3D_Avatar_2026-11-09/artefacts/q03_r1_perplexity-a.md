## Краткий вердикт

Узнаваемость лица достигается многослойным стеком: FLAME-подобный геометрический каркас → фототекстура или гауссианы поверх → отдельные глаза и зубы → анимация через коэффициенты блендшейпов. Ни один слой нельзя выкинуть без попадания в uncanny valley.

## Геометрия и каркас

База — FLAME: модель с артикулированной челюстью, шеей и глазными яблоками, экспрессивными блендшейпами, значительно точнее альтернатив при фитинге к сканам [проверено]. SOTA-пайплайны голов используют его как несущий: GaussianAvatars привязывают 3D-гауссианы прямо к треугольникам FLAME-меша — при анимации меша каждый гауссиан транслируется, вращается и масштабируется родительским треугольником [проверено]. MonoGaussianAvatar идёт дальше: каноническое представление 3D-точек + гауссиановое поле деформации, параметры выражения/позы FLAME дообучаются (fine-tune) прямо при оптимизации аватара — это бьёт SOTA по L1, LPIPS, SSIM и PSNR и на DSLR-, и на смартфон-видео [проверено].[arxiv](https://arxiv.org/html/2312.04558v1)

Практические режимы получения геометрии по съёмке телефоном:

- Оптимизационный монокулярно-видео фитинг FLAME в реальном времени (RealDenseFace: плотные UV-соответствия + глубинные приоры + CUDA-оптимизатор) [проверено].
- Де-факто fallback на iOS: ARKit выдаёт 3D-геометрию лица по TrueDepth-камере в реальном времени [проверено] — но это маркер выражения, а не персистентная идентичность [экспертная оценка].

## Текстуры

Два маршрута, у обоих — известные ограничения:

- **UV-текстура** под меш. Классика плохо держит идентичность: низкое качество текстур, потеря ID, кривые окклюзии; UV-IDM решает это identity-conditioned Latent Diffusion: генерирует высокоточные текстуры за секунды, согласованные с исходным фото [проверено]. Self-supervised подходы дают high-res UV-карты из синтезированных мультивью без разметки [проверено]; FreeUV закрывает восстановление текстуры с мультивью [проверено]. Под XY: реконструируемые UV сохраняют идентичность референсов под контролем [проверено].sciencedirect+3
- **Гауссианы вместо текстуры** (рекомендую): DEGA иерархически раскладывает гауссианы, специализированной инициализацией отдельно прокачивает глаза и зубы, а выученная per-primitive confidence давит плавачки и блоббинги на границах — фотореализм с монокулярного видео [проверено].

## Глаза и зубы — главные источники «мёртвого взгляда»

- **Зубы**: в GaussianAvatars к FLAME-шаблону вручную добавили **168 треугольников** зубов; верхние жёстко привязаны к шее, нижние — к челюсти; при закрытом рте зубные гауссианы скрываются неригидной деформацией области рта [проверено]. GeoAvatar отдельно моделирует части-деформации из-за сложности ротовой области [проверено].
- **Глаза**: отдельные артикулированные яблоки поддержаны самим FLAME [проверено]; поверх — blick/catchlight и материальная влажность роговицы, иначе смотрится как кукла [кино-практика, не верифицировано источником].

## Мимика и блендшейпы

Интерфейс управления выражением — словарь именованных коэффициентов ARKit `blendShapes`: по каждому `BlendShapeLocation` значение float от 0.0 (нейтраль) до 1.0 (максимум); ARKit раскладывает выражение на движения конкретных черт, коэффициентов можно брать сколько нужно; всего — **52 блендшейпа**, они соответствуют FACS action units [проверено]. Эти коэффициенты — де-факто порт для Live Link Face-совместимых ригов [проверено].developer.apple+1

Мост к аватару: ваше представление должно линейно блендиться коэффициентами выражения. Gaussian Blendshapes делают 3D-эквивалент мешевых блендшейпов: нейтральная модель + набор экспрессивных гауссиановых блендшейпов + отдельная модель внутренности рта; синтез — линейное смешивание коэффициентами, рендер **370 FPS**, при этом улавливает морщины, зубы и блики очков [проверено]. Альтернатива — привязка гауссиан к FLAME (автоматом едет по коэффициентам FLAME, которые ARKit-параметры мапятся 1:1 [экспертная оценка]).

## Числа и ограничения

- 52 коэффициента 0.0–1.0 на ARKit [проверено]; +168 треугольников зубов [проверено]; 370 FPS генерация выражений [проверено]; метрики побед MonoGaussianAvatar — L1/LPIPS/SSIM/PSNR лучше SOTA на смартфон-видео [проверено]; UV-генерация за секунды [проверено].arxiv+2
- Лимиты: ARKit-блендшейпы доступны там, где есть face tracking (front TrueDepth-экспериенс [проверено]); на Android нет прямого аналога спецификации 52 — нужна своя калибровка коэффициентных семантик [не проверено источником]. Плохой свет/очки/борода уводят фитинг идентичности — нужен ID-loss (по сути то, что делает UV-IDM conditioning [приближённо подтверждено]).[github](https://github.com/Luh1124/UV-IDM)

## Риски

- Лицензии: FLAME — research-лицензия («available for research purposes») [проверено]; GaussianAvatars наследуют лицензию оригинального Gaussian Splatting (Inria), GUI инспирирован INSTA, меш-рендер из NVDiffRast [проверено] → заложить юристов или свой каркас.
- Монокулярность обучения: все цитируемые методы тренируются на портретных монокулярных видео [проверено] — closed зоны (затылок, подбородок снизу) добавляются догенерацией [экспертная оценка].[arxiv](https://arxiv.org/html/2312.04558v1)
- Uncanny valley концентрирован в глазах/зубах/рте — это прямой повод SOTA делать их отдельными субмоделями [проверено].
- Ре-энактментно-генеративные текстурные методы могут терять идентичность под чужим motion — проблема признана и работами именно для этого предназначены системы типа IFaceUV [проверено].[arxiv](https://arxiv.org/html/2306.04957v1)

## Итоговый стек для команды

1. Каркас: FLAME-фитинг по монокулярному видео (RealDenseFace-подход ).
2. Аппиранс: гауссианы, привязанные к FLAME , с иерархией и confidence по DEGA ; fallback — identity-conditioned UV.[github](https://github.com/Luh1124/UV-IDM)
3. Части: глаза — артикулированные яблоки ; зубы — 168 треугольников ; рот — отдельная субмодель .
4. Анимация: ARKit `blendShapes` (52 коэффициента) → линейный блендинг гауссиановых блендшейпов либо FLAME-параметры с fine-tune.arxiv+1
