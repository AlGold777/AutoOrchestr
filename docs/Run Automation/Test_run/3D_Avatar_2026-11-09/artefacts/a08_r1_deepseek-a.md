**Ключевая идея:** анатомически правдоподобное движение на телефоне достигается не одной «умной» моделью, а **конвейером ограничений**: анатомические лимиты суставов фильтруют вход, IK с контактом стоп фиксирует опору, ретаргетинг с масштабированием цепочек сохраняет пропорции, а упрощённый контроль центра масс не даёт персонажу «падать». Захват с камеры телефона в реальном времени пока уступает лабораторному, но для аватара достаточно приближения с биомеханическими ограничениями; точный биомеханический анализ — офлайн или в облаке.

Все утверждения помечены: **[П]** — проверено по источнику, **[НП]** — не проверено по первоисточнику; цифры из исследований не равны мобильным гарантиям.

## Диапазоны суставов

Анатомические лимиты — самый дешёвый и обязательный слой. Ориентиры: плечо — сгибание **0–170/180°**, разгибание **0–67°**, отведение **0–180°**; локоть — сгибание **0–140/150°**; бедро — сгибание **0–120/125°**, разгибание **0–20°**, отведение **0–40°**; колено — сгибание **0–140/150°** [П: 6†L4-L30]. Это не жёсткие «истины», а клинические диапазоны; для аватара их лучше задавать как soft-constraints, а не как абсолютные стопы, иначе позы станут деревянными. SMPL-X сам по себе не содержит клинических лимитов: его pose-пространство — это axis-angle на сустав, а не анатомические границы [П: 0†L6-L9; 12†L11-L15]. Поэтому constraint-фильтр нужно строить поверх модели, а не ждать его «из коробки».

## Центр масс и равновесие

Равновесие — это не покадровая физика, а **проверка, что проекция центра масс (CoM) лежит внутри базы опоры** (полигона, образованного стопами) [П: 1†L36-L40]. IPMAN вводит дифференцируемые биомеханические сигналы — CoM и центр давления — чтобы получать устойчивые и «заземлённые» статические позы [П: 1†L24-L26]. Momentum control для real-time персонажа отслеживает движение и реагирует на возмущения, изменяя CoM и центр давления [П: 1†L12-L18]. На телефоне полноценная динамика избыточна; практичный минимум — **проверять CoM при генерации позы и мягко корректировать таз/стопы**, а не симулировать падения.

## Контакт стоп

Foot skating — главный визуальный артефакт ретаргетинга. Решение: **IK с целевой точкой стопы**, полученной ray-casting от стопы к земле; как только точка контакта найдена, она становится IK-ключом для ноги [П: 2†L12-L17]. `Feet Contact Stiffness` управляет компромиссом: 1.0 сохраняет трансформации стопы и не вращает голеностоп, 0.0 вращает голеностоп, чтобы минимизировать проникновение в пол [П: 2†L23-L30]. Для мобильного достаточно: определить фазу контакта по скорости и высоте сустава, зафиксировать стопу, решить IK для колена/бедра. Это дёшево и убирает skating без физики.

## Ретаргетинг без искажения пропорций

Наивный перенос углов с источника на цель ломает пропорции и даёт foot skating, самопроникновение и неверные направления из-за разницы rest pose [П: 10†L39-L56]. Рабочие подходы: **PALUM** переносит движение между скелетами с разным числом суставов и пропорциями через part-based attention [П: 3†L26-L32]; **CAMO** вводит обучаемые длины костей, чтобы скелет мог растягиваться/сжиматься под пропорции субъекта [П: 3†L20-L25]. Для real-time на телефоне практичнее **dynamic chain scaling**: целевые позиции конечностей пересчитываются по отношениям длин сегментов, что снижает foot skating и самопроникновение [П: 10†L23-L25]. Ключевое правило: **сохраняйте углы, масштабируйте позиции**, а не наоборот.

## Захват движения камерой телефона с биомеханическими ограничениями

**OpenCap Monocular** — наиболее прямой ориентир: одно статичное видео смартфона → WHAM/ViTPose → **физически ограниченная оптимизация** → OpenSim IK → 3D-кинематика и динамика. Ошибка: **4.8° MAE** по вращениям и **3.4 см** по трансляции таза, что на **48%** лучше чисто регрессионного CV-базлайна по вращению [П: 8†L28-L32; 13†L33-L42]. Для колена при ходьбе сообщается **RMSE 6.1°** [П: 13†L9-L11]. Но это **не реальное время на устройстве**: пайплайн включает оптимизацию и OpenSim, то есть офлайн/облако. **MobilePoser** даёт real-time позу и глобальную трансляцию с IMU телефона/часов/наушников и физический оптимизатор, но это инерциальные датчики, а не камера [П: 9†L11-L23]. Для чистой камеры в реальном времени на телефоне доступны облегчённые модели позы (MediaPipe и аналоги), но они дают keypoints без мышечных сил и контактной механики [П: 15†L20-L23]. Компромисс для продукта: **камера для локальной позы + constraint-фильтр + IK с контактом стоп**, а глобальную трансляцию и биомеханически точные моменты — офлайн или с IMU.

## Рекомендация

1. **Ограничения суставов:** soft-constraints по клиническим диапазонам; не «зажимать» до лабораторных лимитов.
2. **Контакт стоп:** phase detection + IK; фиксировать стопу на земле, решать ногу от бедра.
3. **Ретаргетинг:** dynamic chain scaling по отношениям длин; сохранять углы, масштабировать позиции.
4. **Равновесие:** проверять CoM в базе опоры на этапе генерации позы; мягко править таз.
5. **Захват:** для MVP — камера + облегчённая поза + фильтр ограничений; для качества — офлайн OpenCap-подобный пайплайн; для real-time глобальной трансляции — IMU как дополнение.

## Числа и ограничения

- **OpenCap Monocular:** 4.8° MAE вращения, 3.4 см MAE таза; +48% к CV-базлайну [П: 8†L28-L32; 13†L39-L42].
- **Колено (OpenCap):** RMSE 6.1°, ICC 0.67 [П: 13†L9-L11].
- **Real-time бюджет:** суб-16.6 мс на кадр для 60 FPS [П: 15†L23-L24].
- **MobilePoser:** real-time с IMU, но не камера [П: 9†L11-L23].
- **Диапазоны суставов:** плечо 0–180° сгибание, локоть 0–140/150°, бедро 0–125°, колено 0–150° [П: 6†L4-L30].

Эти цифры — из разных условий; мобильные бюджеты (мс/кадр, память, тепло) измеряйте на целевых устройствах.

## Риски

- **Монокулярная неоднозначность:** глубина и скручивание в поперечной плоскости по одному видео ненадёжны; ошибки >10° возможны [П: 4†L29-L35].
- **Foot skating при ретаргетинге:** без dynamic scaling и IK стопы аватар будет «скользить».
- **Слишком жёсткие лимиты:** анатомические диапазоны могут ломать естественные движения; нужны soft-constraints.
- **Вычислительная стоимость:** OpenCap-подобная оптимизация не укладывается в real-time на телефоне; для кадра — только облегчённые модели.
- **Потеря баланса:** без проверки CoM аватар может визуально «падать» даже при корректных углах.

**Итог:** для мобильного MVP — ограничения суставов + IK контакта стоп + dynamic chain scaling + упрощённый CoM-контроль; захват с камеры — облегчённая поза с фильтрацией, а биомеханически точный анализ — офлайн. Это даёт правдоподобное движение без нереалистичных обещаний лабораторной точности в кадре.
