Разбор вариантов захвата для мобильного 3D-аватараЗадача — получить анимируемый фотореалистичный аватар по съёмке телефоном. Ключевой компромисс: простота захвата vs. геометрическая достоверность. Ниже — разбор четырёх вариантов, рекомендация, инструкции и проверки качества, числа и риски.1. Одно фотоСуть: одна фронтальная фотография, 3D-геометрия «достраивается» генеративной моделью (диффузией или параметрической моделью лица вроде FLAME/SMPL-X).-1Плюсы: минимальный трение для пользователя (3–5 минут на всё); не требует специальных условий; работает на любом телефоне.-49Минусы: фундаментально ограничено. Восстановление полной 3D-информации из одной точки обзора — «значительная проблема» computer vision. Невидимые области (затылок, бока, часто уши) получаются «чрезмерно гладкими» с размытыми текстурами. Лицо на полноростовом снимке занимает около 80×80 пикселей из 512×512, что даёт недостаточно деталей и неконсистентность идентичности. Генеративные модели могут давать артефакты и «усреднённое» лицо, особенно при аксессуарах или сложных причёсках.-1-2-Вывод: допустимо как fallback или для стилизованных аватаров, но не как основной путь для «реалистичного и похожего» продукта.2. Несколько фото (фотограмметрия)Суть: 50–300 снимков с перекрытием вокруг головы/лица, восстановление через фотограмметрию (RealityKit Object Capture, Agisoft Metashape, Meshroom и др.).-97-102Числа и точность: исследования смартфонной фотограмметрии лица дают среднее отклонение 0,22 ± 1,29 мм для фото. Для надёжного покрытия обычно требуется 50+ фото, а оптимум по точности/времени — около 90 снимков. В одном из продакшн-пайплайнов захват ведётся с частотой 1 Гц при разрешении 3024×4032, всего 105 изображений за проход — это сочтено лучшим компромиссом.-10-11-Плюсы: существенно более высокая геометрическая точность и детализация текстуры, чем у видео, поскольку отдельные фото меньше страдают от motion blur и межкадровой компрессии. Фотограмметрия с фото превосходит видеограмметрию по точности (0,22 мм против 0,47 мм).-10-11Минусы: требует от пользователя дисциплины — держать телефон, обходить объект, сохранять перекрытие. Без визуальных подсказок пользователи ошибаются с дистанцией и ориентацией камеры. Время захвата и обработки заметно выше, чем у одного фото.-10Вывод: сильный вариант для качества, но нужен guided-режим с оверлеем силуэта и подсказками движения — иначе качество «плывёт» от пользователя к пользователю.-103. Видео облётаСуть: короткое видео (5–15 секунд) с поворотом головы/обходом, из которого извлекаются кадры для реконструкции.Числа: минимальные требования к видео для аватаров — обычно 1080p и 25–30 fps; 4K даёт больше деталей, но увеличивает файлы и нагрузку. Некоторые пайплайны требуют 60 fps и синхронизированных камер для качественного захвата движения.-55-56-58Плюсы: проще для пользователя, чем серия фото; можно захватить динамику/мимику; короткое видео (1–2 минуты) достаточно для персонализированного волюметрического аватара головы в некоторых методах.-65Минусы: смартфонное видео сжимается H.264/H.265 с агрессивной межкадровой компрессией; блочные артефакты негативно влияют на фотограмметрические признаки и качество облака точек. Извлечённые кадры страдают от motion blur. Точность видеограмметрии ниже, чем у фото (0,47 мм против 0,22 мм). Для анимации всё равно нужна чистая нейтральная геометрия, поэтому видео-путь часто требует дополнительной стабилизации и отбора кадров.-10-11Вывод: лучший баланс «простота для пользователя / приемлемое качество», если приложение умеет отбирать резкие кадры и компенсировать компрессию. Но для максимальной реалистичности проигрывает фотограмметрии по фото.4. LiDAR / TrueDepthTrueDepth (Face ID): инфракрасная структурированная подсветка, диапазон 0,3–1 м, оптимизирован для лица. Точность в исследованиях: RMS 0,86 ± 0,31 мм (iPhone/Bellus3D); по другому исследованию — 1,1 мм отклонения ориентиров. Это миллиметровый уровень, пригодный для реалистичного лица.-20-71-73LiDAR (задний сканер): time-of-flight, диапазон до ~5 м, но потребительская точность — сантиметровая: RMSE 1–10 см в зависимости от приложения и объекта. Для лица LiDAR менее пригоден, чем TrueDepth: у него ниже разрешение и он не оптимизирован для коротких дистанций. Практически TrueDepth даёт примерно 0,5 мм точности на лице, тогда как LiDAR — сантиметры.-20-75-Плюсы: TrueDepth даёт готовую метрическую глубину и масштаб, не требует фотограмметрической реконструкции для глубинной компоненты; работает в темноте (IR). LiDAR полезен для масштаба и грубой геометрии головы/плеч, но не для деталей лица.-20Минусы: только Apple (TrueDepth — Face ID-устройства; LiDAR — iPhone Pro/iPad Pro). ARKit Face Mesh покрывает только лицо, но не полную форму головы; для полной головы всё равно нужна экстраполяция (например, FLAME). Mesh ARKit может «плавать» при поворотах — вершины смещаются до сантиметра. Android-устройства в массе не имеют сопоставимого структурированного depth-сенсора для лица.-16-20-37Вывод: TrueDepth — лучший сенсорный источник для лица на iOS, но он не кросс-платформенный и не покрывает полную голову. LiDAR — вспомогательный инструмент для масштаба, не для лица.РекомендацияГибридная стратегия с единым пользовательским сценарием «видео-облёт + проверки качества», где глубина и геометрия добираются по возможностям устройства:Базовый кросс-платформенный путь (iOS + Android): короткое видео облёта лица/головы (10–15 с, 1080p/30fps минимум), из которого приложение извлекает 20–40 резких кадров с достаточным перекрытием. Это даёт фотограмметрическое ядро с точностью порядка 0,5 мм (видеограмметрия).-11iOS-путь с TrueDepth: то же видео + синхронный depth-поток TrueDepth. Глубина используется для масштаба и стартовой геометрии, а кадры — для текстуры и деталей. Это поднимает точность лица до субмиллиметрового/миллиметрового уровня.-73Fallback: если пользователь не может/не хочет снимать видео — 3–5 фото (фронт + 45° влево/вправо) или одно фото с генеративной реконструкцией, но с явным предупреждением о сниженной реалистичности и «достроенных» зонах.-49Почему не фотограмметрия по 50+ фото как основной путь: слишком высокое трение и время. Почему не одно фото: не соответствует требованию «реалистичный и похожий». Видео-облёт с guided-захватом — лучший компромисс для массового продукта.Инструкции и проверки качества кадраИнструкции пользователю (до и во время съёмки):Освещение: рассеянное, мягкое, спереди; без жёстких теней и пересветов; избегать контрового света.-44-48Фон: однотонный, контрастный к коже/волосам; без объектов, перекрывающих голову.-47Положение: камера на уровне глаз; нейтральное выражение; волосы убраны со лба; для фото — лёгкий нижний угол, чтобы захватить подбородок.-44-46Движение: пользователь остаётся максимально неподвижным; движется камера, а не человек — иначе смаз и потеря точности.-99Дистанция: не слишком близко (обрезка ушей/подбородка) и не слишком далеко (потеря разрешения); guided-оверлей силуэта решает эту проблему.-10Автоматические проверки в приложении:Детекция лица и количества лиц: ровно одно лицо в кадре.-110Резкость / motion blur: покадровая оценка; отбраковка смазанных кадров.-110Экспозиция и равномерность освещения: гистограммный анализ; флаг при недо-/пересвете.-110Окклюзии: проверка перекрытия глаз, рта, контура лица волосами/руками/аксессуарами.-113Поза головы (yaw/pitch/roll): достаточный диапазон поворотов для покрытия боков, но без экстремальных ракурсов.-114Дистанция: лицо не слишком близко/далеко — проверка размера bounding box.-110Apple Vision Face Capture Quality (iOS): интегральная метрика, учитывающая освещение, размытие, окклюзию, экспрессию, позу и фокус — удобна как единый порог качества.-107Ключевые числа и ограничения (сводка)ПараметрЗначениеИсточникТочность фотограмметрии по фото0,22 ± 1,29 мм-11Точность видеограмметрии0,47 ± 1,43 мм-11TrueDepth, RMS по лицу0,86 ± 0,31 мм-73LiDAR, точность~1–10 см (потребительский)-79Оптимальное число фото для головы~90 (диапазон 50–300)-98Разрешение в продакшн-пайплайне3024×4032, ~105 кадров-10Минимальное видео для аватара1080p, 25–30 fps-58РискиАртефакты генеративных моделей: одно фото и «достройка» невидимых зон могут дать непохожесть или «пластиковую» кожу. Кросс-платформенный продукт должен иметь фотограмметрический fallback и не обещать одинаковое качество на всех устройствах.-20-37Конфиденциальность: биометрические данные (3D-скан лица) — чувствительная категория. Нужна явная политика: обработка на устройстве, шифрование, удаление сырых данных после сборки аватара.Производительность анимации: для real-time на мобильном аватара нужны облегчённые меши и blendshapes (ARKit-совместимые, ~52 blendshape), иначе рендеринг не уложится в бюджет кадра.-93Итог: строить захват вокруг видео-облёта с guided-интерфейсом и жёсткими проверками качества, использовать TrueDepth на iOS как ускоритель точности, а фотограмметрию по фото — как fallback для качества. Одно фото — только для стилизованных/быстрых сценариев, не для «реалистичного» ядра продукта.
