**Ключевая идея:** анатомическую достоверность нельзя проверять одной метрикой «похоже/не похоже». Нужен **многоуровневый валидатор**: инварианты скелета (длины костей, пропорции), объём и форма сегментов, диапазоны суставов, взаимопроникновения, качество мышц/кожи — и всё это на **наборе тестовых поз**, а не на одной нейтральной. Пороги приёмки должны быть калиброваны по эталонным данным и по допускам продукта; выдумывать «универсальные» числа нельзя.

В этом ответе я не сверял утверждения с первоисточниками, поэтому конкретные модели, датасеты и цифры помечены **[НП]** — их нужно проверить команде перед фиксацией в спецификации.

## Что проверять

**1. Длины костей и пропорции.**  
Для каждого сегмента (плечо–локоть, локоть–запястье, бедро–колено, колено–стопа, ключица, позвоночные сегменты) проверяйте длину и отношения: например, отношение длины предплечья к плечу, бедра к голени, размах рук к росту. Это ловит «усреднение» и ошибки ретаргетинга. Эталон — антропометрические датасеты (CAESAR, ANSUR II) [НП]. Но для конкретного пользователя важнее **согласованность с его съёмкой**, чем попадание в среднее: сравнивайте длины костей, оценённые по видео, с длинами в финальном риге; расхождение — ошибка пайплайна.

**2. Объём и форма сегментов.**  
Объём меша считается через теорему о дивергенции по замкнутой поверхности; для каждого сегмента (грудь, живот, таз, бёдра, плечи) сравнивайте объём и характерные обхваты с оценкой по съёмке. Это ловит «схлопывание» при LBS и потерю массы. Отдельно проверяйте **сохранение объёма при сгибании**: объём согнутой конечности не должен падать скачкообразно.

**3. Диапазоны суставов.**  
Проверяйте углы на тестовых позах против клинических диапазонов: плечо — сгибание до ~180°, локоть — сгибание ~140–150°, бедро — сгибание ~120–125°, колено — ~140–150° [НП; цифры требуют сверки с клинической литературой]. Это не жёсткие стопы, а **soft-constraints**: валидатор должен сигнализировать о выходе за диапазон, а не обязательно блокировать. Для позвоночника проверяйте распределение изгиба по сегментам, а не только общий наклон.

**4. Взаимопроникновения.**  
Два класса: тело–тело (рука–торс, бедро–бедро, подбородок–грудь) и тело–одежда. Для меша — BVH/точечные тесты и signed distance; для SDF/неявных представлений — знак расстояния. Валидатор должен считать **число проникающих пар, глубину и площадь** на каждой тестовой позе. Порог «ноль» нереалистичен для мягких тканей; нужен допуск, откалиброванный по эталону.

**5. Форма мышц и кожи.**  
Для мышц — сравнение с анатомическим шаблоном или с эталонной деформацией: curvature reconstruction error (CRE) на основе Laplace–Beltrami чувствительнее к локальным искажениям, чем RMSE [НП]. Для кожи — проверка растяжения UV (площадь треугольника до/после деформации), чтобы поры и складки не «плыли». Для складок — сравнение с тестовыми позами, где складки ожидаемы (локоть, колено, пах).

## Эталонные данные

Нужны три уровня: (1) **антропометрические таблицы** для пропорций и диапазонов [НП: CAESAR, ANSUR II]; (2) **сканы/меши** для формы и объёма — например, BEDLAM как синтетика с разнообразием тел [НП], VALID как набор риггованных аватаров [НП]; (3) **собственный «золотой набор»** — 20–30 реальных пользователей с ручной проверкой анатомом/художником. Без третьего уровня автоматические метрики будут проверять соответствие модели, а не человека.

## Тестовые позы

Минимальный набор: нейтральная стойка; руки вверх; сгибание локтя 90° и максимум; сгибание/разгибание запястья; приседание; сгибание колена 90° и максимум; наклон/скручивание позвоночника; поворот головы; подъём бедра; скрещивание рук; контакт руки с торсом; контакт бедра с бедром. Для каждой позы — проверка всех метрик. Позы должны включать **экстремальные** комбинации, потому что артефакты LBS/DQS проявляются именно там.

## Автоматические проверки в конвейере

Валидатор — отдельный сервис/модуль, который запускается на каждом аватаре после генерации и на каждой тестовой позе. Выход — отчёт: метрика, значение, порог, pass/fail, визуальный diff. Встройте его в CI: аватар не попадает в прод, если отчёт красный. Для регрессий — храните baseline и сравнивайте новые версии пайплайна. Это дешевле, чем ручной просмотр каждого аватара.

## Пороги приёмки

Не фиксируйте «универсальные» числа до калибровки. Рабочая схема: (1) соберите распределение метрик на «золотом наборе»; (2) выберите порог по худшему приемлемому аватару, а не по среднему; (3) для каждой метрики задайте **два порога** — warning и fail; (4) пересматривайте после каждого изменения пайплайна. Примеры метрик, для которых нужны пороги: относительное расхождение длин костей, % потери объёма при сгибании, число проникающих пар, максимальная глубина проникновения, CRE, растяжение UV. Конкретные значения — только после калибровки [НП].

## Рекомендация

1. **Скелет:** инварианты длин и пропорций; сравнение с оценкой по съёмке.
2. **Объём:** дивергенция + обхваты; проверка сохранения при сгибании.
3. **Суставы:** soft-constraints по клиническим диапазонам; отчёт о выходе.
4. **Проникновения:** BVH/SDF; число пар, глубина, площадь.
5. **Мышцы/кожа:** CRE + UV-растяжение; визуальный diff на тестовых позах.
6. **Конвейер:** валидатор в CI, baseline, warning/fail, «золотой набор» с ручной разметкой.

## Числа и ограничения

Конкретные цифры в этом ответе не приводятся как проверенные: клинические диапазоны, антропометрические отношения и пороги CRE/UV требуют сверки с источниками [НП]. Ограничения: метрики чувствительны к топологии и масштабу; синтетические эталоны не заменяют реальные сканы; автоматический валидатор не заменяет художественную приёмку, а дополняет её.

## Риски

- **Ложное чувство безопасности:** прохождение метрик не гарантирует визуальную достоверность; нужен ручной просмотр.
- **Переобучение на эталон:** пороги, подогнанные под «золотой набор», могут не обобщаться.
- **Стоимость:** полный валидатор на каждой позе может быть дорогим; запускайте на подмножестве в CI и полностью — перед релизом.
- **Спорные пороги:** слишком строгие ломают естественные позы, слишком мягкие пропускают артефакты.
- **Отсутствие эталона для редких телосложений:** без данных валидатор будет слеп в этих зонах [НП].

**Итог:** стройте валидатор как продуктовый компонент: инварианты скелета, объём, суставы, проникновения, мышцы/кожа — на тестовых позах, с baseline и двумя порогами. Числа калибруйте по эталонам и «золотому набору», а не выдумывайте.
