**Короткий ответ:** для продукта «реалистичный, анимированный, real-time аватар с телефона» оптимальна видеозапись-облёт (или короткое видео головы с поворотами) как основной путь, TrueDepth на iOS как усилитель качества лица, а одно фото — только как деградированный быстрый режим. LiDAR даёт мало для лица, мультифото — рабочий альтернативный путь для Android.

## Варианты захвата

| Режим | Что даёт | Ограничения | Статус данных |

| Одно фото | Быстрый аватар; исследования показывают фотореалистичные аватары из одного кадра через генеративный prior (GASP, CVPR 2025) | Затылок/профили «выдумываются» моделью; ~70–80% точности по оценкам практиков | Проверено: GASP существует и работает от одного изображения или короткого видео [openaccess.thecvf](https://openaccess.thecvf.com/content/CVPR2025/papers/Saunders_GASP_Gaussian_Avatars_with_Synthetic_Priors_CVPR_2025_paper.pdf); цифра 70–80% — из маркетинговой статьи, не из научного источника [3daistudio](https://www.3daistudio.com/3d-generator-ai-comparison-alternatives-guide/single-vs-multiple-photos-for-3d) |
| 3–8 фото с ракурсов | Точность ~90–95% (оценка практиков), 2–5 мин съёмки | Пользователь ошибается с ракурсами; нет перекрытия — нет реконструкции | Цифры — из недостоверного по уровню источника, использовать как прикидку, не как факт [3daistudio](https://www.3daistudio.com/3d-generator-ai-comparison-alternatives-guide/single-vs-multiple-photos-for-3d) |

| TrueDepth (iOS, фронталка) | Структурированный свет, >30 000 ИК-точек, глубина лица в реальном времени; ARKit отслеживает 52 blendshape-движения на меше из 1220 точек при 60 fps | Только ближняя дистанция (~лицо), только устройства с Face ID | Проверено по документации Apple и статьям developer.apple+2 |
| LiDAR (iPhone Pro, тыл) | ToF-глубина сцены, карта достоверности глубины в ARKit | Не оптимизирован для лица: Face ID его не использует; точность на короткой дистанции хуже TrueDepth | Проверено developer.apple+1 |
| ARCore Depth (Android) | Depth API поддерживают >88% активных устройств (по данным Google на май 2026); Raw Depth подходит для 3D-реконструкции | На большинстве устройств — программная глубина, не аппаратный ToF; качество сильно разнится | Проверено developers.google+1 |

## Рекомендация

Main flow: **короткое видео (10–20 секунд) поворота головы перед фронтальной камерой** с подсказками-гайдами на экране, на iOS параллельно писать глубину TrueDepth. Это подтверждённый индустрией паттерн: MetaHuman Animator строит идентичность из трёх кадров видео плюс глубины iPhone, при этом рекомендует 60 fps и максимальное разрешение. Исследовательски GASP показывает фотореалистичный анимированный аватар из короткого видео со смартфона в реальном времени.openaccess.thecvf+2

Fallback-иерархия:

- iOS с Face ID: видео + TrueDepth-глубина.
- Android: видео облёт фронталкой; если ARCore Depth доступен — использовать Raw Depth для валидации геометрии.[developers.google](https://developers.google.com/ar/develop/c/depth/raw-depth)
- Любое устройство, плохие условия: режим «5–8 фото по кольцу» с автопроверкой ракурсов.
- Одно фото: только «мгновенный аватар-черновик» как воронка вовлечения, с предложением досканировать позже.

LiDAR не включать в основной путь для лица: он даёт сцену, а не черты лица. Можно оставить как опцию для скана тела/окружения на Pro-моделях (ARKit scene reconstruction через LiDAR — подтверждено ).lidarnews+1

## Числа и ограничения

- Кадры и перекрытие: 60–70% перекрытия соседних кадров, 60–100 кадров на полный облёт объекта. Для головы в видео при 30–60 fps — держать голову в кадре и поворачивать на ~10–15° между ключевыми позами (это экспертная прикидка из правила перекрытия, не прямая цитата).[3dprinting](https://3dprinting.com/scanners/3d-scanning-with-your-phone/)
- Данные: запись TrueDepth-видео на iPhone по дефолту MetaHuman — ~170 МБ/мин (720p, 60 fps). На телефоне длинную сессию не держать: облачная реконструкция (пример — KIRI Engine, до 200 фото на сервер ) или он-девайс сплаттинг; Instant Skinned Gaussian Avatars заявляют ~5 минут весь пайплайн и ~30 сек генерация аватара на смартфоне — источник не верифицирован, проверить бенчмарком.epicgames+2
- Лицевая анимация: ARKit — 52 blendshape-коэффициента, меш 1220 точек, 60 fps. Для Android-паритета нужен MediaPipe Face Mesh или аналог (не проверено в этой сессии — валидируйте отдельно).[sidekickinteractive](https://www.sidekickinteractive.com/uncategorized/apples-arkit-for-scanning-and-tracking-faces/)
- Точность SfM со смартфонов в ближней зоне — сантиметровый уровень независимо от модели телефона (рецензируемое исследование MDPI Sensors); для аватара «похожести» критичнее текстур и выражений, чем миллиметры.[mdpi](https://www.mdpi.com/1424-8220/24/22/7311)
- Покрытие устройств: Depth API ARCore >88% активных устройств; но реальный realtime-трекинг лица на Android ограничен чипсетами — Epic перечисляет конкретные Snapdragon 8-го поколения и Tensor G3+. Т.е. «широкая поддержка глубины» ≠ «широкая поддержка качественного фейстрекинга».developers.google+1

## Инструкции пользователю и проверки качества кадра

Инструкции в UI (во время съёмки):

1. Мягкий рассеянный свет, без контрового света и жёстких теней.
2. Снять очки и головной убор, убрать волосы от лица (предлагать, не блокировать).
3. Держать телефон на уровне глаз, расстояние 30–50 см (прикидка по рабочей дистанции TrueDepth; точное число — не проверено).
4. Медленно повернуть голову влево → вправо → вверх/вниз по нарисованной траектории; не двигать телефоном.
5. Нейтральное выражение лица на скане; эмоции — отдельная короткая сессия для blendshape-калибровки.

Автоматические проверки (гейтинг, до генерации):

- Резкость (дисперсия Лапласиана) и экспозиция: Epic прямо указывает, что важнейший атрибут кадра — резкость.[epicgames](https://dev.epicgames.com/documentation/metahuman/capture-device-requirements?lang=en-US)
- Покрытие ракурсов: трекинг позы головы (ARKit/Vision, MediaPipe) и проверка, что набрано ≥ N поз (например, ±30° по yaw, ±15° по pitch — значения для MVP, не из источника).
- Confidence-карта глубины TrueDepth/LiDAR: фильтровать низкодостоверные пиксели — это стандартный механизм ARKit.[developer.apple](https://developer.apple.com/documentation/arkit/ardepthdata)
- Детекция лица в кадре на 100% кадров записи; если лицо теряется — переснять фрагмент, а не всё видео.
- Проверка движения на смаз (rolling shutter/дрожание) через оптический поток между соседними кадрами (требование выведено из правила перекрытия SfM).

## Риски

- Похожесть с одного фото ломается в профиле и затылке: prior «дорисует» несуществующие черты. Митигация: показывать пользователю дисклеймер и кнопку апгрейда до видео-режима.[openaccess.thecvf](https://openaccess.thecvf.com/content/CVPR2025/papers/Saunders_GASP_Gaussian_Avatars_with_Synthetic_Priors_CVPR_2025_paper.pdf)
- Разброс Android-железа: «заявлен Depth API» не гарантирует качества; Epic поддерживает realtime-трекинг только на ограниченном белом списке чипсетов. Планируйте feature-detection в рантайме, а не по модели устройства.[epicgames](https://dev.epicgames.com/documentation/metahuman/capture-device-requirements?lang=en-US)
- Приватность и биометрия: глубина лица — чувствительные данные; хранение сырого скана на сервере увеличивает регуляторные риски (общий вывод, нормативные детали не проверялись в этой сессии).
- Стоимость облачной обработки одного аватара и её latency — не проверено; типовая обработка сплаттинга минуты, не секунды, поэтому «реальное время» в продукте относится к анимации/рендеру, а не к генерации.[gaussian-vrm](https://gaussian-vrm.github.io/)
- Дети, очки, борода, головные уборы — классические точки отказа детектора лица; нужны ручные сценарии восстановления.

Итог: видео + TrueDepth на iOS как золотой путь, мультифото как Android-fallback, одно фото как фича вовлечения с явным дисклеймером; LiDAR — вне основного пайплайна лица.
