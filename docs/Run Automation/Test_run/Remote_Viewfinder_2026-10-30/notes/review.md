# Ревью прогона «Remote Viewfinder» (Basic), 2026-10-30

Версии расширения за день: 2.81.932 → 2.81.941. Прогон-образец: `exports/Basic_2026-10-30_08-08_run-2.81.937.json` (завершён, итог 15552 символа). Второй прогон на 2.81.940 (`…09-00…`) остановлен вручную и шёл по схеме с моей ошибкой (см. A1). Ревью сделали пять направлений: интерфейс, логика и запрос к моделям, транспорт, качество итогового документа, процесс. Каждая находка ниже со ссылкой на её направление; полные отчёты — в журнале сессии, ключевые доказательства — в экспортах рядом.

Приоритеты: **P0** — блокирует работу, чинить первым; **P1** — мешает, чинить следом; **P2** — позже.

## Итог по сути

- Результат получен: архитектура связная, все требования владельца имеют решение и раздел. Готовность к передаче в разработку — **4 из 10** (нет каталога протокола, полной модели состояний, числовых критериев приёмки, решения по пути кадров на Android).
- Процесс получения документа окупился в основном на шагах r1 (три варианта), r2 (свод), r3 GPT-аудит (21 замечание, принято ~14 полностью, ~7 частично), r4. Perplexity в r3 не дал вклада: приёмка приняла эхо задания и мусор страницы как ответ.
- Главные риски системы: **завершение ответа определяется слабыми признаками** (тишина, Stop на EN, DOM-классы), **приёмка пропускает мусор**, **окна без таймера и с опасными кнопками**.
- Моя ошибка: личные `task` участников, добавленные в схему ради подсказок, заменяют общее задание шага целиком. Исправлено в схеме (`schema/remote-viewfinder.schema.json`) и в запросе для моделей.

## D. Итоговый документ (качество)

Критично: противоречие §10 и §6 по смене камеры при записи; путь кадров Android → WebRTC не описан; безопасность QR («первый сфотографировавший вытесняет B»); потеря до 10 мин записи при аварийном завершении; таблицы слиплись. Потеряно без обоснования относительно вариантов: лимит зума 10/с, лестница деградации, запрет B-кадров, NACK/PLI/FEC, таймер ICE. Для следующей версии вернуть журнал отклонений замечаний (в r5 удалён).

Высокорисковые технические утверждения (не проверены): libwebrtc без STUN/TURN и mDNS-обфускация; одновременные аппаратные энкодеры 720p30 и 1080p30; комбинации CameraX Preview + VideoCapture; общий VideoDataOutput для WebRTC и AVAssetWriter; камера в фоне на iOS и Android 14+; iOS Local Network; изоляция клиентов в hotspot; self-signed TLS и пиннинг на локальной сети; краш-безопасность MP4.

### Вопросы владельцу продукта (с вариантами)

1. Смена камеры при записи: разрыв 0,5–1,5 с и несколько файлов / запрещено во время записи / сначала ручной стоп.
2. Допустимая потеря записи при аварийном завершении: до 10 мин / не более ~1 с (фрагментированная запись).
3. Подтверждение B на A: «Разрешить» / модель устройства B / код сверки на обоих экранах.
4. Минимальные версии: iOS 16+/17+/18+; Android minSdk и target.
5. Файл записи: только хранилище A / экспорт в «Фото»/галерею.
6. Hotspot: ручное подключение / параметры сети в QR.
7. Приёмка задержки: только 5 ГГц / 5 и 2,4 ГГц; достаточно ли 300 измерений на конфигурацию.
8. Задержка в интерфейсе: индикатор / только диагностика.
9. Ориентация записи: по моменту старта / динамическая.
