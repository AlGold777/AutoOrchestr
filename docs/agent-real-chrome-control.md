# Управление страницей расширения в обычном Chrome User’а (macOS)

Инструкция для агента Claude, которому нужно нажать кнопку или иначе проверить страницу расширения (`chrome-extension://<id>/<страница>.html`) в **обычном Chrome User’а**, а не в тестовом браузере. Способ проверен 26.10.2026 на Google Chrome 155, macOS: настоящий клик мыши по элементу страницы и изменение этого элемента на экране подтверждены снимками «до/после» при нетронутой User’ом странице.

Тестовый Chrome по CDP (`Extensions.loadUnpacked`, отдельный профиль) описан в `agent-live-chrome.md`; здесь — другой случай: страница уже открыта или должна открыться в браузере User’а, с его профилем и загруженным расширением.

## 1. Что не работает (не тратить время)

| Попытка | Результат |
|---|---|
| `Claude in Chrome` (`mcp__claude-in-chrome__*`): `navigate` на `chrome-extension://…` или `chrome://…` | Схема переписывается на `https://chrome-extension//…`, открывается страница ошибки |
| `Claude in Chrome`: переход на странице совпадающего сайта скриптом `location.href='chrome-extension://…'` | Страница открывается, но снимок, клики и JS недоступны: «Cannot attach debugger to chrome-extension:// pages» |
| Вставка страницы расширения во `<iframe>` на сайте из `web_accessible_resources` | Фрейм не появился |
| `osascript … execute javascript` в Chrome | Отказ, пока в Chrome (Вид → Разработчикам) не включено «Разрешить JavaScript из событий Apple»; настройка живёт в профиле и у User’а не закрепилась (ключ `browser.allow_javascript_apple_events` не найден ни в одном профиле) |
| Клик через `System Events`: `click at {x,y}` | Попадает в кнопку (в ответе — путь элемента), но у этой страницы состояние не меняет: эта команда нажимает элемент как `AXPress`, без событий мыши |
| `osascript` из инструмента `Bash` | Ошибка `-1719` «Функции Упрощенного доступа для osascript не разрешены» — доступ действует только для запуска из вкладки терминала приложения |
| Полный обход `entire contents` окна Chrome | Не завершился за 1 мин 44 с |

Рабочий способ — настоящие события мыши (движение, нажатие, отпускание), отправленные скриптом JXA, из вкладки терминала приложения, с проверкой снимком.

## 2. Что нужно заранее

1. Chrome запущен, расширение загружено в нём (ID расширения — на странице `chrome://extensions` у User’а; на 26.10.2026 `egfijmjjpedpikkfmfaekjbhjjjlhlgo`).
2. В «Системные настройки → Конфиденциальность и безопасность → Универсальный доступ» включён переключатель у `/usr/bin/osascript`. Включает только User, агент настройки безопасности не меняет. Если при проверке пункта 4 раздела 4 будет `-1719`, попросить User’а добавить `/usr/bin/osascript` (кнопка «+», ⇧⌘G, путь) и полностью перезапустить приложение Claude (Cmd+Q и заново).
3. `screencapture` работает без дополнительных разрешений (снимок экрана читается инструментом `Read`).
4. User **не трогает страницу**, пока идёт проверка: иначе изменение на экране нельзя приписать вашему клику. Скажите ему об этом до начала.
5. Ваши клики и активация Chrome перехватывают фокус: предупредите User’а, что окно Chrome выйдет на передний план.

## 3. Какой инструмент для чего

| Действие | Инструмент |
|---|---|
| `open -a "Google Chrome" "<адрес>"`, `screencapture`, чтение файлов, правка скриптов | `Bash` |
| Любой `osascript` (активация Chrome, проверка переднего окна и адреса вкладки, JXA-клик, чтение AX-дерева) | `mcp__terminal__run_in_terminal` — вкладка терминала приложения; результат писать в файл и читать `Bash`-ом (`cat`) или `read_terminal` |
| Просмотр снимков | `Read` на PNG |

Правила `run_in_terminal`: команда — одна строка в ASCII; длинное оформляйте скриптом в файле (`Write`) и запускайте `zsh <файл> …`; вывод перенаправляйте в файл и читайте отдельно; одну и ту же вкладку (`tab_id`) используйте повторно, пока она свободна. Каждая строка подтверждается User’ом. Долгие команды ждите через `read_terminal` с `wait_for_output_ms`; в `Bash` не используйте `sleep` длиннее нескольких секунд (блокируется).

## 4. Скрипты

Положите оба файла в одну папку (папка scratchpad сессии, путь — полный). `chrome-click.sh` находит `realclick.js` рядом с собой.

`realclick.js` — настоящий клик (движение, нажатие, отпускание) в экранных пунктах:

```js
ObjC.import('ApplicationServices');
ObjC.import('Foundation');
function post(type, x, y) {
  var ev = $.CGEventCreateMouseEvent($(), type, { x: x, y: y }, $.kCGMouseButtonLeft);
  $.CGEventPost($.kCGHIDEventTap, ev);
}
function run(argv) {
  var x = parseFloat(argv[0]), y = parseFloat(argv[1]);
  post($.kCGEventMouseMoved, x, y);
  $.NSThread.sleepForTimeInterval(0.2);
  post($.kCGEventLeftMouseDown, x, y);
  $.NSThread.sleepForTimeInterval(0.08);
  post($.kCGEventLeftMouseUp, x, y);
  return 'real click at ' + x + ',' + y;
}
```

`chrome-click.sh X Y ПРЕФИКС ЧИСЛО_КЛИКОВ` — выводит Chrome вперёд, **проверяет**, что он впереди и что активная вкладка — страница расширения, делает снимок «до», кликает ЧИСЛО_КЛИКОВ раз, после каждого клика снимает экран. `ЧИСЛО_КЛИКОВ = 0` — только снимок «до» (так получают картинку для поиска координат). Адрес вкладки ожидается с `chrome-extension://`; другой префикс задайте переменной `PAGE_URL`.

```zsh
#!/bin/zsh
# usage: chrome-click.sh X Y OUT_PREFIX COUNT
S=$(cd "$(dirname "$0")" && pwd)
X=$1; Y=$2; P=$3; N=${4:-1}
PAGE_URL=${PAGE_URL:-chrome-extension://}

guard() {
  osascript -e 'tell application "Google Chrome" to activate' -e 'delay 1'
  local f u
  f=$(osascript -e 'tell application "System Events" to get name of first process whose frontmost is true')
  u=$(osascript -e 'tell application "Google Chrome" to get URL of active tab of front window')
  if [ "$f" != "Google Chrome" ]; then echo "ABORT front=$f"; exit 1; fi
  case "$u" in "$PAGE_URL"*) ;; *) echo "ABORT url=$u"; exit 1;; esac
}

open -a "Google Chrome"
osascript -e 'delay 1'
guard
screencapture -x -R0,0,1168,743 "$P-0.png"
i=1
while [ $i -le $N ]; do
  guard
  osascript -l JavaScript "$S/realclick.js" "$X" "$Y"
  sleep 1.5
  screencapture -x -R0,0,1168,743 "$P-$i.png"
  i=$((i+1))
done
echo finished
```

Размер области `-R0,0,1168,743` — ширина и высота экрана в пунктах (на 26.10.2026 у User’а 1168×743 при снимке 2336×1486); у другого экрана подставьте его размер (`system_profiler SPDisplaysDataType | grep Resolution` даёт пиксели, делите на масштаб, обычно 2).

## 5. Пошаговая процедура

**Шаг 0. Проверка доступа** (`run_in_terminal`, вывод в файл):

```bash
osascript -e 'tell application "System Events" to tell process "Google Chrome" to get {name of window 1, position of window 1, size of window 1}'
```

Ответ `название окна, x, y, ширина, высота` — доступ есть. `-1719` — вернитесь к разделу 2, пункт 2. Дальше не идите: клики без доступа не сработают.

**Шаг 1. Открыть страницу** (`Bash`):

```bash
open -a "Google Chrome" "chrome-extension://<id>/<страница>.html"
```

Страница откроется во вкладке последнего активного окна Chrome (профиль последнего активного окна). Если у User’а несколько профилей и окон, убедитесь на снимке шага 3, что открылась нужная.

**Шаг 2. Вывести Chrome вперёд и проверить**. Это делает `chrome-click.sh` сам (`guard`): `activate`, пауза, имя переднего приложения должно быть `Google Chrome`, адрес активной вкладки — с `chrome-extension://`. При любом несовпадении скрипт печатает `ABORT front=…` или `ABORT url=…` и **ничего не кликает**. Только `activate` без `open -a` иногда оставляет вперёди приложение Claude; клик в таком случае уйдёт в окно Claude.

**Шаг 3. Снимок страницы** — запуск с нулём кликов (`run_in_terminal`):

```bash
zsh <папка>/chrome-click.sh 0 0 <папка>/snap 0 > <папка>/out.txt 2>&1; cat <папка>/out.txt
```

Откройте `<папка>/snap-0.png` через `Read`. Снимок покажет всё окно: меню Chrome, адресную строку, страницу.

**Шаг 4. Координаты элемента.** Клику нужны **экранные пункты** левого верхнего угла экрана:
- Снимок — 2336×1486 пикселей, а `Read` показывает его уменьшенным до 2000 пикселей по ширине (подпись под картинкой: «Multiply coordinates by 1.17»). Пункты = координата на показанной картинке × (1168 / 2000) = × 0,584. Либо координата в пикселях оригинала ÷ 2.
- Берите центр элемента. Окно Chrome стоит в точке (0, 28), снимок начинается с (0, 0), поэтому пересчитанная точка уже в экранных координатах, ничего прибавлять не надо.
- Пример: на показанной картинке кнопка в точке (1030, 285) → пункты (601, 166).
- Быстрее и точнее для известного набора кнопок: прочитать координаты у системы специальных возможностей. Для группы кнопок, путь к которой известен, команда
  скрипт ниже (проверен: выполняется за доли секунды) возвращает имя, позицию (левый верхний угол) и размер каждой кнопки в экранных пунктах; центр = позиция + размер / 2. Сохраните его в файл `ax-list.applescript` и запустите `osascript ax-list.applescript` из вкладки терминала:

  ```applescript
  tell application "System Events" to tell process "Google Chrome"
  	set root to <путь к группе кнопок> of window 1
  	set out to ""
  	repeat with b in (every button of root)
  		set p to position of b
  		set s to size of b
  		set out to out & (name of b) & " | pos=" & (item 1 of p) & "," & (item 2 of p) & " | size=" & (item 1 of s) & "," & (item 2 of s) & linefeed
  	end repeat
  	return out
  end tell
  ```

  Путь вида `group 1 of group 2 of UI element "<заголовок страницы>" of scroll area 1 of …` зависит от разметки страницы и заголовка окна: найти его можно в ответе команды `System Events click at`, но та команда **нажимает** элемент, поэтому используйте её только на безопасном элементе. Полный обход всего окна (`entire contents`) слишком медленный, не применять. Состояние переключателя (выбран/не выбран) система специальных возможностей не показывает (`selected=false` у всех), оно видно только на снимке.

**Шаг 5. Клик** (`run_in_terminal`):

```bash
zsh <папка>/chrome-click.sh 601 166 <папка>/step 1 > <папка>/out.txt 2>&1; cat <папка>/out.txt
```

Получатся `step-0.png` (до) и `step-1.png` (после). Для проверки «нажать и вернуть» передайте `2`: будет `step-2.png` после второго клика.

**Шаг 6. Проверка результата.** Откройте оба снимка через `Read` и сравните видимое: цвет, подсветку, появившуюся подсказку, открывшуюся панель, изменившийся вид. Сравнение файлов `cmp` для этого не годится: в строке меню на снимке меняются часы, байты различаются всегда. Успех — видимое изменение именно этого элемента при нетронутой странице. Ответ команды `real click at …` означает только «события отправлены».

**Шаг 7. Вернуть исходное состояние** любых переключателей и настроек, которые вы меняли: повторите клик и подтвердите снимком, что страница выглядит как на `…-0.png`.

## 6. Что нажимать нельзя без явной просьбы User’а

Нажатие настоящее и действует на реальные данные и аккаунты User’а. Не нажимайте без прямого поручения: отправку и запуск (запрос уйдёт во внешние сервисы), удаление и очистку (корзины, «очистить»), скачивание и экспорт, добавление в избранное и любое сохранение данных, кнопки с неизвестным назначением. Назначение элемента устанавливайте по подсказке (наведите курсор или посмотрите подпись после клика безопасного соседа) и по исходному коду страницы (`result_new.html`, `results.js`), а не по значку. Нужно изменить состояние — возвращайте обратно (шаг 7) и называйте это в отчёте.

## 7. Типичные сбои

| Симптом | Причина и действие |
|---|---|
| `ABORT front=Claude` | Chrome не вышел вперёд. Повторите запуск (скрипт делает `open -a` и `activate`); если не помогает — свернуть окно Claude или попросить User’а кликнуть окно Chrome |
| `ABORT url=…` | Активная вкладка — не страница расширения (другая вкладка или другой профиль). Выполните шаг 1 |
| `-1719` из `osascript` | Нет доступа «Универсальный доступ». Запуск не из вкладки терминала (из `Bash` доступа нет) или `osascript` не включён: раздел 2 |
| Клик ушёл в окно Claude | Передним было приложение Claude. Проверьте переписку на случайные действия; в скрипте это исключает `guard` |
| Снимок до и после одинаков | Клик не попал в элемент (неверные координаты, пересчёт в пункты) или у элемента нет видимого состояния. Проверьте центр элемента на `…-0.png`, пересчёт ×0,584, повторите. Не объявляйте успех без видимой разницы |
| Страница другая, чем ожидалась | `open -a` открыл вкладку в окне другого профиля. Закройте лишнюю вкладку, активируйте нужное окно и повторите |
| Окно сместилось или размер другой | Координаты в пунктах привязаны к экрану, а не к странице: после изменения размера окна снимайте заново |

## 8. Что сообщать в отчёте

Что нажато (по подписи элемента), как это видно на снимках до/после, вернули ли исходное состояние, были ли промахи (клик не в Chrome и т. п.). Версию расширения указывайте из `manifest.json` проверяемого чекаута (`grep '"version"'`).

## 9. Что не проверено

- Клавиатурный ввод в поля страницы настоящими событиями (через JXA отправлялись только события мыши).
- Прокрутка страницы, перетаскивание, правая кнопка.
- Работа с несколькими мониторами и с масштабом экрана, отличным от 2.
- Поведение при нескольких окнах Chrome разных профилей.
