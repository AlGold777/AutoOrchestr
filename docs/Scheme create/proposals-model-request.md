# Предложения к запросу `basic-model-request.md`

Статус: предложения владельца мастерства схем. Сам запрос (`docs/Scheme create/basic-model-request.md`) сверяется тестами (`tests/basic-docs-refs.test.js`, `tests/basic-schema-guide.test.js`, `tests/basic-model-request.test.js`) и здесь не менялся; правку делает «Реестр проблем Basic» или ведущий и прогоняет тесты. Основание каждого предложения — данные прогонов, источник указан. Приоритет: В — высокий, С — средний, Н — низкий.

## П-1 (В). Критерии проверки распределять по проверяющим

Где: раздел 2 «Метод решения», абзац про независимость и проверку; пример схемы с проверкой.
Добавить: «Если проверяют несколько моделей, дайте каждой общий список критериев и личный приоритет (своё главное направление: факты и расчёты / ссылки и свежесть / взгляд будущего читателя). Личное `task` заменяет общее, поэтому копируйте в него общий список целиком».
Основание: пособие §14, п. 3; в комарах GPT с критерием «физика и арифметика» нашёл ошибки, которые остальные проверяющие не дали (`notes/audit-gpt-r3.md`).

## П-2 (В). Источник для каждого внешнего факта

Где: раздел 2, перечень требований к доказательствам в `task`.
Добавить: «Для утверждений о внешних фактах (платформа, стандарт, продукт) требуйте в `task` ссылку на конкретную страницу, которую модель открыла, год и статус; страница-главная сайта и общий адрес источником не считаются; если проверить не удалось — «источник не найден» или «ссылка не проверена»».
Основание: опросник комаров — 37 ссылок на 83 варианта, часть ведёт на главную страницу (`artefacts/mosquito-trap-questionnaire.md`).

## П-3 (В). Сверка последнего этапа с глаголом задачи

Где: раздел 1, после перечня `spec`.
Добавить: «Выпишите глагол результата из задачи User («получил конструкцию», «выбрал», «утвердил») и проверьте, что последний этап схемы даёт именно это, а не промежуточный документ».
Основание: схема комаров v3 заканчивалась опросником, а задача обещала конструкцию (`schema/task.txt`).

## П-4 (С). Контроль итога после правок человека

Где: раздел 3, абзац про шаг User.
Добавить: «После шага User и итоговой правки ставьте этап контроля: независимая модель сверяет итог с решениями User и ищет противоречия между разделами; документ она не переписывает, ответ читает User».
Основание: RV v2, прогон 948: итог после правок владельца никто не проверял; правки вносят противоречия (пособие §14, п. 4).

## П-5 (С). Разные линзы у авторов независимых вариантов

Где: раздел 2, про независимые предложения.
Добавить: «Независимость истории не делает варианты разными. Если нужно разнообразие, дайте каждому автору свою линзу (платформа / риски и отказы / минимальное решение) в личном `task` вместе с полным общим заданием».
Основание: RV v2 r1 (один запрос трём авторам, усреднённый свод); комары r1 (четыре направления дали четыре разных ответа, `Basic 20261030_16-13.json`).

## П-6 (С). Известные риски моделей — в запрос

Где: рядом с правилом `required`.
Добавить: «Ненадёжные для данной роли модели ставьте `required: false`. По данным прогонов: Perplexity как проверяющий (два настоящих ответа из девяти попыток), Gemini и Qwen как проверяющие не подтверждены. Автора документа и итога не делайте необязательным» (источник: пособие §13). Таблицу обновлять по мере прогонов; в запрос брать только подтверждённое.

## П-7 (С). Размер запроса

Где: раздел про `input`.
Добавить: «Ссылка на шаг вставляет ответы целиком; подавайте только нужные материалы. Длинные запросы к Claude (до 33 тыс. символов) в прогонах принимались, но один отказ отправки при 16,3–16,8 тыс. (кнопка неактивна) причиной не объяснён».
Поправка: ранняя версия пособия называла 16 тыс. порогом; данные этого не подтверждают.
Основание: прогон 948, r5 — 16776 символов, `notes/run-report.md` папки Remote_Viewfinder_v2_2026-10-30_13-48; `docs/Platform specifics/claude.md`.

## П-8 (Н). Явный разбор последствий «принято ≠ хорошо»

Где: чек-лист схемы.
Добавить пункт: «В задании проверяющего не просите короткий ответ: короткие ответы принимаются за строки прогресса и отклоняются».
Основание: GPT r3, прогон 948: ответ 36 символов принят до исправления 2.81.949.
