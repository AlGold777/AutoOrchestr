# Шаблоны заданий шагов (проверено прогонами)

Для кого: авторы схем Basic. Здесь только формулировки, которые уже шли в прогонах; у каждой — где и что показано. Подставляйте свой предмет вместо слов в угловых скобках; общие правила — [пособие](schema-craft-handbook.md), §4. Задание ставится на шаге (`task` шага); личное `task` модели заменяет его целиком (§4.1).

Оценки «сработало» — по экспортам в `docs/pipelines/*/exports/` и заметкам `notes/`; «не доказано» — не проверено прогоном.

## 1. Независимые варианты

```text
Предложи <что> по задаче User. Дай решения и для каждого — альтернативы и причину выбора: <перечень вопросов по именам>.
```
Сработало: RV v2, r1 — три модели, ответы 4,6–8,9 тыс. символов (экспорты 945–948). Недостаток: один запрос всем даёт усреднённый свод; для разнообразия — личные `task` с линзой (RV v3) — не доказано.

## 2. Свод

```text
Сведи <N> предложений в один документ «<Название v1>»: <разделы по именам>. Противоречия между предложениями реши и объясни выбор, слабые идеи отбрось.
```
Сработало: RV, Claude, 9,5–12,0 тыс. символов (937–948). Для опросника: «каждый вариант — отдельная строка вида «☐ N.M Название — … источник: URL; статус»; таблицы не используй» (комары, Gemini, 25 тыс. символов, 948). Добавка из комаров: «ссылки сохраняй только те, что даны в исследованиях».

## 3. Аудит по критериям

```text
Независимо проверь документ «<Название>» по критериям: <критерии через «;», каждый по сути>. Каждое замечание: где, что не так, как исправить, серьёзность. Дополнительно (premortem): назови <5> наиболее вероятных причин провала и укажи, какой отказ или решение в документе их не покрывает.
```
Сработало: GPT, 7,6–8,0 тыс. символов (937, 945–948). Для исследования добавьте: «ищи в интернете сам; существуют ли названные модели, открываются ли ссылки; физика и арифметика (энергобюджет, расход)» — GPT нашёл выдуманные пары этанола, расход CO₂, 404 DOI (`notes/audit-gpt-r3.md`). Не просите короткий ответ.

## 4. Правка с журналом отклонённых замечаний

```text
Примени замечания проверяющих к своему документу: принятые внеси, отклонённые перечисли в разделе «Журнал отклонённых замечаний» (замечание, причина одной фразой). Добавь разделы: матрица трассировки (требование → компонент → проверка), реестр рисков (риск, вероятность, влияние, мера), план проверки, открытые вопросы (каждый с вариантами ответа). Учти решения владельца из задачи. Верни документ «<Название v2>» целиком.
```
Сработало: Claude, 11,9–17,8 тыс. символов, 5 из 5 принято; журнал в итоге присутствовал (раздел 14, прогон 948).

## 5. Шаг человека с вопросами

```text
Прочитайте <документ>. Ответьте на вопросы из раздела «Открытые вопросы» прямо в тексте, исправьте текст или впишите, что изменить, и нажмите «Отправить».
```
Сработало: RV v2, окно утверждения прошло, ответы дошли до r5 (945). Вопросы в документе — с вариантами и рекомендацией (§7).

## 6. Итог «верни целиком»

```text
Ниже — <документ> в версии User: его правки, указания и ответы на открытые вопросы. Выполни указания, перенеси решённые вопросы в таблицу решений, убери указания из текста. Матрицу трассировки, реестр рисков, план проверки и журнал отклонённых замечаний сохрани и обнови. Верни документ «<Название>» целиком.
```
Сработало: Claude, 15,6–19,3 тыс. символов (937, 945, 946). Фразы «сохрани и обнови» и «целиком» удерживают разделы. Риск: на 948 запрос r5 (около 16,3 тыс. символов) не отправился, причина не установлена (размер или лимит аккаунта).

## 7. Исследовательский шаг с источниками

```text
Направление: <своё направление и перечень предметов>. <Адресат и его задачи>. Для каждого найденного решения одной строкой: (1) название; (2) чем отличается и для какой задачи; (3) источник года <годы>, полный URL, который ты открыл; (4) число независимых источников; (5) отзывы или данные, если есть; (6) статус «подтверждено» (≥2 независимых источника или официальная документация) или «не подтверждено». Не выдумывай ссылки и модели: нет данных — «не нашёл». Список, каждое решение с новой строки, без таблиц.
```
Сработало: комары, 948 — GPT, Gemini, DeepSeek, Perplexity (3,8–7,4 тыс. символов), направления разные, критерии повторены в каждом личном `task`. Слабость: часть ссылок вела на главную страницу — в v4 добавлено «ссылка на конкретную страницу; иначе «ссылка не проверена»». Строки без переводов строк в экспорте — потери на стороне движка (§12).

## 8. Вопросы владельцу с вариантами

```text
Открытые вопросы: <номер>. <Вопрос>. Варианты: (а) …, (б) …. Рекомендация: (а), потому что …
```
Сработало: RV v2, шесть вопросов Q1–Q6 с рекомендациями; ответы приняты как рекомендованные (`Remote_Viewfinder_v2_2026-10-30_10-31/notes/run-report.md`).

## 9. Не проверено

Шаг «Контроль итога», шаги «Выбор» и «Конструкция» (комары v4), линзы авторов (RV v3) — в схемах `mosquito-trap-v4.schema.json` и `remote-viewfinder-v3.schema.json`, прогонов не было.
