# Продуктовая часть: выбор решения

Спроектируйте процесс, который помогает выбрать подходящий вариант и понять последствия выбора. Начните с решения, которое предстоит принять User, и условий, при которых оно будет полезным.

## 1. Постановка задачи

Определите, что выбирается, для кого, в какой ситуации и на какой срок. Зафиксируйте обязательные ограничения, доступные ресурсы и приоритеты. Укажите, что будет считаться успешным выбором и кто принимает окончательное решение.

Разделите обязательные условия и предпочтения. Недопустимый вариант не должен становиться победителем за счёт достоинств по второстепенным критериям. Если отказ от изменения или сохранение текущего решения допустимы, включите их в рассмотрение.

## 2. Метод решения

Определите набор реалистичных альтернатив и общие основания сравнения. Сначала проверьте соответствие обязательным условиям, затем сопоставьте пользу, затраты, риски и компромиссы, существенные для задачи.

Смысловые сущности: альтернатива, критерий, ограничение, свидетельство, компромисс, рекомендация. Каждая оценка должна иметь основание; отсутствие сведений отмечайте как неизвестность. Не заменяйте неизвестность нулевой оценкой.

Используйте численные оценки и веса только тогда, когда их смысл и происхождение можно объяснить. Если предпочтения User не заданы, покажите, как выбор зависит от них. Проверьте, сохраняется ли рекомендация при правдоподобном изменении ключевых допущений.

## 3. Этапы и артефакты

Предусмотрите необходимые этапы: определение критериев, формирование альтернатив, сбор оснований, сопоставление, проверка рекомендации и подготовка вывода. Число вариантов выбирайте по задаче; не добавляйте заведомо слабые варианты ради сравнения.

Для каждого этапа задайте назначение, исполнителя, необходимые сведения, результат и критерий завершения. Сохраните связь оценки с источником и условиями её применимости. Результат сравнения должен позволять следующему участнику понять причины предпочтения.

Если нужна доработка рекомендации после проверки или решения User, определите, какие замечания и выбранные условия должны попасть в итог.

## 4. Взаимодействие участников и User

Независимый поиск альтернатив полезен, когда существует риск слишком рано остановиться на очевидном варианте. Независимому проверяющему поручайте оспорить основания рекомендации, найти пропущенную альтернативу или условие, при котором выбор ухудшается.

User привлекается для определения личных приоритетов и принятия компромисса, который нельзя вывести из данных. Подготовьте понятные варианты и рекомендацию с причинами. Если задача состоит только в обоснованной рекомендации, отдельное утверждение в процессе не обязательно.

## 5. Итоговый результат и приёмка

Итог должен называть рекомендуемый вариант, основания выбора, существенные недостатки и условия применимости. Покажите ближайшую альтернативу и объясните, в какой ситуации она предпочтительнее. Если данных недостаточно для выбора, укажите решающий пробел и способ его устранения.

Результат готов, когда:

- альтернативы сравнены по одинаковым существенным критериям;
- обязательные ограничения проверены;
- оценки опираются на сведения, а допущения явно обозначены;
- преимущества и издержки рекомендации понятны;
- указаны условия, при которых рекомендация изменится.

На выходе проектирования представьте постановку задачи, метод сравнения, последовательность этапов и передачу артефактов, участие User и критерии обоснованного выбора.
