# Продуктовая часть: проектирование

Спроектируйте процесс разработки согласованного решения: системы, услуги, устройства, рабочего процесса или другой конструкции. Результат должен быть достаточно определён, чтобы следующий исполнитель мог использовать его по назначению.

## 1. Постановка задачи

Определите потребителя решения, его потребности, условия использования и проблему существующего подхода. Зафиксируйте необходимые возможности, ограничения, исходные материалы и границы проектирования.

Укажите требуемую глубину результата: концепция, проработанный проект или спецификация для реализации. Определите, кто получит результат и какие решения он должен суметь принять без повторного выяснения основных требований.

Отделите потребность от заранее предложенного способа её удовлетворения. Сохраняйте явно обязательные решения User; остальные рассматривайте как варианты, если они ещё не обоснованы.

## 2. Метод решения

Начните с сценариев использования и требований, затем определите устройство решения и проверьте его на этих сценариях. Для значимых решений рассмотрите альтернативы и объясните выбор. Уровень детализации должен соответствовать риску и следующему действию.

Смысловые сущности: потребность, сценарий, требование, часть решения, связь, ограничение, проектное решение. Проследите, какая часть решения удовлетворяет каждому существенному требованию и какие условия ей необходимы.

Проверьте совместимость частей, пограничные ситуации и последствия отказа. Проектные предположения, требующие эксперимента или измерения, обозначайте отдельно от подтверждённых свойств.

## 3. Этапы и артефакты

Предусмотрите необходимые этапы: уточнение требований, разработка подходов, выбор целостного решения, детализация, проверка и доработка. Не делайте отдельные этапы для частей, которые невозможно осмысленно оценить без совместного рассмотрения.

Для каждого этапа определите назначение, исполнителя, исходные требования, результат и критерий завершения. При передаче проекта сохраняйте причины ключевых решений, ограничения и нерешённые вопросы.

Если части разрабатывают разные участники, заранее определите их границы и согласуйте общие предположения. В итоговом артефакте устраните противоречия между частями и покажите результат целиком.

## 4. Взаимодействие участников и User

Независимые предложения полезны для решений с несколькими жизнеспособными подходами. Проверяющий должен оценивать проект по исходным требованиям и сценариям, включая неудобные случаи, а не только по объяснениям автора.

User выбирает приоритеты и существенные компромиссы: например, простоту против гибкости или полноту против стоимости. Подготовьте последствия вариантов до обращения к нему. Обычные проектные детали разрешайте в рамках уже заданных требований.

## 5. Итоговый результат и приёмка

Итог должен описывать назначение и устройство решения, взаимодействие его частей, ключевые решения с основаниями, ограничения и открытые вопросы. Добавляйте схемы, таблицы и примеры там, где они снимают неоднозначность.

Результат готов, когда:

- существенные требования покрыты или явно названы исключения;
- части решения согласованы между собой;
- основные и пограничные сценарии разобраны;
- проверенные свойства отделены от предположений;
- получателю достаточно деталей для заявленного следующего действия.

На выходе проектирования процесса представьте постановку задачи, способ разработки решения, этапы и передачу артефактов, распределение ответственности и критерии готовности проекта. Выпуск работающего продукта относится к отдельной задаче создания продукта.
