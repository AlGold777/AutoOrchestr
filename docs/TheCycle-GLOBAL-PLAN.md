# TheCycle — ГЛОБАЛЬНЫЙ ПЛАН (единый приоритет разработки)

**Статус:** обязательный маршрут к полностью работающему продукту.  
**Дата фиксации:** 2026-11-26.  
**Рабочая ветка:** `thecycle/c01-basic-adapter`.

## Цель

Один целостный автономный исследовательский движок над существующим Chrome MV3/Basic: принимает задачу, исполняет конечные Basic-pipeline через реальных провайдеров, анализирует результаты, сохраняет знания и открытые вопросы, выбирает следующий шаг, повторяет циклы до доказанного результата либо исчерпания допустимых ресурсов, корректно останавливается и восстанавливается после сбоев.

**Единица прогресса — завершённый сквозной пользовательский сценарий, а не количество модулей, коммитов и тестов отдельных утилит.**

## Правило отсутствия отклонений

1. Работать **исключительно по этапам G1 → G2 → G3 → G4 → G5**, без самостоятельных боковых задач.
2. Исправление отдельных компонентов разрешено **только если конкретный дефект блокирует следующий приёмочный сквозной сценарий**. Исправление включается в тот же этап и сразу проверяется в его интеграционном тесте.
3. Нельзя объявлять этап завершённым по наличию кода: нужен запускаемый сценарий и зафиксированное воспроизводимое доказательство.
4. Нельзя начинать polishing, рефакторинг, косметику, новые abstraction layers, backup/restore расширения или оптимизации без доказанной необходимости для критического пути.
5. Если реальный Chrome/учётные записи недоступны для автоматического испытания, этап помечается **BLOCKED: BROWSER/PROVIDER PROOF**; не подменять доказательство unit-тестом или декларацией.
6. Basic остаётся исполнительным движком, TheCycle — управляющим. Не создавать альтернативный несовместимый движок.

## G1 — СОБРАТЬ РАБОТАЮЩУЮ СИСТЕМУ (P0)

**Результат:** пользователь запускает TheCycle из UI, один конечный Basic pipeline исполняется через существующий транспорт провайдеров; по завершении появляется долговечно сохранённый результат.

Обязательные интеграции:
- UI команды Start/Stop/Status;
- `Research Orchestrator → Basic Adapter → Basic Engine → existing transport → Basic result`;
- версии pipeline, идентификаторы исследования/run и единственный владелец;
- durable intent до отправки и запрет повторной отправки при UNKNOWN;
- явная обработка отказов/невозможности доступа к моделям.

**Приёмка G1:** один запуск из реального UI, не менее одного фактического ответа модели, результат после перезагрузки страницы; лог отправки без дублирования.

## G2 — ЗАМКНУТЬ ВНЕШНИЙ ЦИКЛ (P0)

**Результат:** на основе результата первого Basic-run контроллер выбирает следующий запуск, передаёт контекст и выполняет не менее трёх последовательных циклов без повторных нажатий пользователя.

- аналитический слой извлекает наблюдения, ошибки, пробелы;
- состояние цикла и агрегированный контекст передаются между запусками;
- policy принимает проверяемое решение продолжить / остановить;
- бюджет, Stop и UNKNOWN ограничивают продолжение;
- цикл не зависит от бессрочной жизни MV3 service worker.

**Приёмка G2:** минимум три цикла одной задачи в реальном браузере, история решений и результаты доступны после рестарта.

## G3 — ДОБАВИТЬ ИНТЕЛЛЕКТУАЛЬНОЕ УПРАВЛЕНИЕ (P0)

**Результат:** система не только повторяет Basic, но строит и уточняет знания, отслеживает противоречия и меняет стратегию.

- атомизация выводов, доказательства, противоречия и открытые обязательства;
- независимая верификация решений с зафиксированной изоляцией контекста;
- planner предлагает проверяемую стратегию/план, policy валидирует её;
- запрещён ложный статус VERIFIED_SOLUTION;
- все решения объясняются референсами на результаты.

**Приёмка G3:** задача с неопределённым первым ответом требует изменения стратегии, закрытия проверки и зафиксированного объяснения финального решения.

## G4 — АВТОНОМНОСТЬ И ВОССТАНОВЛЕНИЕ (P0)

**Результат:** длительное исследование продолжается корректно в рамках ресурсов; отсутствие worker, закрытие страницы, остановка пользователя и аварии не приводят к невидимой потере данных или двойной отправке.

- durable scheduler / wakeup;
- reconcile UNKNOWN по подтверждённым данным провайдера, иначе безопасная пауза;
- обязательный проверенный post-commit backup перед продолжением;
- восстановление из копии с проверкой и безопасной активацией;
- защита от устаревшего владельца и неверного состояния.

**Приёмка G4:** сбои worker/tab/backup/permission/transport воспроизводимы; отсутствие повторной отправки и корректный конечный статус доказаны.

## G5 — ИНТЕГРАЛЬНАЯ ПРИЁМКА (P0)

**Результат:** TheCycle как единый продукт доказан сквозными испытаниями.

- реальные браузерные сценарии: 1 цикл, ≥3 цикла, смена стратегии, проверенный финал, лимит бюджета, Stop, worker restart, UNKNOWN, backup/restore, отказ разрешения;
- контроль логов, отсутствия дубликатов, бюджета, версий схем;
- 60 последовательных циклов с заданными фикстурами, отдельно ограниченный ресурсами реальный эксперимент;
- CI с проверкой маршрутов и браузерные тесты, записанные как PASS/FAIL с артефактами;
- установка расширения без деградации текущего Basic.

**Приёмка G5:** все обязательные P0 сценарии PASS, иначе проект не считается завершённым.

- entrypoint/пользовательский сценарий;

## Circle — реализация вертикального перехода G1 → G2

Терминология: Basic Engine — неизменяемый движок; Classic — существующий тип pipeline; Circle — новый тип; TheCycle — первая реализация Circle. Кнопка Start Circle запускает отдельный multi-run runtime. Предыдущий подтверждённый пакет и первичные ответы формируют ограниченный контекст следующего Basic-run. Программная fixedPolicy разрешает продолжение только после полного технического результата, до исчерпания общего бюджета или Stop. Это не G3: нет семантической верификации решения. Перед запуском требуется настроенный каталог, проверенная начальная копия, после каждого пакета и решения — подтверждённая копия. Исполнение пока зависит от открытой страницы результатов; закрытие страницы требует G4. G1 и Classic сохраняются; G1/G2 browser acceptance не объявляется пройденной. 

## Circle — штатная точка входа

Circle зарегистрирован в общем списке Pipelines (`CIRCLE`, runner `circle`). Выберите Circle, настройте модели на canvas, каталог резервирования и общий лимит вызовов, введите задачу в штатный composer и нажмите Run. Stop управляет всем исследованием; Status показывает сохранённое состояние. Экспериментальная панель скрыта. Classic и Basic Engine не изменены. Приёмка в реальном браузере требует установки текущей ветки.

## Перенос на 2.81.1116 (Claude, 2026-11-26)

Ветка влита в рабочую линию расширения слиянием (до коммита 2ae4ba91); новые коммиты ветки вливаются так же. Изменено при переносе:

- Рабочая страница Circle — `pipeline_panel.html` (там Basic в текущей версии); `result_new.html` сохранён.
- Адаптер и мост — под Basic 2.81.1116: исход шага по `model.id`; шаги `owner` отклоняются; при `input:none` отклоняется только `defaults.roundTask`.
- Исключение до вызова транспорта — `NOT_SENT` (бюджет возвращается), не `DISPATCH_UNKNOWN`. Доставленная неудача одной модели — её «нет ответа»; `UNKNOWN` — только когда неизвестно, ушёл ли запрос.
- Stop прерывает запросы моста (составной сигнал + `cancelRun` транспорта).
- `controller.releaseSettled` в `finally` обоих runtime: после штатного конца и Stop владение снимается, если запуск завершён и бэкап выполнен.
- `estimateCalls` в адаптере: цикл не стартует при остатке меньше оценки, пауза `BUDGET_INSUFFICIENT_FOR_CYCLE`.
- Мост `hold/release` на всё исследование: в паузах между циклами Basic, второй запуск, смена pipeline и редактирование заблокированы.
- `background/index.js`: модули TheCycle подключаются после основного `importScripts`, в try/catch.
- Тесты на `node:test` — `npm run test:thecycle`; Jest их исключает (`tests/jest.config.js`).

- `usesBasicCanvas()` в `results.js`: холст и схема Basic работают и для `runner: 'circle'`; `resumeCustomFromPage` отказывает при `circlePageRunner || theCycleHeld`.
- Доступ к каталогу: `directory-handle-manager.ensurePermission` / `restoreBackupDirectoryAccess` — первым действием в `startDebateFromPage` при Circle и в кнопке «Создать копию»; отказ — `RUN_BLOCKED` до первой отправки.
- Ротация: `backup-retention.createRetention` после проверенной копии в путях записи runtime, alarm и ручной копии (`recovery-runtime.js` и `backup-policy.js` ротацию пока не вызывают; порядок «10 последних» — по `createdAt` часов, не по порядку записи); хранит 10; защищены новая копия, `lastBackupId` незавершённых исследований, копии вне ledger `thecycleBackupLedger`.
- Stop во время отправки: `state-store.abandonRun` + `controller.closeStopped` — пачки остаются UNKNOWN, исследование `COMPLETED` с `closedReason: 'OWNER_STOP_UNRESOLVED'` (виден в Status), владение снято; `STALE_STATE` от Stop — пауза.
- Тесты: in-memory IndexedDB `tests/thecycle-fake-idb.js`.

Найдено при переносе и оставлено этапам G2/G4:
- Кнопка «Start Circle» G1-панели не запрашивает доступ к каталогу (запуск отклоняется в `openBackup`); `g1-runtime.js` без `closeStopped` — после Stop во время отправки владение остаётся.
- После сбоя или перезагрузки страницы во время отправки состояние остаётся RECONCILE/RUNNING, а владение — за прежним `ownerId`; новый запуск падает `TRANSPORT_OWNED`. Нужен путь `reconcile`/`takeOver` из UI. Очистка сохранённых данных способом восстановления не является.
- `maxAttempts: 1` в адаптере отключает исправляющие повторы Basic (`too_long`, формат): такой шаг сразу PARTIAL, политика ставит паузу.
- Живые проверки 26.11.2026 — `docs/pipelines/Circle_2026-11-26/notes/live-checks.md`: 1, 2, 5 PASS; 3 частично на 2.81.1116, PASS на 2.81.1117; 4 не получено. FSA-хэндл в service worker работает (фоновая копия по alarm проверена).

Установлено другое: мост брал `forceNewTabs` из снятого чекбокса и писал в уже открытые вкладки, в том числе в чат пользователя. С 2.81.1117 каждый цикл открывает новые вкладки; один повтор Stop → запуск прошёл. Старые вкладки не закрываются.
- Локальная модель (Qwen 4B), выбранная сверху, не попадает в схему Circle.
