# Задание для Codex: карточка ▶ — общие значения Custom для всех шагов

База: `main` 2.81.643 (54b4f12). Файлы: `results.js`, `disput/custom-engine.js`, `styles/pipeline.css`, `pipeline_panel.html` / `result_new.html` (только если нужна разметка), тесты, документация.

## Суть

Клик по `.entry-point` (`#entryPoint`, ▶ в колонке In) открывает карточку **общих значений** pipeline Custom.
Каждое значение действует во всех шагах, кроме тех, где у модели задано своё.

**Это наследование, а не копирование.** Значение из ▶ никогда не записывается в настройки модели.
При сборке запроса каждое поле разрешается по цепочке:

```
модель в шаге (customCardSettings[ref][model]) → ▶ (новое) → значение из кода (как сейчас)
```

Пустое / отсутствующее поле = «берётся уровнем выше». Правка в ▶ сразу действует везде, где нет своего значения.
Цепочку сделать одной функцией разрешения, через которую идут и сборка запроса, и карточка модели, и предпросмотр —
без второго пути. Структуру оставить готовой к уровню «раунд» между моделью и ▶ (UI раунда в эту задачу не входит).

## Что в карточке ▶

Только то, что сейчас вшито в код и пользователю недоступно:

| Поле | Сейчас в коде | Куда действует |
| --- | --- | --- |
| Задание раундов со входом (R2+) | `CUSTOM_ROUND_TASK`, `results.js` | `step.task` раундов, у которых есть вход. R1 не затрагивается (у него нет входа и задания) |
| Задание синтеза | `SYNTHESIS_TASK`, `disput/custom-engine.js` | шаги синтеза |
| Дисциплина: длина (шаблон), требования к содержанию, доставка, вопрос владельцу, исправление | `customDisciplineDefaults()` | те же поля, что сейчас в карточке модели |

**Не включать:**
- длину ответа в словах — она в шапке (`#debate-length-select`), общая с другими pipeline; второе место для неё не нужно;
- задачу — она в поле ввода;
- порядок работы и вход — UI для них нет нигде, отдельная задача.

UI, кнопки редактирования/очистки/сохранения, модальное окно — переиспользовать из `renderCustomBlockInspector`
(AGENTS.md: reuse before implementation). Во время прогона — только чтение, как у карточки модели.

## Изменения в карточке модели

1. Каждое поле показывает, откуда значение: **своё** или **общее (▶)**. У своего — действие «вернуть к общему» = удалить override.
2. Сохраняется только отличие: если введённое значение равно унаследованному, override не записывается.
   Иначе снимок общего значения «застынет» в модели и перестанет следовать за ▶.
3. Персональный запрос (`promptTemplate`) — полный текст, он уже не следует за заданием из ▶.
   Это верно, но в карточке нужна пометка: «Персональный запрос: общее задание не применяется; дисциплина применяется».
   (Дисциплина добавляется отдельно в `prepareCustomPrompts`, поэтому она продолжает наследоваться — проверить.)
4. Сравнение «персональный или собирается автоматически» (`request.value === preview.template`) должно идти с предпросмотром,
   собранным уже с учётом ▶; иначе после правки ▶ все модели покажутся «персональными».

## Хранение

Рядом с `customModelSettings` в конфиге pipeline (`capturePipelineConfig`), тем же механизмом, что `customCardSettings`:
- сохранённый pipeline хранит значения ▶ в своём конфиге;
- встроенный шаблон (Custom и др.) — только до перезагрузки страницы, шаблон не перезаписывается (правило шаблонов);
- «+» (новый pipeline) начинает с пустой ▶ = значения из кода;
- Export/Import pipelines переносят значения ▶.

## Проверка (тесты)

Проверять **текст, который реально уходит** (вход `runModelBatch` / `MessageDelivery.prepare`), а не только предпросмотр —
расхождение карточки и отправки уже было.

1. Правка задания в ▶ → уходит в R2+ у всех моделей без своего значения; R1 не меняется.
2. У модели своё значение → оно уходит, правка ▶ его не меняет.
3. «Вернуть к общему» → снова следует за ▶.
4. Ввод в модели значения, равного общему → override не сохраняется; последующая правка ▶ до модели доходит.
5. Персональный запрос: правка задания в ▶ не влияет, правка дисциплины в ▶ влияет.
6. Сохранение / загрузка / экспорт-импорт pipeline сохраняют ▶; встроенный шаблон после перезагрузки возвращается к коду.
7. Карточка модели корректно показывает «своё / общее» после правки ▶.
